## Hints

- Can a value of type `Point` have more properties than `x` and `y`?
- Is `Point` an exact type or an open one?
- When is it safe to cast the keys, and what can you use instead of a cast?

## Answer

Because TypeScript is **structurally typed, object types are open**. A value of type `Point` must have *at least* `x` and `y`, but it can carry any number of extra properties. At runtime `Object.keys` returns all of them, so `(keyof Point)[]` would be a lie:

```ts
interface Point { x: number; y: number }

const labelled = { x: 1, y: 2, label: 'A' };
const p: Point = labelled; // OK: extra properties are allowed (not a fresh object literal)

function sum(p: Point) {
  let total = 0;
  for (const k of Object.keys(p) as (keyof Point)[]) {
    total += p[k]; // at runtime k is also 'label', so total becomes "3A"
  }
  return total;
}
```

Without the cast, `p[k]` is an error ("`string` can't be used to index `Point`"). That error is TypeScript being correct, not annoying.

**Type-safe options:**

- **Iterate over a known list of keys** instead of the object:

  ```ts
  const POINT_KEYS = ['x', 'y'] as const satisfies readonly (keyof Point)[];
  for (const k of POINT_KEYS) total += p[k];
  ```

- **Use `Object.entries` / `Object.values`** when you only need values. For a type with an index signature (`Record<string, number>`) you get typed values; for a plain interface you get `any`, so add your own check.
- **Use a `Map`** when the keys are really dynamic data, not a fixed shape.
- **Cast only when you created the object yourself** and know it has no extra keys (for example a constant config literal), and keep the cast inside one small helper:

  ```ts
  const typedKeys = <T extends object>(o: T) => Object.keys(o) as (keyof T)[];
  ```

  Name it so reviewers know it's an assertion, not a guarantee.

**Related:** `for...in` has the same problem and also walks the prototype chain. Excess property checks only apply to *fresh* object literals, which is why `const p: Point = { x: 1, y: 2, label: 'A' }` is an error but the example above isn't.
