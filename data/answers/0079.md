## Hints

- How does FastAPI know whether a parameter comes from the path, the query string or the JSON body?
- What HTTP status code and response body does the client get when validation fails?
- How do you add constraints such as minimum length or custom business rules?

## Answer

FastAPI reads your **type hints** and uses **Pydantic v2** to parse, validate and convert input:

- Simple types matching a path placeholder → **path params**.
- Other simple types → **query params**.
- Parameters typed as a `BaseModel` → **JSON body**.
- `Header()`, `Cookie()`, `Form()`, `File()` for other sources.

```python
from typing import Annotated
from pydantic import BaseModel, EmailStr, Field, field_validator
from fastapi import FastAPI, Query

class UserCreate(BaseModel):
    email: EmailStr
    name: str = Field(min_length=1, max_length=100)
    age: int = Field(ge=13)

    @field_validator("name")
    @classmethod
    def strip_name(cls, v: str) -> str:
        return v.strip()

class UserOut(BaseModel):
    id: int
    email: EmailStr

app = FastAPI()

@app.post("/users", response_model=UserOut, status_code=201)
async def create_user(user: UserCreate, notify: Annotated[bool, Query()] = False):
    ...
```

If validation fails, FastAPI returns **422 Unprocessable Entity** with a JSON list of errors (location, message, type), before your code runs. Types are coerced in lax mode (`"42"` → `42`).

`response_model` (or the return type annotation) **filters and validates output**, which prevents leaking fields like password hashes. All models also feed the auto-generated OpenAPI docs at `/docs`.

v2 specifics worth knowing: `field_validator`/`model_validator` replace v1's `validator`/`root_validator`, `model_config = ConfigDict(...)` replaces `class Config`, and `model_dump()` replaces `.dict()`.
