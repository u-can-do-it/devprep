## Hints

- What can an attribute's constructor arguments be, and why can't you pass a lambda or a `new` object?
- Which of `typeof(T)`, `GetProperties()`, `PropertyInfo.GetValue` and `MethodInfo.Invoke` is expensive, and what can you cache?
- How does the DI container know which constructor to call, and what would that look like without reflection?

## Answer

**Attributes** are metadata attached to types, members, parameters or assemblies. They do nothing on their own; something has to **read** them, usually a framework through reflection: `[HttpGet]` (routing), `[Required]` (validation, #587), `[Authorize]` (#586), `[JsonPropertyName]` (#607), `[Fact]` (xUnit discovery, #588). A few are read by the compiler instead: `[Obsolete]`, `[Conditional]`, `[CallerMemberName]`.

```csharp
[AttributeUsage(AttributeTargets.Property, AllowMultiple = false, Inherited = true)]
public sealed class AuditedAttribute(string reason) : Attribute
{
    public string Reason { get; } = reason;
    public bool IncludeOldValue { get; init; } = true;       // named argument: [Audited("GDPR", IncludeOldValue = false)]
}

public sealed class Patient
{
    [Audited("medical data")] public string Diagnosis { get; set; } = "";
    public string Nickname { get; set; } = "";
}
```

Arguments must be **compile-time constants** (primitives, strings, enums, `typeof(...)`, arrays of those) because they're stored in metadata, not executed. Generic attributes (`[Validator<Order>]`) exist since C# 11; the `Attribute` suffix is optional at the use site.

**Reading them with reflection**

```csharp
static IEnumerable<(string Name, AuditedAttribute Audit)> AuditedProperties(Type type) =>
    from p in type.GetProperties(BindingFlags.Public | BindingFlags.Instance)
    let a = p.GetCustomAttribute<AuditedAttribute>()
    where a is not null
    select (p.Name, a);

foreach (var (name, audit) in AuditedProperties(typeof(Patient)))
    Console.WriteLine($"{name}: {audit.Reason}");               // Diagnosis: medical data
```

Reflection lets code inspect and use types it didn't know at compile time: `GetProperties()`, `GetMethod(...)`, `PropertyInfo.GetValue(obj)`, `MethodInfo.Invoke(obj, args)`, `Activator.CreateInstance(type)`, `Assembly.GetTypes()`, `MakeGenericType(...)`. Typical uses in application code: registering every `IEventHandler<T>` found in an assembly (what Scrutor does), mapping objects, plugin loading with `AssemblyLoadContext`, test and benchmark discovery.

```csharp
var handlers = typeof(Program).Assembly.GetTypes()
    .Where(t => t is { IsAbstract: false, IsInterface: false })
    .SelectMany(t => t.GetInterfaces()
        .Where(i => i.IsGenericType && i.GetGenericTypeDefinition() == typeof(IEventHandler<>))
        .Select(i => (Service: i, Impl: t)));
foreach (var (service, impl) in handlers) builder.Services.AddScoped(service, impl);
```

**What it costs**

- **Lookups** (`GetProperties`, `GetCustomAttribute`) walk metadata and allocate on every call: **cache** the result per type (`ConcurrentDictionary<Type, …>`, #592, or a static generic class `Cache<T>`).
- **Late-bound calls** (`MethodInfo.Invoke`, `PropertyInfo.GetValue`) box arguments and results and check access each time. .NET 7+ made `Invoke` several times faster, but it's still far slower than a direct call. For hot paths create a **delegate** once (`method.CreateDelegate<Func<Patient, string>>()`) or compile an expression tree, which is what serializers and mappers did for years.
- Reflection defeats the **trimmer and Native AOT** (#601): members found by name at run time are invisible to the linker. Annotate with `[DynamicallyAccessedMembers]` or avoid it.
- `BindingFlags.NonPublic` breaks encapsulation and breaks at run time on a rename. `[UnsafeAccessor]` (.NET 8) gives compile-checked, zero-cost access to a private member when you really need it (tests, framework code).

**Compile-time alternatives**

| Need | Instead of reflection |
|---|---|
| a member's name for logs, exceptions, binding | `nameof(x.Prop)`, `[CallerMemberName]`, `[CallerArgumentExpression]` |
| serialization, logging, regex, DTO mapping | **source generators**: `[JsonSerializable]`, `[LoggerMessage]` (#589), `[GeneratedRegex]`, Mapperly; they emit the code you'd write by hand, checked at build time |
| "what type is this?" decisions | polymorphism, pattern matching (#580), generics with constraints (#577) |
| finding implementations | explicit registration, or a generated registry; startup time stays predictable |

Rule of thumb: reflection is fine at **startup** (scan once, build caches) and in tooling; keep it out of per-request paths, and prefer a generator when the information is already known at compile time.

**Follow-up:** `typeof(Patient).GetProperty("diagnosis")` returns `null`. Why, and how do you make it robust? (Reflection lookups are case-sensitive; pass `BindingFlags.IgnoreCase | BindingFlags.Public | BindingFlags.Instance`, or avoid string lookups altogether with `nameof(Patient.Diagnosis)`.)
