## Hints

- What problem do all of these approaches try to solve in global CSS?
- Which approaches add work at runtime in the browser, and which are fully compiled?
- How do React Server Components and streaming change the picture for CSS-in-JS?

## Answer

Every approach tries to tame the same thing: **global scope and specificity conflicts**, plus dead CSS, in large codebases.

**BEM (naming convention)** — `.card__title--large`

- Pros: no tooling, flat single-class specificity, readable.
- Cons: enforced only by discipline, long names, and dead styles pile up because nothing tracks usage.

**CSS Modules** — `import s from './Card.module.css'` gives locally scoped class names generated at build time.

- Pros: real scoping, plain CSS, zero runtime, works with Server Components, built into Vite and Next.js.
- Cons: dynamic styling goes through class toggles or CSS variables. Sharing styles takes `composes` or global tokens.

**Utility-first (Tailwind v4)** — `class="flex gap-4 rounded-lg p-4"`

- Pros: very fast to build with, a consistent design scale, the CSS bundle grows slowly because utilities are reused, no naming, zero runtime, and styles are deleted together with the markup.
- Cons: noisy markup, a learning curve, components need abstractions to avoid repetition (`cva`, `tailwind-merge`), and it's harder to express complex selectors.

**CSS-in-JS**

- **Runtime** (styled-components, Emotion): co-located and dynamic from props. But it injects styles during render, which costs performance, and it **doesn't work in React Server Components**, so it needs client components and SSR workarounds. styled-components is now in maintenance mode, and the ecosystem has moved away from runtime injection.
- **Zero-runtime** (vanilla-extract, Panda CSS, StyleX, Linaria): TypeScript-authored, type-safe, and extracted to static CSS at build time. Compatible with RSC.

**How I'd choose for a React app in 2026:**

- Product apps and fast teams: **Tailwind**, plus a headless component library (Radix, React Aria) and CSS variables for tokens.
- A design system that needs strict APIs or type-safe tokens: **CSS Modules** or a **zero-runtime CSS-in-JS** library.
- Don't start new code on runtime CSS-in-JS with the App Router.
- Whatever you choose, keep **design tokens** in CSS custom properties, and use `@layer` to control the order of third-party, base and utility styles.

**Follow-up:** the decision is also organizational. Consistency, onboarding time and the cost of migrating later often matter more than raw performance.
