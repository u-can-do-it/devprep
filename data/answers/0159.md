## Hints

- What exactly does `const` protect: the variable binding or the value it points to?
- Does `Object.freeze` affect nested objects?
- What happens when you write to a frozen object in strict mode compared with sloppy mode?

## Answer

**`const`** stops the **variable** from being **reassigned**. The object it points to can still be changed:

```js
const user = { name: 'Ann' };
user.name = 'Bo';     // fine
user = {};            // TypeError: Assignment to constant variable
```

**`Object.freeze(obj)`** protects the **object**: no new properties, no deletes, and all existing properties become non-writable and non-configurable. Writes are silently ignored in sloppy mode and throw a TypeError in strict mode (which includes modules and classes).

The freeze is **shallow**:

```js
const cfg = Object.freeze({ db: { host: 'x' } });
cfg.db = null;        // blocked
cfg.db.host = 'y';    // allowed: the nested object isn't frozen
```

Weaker levels of protection:

- `Object.seal`: no adding or removing properties, but existing values can still change.
- `Object.preventExtensions`: no new properties only.

For real immutability, freeze recursively:

```js
function deepFreeze(obj) {
  for (const value of Object.values(obj)) {
    if (value && typeof value === 'object' && !Object.isFrozen(value)) deepFreeze(value);
  }
  return Object.freeze(obj);
}
```

In practice, most code achieves immutability by convention instead: create new objects rather than mutating (`{ ...state, x: 1 }`, `toSorted`, `structuredClone`), and enforce it at compile time with TypeScript (`readonly`, `as const`). Freezing is useful for shared config, constants and catching accidental mutation in development.

**Follow-up:** freezing doesn't help with `Map`/`Set` contents or `Date` values, because their data lives in internal slots, not in properties.
