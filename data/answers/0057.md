## Hints

- Does adding `role="button"` to a `<div>` make it keyboard-accessible?
- Which native HTML element would you use instead of building one with ARIA?
- How does a screen reader learn that a custom dropdown just opened, or that a toast appeared?

## Answer

ARIA (Accessible Rich Internet Applications) adds **semantics** to the accessibility tree — roles, states and properties — that assistive technology reads. It **does not add behavior**: no focusability, no keyboard handling, no styling.

**The first rule of ARIA: don't use it if a native element does the job.** `<button>`, `<a href>`, `<input type="checkbox">`, `<dialog>`, `<details>`, `<select>` come with roles, states and keyboard support built in. Surveys of real sites consistently find pages with ARIA have *more* accessibility errors, because it's easy to get wrong.

```html
<!-- Bad: looks like a button, isn't one -->
<div role="button" onclick="save()">Save</div>  <!-- no focus, no Enter/Space -->

<!-- Good -->
<button type="button" onclick="save()">Save</button>
```

**When ARIA is the right tool:**

- **Labels** where there's no visible text: `aria-label` on an icon button, `aria-labelledby`/`aria-describedby` to link text.
- **States** of custom or disclosure widgets: `aria-expanded`, `aria-pressed`, `aria-selected`, `aria-current="page"`, `aria-invalid`.
- **Live regions** for dynamic updates: `aria-live="polite"` or `role="status"`/`role="alert"` for toasts and form errors.
- **Composite widgets** with no native equivalent (tabs, combobox, tree grid) — follow the WAI-ARIA Authoring Practices patterns, including their keyboard interactions.
- **Hiding decorative content**: `aria-hidden="true"` (never on focusable elements).

**Common mistakes:** redundant roles (`<button role="button">`), `aria-label` on non-interactive `<div>`s, conflicting roles (`<h2 role="button">`), stale states that aren't updated, `aria-hidden` on content that still receives focus.

**Follow-up:** test with a real screen reader (VoiceOver, NVDA) and axe/Lighthouse — automated tools only catch part of the issues.
