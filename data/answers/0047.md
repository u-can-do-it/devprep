## Hints

- What does the HTML parser do when it hits a plain `<script src>` in the middle of the document?
- Do `async` scripts run in the order they appear in the HTML?
- Which one is guaranteed to run after the DOM is fully parsed?

## Answer

> A script tag can block the browser from showing the page. A plain `<script>` stops HTML parsing until the script downloads and runs. `async` downloads in parallel and runs as soon as it arrives, in no guaranteed order, which suits independent scripts like analytics. `defer` also downloads in parallel but runs after parsing finishes, in document order, which suits app code that uses the DOM. Module scripts (`type="module"`) are deferred by default.

All three differ in **when the script is downloaded and when it executes** relative to HTML parsing.

- **`<script>` (classic)** — the parser **stops**, downloads the script, executes it, then continues. This is **render-blocking**, which is why scripts used to be placed at the end of `<body>`.
- **`<script async>`** — downloaded **in parallel** with parsing and executed **as soon as it arrives**, pausing the parser briefly. Execution order is **not guaranteed**. Good for independent scripts: analytics, ads.
- **`<script defer>`** — downloaded in parallel, executed **after parsing finishes**, right before `DOMContentLoaded`, **in document order**. Good for app code that touches the DOM or depends on other scripts.

```html
<script src="/analytics.js" async></script>
<script src="/vendor.js" defer></script>
<script src="/app.js" defer></script> <!-- runs after vendor.js -->
```

Notes:

- **`type="module"`** scripts are **deferred by default**; adding `async` makes them run as soon as they and their imports are ready.
- `async`/`defer` only apply to external scripts (with `src`), except `async` on inline modules.
- Scripts inserted dynamically via JS behave like `async` by default.
- CSS still blocks script execution: a script waits for pending stylesheets because it might read computed styles.

**Follow-up:** use `<link rel="preload">` or `modulepreload` to fetch critical scripts earlier, and Next.js's `<Script strategy="afterInteractive" | "lazyOnload">` for third-party code.
