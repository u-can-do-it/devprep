## Hints

- Which tool can tell you not only *that* a component rendered, but *why*?
- When a parent re-renders, what happens to its children by default?
- Before memoizing, could you move the state somewhere so fewer components depend on it?

## Answer

**1. Measure first, in a profiling or production-like build:**

- **React DevTools Profiler:** record an interaction, then use the flamegraph and ranked views to see render durations. Enable "Record why each component rendered" to get answers like "props changed: `onSelect`", "hook 2 changed", or "parent rendered".
- **"Highlight updates when components render"** shows re-renders visually.
- **React Performance tracks** in the browser's Performance panel (React 19.2) show scheduler priorities and component work alongside the rest of the frame.
- The **`<Profiler onRender>`** API, for collecting timings programmatically.

**2. Common causes:**

- A parent re-renders, so all its children re-render. That's the default, and usually cheap.
- A new object, array or function prop every render defeats `memo`.
- A Context value changes, so every consumer re-renders.
- State lives too high. Typing in a search box re-renders the whole page.
- Unstable `key`s cause remounts, not just re-renders.

**3. Fixes, from structural to tactical:**

- **Move state down** into the component that uses it.
- **Lift content up:** pass expensive subtrees as `children`. Elements created by the parent don't re-render when the wrapper's state changes.
- **Split Contexts** and use selector-based stores.
- **Memoize:** `React.memo` plus stable props, or let the **React Compiler** do it.
- **Make expensive work non-urgent** with `useTransition`/`useDeferredValue`, or **virtualize** long lists.

```jsx
// Typing in <SearchBox> no longer re-renders <ExpensiveGrid>
function Page() {
  return <Shell header={<SearchBox />}><ExpensiveGrid /></Shell>;
}
```

**Remember:** a re-render isn't a bug by itself. Optimize only renders that are measurably slow or that hurt INP.
