## Hints

- Does every keystroke really need to go through React state?
- What does a function passed to `<form action>` receive, and what happens to the inputs after it succeeds?
- If you validate on the client, do you still need to validate on the server?

## Answer

There are three main approaches. Choose by form size and needs.

**1. Controlled with `useState`.** Every field is bound to state. It's simple for small forms and for fields that need live behavior (input masks, dependent fields, instant validation). The cost is a re-render on every keystroke and boilerplate as the form grows.

**2. Uncontrolled with React 19 form actions.** The DOM holds the values. Pass a function to `action` and read a `FormData`. Pair it with `useActionState` for result and pending state, and `useFormStatus` in the submit button:

```jsx
const [state, formAction, isPending] = useActionState(async (prev, fd) => {
  const parsed = Schema.safeParse(Object.fromEntries(fd));
  if (!parsed.success) return { errors: parsed.error.flatten().fieldErrors, values: Object.fromEntries(fd) };
  await save(parsed.data);
  return { errors: {} };
}, { errors: {} });

<form action={formAction}>
  <input name="email" type="email" required defaultValue={state.values?.email} />
  ...
</form>
```

This works with Server Actions and progressive enhancement. Note: React **resets** the form after the action. To keep the user's input on error, return the values and use `defaultValue`.

**3. React Hook Form (+ Zod resolver).** Inputs are registered as uncontrolled, so re-renders are minimal. You get field arrays, dirty and touched tracking, and schema validation. It's the usual choice for large, dynamic forms.

**Validation in every approach:**

- Use native constraints (`required`, `type`, `pattern`) as a free first layer.
- Use a schema (Zod or Valibot) **shared between client and server**.
- **Always re-validate on the server.** Client checks are only for UX.
- Use accessible errors: `aria-invalid`, `aria-describedby`, and focus the first invalid field.

**Follow-up:** Formik and Redux-Form are legacy. New code uses one of the three approaches above.
