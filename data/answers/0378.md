## Hints

- If an attacker can make your browser use a session ID they already know, what happens after you log in?
- What should happen to the session identifier when a user's privilege level changes?
- What does "log out" need to do on the server, not just in the browser?

## Answer

**Session fixation**: the attacker gets a valid session ID first (by visiting the site), then makes the victim use it (a link with `?sessionid=...`, a cookie set from a compromised subdomain, or a shared computer). The victim logs in, the server marks **that same ID** as authenticated, and the attacker, who knows the ID, is now logged in as the victim.

**Fix: regenerate the session ID on login** and on any privilege change (MFA completed, role elevation, "sudo mode"). Throw away the old ID.

```js
// express-session
app.post('/login', async (req, res, next) => {
  const user = await verifyCredentials(req.body);
  req.session.regenerate((err) => {
    if (err) return next(err);
    req.session.userId = user.id;
    res.redirect('/dashboard');
  });
});
```

A secure session lifecycle overall:

- **Creation**: a long random ID from a CSPRNG (128+ bits of entropy), opaque, with no user data in it.
- **Transport**: cookie only, never in URLs; `HttpOnly; Secure; SameSite=Lax`, ideally with the `__Host-` prefix so subdomains can't set it.
- **Accept only server-issued IDs**: reject unknown IDs instead of adopting them.
- **Timeouts**: an idle timeout (e.g. 30 min for sensitive apps) and an absolute lifetime, both enforced **server-side**.
- **Logout**: delete the session on the server and clear the cookie. Offer "log out of all devices" by deleting all of a user's sessions, and do that automatically after a password change.
- **Re-authenticate** for sensitive actions (change email/password, payouts).
- **Monitoring**: optionally bind sessions to signals like device or rough geo and flag big changes, without hard-binding to IP (mobile IPs change).

**Follow-up:** How is this different with JWTs? Stateless tokens can't be revoked server-side without a denylist or short expiry, which is why many apps keep server sessions.
