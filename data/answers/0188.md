## Hints

- Which proposal does TypeScript 5.0+ implement when `experimentalDecorators` is off?
- What arguments does a standard decorator receive, compared with a legacy one?
- Why can't NestJS-style parameter decorators simply switch to the new standard?

## Answer

TypeScript now supports **two incompatible decorator systems**:

**1. Standard decorators (TC39 Stage 3, TS 5.0+, no flag).** A decorator is a function `(value, context)`:

- `value` is the decorated thing (method, class, getter, field initializer).
- `context` describes it: `kind`, `name`, `static`, `private`, `addInitializer` and `metadata`.
- It can return a replacement (for example a wrapped method).

```ts
function logged<This, Args extends unknown[], R>(
  target: (this: This, ...args: Args) => R,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => R>,
) {
  return function (this: This, ...args: Args): R {
    console.log(`calling ${String(context.name)}`);
    return target.call(this, ...args);
  };
}

class Api {
  @logged getUser(id: string) { /* ... */ }
  @tracked accessor count = 0;   // `accessor` keyword: auto getter/setter
}
```

Decorator metadata works through `context.metadata` and `Class[Symbol.metadata]` (TS 5.2). Native engine support is still limited, so TypeScript, Babel or esbuild transpile them.

**2. Legacy `experimentalDecorators`.** These use a different signature (`target, propertyKey, descriptor`). They support **parameter decorators** and, with `emitDecoratorMetadata` plus `reflect-metadata`, emit runtime type info (`design:type`, `design:paramtypes`). NestJS and TypeORM rely on this for dependency injection and ORM mapping.

**Key differences:**

| | Standard | Legacy |
|---|---|---|
| Spec | TC39 Stage 3 | old TS-only design |
| Parameter decorators | no | yes |
| Emitted type metadata | no | yes (`emitDecoratorMetadata`) |
| Field decorators | can only transform the initial value | receive the prototype |

**In practice:** use standard decorators for new code that doesn't depend on a framework. Keep the legacy flag if your framework requires it, and don't mix the two systems in one project. Decorators are **not erasable syntax**, so Node's type stripping can't run them without a transform step.
