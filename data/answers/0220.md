## Hints

- How would you design `<Tabs>` so users can rearrange tabs and panels freely, without passing a huge config object?
- How do `Tabs.Tab` and `Tabs.Panel` know which one is active without the user wiring props between them?
- Should the component work both controlled and uncontrolled?

## Answer

**Compound components** are a set of components that work together and share implicit state through Context, while the consumer controls the **structure and markup**. Think of `<select>` and `<option>`. Compare it to a "config" API (`<Tabs items={[...]} />`), which grows a prop for every customization.

```tsx
const TabsCtx = createContext<{ value: string; setValue(v: string): void; id: string } | null>(null);
const useTabs = () => {
  const ctx = use(TabsCtx);
  if (!ctx) throw new Error('Tabs.* must be used inside <Tabs>');
  return ctx;
};

function Tabs({ value: controlled, defaultValue, onValueChange, children }: TabsProps) {
  const [inner, setInner] = useState(defaultValue ?? '');
  const value = controlled ?? inner;
  const setValue = (v: string) => { if (controlled === undefined) setInner(v); onValueChange?.(v); };
  const id = useId();
  return <TabsCtx value={{ value, setValue, id }}>{children}</TabsCtx>;
}

function Tab({ value, children }: { value: string; children: React.ReactNode }) {
  const t = useTabs();
  return (
    <button role="tab" id={`${t.id}-tab-${value}`} aria-selected={t.value === value}
            aria-controls={`${t.id}-panel-${value}`} onClick={() => t.setValue(value)}>
      {children}
    </button>
  );
}
Tabs.List = (p: { children: React.ReactNode }) => <div role="tablist">{p.children}</div>;
Tabs.Tab = Tab;
Tabs.Panel = /* role="tabpanel", hidden unless active */ TabPanel;
```

**API design principles:**

- **Controlled and uncontrolled** support (`value`/`defaultValue`/`onValueChange`), like native inputs.
- **Accessibility built in:** roles, `aria-*` links via `useId`, roving-tabindex keyboard navigation.
- **Escape hatches:** forward `className` and other props and `ref` to the DOM, and consider `asChild` for custom elements.
- **Helpful errors** when parts are used outside the root.
- **Headless** option: ship behavior separately from styles. Radix, React Aria and Ark UI all follow this pattern.

**Trade-offs:** more exports to learn, Context re-renders all parts when state changes (fine for small widgets), and harder static validation of children. Avoid `React.Children.map`/`cloneElement` for this. They break as soon as a part is wrapped in another component.
