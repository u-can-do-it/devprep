## Hints

- Does the browser download HTML or something else when you click a `<Link>`?
- Which parts of the tree are re-rendered when you move from `/dashboard/a` to `/dashboard/b`?
- Where does the "instant" feeling come from, and when does Next.js fall back to a full page load?

## Answer

**Initial load (hard navigation):** the server returns **HTML** for a fast first paint, plus the **RSC payload** (the serialized Server Component tree with client component references) inlined in the document. React hydrates the Client Components, and the router seeds its client cache with the current segments.

**Prefetch:** in production, `<Link>`s in the viewport (or on hover) trigger background requests for the target's RSC data. Static routes are prefetched fully. Dynamic routes are prefetched up to the nearest `loading.tsx` (or the static shell with Cache Components). Since v16, shared layouts are fetched once and only missing segments are requested.

**Click → soft navigation:**

1. `<Link>` prevents the browser's default navigation and calls the router inside a **React transition**, so the current UI stays interactive.
2. The router compares the current and target **segment trees**. Only segments below the first changed one need new data. Shared layouts are **not** re-rendered (partial rendering), so their client state survives.
3. If prefetched data is in the **client router cache**, it renders immediately. Otherwise it shows the prefetched `loading.tsx` and requests the RSC payload (an `RSC` request header for the changed segments).
4. The server renders those Server Components and **streams** the payload. React reconciles it into the existing tree and fills in Suspense boundaries as chunks arrive.
5. The URL is updated with the History API, and scroll is handled (scroll to the new page segment, or keep the position with `scroll={false}`).

**Back/forward** reuses cached segments and restores scroll. **`router.refresh()`** re-fetches the current route's server data while keeping client state. A Server Action that revalidates sends a fresh payload in the **same response**.

**Hard navigations still happen** when crossing **different root layouts**, using a plain `<a>` or `window.location`, on errors in the router, or on **version skew** (a deployment ID mismatch after a deploy).

**Caching nuances:** cached segments have a stale time (`cacheLife` stale, `staleTimes` config, with a minimum of 30 s for cached data). Since v15, dynamic page segments aren't reused from the client cache by default, which avoids showing stale personalized data.

**Follow-up:** explain why Server Component code never runs in the browser, yet the UI updates: the browser only receives the payload, never the component's code.
