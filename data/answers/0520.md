## Hints

- Why is `setCount((c) => c + 1)` safer than `setCount(count + 1)`?
- How do you add, change and remove an item in an array in state without mutating it?
- Does "items left" or the filtered list need its own state?
- What should you use as the `key` for todos?

## Answer

**Counter:** use the functional update so several updates in one event don't overwrite each other (#34).

```jsx
function Counter({ step = 1 }) {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount((c) => c - step)} aria-label="Decrease">−</button>
      <output aria-live="polite">{count}</output>
      <button onClick={() => setCount((c) => c + step)} aria-label="Increase">+</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
```

**Todo list:**

```jsx
function TodoApp() {
  const [todos, setTodos] = useState([]);
  const [text, setText] = useState('');
  const [filter, setFilter] = useState('all');   // 'all' | 'active' | 'done'

  function addTodo(e) {
    e.preventDefault();                          // a <form> gives you "Enter to add" for free
    const title = text.trim();
    if (!title) return;
    setTodos((list) => [...list, { id: crypto.randomUUID(), title, done: false }]);
    setText('');
  }

  const toggle = (id) =>
    setTodos((list) => list.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
  const remove = (id) => setTodos((list) => list.filter((t) => t.id !== id));

  // derived values: computed on every render, not stored in state
  const visible = todos.filter((t) => (filter === 'all' ? true : filter === 'done' ? t.done : !t.done));
  const left = todos.filter((t) => !t.done).length;

  return (
    <section>
      <form onSubmit={addTodo}>
        <label htmlFor="new-todo">New todo</label>
        <input id="new-todo" value={text} onChange={(e) => setText(e.target.value)} />
        <button type="submit">Add</button>
      </form>

      <ul>
        {visible.map((t) => (
          <li key={t.id}>
            <label>
              <input type="checkbox" checked={t.done} onChange={() => toggle(t.id)} />
              <span style={{ textDecoration: t.done ? 'line-through' : 'none' }}>{t.title}</span>
            </label>
            <button onClick={() => remove(t.id)} aria-label={`Delete ${t.title}`}>×</button>
          </li>
        ))}
      </ul>

      <p>{left} {left === 1 ? 'item' : 'items'} left</p>
      <div role="group" aria-label="Filter">
        {['all', 'active', 'done'].map((f) => (
          <button key={f} onClick={() => setFilter(f)} aria-pressed={filter === f}>{f}</button>
        ))}
      </div>
    </section>
  );
}
```

**What they check:**

- **Immutable updates:** spread to add, `map` to change, `filter` to remove. Never `push` or `todo.done = true` (#199).
- **Stable keys:** a generated id, not the array index. Index keys break when items are removed or reordered (#32).
- **Derived state:** the visible list and the "left" count are computed, not stored.
- **Functional updates** (`setTodos((list) => ...)`) whenever the new state depends on the old one.
- **Accessibility:** labelled inputs, a real checkbox, and delete buttons that say what they delete.

**Follow-ups:** inline editing (double-click to edit, Enter saves, Escape cancels), "clear completed", saving to `localStorage` (#511), and moving the logic into `useReducer` (#202).
