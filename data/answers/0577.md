## Hints

- Are .NET generics erased at runtime like Java's, or does the runtime know `List<int>` from `List<string>`?
- If `List<string>` were a `List<object>`, what could you `Add` to it?
- Why is it safe to treat a *producer* of strings as a producer of objects, and a *consumer* of objects as a consumer of strings?

## Answer

**Reified generics.** Unlike Java, .NET keeps generic type arguments at runtime: `typeof(List<int>) != typeof(List<string>)`, and `default(T)`, `typeof(T)` and `new T()` work. For value types the JIT generates specialized code per type (`List<int>` stores raw `int`s, no boxing, see #562); reference types share one implementation.

**Constraints** say what `T` must support, so the compiler lets you use it:

| Constraint | Meaning |
|---|---|
| `where T : class` / `class?` | reference type (non-nullable / nullable) |
| `where T : struct` | non-nullable value type |
| `where T : notnull` | any non-nullable type |
| `where T : unmanaged` | a value type with no references inside (usable with pointers, `stackalloc`) |
| `where T : new()` | has a public parameterless constructor |
| `where T : IComparable<T>` / `BaseClass` | implements the interface / derives from the class |
| `where T : allows ref struct` | C# 13+: `T` may be a `ref struct` like `Span<T>` |

```csharp
public static T Max<T>(IEnumerable<T> items) where T : IComparable<T>
{
    using var e = items.GetEnumerator();
    if (!e.MoveNext()) throw new InvalidOperationException("Empty sequence");
    var max = e.Current;
    while (e.MoveNext())
        if (e.Current.CompareTo(max) > 0) max = e.Current;
    return max;
}
```

Static abstract interface members (C# 11, used by generic math: `INumber<T>`) let a constraint require static methods and operators too.

**Variance: why `List<string>` is not a `List<object>`**

If it were, this would compile and break type safety at runtime:

```csharp
List<object> objects = new List<string>();   // not allowed
objects.Add(42);                             // an int in a list of strings
```

`List<T>` both **takes `T` in** (`Add`) and **gives `T` out** (indexer), so it must be **invariant**. Interfaces and delegates can declare variance when `T` only flows in one direction:

| | Keyword | `T` appears only as | Allowed conversion | Examples |
|---|---|---|---|---|
| Covariance | `out T` | return values | `IEnumerable<string>` → `IEnumerable<object>` | `IEnumerable<out T>`, `IReadOnlyList<out T>`, `Func<out TResult>` |
| Contravariance | `in T` | parameters | `IComparer<object>` → `IComparer<string>` | `IComparer<in T>`, `Action<in T>`, `IEqualityComparer<in T>` |

```csharp
IEnumerable<object> items = new List<string> { "a" };   // OK: you can only read objects out of it
Action<object> printAny = o => Console.WriteLine(o);
Action<string> printString = printAny;                    // OK: something that accepts any object accepts a string
```

Rules: variance only applies to **interfaces and delegates** (not classes), and only to **reference types** (`IEnumerable<int>` is not an `IEnumerable<object>`, because that would need boxing).

**Arrays are the exception:** they are covariant for historical reasons, so `object[] arr = new string[1]; arr[0] = 1;` compiles and throws `ArrayTypeMismatchException` at runtime. It's also why every write to a reference-type array has a hidden type check.

**Follow-up:** why does a method that only reads a collection take `IEnumerable<T>` or `IReadOnlyList<T>` instead of `List<T>`? (It accepts more callers, including covariant ones like passing `List<Dog>` where `IReadOnlyList<Animal>` is expected, and it states that the method won't modify the collection.)
