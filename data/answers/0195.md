## Hints

- Which JavaScript expressions can you put inside `{}`, and which statements can't go there?
- What does React render for `false`, `null`, `undefined`, and for the number `0`?
- What does each item in a `.map()` need so React can track it?

## Answer

JSX only accepts **expressions**, so you use JavaScript expressions instead of `if` and `for` statements:

```jsx
function Inbox({ user, messages }) {
  if (!user) return null;                 // early return
  return (
    <>
      {user.isAdmin ? <AdminBar /> : <UserBar />}   {/* either/or */}
      {messages.length > 0 && <Badge n={messages.length} />}
      <ul>
        {messages.map(m => <li key={m.id}>{m.subject}</li>)}
      </ul>
    </>
  );
}
```

- `cond ? a : b` picks between two branches.
- `cond && <X />` renders X or nothing.
- `.map()` turns an array into elements. Every item needs a stable `key`, ideally an id from the data.
- `.filter()` before `.map()` to remove items.
- For complex logic, assign JSX to a variable or extract a component.

**The `0` pitfall:** `false`, `null`, `undefined` and `true` render nothing, but **numbers render**. `{items.length && <List />}` evaluates to `0` when the array is empty, so a literal "0" appears on the page. In React Native it can even crash ("text strings must be rendered within a `<Text>`"). Make the left side a real boolean:

```jsx
{items.length > 0 && <List />}
{!!items.length && <List />}
```

**Pitfalls:** using `Math.random()` or the array index as a key for lists that can reorder, and forgetting that `""` (empty string) also renders as an empty text node.
