## Hints

- Does `<StrictMode>` affect production builds?
- If a component's render has a side effect, how could running it twice expose that?
- Why would React mount, unmount and remount an effect on purpose?

## Answer

`<StrictMode>` is a **development-only** wrapper that helps you find bugs early. It renders no UI and does nothing in production.

In development, it:

1. **Renders components twice.** It double-invokes component bodies, `useState`/`useMemo` initializers, reducers and updater functions. These should be pure, so the second call should give the same result. If it doesn't, you have a hidden side effect (mutating a prop, pushing to a module-level array, and so on).
2. **Runs effects twice on mount:** setup, then cleanup, then setup again. This simulates the component being unmounted and remounted, which really happens with Fast Refresh, `<Activity>`, and navigation. A missing cleanup shows up immediately as duplicate subscriptions, two WebSocket connections, or double-counted analytics.
3. **Runs ref callbacks twice** (React 19) to check that their cleanup works.
4. **Warns about deprecated APIs.**

```jsx
useEffect(() => {
  const conn = connect(roomId);
  return () => conn.disconnect(); // without this, StrictMode reveals the leak
}, [roomId]);
```

React DevTools shows logs from the second render dimmed so they don't confuse you.

**How not to "fix" it:** don't add a `useRef` guard like `didRun.current` to skip the second effect, and don't remove StrictMode. Write a proper cleanup, or move the logic out of the effect. A one-time POST belongs in an event handler. Fetching belongs in a data library, which deduplicates requests.

**Follow-up:** "My API is called twice in dev, is that a bug?" No, it's StrictMode. It won't happen in production, but it shows the effect isn't resilient to remounting.
