## Hints

- Which of these removes an element from the accessibility tree, and which only makes it invisible?
- How would you give an icon-only button a text label that screen readers announce?
- What goes wrong if a hidden element can still receive keyboard focus?

## Answer

| Technique | Visible? | Takes space? | Screen readers? | Focusable? |
|---|---|---|---|---|
| `display: none` / `hidden` attribute | No | No | **Hidden** | No |
| `visibility: hidden` | No | **Yes** | **Hidden** | No |
| `opacity: 0` | No | Yes | **Read** | **Yes** (a trap for keyboard users) |
| `aria-hidden="true"` | **Yes** | Yes | **Hidden** | Still focusable unless you prevent it |
| `inert` attribute | Yes | Yes | Hidden | **No**, and no clicks either |
| **`.sr-only`** (visually hidden) | No | No (effectively) | **Read** | Yes, if it's interactive |

**Visually hidden, but still announced:**

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}
```

```html
<button type="button">
  <svg aria-hidden="true" focusable="false">...</svg>
  <span class="sr-only">Close dialog</span>
</button>
```

Use it for icon-only button labels, extra context ("Read more <span class='sr-only'>about pricing</span>"), table captions and live-region text. Tailwind ships this as the `sr-only` class. Don't use `display: none` for this. That hides it from screen readers too.

**Hidden from screen readers but visible:** `aria-hidden="true"` for **decorative** icons, duplicated text and visual flourishes. **Never** put it on focusable elements or their parents: keyboard users would land on something that announces nothing.

**Skip links** use a variant that becomes visible on focus:

```css
.skip-link:not(:focus) { /* same rules as .sr-only */ }
```

**Hiding whole regions** (behind a modal, or an off-screen drawer): use `inert`. It removes interaction and screen-reader access in one attribute.

**Follow-up:** `hidden="until-found"` hides content but lets the browser's find-in-page reveal it, which suits accordions.
