## Hints

- Which of these turns off type checking, and which one forces you to check the type before using the value?
- Which type has no values at all, and where does it show up naturally?
- What type should a `catch (e)` variable or a `JSON.parse` result have?

## Answer

**`any`** turns off type checking. Any value can be assigned to it, and anything can be done with it. It also **spreads**: whatever you get from an `any` is `any` too. Use it only as a temporary escape hatch.

**`unknown`** is the **type-safe top type**. Any value can be assigned to it, but you can't use it until you **narrow** it. Use it for untrusted input: `JSON.parse`, API responses, `catch` variables (`useUnknownInCatchVariables` is part of `strict`).

```ts
function parse(input: unknown): string {
  // input.toUpperCase();          // error: 'input' is of type 'unknown'
  if (typeof input === 'string') return input.toUpperCase();
  if (input instanceof Date) return input.toISOString();
  throw new Error('Unsupported');
}

const a: any = 'x';  a.foo.bar();          // compiles, crashes at runtime
```

For object data, validate with a type guard or a schema library such as Zod or Valibot.

**`never`** is the **bottom type**. It has no values. It represents things that cannot happen:

- functions that never return (they always throw, or loop forever),
- impossible branches after full narrowing,
- members removed from a union by conditional types (`Exclude<T, U>` produces `never`).

```ts
type Shape = { kind: 'circle'; r: number } | { kind: 'square'; s: number };

function area(s: Shape) {
  switch (s.kind) {
    case 'circle': return Math.PI * s.r ** 2;
    case 'square': return s.s ** 2;
    default: {
      const _exhaustive: never = s; // a compile error if a new kind is added
      return _exhaustive;
    }
  }
}
```

**Summary:** `any` means "trust me" (unsafe). `unknown` means "check before using" (safe). `never` means "this can't happen". Lint rules such as `@typescript-eslint/no-explicit-any` help keep `any` out of a codebase.
