## Hints

- Where does the engine look when it can't find a property on the object itself?
- What is the difference between `__proto__` / `Object.getPrototypeOf(obj)` and `Fn.prototype`?
- Is `class` a new inheritance model or something else?

## Answer

Every object has an internal `[[Prototype]]` link to another object, or to `null`. When you read a property, the engine checks the object first. If the property isn't there, it follows the link and checks the next object, and so on until it reaches `null`. This is the **prototype chain**.

```js
const animal = { eats: true, describe() { return `eats: ${this.eats}`; } };
const rabbit = Object.create(animal); // rabbit.[[Prototype]] = animal
rabbit.jumps = true;
rabbit.eats;       // true (inherited)
rabbit.describe(); // 'eats: true' (this = rabbit)
```

**Key concepts**

- `Object.getPrototypeOf(obj)` returns the actual link. `__proto__` is the legacy way to access it.
- `Fn.prototype` is a normal property on functions. It is the object that becomes the `[[Prototype]]` of instances created with `new Fn()`.
- **Writes don't walk the chain.** Assigning `rabbit.eats = false` creates an own property that *shadows* the inherited one.
- Methods placed on the prototype are **shared** by all instances, which saves memory.

**ES6 classes are syntactic sugar** over the same mechanism:

```js
class Animal { speak() { return 'sound'; } }
class Dog extends Animal { speak() { return 'woof ' + super.speak(); } }
Object.getPrototypeOf(Dog.prototype) === Animal.prototype; // true
```

Classes do add real differences: the body runs in strict mode, a class can't be called without `new`, methods are non-enumerable, and private fields (`#x`) are supported.

**Follow-ups:** `instanceof` walks the prototype chain. Prefer `Object.hasOwn(obj, key)` over `obj.hasOwnProperty`. Also be ready to discuss composition over inheritance.
