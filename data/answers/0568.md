## Hints

- If you hold a `Dog` in a variable of type `Animal` and call `Speak()`, which version runs? Does the keyword change the answer?
- Why does the compiler warn you when a derived class declares a method with the same name as a base method?
- Can you override a method that isn't marked `virtual`?

## Answer

**Polymorphism** means one call works on objects of different types, and each type supplies its own behaviour. In C# that's **virtual dispatch**: the method that runs depends on the object's **runtime type**, not the variable's declared type.

- `virtual` in the base class: "subclasses may replace this". Methods are **not virtual by default** in C# (unlike Java).
- `override` in the derived class: replaces it. Calls through **any** reference type reach the override.
- `abstract`: virtual with no body; subclasses must override (#566).
- `new`: **hides** the base member. It's a different method that only runs when the **variable's type** is the derived class. No polymorphism.

```csharp
class Animal
{
    public virtual string Speak() => "...";
    public string Describe() => "an animal";
}

class Dog : Animal
{
    public override string Speak() => "Woof";          // replaces
    public new string Describe() => "a dog";            // hides
}

Animal a = new Dog();
Dog d = (Dog)a;

a.Speak();      // "Woof"       virtual dispatch: runtime type wins
d.Speak();      // "Woof"
a.Describe();   // "an animal"  hidden: the declared type decides
d.Describe();   // "a dog"
```

| | `override` | `new` |
|---|---|---|
| Base member must be | `virtual`, `abstract` or `override` | anything |
| Called through a base-type reference | derived version | **base** version |
| Polymorphic | yes | no |

Without either keyword, a same-named method hides with a **warning** (CS0108). `new` only silences it. Hiding is almost always a design smell; it appears mainly when a base library later adds a member with the same name as yours.

**Other details:**

- `base.Speak()` calls the base implementation from inside the override.
- `sealed override` stops further overriding.
- Don't call virtual methods from a constructor: the derived override runs before the derived constructor body has run, so anything set up there is still missing (field initializers have run, constructor assignments haven't).

**Follow-up:** what's the difference between overriding and overloading? (Overriding replaces a base method with the same signature and is chosen at run time; overloading is several methods with the same name but different parameters, chosen at compile time.)
