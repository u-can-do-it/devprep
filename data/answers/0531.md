## Hints

- Two stacked paragraphs each have `margin: 20px`. What is the gap between them, 20 or 40 pixels?
- Why does a child's `margin-top` sometimes push its parent down instead of creating space inside the parent?
- Why does a container of floated children have zero height, and what does `display: flow-root` change?

## Answer

**Margin collapsing** is a rule of normal block flow: when two **vertical** margins touch, they merge into one margin instead of adding up.

Cases where it happens:

- **Adjacent siblings:** `margin-bottom: 20px` followed by `margin-top: 30px` gives a 30px gap, not 50px.
- **Parent and first/last child:** if nothing separates them (no border, padding, inline content, or height), the child's margin escapes and becomes the parent's margin. That is why a heading's `margin-top` can push the whole section down.
- **Empty blocks:** an element with no height, padding or border collapses its own top and bottom margins together.

The result: both positive, take the **larger**; both negative, take the **more negative**; mixed, **add** them.

It never happens for horizontal margins, between flex or grid items, for floated or absolutely positioned elements, for `inline-block`, or across a **block formatting context** boundary.

**Block formatting context (BFC)**: a region of the page that lays out its blocks independently. Floats inside it are contained, margins inside don't collapse with margins outside, and the box doesn't overlap floats next to it. A new BFC is created by the root element, floats, absolutely positioned elements, `inline-block`, table cells, flex and grid items, `overflow` other than `visible`, `contain: layout`, and the purpose-built `display: flow-root`.

```css
/* 1. Child margin escaping the parent: stop the collapse */
.card { display: flow-root; }          /* or padding-top: 1px, or a border */

/* 2. Container of floats has zero height: contain them */
.clearfix { display: flow-root; }      /* modern replacement for ::after { clear: both } */

/* 3. Text wrapping under a float: give the text its own BFC */
.sidebar { float: left; width: 200px; }
.content { display: flow-root; }       /* no longer flows under .sidebar */
```

Before `flow-root`, people used `overflow: hidden` for the same effect, with the side effect of clipping shadows and dropdowns.

**Why it matters in daily work:** a "mystery gap" above a component, inconsistent spacing between stacked components, and a parent that gets no height from its floated children are all this one mechanism. In flex and grid layouts the problem disappears, which is one reason spacing with `gap` is more predictable than margins (#51). Component libraries often set `margin: 0` on headings and paragraphs and control spacing from the parent for the same reason.

**Follow-up:** does `padding` on the parent stop the first child's margin from collapsing? (Yes, any padding or border between them does. `gap` in flex and grid never collapses.)
