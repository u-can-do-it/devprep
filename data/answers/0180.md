## Hints

- Which bugs does `strictNullChecks` catch that you'd otherwise only see in production?
- Is `strict` one flag or a group of flags?
- What does `arr[0]` return with `noUncheckedIndexedAccess` on?

## Answer

`strict: true` is a **group of flags**. New flags added to the group are turned on automatically when you upgrade TypeScript. It includes:

- **`strictNullChecks`:** `null`/`undefined` are separate types, so you must handle them. This is the most valuable flag.
- **`noImplicitAny`:** an error when the compiler can't infer a type and would silently use `any`.
- **`strictFunctionTypes`:** function parameters are checked contravariantly.
- **`strictBindCallApply`:** `bind`/`call`/`apply` arguments are type-checked.
- **`strictPropertyInitialization`:** class fields must be initialized in the constructor.
- **`noImplicitThis`, `alwaysStrict`, `useUnknownInCatchVariables`** (`catch (e)` gives `unknown`), and newer additions such as `strictBuiltinIteratorReturn`.

Since TypeScript 6/7, `strict` is **on by default**.

**Extra flags worth enabling (not part of `strict`):**

- **`noUncheckedIndexedAccess`:** `arr[i]` and `record[key]` include `| undefined`. Catches many real crashes.
- **`exactOptionalPropertyTypes`:** `{ a?: string }` no longer accepts an explicit `a: undefined`.
- **`noImplicitOverride`:** subclass methods must say `override`.
- **`noFallthroughCasesInSwitch`, `noImplicitReturns`.**
- **`verbatimModuleSyntax` / `isolatedModules`:** safe for single-file transpilers.
- **`erasableSyntaxOnly`:** required if you run TS directly with Node type stripping.

```ts
const users: Record<string, User> = {};
const u = users['ann'];   // with noUncheckedIndexedAccess: User | undefined
u.name;                   // error: 'u' is possibly 'undefined'
```

**Migrating a legacy codebase:** turn flags on one at a time, starting with `noImplicitAny` and then `strictNullChecks`. Use per-folder `tsconfig`s or a strict plugin, and add `// @ts-expect-error` with a ticket for known gaps. Track the remaining errors and fix new code first.

**Note:** `skipLibCheck: true` speeds up builds but hides type errors in `.d.ts` files. It's a common, accepted trade-off.
