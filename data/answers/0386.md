## Hints

- How does a user in Sydney end up talking to a server near Sydney when your origin is in Frankfurt?
- What decides whether two requests can be served from the same cached copy?
- Can a CDN help with a personalized API response that's different for every user?

## Answer

A **CDN** is a globally distributed network of edge servers (points of presence, PoPs) that sit between users and your **origin**.

**How a request reaches the edge:** your domain points to the CDN (CNAME or CDN-managed DNS). Through **anycast** routing or geo-aware DNS, the user's request lands at a nearby PoP. The edge terminates TLS, checks its cache, and on a miss fetches from the origin (often via an **origin shield**, a mid-tier cache that reduces origin load), stores the response according to your caching rules, and returns it.

**What it speeds up:**

- **Static assets** (JS, CSS, images, fonts, video segments): served from cache close to users. Use hashed file names and long cache lifetimes.
- **Cacheable HTML and API responses**, if you mark them cacheable for shared caches (`s-maxage`, `stale-while-revalidate`).
- **Even uncacheable traffic**: TLS and TCP handshakes happen at the nearby edge, and the edge keeps warm, optimized connections to the origin, so dynamic requests still get faster.
- Extras: HTTP/3, compression (Brotli), image optimization, DDoS absorption, WAF, edge functions.

**What it can't (easily) speed up:** personalized or per-user responses, writes, and anything slow at the origin (a 2-second DB query is still 2 seconds on a cache miss).

**Things to get right:**

- **Cache key**: by default URL plus some headers. Accidentally caching a response that depends on cookies or `Authorization` can leak one user's data to others.
- **Invalidation**: purge by URL or tag on deploy/content change, or rely on versioned URLs.
- **Origin protection**: only accept traffic from the CDN, so attackers can't bypass the WAF.

**Follow-up:** How do you measure CDN effectiveness? Cache hit ratio, origin offload, and edge vs origin response times (e.g. TTFB by region).
