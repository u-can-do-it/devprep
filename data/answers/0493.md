## Hints

- How does the user know their click did something?
- What should happen before a user deletes 200 records?
- Why should the same action look and behave the same on every screen?

## Answer

A UI/UX-minded developer implements the design **and** notices when something will confuse users. **Nielsen's 10 usability heuristics** are the most common checklist:

1. **Visibility of system status:** feedback within ~100 ms. Pressed states, spinners or skeletons for loading, progress for long tasks, a toast or inline confirmation after saving.
2. **Match with the real world:** the user's language, not the database's ("Delivery address", not `shipping_addr_id`). Sensible date and number formats for the locale.
3. **User control and freedom:** undo instead of "Are you sure?" where possible, a cancel button, a working Back button, the ability to leave a flow without losing data.
4. **Consistency and standards:** the same action uses the same component, label and position everywhere. That's what a design system enforces. Follow platform conventions such as links looking like links.
5. **Error prevention:** disable invalid options, use input types and constraints, confirm destructive actions with specifics ("Delete 200 invoices?").
6. **Recognition rather than recall:** visible options, recent items, autocomplete, filter chips showing what's applied.
7. **Flexibility and efficiency:** keyboard shortcuts, bulk actions and saved filters for power users, without hurting beginners.
8. **Aesthetic and minimalist design:** every extra element competes for attention. Prioritise primary actions visually.
9. **Help users recover from errors:** plain-language messages next to the field, saying what's wrong and how to fix it, with input preserved.
10. **Help and documentation:** contextual hints and tooltips where tasks are complex.

**Other things to check while building:**

- **Perceived performance:** optimistic updates, skeletons instead of layout jumps, avoiding spinners that flash for 50 ms.
- **Forms:** labels above fields, inline validation on blur rather than on every keystroke, sensible tab order, `autocomplete` attributes.
- **Empty states** that explain what to do next, not a blank table.
- **Accessibility** is part of usability: contrast, focus visibility, target size, readable text.

**How to raise issues:** show the problem concretely (a screen recording with long data, a mobile screenshot), propose an alternative, and let the designer or product owner decide. Usability testing and analytics settle disagreements better than opinions.

**Follow-up:** which of these heuristics does a "Save" button that does nothing visible for 3 seconds violate, and how would you fix it?
