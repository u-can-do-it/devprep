## Hints

- How could `add(1)(2)(3)` work if every call returns a function?
- How does a curried function know when it has received enough arguments?
- In which direction does `compose(f, g)(x)` apply the functions, and how does `pipe` differ?

## Answer

**Currying** turns a function of N arguments into a chain of functions that each take some of the arguments. The original function runs once all N have been provided. It is closely related to **partial application**, which fixes some arguments up front (as `fn.bind(null, a)` does).

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn.apply(this, args);
    return (...more) => curried.apply(this, [...args, ...more]);
  };
}

const add3 = curry((a, b, c) => a + b + c);
add3(1)(2)(3);   // 6
add3(1, 2)(3);   // 6
const add10 = add3(4, 6);
add10(5);        // 15
```

`fn.length` doesn't count rest parameters or parameters with default values. For those, pass the arity explicitly.

**Composition** combines small functions into a pipeline:

```js
const compose = (...fns) => (x) => fns.reduceRight((v, f) => f(v), x); // right to left
const pipe    = (...fns) => (x) => fns.reduce((v, f) => f(v), x);      // left to right

const slugify = pipe(
  (s) => s.trim(),
  (s) => s.toLowerCase(),
  (s) => s.replace(/\s+/g, '-'),
);
slugify('  Hello World '); // 'hello-world'
```

**Why it's useful:**

- Reusable, specialized functions: `const getJSON = request('GET')`.
- **Point-free**, declarative data pipelines.
- Fits well with `map`/`filter`, middleware, and higher-order components.
- Libraries: Ramda, lodash/fp.

**Pitfalls:**

- Readability suffers if the team isn't used to this style.
- Stack traces get harder to read.
- `this` and variadic functions don't fit well.

**Follow-up:** "Implement `sum(1)(2)(3)()` with unlimited calls." Accumulate the arguments until a call with no arguments.
