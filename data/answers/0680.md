## Hints

- There is no `<form>` element and no submit event. What triggers a submit?
- Which props decide the keyboard layout and whether the password manager offers to fill a field?
- How does the "next" key on the keyboard move to the following field?

## Answer

> A form is a set of `TextInput`s plus a button that calls your submit function. The work is in the details: the right keyboard and autofill hints per field, moving focus with the keyboard's "next" key, keeping fields visible above the keyboard, and showing errors next to the field. React Hook Form works well, but you connect each input through `Controller`, because there are no DOM inputs to register.

**`TextInput` props that matter**

| Prop | Purpose |
|---|---|
| `value`, `onChangeText` | controlled input; the callback receives the string |
| `keyboardType` / `inputMode` | `email-address`, `numeric`, `decimal-pad`, `phone-pad`, `url` |
| `autoCapitalize`, `autoCorrect` | turn off for emails, usernames, codes |
| `autoComplete` | autofill hint: `email`, `current-password`, `new-password`, `one-time-code`, `postal-code` |
| `textContentType` | extra iOS hint for the same purpose |
| `secureTextEntry` | hides the text for passwords |
| `returnKeyType` | label of the return key: `next`, `done`, `search`, `send` |
| `onSubmitEditing` | fires when the return key is pressed |
| `submitBehavior` | `submit` keeps the keyboard open, `blurAndSubmit` closes it |
| `multiline`, `maxLength`, `editable` | as named |

Correct `autoComplete` values let the password manager fill logins and let the system offer the SMS code above the keyboard.

**React Hook Form with `Controller`**

```tsx
const schema = z.object({ email: z.email(), password: z.string().min(8) });
type Form = z.infer<typeof schema>;

function SignInForm() {
  const { control, handleSubmit, setFocus, formState: { errors, isSubmitting } } =
    useForm<Form>({ resolver: zodResolver(schema), defaultValues: { email: '', password: '' } });

  const onSubmit = handleSubmit(async (values) => { await signIn(values); });

  return (
    <View style={{ gap: 12 }}>
      <Controller
        control={control}
        name="email"
        render={({ field: { ref, value, onChange, onBlur } }) => (
          <TextInput
            ref={ref}
            value={value}
            onChangeText={onChange}
            onBlur={onBlur}
            accessibilityLabel="Email"
            keyboardType="email-address"
            autoCapitalize="none"
            autoComplete="email"
            returnKeyType="next"
            submitBehavior="submit"
            onSubmitEditing={() => setFocus('password')}
          />
        )}
      />
      {errors.email && <Text style={styles.error}>{errors.email.message}</Text>}

      {/* password: secureTextEntry, autoComplete="current-password",
          returnKeyType="done", onSubmitEditing={onSubmit} */}

      <Pressable onPress={onSubmit} disabled={isSubmitting} accessibilityRole="button">
        <Text>{isSubmitting ? 'Signing in…' : 'Sign in'}</Text>
      </Pressable>
    </View>
  );
}
```

- `setFocus` works because the input's `ref` is passed through, and `TextInput` has a `focus()` method.
- Submit from two places: the button, and the return key of the last field.
- In a real app, wrap `Controller` plus label plus error in one `<FormField>` component.

**Validation and errors**

- Validate on blur or on submit, not on every key press, and validate again on the server.
- Show the message under the field, in text, not only as a red border.
- On submit, focus or scroll to the first invalid field.
- Announce errors to screen readers (#689), and map server validation errors back to fields with `setError`.

**Keyboard and layout**

- Put the form in a keyboard-aware scroll view, so the focused field and the button stay visible (#679).
- Set `keyboardShouldPersistTaps="handled"`, or the first tap on "Sign in" only closes the keyboard.
- Dismiss the keyboard on submit.

**Other inputs**

Date pickers, selects and switches have no HTML equivalent. Use native pickers or a UI library, and connect them through `Controller` the same way.

**Follow-up:** the user must enter a 6-digit code from an SMS. How do you make it quick? (`keyboardType="number-pad"`, `autoComplete="one-time-code"` so the system suggests the code, `maxLength={6}`, and submit automatically when six digits are entered.)
