## Hints

- Which phase may React start, pause, throw away and restart, and which phase must run all at once?
- How can React pause recursive rendering if the old implementation used the JavaScript call stack?
- If a component mutates a global variable during render and that render is discarded, what happens?

## Answer

**Two phases:**

1. **Render phase:** React calls your components, compares the result with the previous tree, and works out what changed. It produces **no visible side effects**. With concurrent features (transitions, Suspense), this phase is **interruptible**. React can yield to the browser, pause, restart with newer state, or **throw the work away** entirely.
2. **Commit phase:** React applies the changes to the DOM **synchronously and atomically**, so the user never sees a half-updated UI. It then attaches refs and runs `useLayoutEffect`. After paint, it runs `useEffect`.

**Fiber** is the data structure and reconciler (since React 16) that makes interruption possible. Each component instance or element is a **fiber node**: a plain object with `type`, `props`, its hooks state (a linked list), and pointers to `child`, `sibling` and `return` (parent). Because the tree is a linked structure, React walks it in a loop **one unit of work at a time**, not by recursion on the call stack. So it can stop between fibers and check whether higher-priority work is waiting.

Other key pieces:

- **Double buffering:** a `current` tree (on screen) and a `workInProgress` tree (being built). Commit swaps them.
- **Lanes:** bitmask priorities. A keystroke (sync lane) can interrupt a transition lane render.

**Why render must be pure:** a render may run **more than once**, or run and be **discarded**:

- StrictMode deliberately double-renders.
- Concurrent rendering restarts interrupted work.
- The React Compiler skips re-running memoized parts.

Side effects during render (mutating props or globals, network calls, writing refs, logging analytics) can therefore run 0, 1 or many times, leak into abandoned trees, or show inconsistent UI. Put side effects in **event handlers** or **effects**, which run only for committed renders.

**Follow-up:** "pure" means the same props, state and context give the same JSX, and nothing outside the component is changed. Creating and mutating *local* variables during render is fine.
