## Hints

- What makes `len(obj)`, `obj == other`, `obj in coll` and `print(obj)` work for your own class?
- Which methods must stay consistent so an object can be used as a dict key?
- What should `__eq__` return when compared with an unrelated type?

## Answer

Dunder ("double underscore") methods are hooks Python calls to implement **built-in syntax and protocols**. `a + b` calls `a.__add__(b)`, `len(x)` calls `x.__len__()`, `with x:` calls `__enter__`/`__exit__`, and so on. You implement them; you rarely call them directly.

For an immutable value object such as `Money`:

```python
from functools import total_ordering

@total_ordering
class Money:
    __slots__ = ("amount", "currency")

    def __init__(self, amount: int, currency: str):
        object.__setattr__(self, "amount", amount)
        object.__setattr__(self, "currency", currency)

    def __setattr__(self, *_):
        raise AttributeError("Money is immutable")

    def __repr__(self):                    # for developers / debugging
        return f"Money({self.amount!r}, {self.currency!r})"

    def __str__(self):                     # for end users
        return f"{self.amount / 100:.2f} {self.currency}"

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented          # let Python try the other side
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __hash__(self):                    # must agree with __eq__
        return hash((self.amount, self.currency))

    def __lt__(self, other):
        if not isinstance(other, Money) or other.currency != self.currency:
            return NotImplemented
        return self.amount < other.amount

    def __add__(self, other):
        if not isinstance(other, Money) or other.currency != self.currency:
            return NotImplemented
        return Money(self.amount + other.amount, self.currency)

    def __bool__(self):
        return self.amount != 0
```

Other common groups: containers (`__len__`, `__getitem__`, `__iter__`, `__contains__`), callables (`__call__`), context managers, and attribute hooks (`__getattr__`).

Rules: equal objects **must** have equal hashes, and only immutable objects should be hashable. Return `NotImplemented` (not `False`) for unsupported types.

In practice, `@dataclass(frozen=True, slots=True, order=True)` generates most of this for you.
