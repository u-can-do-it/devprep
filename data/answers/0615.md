## Hints

- Where does the type parameter go when a component is a plain function, and why does `<T>` break in an arrow function inside a `.tsx` file?
- How does TypeScript pick `T` when you write `<List items={users} ... />`, and how do you pass it explicitly?
- What happens to the type parameter when you wrap the component in `React.memo` or type it as `React.FC`?
- How would you type a table `columns` prop so that `render` receives the right type for each column's `key`?

## Answer

A generic component is a function with a type parameter. TypeScript infers `T` from the props, so the callbacks get the item type without any annotations:

```tsx
type ListProps<T> = {
  items: T[];
  getKey: (item: T) => React.Key;
  renderItem: (item: T) => React.ReactNode;
};

function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return <ul>{items.map((item) => <li key={getKey(item)}>{renderItem(item)}</li>)}</ul>;
}

<List items={users} getKey={(u) => u.id} renderItem={(u) => u.name} />;  // T = User
<List<User> items={[]} getKey={(u) => u.id} renderItem={(u) => u.name} />; // explicit T
```

**Arrow functions in `.tsx`:** `const List = <T>(props: ListProps<T>) => ...` doesn't compile, because `<T>` is parsed as a JSX tag. Write `<T,>` or `<T extends unknown>` instead.

**Constraints:** constrain `T` only as far as the component needs. `T extends { id: string }` lets you drop `getKey`. A `getKey` prop keeps the component usable with any shape.

**Controlled generic `Select`:** `value: T`, `options: T[]` and `onChange: (value: T) => void` tie together, so passing a `Status` value with `string` options is a compile error. If a prop shouldn't drive inference (a `defaultValue` that would widen `T`), type it as `NoInfer<T>`.

**Per-column types in a table:** `columns: { key: keyof T; render: (value: T[keyof T]) => ... }[]` gives `render` a union of every field's type. A mapped type gives each column its own pair:

```tsx
type Column<T> = {
  [K in keyof T]: { key: K; header: string; render?: (value: T[K], row: T) => React.ReactNode };
}[keyof T];

type TableProps<T> = { rows: T[]; columns: Column<T>[] };
// { key: 'createdAt', render: (d) => d.toLocaleDateString() }  → d: Date
```

**Pitfalls:**

- `React.FC` can't express a generic component (`const List: React.FC<ListProps<T>>` has no `T` in scope). Use a plain function.
- `React.memo` (and `forwardRef`) return non-generic types, so `T` becomes `unknown`. The usual fix is a cast: `export const MemoList = memo(List) as typeof List`. In React 19 `ref` is a regular prop, so you no longer need `forwardRef`: add `ref?: React.Ref<HTMLUListElement>` to the props.
- Context can't be generic at module level. Use a factory, `function createListContext<T>() { return createContext<ListState<T> | null>(null); }`, or keep the generic part in props.
- Don't make a component generic when `T` appears only once. If nothing in the props connects `T` to another prop, a plain union or `unknown` is simpler.

**When reviewing AI-written code:** look for `any[]` or `items: unknown[]` with casts in `renderItem`, which is the generic component the author should have written. Also look for `memo` wrappers that silently drop the type parameter.
