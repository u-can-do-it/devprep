## Hints

- If you have used the Next.js App Router, which ideas look familiar?
- What does a `_layout.tsx` file define?
- Every screen has a URL. What do you get for free from that?

## Answer

> Expo Router is file-based routing for React Native, built on top of React Navigation. Every file in `app/` is a screen with a URL. A `_layout.tsx` file chooses the navigator (stack, tabs) for its folder. You get deep links to every screen, typed `href`s and web support without writing a route config. Use React Navigation directly when routes are built dynamically at runtime, or when an existing app already has a large hand-written navigation tree.

**File conventions**

```
app/
  _layout.tsx              root layout: a Stack
  +not-found.tsx           unmatched URLs
  sign-in.tsx              /sign-in
  (tabs)/                  group: no URL segment
    _layout.tsx            Tabs
    index.tsx              /
    orders.tsx             /orders
  orders/[id].tsx          /orders/42
  docs/[...path].tsx       catch-all
```

- `_layout.tsx`: the navigator for that folder and shared UI around its screens.
- `(group)`: organises files and layouts without adding a URL segment.
- `[id]`: a dynamic segment, read with `useLocalSearchParams()`.

**Navigating**

```tsx
<Link href="/orders/42">Open order</Link>
<Link href={{ pathname: '/orders/[id]', params: { id: order.id } }} />

const router = useRouter();
router.push('/orders/42');   // also replace, back, dismiss
```

With typed routes enabled, `href` values are checked by TypeScript, so a renamed file breaks the build instead of the app.

**Protected screens**

```tsx
// app/_layout.tsx
export default function RootLayout() {
  const { session, isLoading } = useSession();
  if (isLoading) return null;                 // keep the splash screen visible

  return (
    <Stack>
      <Stack.Protected guard={!!session}>
        <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
        <Stack.Screen name="orders/[id]" />
      </Stack.Protected>
      <Stack.Protected guard={!session}>
        <Stack.Screen name="sign-in" />
      </Stack.Protected>
    </Stack>
  );
}
```

When the guard turns false, the user is moved out of the protected screens, and deep links into them fall back to an available screen. This is client-side navigation control, not security: the API must still check the session.

**What you get**

- **Deep linking by default.** Every screen has a URL, so a push notification or a web link can open any of them (#684).
- **Universal apps.** The same routes work on the web with real URLs, and with static or server rendering.
- **Async routes** (lazy bundling per route) and API routes (`+api.ts`) for small server endpoints.
- Standard React Navigation underneath: the same native stack, tabs, options and hooks (#674).

**What still applies from React Navigation**

Screens stay mounted when covered, focus events instead of mount and unmount, small serialisable params, platform conventions for back.

**When to use React Navigation directly**

- The navigation structure is data-driven or built at runtime (server-driven screens, a plugin system).
- A large existing app with a hand-written navigator tree, where a migration has little payoff.
- A brownfield app where native code owns navigation (#705).

For a new Expo app, Expo Router is the default choice.

**Common mistakes**

- Putting non-route files (components, hooks) in `app/`. Every file there becomes a route. Keep them in `src/components` or similar.
- Rendering a redirect before the root layout has mounted its navigator.
- Passing large objects through params instead of ids.

**Follow-up:** a push notification should open `/orders/42`, but the user is logged out. What should happen? (Remember the target URL, show sign-in, then navigate to the saved URL after login; see #684.)
