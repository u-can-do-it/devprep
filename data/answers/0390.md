## Hints

- How does pytest know which fixture to pass to a test function?
- How do you run cleanup code after a test that used a fixture?
- How do you share a fixture across many test files, and how do you make an expensive one run only once?

## Answer

A **fixture** is a function decorated with `@pytest.fixture` that provides setup (and optionally teardown) for tests. Tests request fixtures by **naming them as parameters**; pytest resolves them by name, including fixtures that depend on other fixtures.

```python
import pytest

@pytest.fixture(scope="session")
def engine():
    eng = create_engine(TEST_DB_URL)
    yield eng                 # everything after yield is teardown
    eng.dispose()

@pytest.fixture
def db(engine):               # function scope by default
    with engine.connect() as conn:
        tx = conn.begin()
        yield Session(bind=conn)
        tx.rollback()          # each test starts clean

def test_create_user(db):
    user = create_user(db, email="a@b.com")
    assert user.id is not None
```

**Scopes** control how often a fixture is created: `function` (default, per test), `class`, `module`, `package`, `session` (once per run). Use wide scopes for expensive, read-only resources (DB engine, containers) and function scope for mutable state, so tests stay isolated.

**`yield` teardown** runs even if the test fails, in reverse order of setup.

**`conftest.py`**: fixtures defined there are available to all tests in that directory and below, without imports. Put shared fixtures (app client, DB) in the root `conftest.py`.

**Parametrization** runs one test with many inputs:

```python
@pytest.mark.parametrize("email,valid", [
    ("a@b.com", True), ("no-at-sign", False), ("", False),
])
def test_email_validation(email, valid):
    assert is_valid_email(email) is valid
```

Fixtures can be parametrized too (`params=[...]`, with `request.param`). Useful built-ins: `tmp_path`, `monkeypatch`, `capsys`. Mark a fixture `autouse=True` to apply it everywhere in scope. Use it sparingly, since it hides dependencies.

**Follow-up:** For FastAPI, combine a `TestClient`/`httpx.AsyncClient` fixture with `app.dependency_overrides` to inject the test DB session.
