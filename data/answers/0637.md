## Hints

- What does `p: 2` mean inside `sx`, and where does the number come from?
- You need the same restyled button in 40 places. `sx`, `styled()` or the theme?
- How do you style a `TextField`'s outline only when it is focused, without a hashed `.css-1x2y3z` selector?
- How do you add a `brand` colour so `<Button color="brand">` type-checks?
- How do you write dark-mode styles without checking `theme.palette.mode` in every component?

## Answer

Material UI (MUI) is a React implementation of Material Design, styled with Emotion (CSS-in-JS) since v5. Customization goes from local to global; pick the narrowest level that fits.

**1. The theme: one source of truth**

```ts
const theme = createTheme({
  cssVariables: true,                                   // theme values exposed as --mui-* CSS variables
  colorSchemes: { light: true, dark: true },
  palette: { primary: { main: '#e20074' }, brand: { main: '#5c2d91' } },
  typography: { fontFamily: 'var(--font-inter), sans-serif', button: { textTransform: 'none' } },
  shape: { borderRadius: 8 },
  spacing: 8,                                           // theme.spacing(2) === '16px'
  components: {
    MuiButton: {
      defaultProps: { disableElevation: true, variant: 'contained' },
      styleOverrides: { root: ({ theme }) => ({ fontWeight: 600, padding: theme.spacing(1, 2) }) },
      variants: [{ props: { variant: 'dashed' }, style: { border: '1px dashed currentColor' } }],
    },
    MuiTextField: { defaultProps: { size: 'small', fullWidth: true } },
  },
});

<ThemeProvider theme={theme}><CssBaseline />{children}</ThemeProvider>
```

**2. Choosing the level**

| Tool | When |
|---|---|
| `sx` prop | One-off styling of one instance. Theme-aware shorthand: `sx={{ p: 2, color: 'text.secondary', display: { xs: 'none', md: 'block' } }}` |
| `styled(Component)` | A reusable styled component used in several places |
| Theme `components` (`defaultProps`, `styleOverrides`, `variants`) | The design system: every `Button` looks like this |
| `GlobalStyles` / `CssBaseline` | Global CSS |

`sx` values come from the theme: `p: 2` is `theme.spacing(2)`, `'primary.main'` is a palette path, `borderRadius: 1` multiplies `shape.borderRadius`, and object values are responsive by breakpoint.

**3. Inner elements and states.** Use the stable class names and slots, not generated `.css-…` classes:

```tsx
<TextField
  sx={{
    '& .MuiOutlinedInput-root.Mui-focused .MuiOutlinedInput-notchedOutline': { borderColor: 'brand.main' },
    '& .MuiInputBase-input.Mui-disabled': { WebkitTextFillColor: 'unset' },
  }}
  slotProps={{ htmlInput: { maxLength: 20 }, inputLabel: { shrink: true } }}
/>
```

State classes (`.Mui-disabled`, `.Mui-focused`, `.Mui-error`, `.Mui-selected`) are combined with the component class: `'&.Mui-disabled'`. In v6/v7, `slotProps` replaces `InputProps`, `inputProps` and `componentsProps`, which you'll still see in older code.

**4. TypeScript augmentation** for custom colours and variants:

```ts
declare module '@mui/material/styles' {
  interface Palette { brand: Palette['primary'] }
  interface PaletteOptions { brand?: PaletteOptions['primary'] }
}
declare module '@mui/material/Button' {
  interface ButtonPropsColorOverrides { brand: true }
  interface ButtonPropsVariantOverrides { dashed: true }
}
```

**5. Dark mode.** With `colorSchemes` and `cssVariables`, `useColorScheme()` switches modes, and styles use `theme.applyStyles('dark', { ... })` instead of `theme.palette.mode === 'dark' ? … : …`. Because colours are CSS variables, the server-rendered HTML doesn't flash the wrong theme.

**Layout primitives:** `Box`, `Stack` (one-dimensional with `spacing`), `Grid` (in v7 the new grid with `size={{ xs: 12, md: 6 }}`; the old one is `GridLegacy`), `Container`.

**Anti-patterns:** hard-coded hex colours instead of palette tokens; `!important` battles instead of theme overrides; deep selectors on hashed classes; a new `createTheme` on every render; mixing several styling systems without rules.

**Legacy code:** MUI v4 (`@material-ui/core`) used JSS with `makeStyles`/`withStyles`. In v5 these moved to the deprecated `@mui/styles`; migrate to `styled`/`sx`, or use `tss-react` as a bridge.

**Follow-up:** "MUI or a headless library?" See #457. For an internal self-service app with a small team, MUI's ready components (tables, dialogs, pickers) usually win over building a design system from primitives.
