## Hints

- Does `this` depend on where a function is defined or on how it is called?
- What changes when a function is called with `new`, with `.call`, or as `obj.method()`?
- Why do arrow functions behave differently?

## Answer

For regular functions, `this` is set **at call time**, based on *how* the function is called. The rules, in order of precedence:

1. **`new` binding:** `new Fn()` sets `this` to the newly created object.
2. **Explicit binding:** `fn.call(obj)`, `fn.apply(obj)`, `fn.bind(obj)` set `this` to `obj`. A bound function can't be re-bound.
3. **Implicit binding:** `obj.method()` sets `this` to `obj`, the object to the left of the dot.
4. **Default binding:** a plain `fn()` call gives `undefined` in strict mode and in modules, or `globalThis` in sloppy mode.

**Arrow functions** have no `this` of their own. They use `this` from the enclosing scope at the place they are defined, and `call`/`bind` can't change it.

```js
const user = {
  name: 'Ann',
  hi() { return this.name; },
  arrow: () => this?.name,
};
user.hi();               // 'Ann'
const f = user.hi;
f();                     // TypeError in strict mode (this is undefined)
user.arrow();            // undefined: this is the outer (module) scope
setTimeout(user.hi, 0);  // loses this
setTimeout(() => user.hi(), 0); // ok
```

**Common gotchas:**

- **Lost binding** when you pass a method as a callback. Fix it with `.bind`, an arrow wrapper, or class fields written as arrow functions.
- In DOM listeners registered with a regular function, `this` is `event.currentTarget`.
- In classes, methods are not auto-bound.

**Follow-up:** "Implement `bind`." Return a function that calls `fn.apply(ctx, [...preset, ...args])`, and handle the `new` case.
