## Hints

- What does `[10, 9, 1].sort()` return, and what happened to the original array?
- Why does mutating an array break change detection in UI frameworks?
- Which methods were added in ES2023 to give copying versions of `sort`, `reverse` and `splice`?

## Answer

**Methods that mutate the array:** `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill` and `copyWithin`. `sort` and `reverse` also return the same array, which makes it easy to forget that the original was changed.

**Methods that return a new array:** `map`, `filter`, `slice`, `concat`, `flat`, `flatMap`, and the ES2023 copying methods:

| Mutating | Non-mutating |
|---|---|
| `arr.sort(cmp)` | `arr.toSorted(cmp)` |
| `arr.reverse()` | `arr.toReversed()` |
| `arr.splice(i, n, ...items)` | `arr.toSpliced(i, n, ...items)` |
| `arr[i] = v` | `arr.with(i, v)` |

```js
const prices = [10, 9, 1];
prices.sort();                     // [1, 10, 9]: compares as strings by default!
const sorted = prices.toSorted((a, b) => a - b); // [1, 9, 10], prices unchanged
const updated = todos.with(2, { ...todos[2], done: true });
```

**Why it matters:**

- **Shared references.** Sorting an array you got as a function argument changes the caller's data too.
- **UI state.** React and other frameworks compare state by reference. If you mutate an array in place, the reference stays the same, so the UI may not re-render.
- **Predictability.** Pure functions that don't mutate are easier to test and reason about.

**Pitfalls:** the default `sort` compares values as strings, so always pass a comparator for numbers. For strings, use `localeCompare` or `Intl.Collator`. Spread (`[...arr]`) and `toSorted` copy only the array itself. The objects inside are still shared.
