## Hints

- How does React know which `useState` call corresponds to which piece of state between renders?
- What would happen to that bookkeeping if a hook were called inside an `if`?
- Which kinds of functions are allowed to call hooks at all?

## Answer

> React doesn't know hooks by name. It stores each component's hook state in a list and matches hooks to their state by the order they're called on every render. That's why there are two rules: call hooks only at the top level, never inside conditions, loops or after an early `return`, and call them only from components or custom hooks. If the call order changes between renders, one hook gets another hook's state. The `eslint-plugin-react-hooks` plugin enforces both rules.

There are two rules:

1. **Only call hooks at the top level** of a component or custom hook — never inside conditions, loops, nested functions, or after an early `return`.
2. **Only call hooks from React functions** — function components or custom hooks (functions named `useSomething`), not from plain utilities, class components, or event handlers.

**Why:** React does not identify hooks by name. It stores hook state in an ordered list attached to the component's fiber and matches them by **call order** on every render. If the order changes between renders, state from one hook gets handed to another.

```jsx
function Profile({ user }) {
  if (!user) return null;           // early return before a hook...
  const [tab, setTab] = useState(0); // ...breaks the order when user toggles
}
```

Fix it by calling the hook first and branching afterwards, or by moving the conditional logic inside the hook/effect.

The `eslint-plugin-react-hooks` plugin enforces both rules (and `exhaustive-deps`), and the React Compiler relies on them too.

**Follow-up:** React 19's `use()` is the exception — it can be called conditionally because it doesn't store state in the hook list the same way.
