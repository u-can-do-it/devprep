## Hints

- Where does the "source of truth" for the input's current value live in each case?
- How do you read the value of an input that React doesn't track?
- What happens if you pass `value` but no `onChange`?

## Answer

The difference is **who owns the value**.

**Controlled:** React state is the source of truth. You pass `value` and update state in `onChange`. Every keystroke re-renders.

```jsx
const [email, setEmail] = useState('');
<input value={email} onChange={e => setEmail(e.target.value)} />
```

Good for: instant validation, conditional UI, formatting input, disabling submit until the form is valid.

**Uncontrolled:** the DOM keeps the value. You set an initial `defaultValue` and read it when needed — via a `ref` or from `FormData` on submit.

```jsx
function Signup() {
  function handleSubmit(e) {
    e.preventDefault();
    const data = new FormData(e.currentTarget);
    console.log(data.get('email'));
  }
  return (
    <form onSubmit={handleSubmit}>
      <input name="email" defaultValue="" />
    </form>
  );
}
```

Good for: simple forms, file inputs (`<input type="file">` is always uncontrolled), wrapping non-React widgets, and fewer re-renders. React 19 form Actions (`<form action={fn}>`) also work naturally with uncontrolled inputs.

**Pitfalls:**

- `value` without `onChange` makes the field read-only (React warns).
- Switching from `undefined` to a defined `value` flips uncontrolled → controlled and triggers a warning; initialize with `''`.

**Follow-up:** libraries like React Hook Form use uncontrolled inputs plus refs for performance.
