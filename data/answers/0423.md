## Hints

- If every keystroke triggers a request, how many requests per second hit your backend, and how fast must each one be?
- Which data structure answers "all popular terms starting with `ja`" quickly?
- Does the suggestion list have to update in real time, or can it lag behind by minutes or hours?

## Answer

**1. Requirements:** return the top 5–10 suggestions for a prefix, ranked by popularity (and possibly personalization), within about **100 ms end to end**. The system is read-heavy (one query per keystroke), spans billions of historical queries, and suggestions can be minutes or hours stale. Filter offensive or removed terms.

**2. Data structure:** a **trie** (prefix tree) where each node stores the **precomputed top-k completions** for that prefix. Lookup is then *O(length of prefix)*, with no subtree traversal at query time. Alternatives: a sorted list of terms with binary search, Redis sorted sets per prefix, or a search engine's completion suggester (Elasticsearch/OpenSearch, or edge n-grams).

**3. Architecture**

```text
Client (debounce ~150 ms, cancel stale requests, local cache)
  -> CDN / edge cache (popular short prefixes)
  -> Suggest service (in-memory trie, sharded by prefix range)
        ^ built periodically by
Query logs -> stream/batch aggregation (counts with time decay)
           -> trie builder -> versioned snapshot in object storage
```

- **Read path:** serve from memory, replicate for throughput, and **cache aggressively**. The top few thousand prefixes cover most traffic, and 1–2 character prefixes are ideal for CDN caching.
- **Write path:** don't update the trie on every search. Aggregate query logs (e.g. hourly or daily with exponential decay so trends rise), build a new trie offline, and swap it in atomically (blue-green snapshot). For breaking trends, add a small real-time layer merged at query time.
- **Sharding:** by prefix range or hash of the first characters. Watch for hot prefixes ("a", "s") and rebalance on observed load.

**4. Client side:** debounce input, abort in-flight requests with `AbortController`, cache prefix results locally, use an accessible combobox pattern (`role="combobox"`, keyboard navigation).

**5. Extras:** personalization (blend the user's history at the service layer), multi-language support, typo tolerance (fuzzy matching is costlier, so keep it as a fallback), and a blocklist applied at build time.

**Follow-up:** "How do you rank?" Popularity with time decay, plus CTR on suggestions, plus context (location, user history).
