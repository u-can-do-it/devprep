## Hints

- What can `ADD` do with a URL or a `.tar.gz` file that `COPY` can't?
- Why can surprising "magic" behavior be a problem in a build?
- What gets sent to the Docker builder when you run `docker build .`?

## Answer

**`COPY`** copies files from the build context (or from another stage with `--from`) into the image. It does nothing else, which is why it's predictable.

**`ADD`** does the same plus extra behavior:

- automatically **extracts local tar archives** (`.tar`, `.tar.gz`, ...),
- can download from a **remote URL** or a Git repository.

Best practice: **default to `COPY`**. Use `ADD` only when you really want auto-extraction of a local archive. For downloads, `RUN curl ... && verify checksum` or `ADD --checksum=sha256:...` is clearer and verifiable.

**`.dockerignore`** works like `.gitignore` for the **build context**, the files sent to the builder. Excluding files:

- makes builds faster (no huge `node_modules` or `.git` upload),
- prevents secrets (`.env`, keys) from ending up in an image through `COPY . .`,
- avoids pointless cache invalidation when irrelevant files change.

```text
# .dockerignore
node_modules
.git
.env*
dist
coverage
*.log
Dockerfile
```

**Pitfall:** copying a host `node_modules` into a Linux image can break native modules built for macOS or Windows. Ignore it and install inside the image.
