## Hints

- How many round trips does it cost to open a new HTTPS connection before the first byte of the request is sent?
- What happens if the load balancer keeps an idle connection open longer than the backend does?
- What happens to requests when all connections in a pool are busy?

## Answer

Opening a connection is expensive: DNS lookup, TCP handshake, TLS handshake. That's several round trips plus CPU, before any data moves. **Keep-alive** (persistent connections, the default in HTTP/1.1) reuses a TCP/TLS connection for many requests. **Connection pooling** keeps a set of open connections per host and hands them out to requests. HTTP/2 and HTTP/3 go further and **multiplex** many concurrent requests over one connection.

Modern clients pool by default: Node's `fetch` (undici) and, since Node 19, the global `http.Agent` keep connections alive; in Python, reuse a `requests.Session` or `httpx.AsyncClient` instead of creating one per call.

```python
# Create once (app startup), reuse everywhere
client = httpx.AsyncClient(timeout=5.0, limits=httpx.Limits(max_connections=100))
```

**What goes wrong:**

- **No reuse**: creating a new client per request means a full handshake every time. You see high latency, CPU spent on TLS, and **ephemeral port exhaustion** / lots of `TIME_WAIT` sockets under load.
- **Idle-timeout mismatch causing random 502s**: the load balancer reuses an idle upstream connection that the backend has just closed. The backend's keep-alive timeout must be **longer** than the LB's idle timeout. Node's default `server.keepAliveTimeout` is 5s while an AWS ALB defaults to 60s, so raise Node's (and `headersTimeout` above it).
- **Pool exhaustion**: max connections too low, or slow upstream responses, so requests queue waiting for a connection. Add timeouts on acquiring a connection, plus request timeouts and circuit breakers.
- **Stale connections** after a server restart or DNS change: retry idempotent requests on connection reset, and cap connection lifetime so traffic picks up new backends or IPs.
- **Too many connections** from many instances × large pools overwhelming the upstream (same idea as DB pools).

**Follow-up:** Why can one HTTP/2 connection to a load balancer hurt balancing? All requests ride one long-lived connection to a single backend; L7 balancing per request fixes it.
