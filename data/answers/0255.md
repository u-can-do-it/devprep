## Hints

- Should the rest of the page stay interactive while this UI is open?
- What does "light dismiss" mean, and which kinds of UI expect it?
- What do both features get from being rendered in the "top layer"?

## Answer

Both render in the browser's **top layer**, above every stacking context, so you don't need z-index tricks or portals. They are built for different interactions.

**`<dialog>` with `showModal()`** is for **modal** interactions that block the rest of the page: confirmations, forms that need an answer, critical warnings.

- The rest of the document becomes **inert** (not clickable, focusable or readable).
- You get a `::backdrop` pseudo-element and **Escape** to close.
- Focus moves into the dialog and returns to the trigger when it closes.
- `<form method="dialog">` closes it and sets `returnValue`.

```html
<dialog id="confirm-dialog" aria-labelledby="t">
  <h2 id="t">Delete project?</h2>
  <form method="dialog">
    <button value="cancel">Cancel</button>
    <button value="delete">Delete</button>
  </form>
</dialog>
<button onclick="document.getElementById('confirm-dialog').showModal()">Delete</button>
```

`dialog.show()` opens it **non-modally**, which is rarely what you want.

**The `popover` attribute** is for **non-modal** UI over the page: menus, dropdowns, toggletips, toasts, teaching bubbles.

```html
<button popovertarget="menu">Options</button>
<div id="menu" popover>
  <button>Rename</button>
  <button>Duplicate</button>
</div>
```

- It works **without JavaScript**.
- `popover="auto"` (the default) gives **light dismiss**: clicking outside or pressing Escape closes it, and opening one auto popover closes the others. `popover="manual"` gives you full control, which suits toasts.
- The page stays interactive and focus is **not trapped**.
- The browser links the invoker and the popover for accessibility (`aria-expanded`), but you still choose suitable roles for the content.

**Rule of thumb:** if the user must respond before continuing, use a modal `<dialog>`. If it's lightweight UI they can ignore, use a popover. Pair popovers with **CSS anchor positioning** to place them next to their trigger.

**Follow-up:** you can open a dialog with `popover` too, but that makes it non-modal. Newer additions such as declarative invoker commands (`command`/`commandfor`) and `closedby` reduce the JavaScript needed even more.
