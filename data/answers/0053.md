## Hints

- A card component sits in a wide main column on one page and a narrow sidebar on another. What should its layout respond to?
- What does a media query actually measure?
- What do you need to declare on a parent before a container query can work?

## Answer

**Media queries** respond to the **viewport/device**: width, orientation, resolution, and user preferences. **Container queries** respond to the **size (or style) of an ancestor container**, so a component adapts to the space it's actually given.

```css
/* Page-level: layout of the whole page */
@media (min-width: 768px) {
  .page { grid-template-columns: 240px 1fr; }
}

/* Component-level: card adapts to its slot */
.card-wrapper { container-type: inline-size; container-name: card; }

@container card (min-width: 400px) {
  .card { display: grid; grid-template-columns: 120px 1fr; }
}
```

Container query units (`cqi`, `cqw`) let you size things like font relative to the container.

**Use media queries for:**

- Page-level layout and breakpoints (navigation collapse, number of columns).
- User preferences: `prefers-color-scheme`, `prefers-reduced-motion`, `prefers-contrast`.
- Input capabilities: `hover`, `pointer: coarse`, and print styles.

**Use container queries for:**

- Reusable components (cards, widgets) placed in containers of different widths — the design-system use case.
- Avoiding components that "know" about page breakpoints.

**Gotchas:** an element can't query itself — the query targets an ancestor with `container-type`. `inline-size` applies size containment on the inline axis, so the container can't size itself from its children's width.

Responsive design also includes fluid techniques that need no queries: `clamp()` for typography, `minmax()`/`auto-fill` grids, relative units, and responsive images.

**Follow-up:** style queries (`@container style(--variant: compact)`) for custom properties are newer than size queries, so check current browser support before relying on them; size queries work in all modern browsers.
