## Hints

- Does the code inside an `async` function run synchronously up to the first `await`?
- When the call stack empties, which queue runs first: microtasks or timers?
- Where does the code after an `await` get queued?

## Answer

A typical puzzle:

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
(async () => {
  console.log('4');
  await null;
  console.log('5');
})();
queueMicrotask(() => console.log('6'));
console.log('7');
```

**Output: `1 4 7 3 5 6 2`**

How to work it out step by step:

1. **Synchronous code runs first, top to bottom.** It logs `1`. `setTimeout` puts its callback in the **task (macrotask) queue**. `.then` puts `3` in the **microtask queue**.
2. **An async function runs synchronously until its first `await`.** It logs `4`. `await null` pauses the function and queues the rest (`5`) as a microtask.
3. `queueMicrotask` queues `6`. The last line logs `7`.
4. **The stack is empty, so all microtasks run in FIFO order:** `3`, `5`, `6`. Any microtask queued while this happens also runs before moving on.
5. **Only then does the next task run:** `2`.

**Rules to remember:**

- Promise callbacks, `await` continuations and `queueMicrotask` are microtasks. `setTimeout`, `setInterval`, I/O and UI events are tasks.
- The microtask queue is fully drained after each task, before the browser renders.
- `await` on a native promise costs one microtask tick. Returning a promise from inside `.then` adds extra ticks, so such chains can finish "later than expected".
- `new Promise(executor)` runs the executor **synchronously**.

**Strategy in the interview:** write down three columns (stack, microtasks, tasks), move each line into its column, then drain them in order. In Node, `process.nextTick` runs before promise microtasks.
