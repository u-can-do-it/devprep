## Hints

- Is `async`/`await` a different mechanism, or does it build on promises?
- How do you handle errors in each style?
- How would you run two independent requests in parallel with `await`?

## Answer

They are the **same mechanism with different syntax**. An `async` function always returns a Promise. `await` pauses that function (without blocking the thread) until the awaited promise settles. The rest of the function then continues as a microtask.

```js
// Promise chain
function load() {
  return fetch('/api/user')
    .then(r => r.json())
    .then(user => fetch(`/api/posts?u=${user.id}`))
    .then(r => r.json())
    .catch(err => { console.error(err); return []; });
}

// async/await
async function load() {
  try {
    const user = await (await fetch('/api/user')).json();
    const res = await fetch(`/api/posts?u=${user.id}`);
    return await res.json();
  } catch (err) {
    console.error(err);
    return [];
  }
}
```

**Why `async`/`await` is usually preferred:**

- It reads like synchronous code, which makes conditionals and loops natural.
- One `try/catch` handles both sync and async errors.
- Stack traces are clearer.

**Pitfalls:**

- **Accidental serialization.** Awaiting independent calls one after another makes them run in sequence. Start them together instead:
  ```js
  const [a, b] = await Promise.all([getA(), getB()]);
  ```
- `await` inside `forEach` doesn't wait. Use `for...of` (sequential) or `Promise.all(arr.map(...))` (parallel).
- If you forget `await`, you get a Promise instead of a value, and its errors escape your `try/catch`.

`.then()` still makes sense for short one-off transforms. Top-level `await` works in ES modules.
