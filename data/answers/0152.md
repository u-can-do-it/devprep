## Hints

- What does `typeof null` return, and why is that a problem?
- How does `instanceof` decide its answer, and what happens with values from another iframe?
- Which built-in helpers exist for arrays and `NaN`?

## Answer

**`typeof`** returns a string and works on any value, even an undeclared variable. Its quirks:

- `typeof null === 'object'`. This is a historical bug that can't be fixed.
- Arrays, dates, maps and regexes are all `'object'`.
- Functions and classes are `'function'`.
- `typeof NaN === 'number'`.

**`instanceof`** walks the prototype chain: `x instanceof C` checks whether `C.prototype` appears in the chain of `x`. Pitfalls:

- It fails across **realms**. An array from an iframe is not `instanceof Array` in the parent page.
- Primitives are never instances: `'a' instanceof String` is `false`.
- The chain can be changed (`Object.setPrototypeOf`), and `Symbol.hasInstance` can override the check.

**Reliable checks:**

```js
x === null;                       // null
Array.isArray(x);                 // arrays, works across realms
Number.isNaN(x);                  // NaN only (global isNaN coerces: isNaN('abc') === true)
Number.isInteger(x);
typeof x === 'object' && x !== null; // any non-null object
Object.prototype.toString.call(x);   // '[object Date]', '[object Map]', ...
```

A small helper:

```js
const typeOf = (x) => Object.prototype.toString.call(x).slice(8, -1).toLowerCase();
typeOf(null);        // 'null'
typeOf([]);          // 'array'
typeOf(new Date());  // 'date'
```

For your own classes, `instanceof` is usually fine. For data from outside (JSON, other frames, workers), check the structure instead of the prototype, for example with a schema validator.

**Follow-up:** "What does `typeof typeof 1` return?" `'string'`, because `typeof` always returns a string.
