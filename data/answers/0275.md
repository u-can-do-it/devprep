## Hints

- What does a tooltip library do on every scroll and resize to stay attached to its trigger?
- What should happen when the tooltip would overflow the viewport edge?
- Which other native features pair naturally with this, so menus need almost no JavaScript?

## Answer

Attaching a floating element (tooltip, dropdown, popover menu) to a trigger used to need JavaScript such as Floating UI or Popper. The script measures the trigger with `getBoundingClientRect()`, computes coordinates, listens to scroll and resize, and **flips** the element when it would overflow. That runs on the main thread, can lag behind scrolling, and is often fought by `overflow: hidden` and stacking contexts.

**CSS anchor positioning** does this declaratively in the browser's layout engine:

```css
.trigger { anchor-name: --menu-trigger; }

.menu {
  position: absolute;               /* or fixed */
  position-anchor: --menu-trigger;
  position-area: block-end span-inline-end; /* below, aligned to the start edge */
  margin-top: 0.25rem;
  position-try-fallbacks: flip-block, flip-inline; /* flip if it doesn't fit */
}

/* finer control with the anchor() function */
.tooltip {
  position: absolute;
  position-anchor: --menu-trigger;
  bottom: anchor(top);
  left: anchor(center);
  translate: -50% 0;
  width: anchor-size(width);       /* match the trigger's width */
}
```

Key pieces:

- `anchor-name` / `position-anchor` link the two elements. Popovers opened with `popovertarget` get an **implicit anchor**, so even this can be skipped.
- `position-area` is a 3×3 grid around the anchor, a shorthand for common placements.
- `position-try-fallbacks` (plus custom `@position-try` rules) give automatic **collision handling**.
- `anchor-size()` sizes relative to the anchor.

**Compared with JavaScript libraries:**

| | Anchor positioning | Floating UI etc. |
|---|---|---|
| Runs | In layout, no scroll listeners | Main-thread JS on scroll and resize |
| Jank/lag | None | Possible on low-end devices |
| Bundle | 0 KB | A few KB, plus framework wrappers |
| Edge cases (virtual elements, complex middleware) | Limited | Very flexible |
| Support | Chromium since 2024, Safari 26; check other engines | Everywhere |

**Practical approach in 2026:** combine `popover` (top layer and light dismiss) with anchor positioning for menus and tooltips. Use feature detection (`@supports (anchor-name: --a)`) and keep a JS fallback while your support matrix needs it.

**Follow-up:** the anchor must be laid out before the positioned element, and both must be in a compatible containing-block context. Most "it doesn't attach" bugs come from that.
