## Hints

- What did the code look like, and why did it seem right at first?
- What made you suspicious: a test, a type error, a review habit, a production symptom?
- What did you change in your workflow afterwards?

## Answer

Interviewers ask this to check that you **review AI output critically** and own the result. Use STAR and keep it to about 90 seconds.

**Structure:**

- **Situation:** the feature and which tool you used (Claude Code, Cursor, Copilot, Codex).
- **Task:** what you asked it for.
- **Action:** what the tool produced, why it *looked* right, how you found the problem, how you fixed it.
- **Result:** the outcome, and the habit you changed (tests first, smaller tasks, better context files, specific review checklist).

**Good examples of "plausible but wrong":**

- A data-fetching `useEffect` without cleanup that showed stale data when the user switched quickly between items (race condition).
- An API response cast with `as User` that hid a field rename on the backend until it crashed in the UI.
- A test that passed because it mirrored the implementation (it mocked the function under test) and never exercised the real logic.
- A config option or hook from a different library version that compiled against stale types but did nothing at runtime.
- A "performance fix" with `useMemo` everywhere that didn't address the real cause, which a profiler showed was a large list re-rendering.

**Example answer (replace with your own story):**

> "I asked Claude Code to add filtering to a list page fed by an API. The code compiled and the happy path worked. In review I noticed the response was typed with `as Item[]`, and the filter state lived in an effect that refetched on every keystroke without cancelling earlier requests. I reproduced it by typing fast on a throttled connection: results flickered and sometimes showed the wrong filter. I moved the fetching to TanStack Query keyed by the filter, added a schema check on the response, and wrote a test for the fast-typing case. Since then I ask the agent for a plan first and I specifically check async code for cancellation and casts at API boundaries."

**What not to say:** "AI is never wrong for me" (not credible) or "I don't use AI tools" (for an AI training role, that's a red flag). Show that you use the tools heavily *and* verify their output.
