## Hints

- By default, can a method make the caller's variable point to a different object?
- Which of `ref`, `out` and `in` requires the caller to initialize the variable, and which requires the method to assign it?
- Where in the base library do you use `out` every day?

## Answer

By default C# passes arguments **by value**: the method gets a copy of the value (or of the reference, for classes, #561). The modifiers pass the **variable itself** (by reference) instead.

| Modifier | Caller must initialize | Method must assign | Method can modify | Typical use |
|---|---|---|---|---|
| (none) | yes | no | its own copy | default |
| `ref` | **yes** | no | yes, the caller sees it | swap, in-place updates of structs |
| `out` | no | **yes**, before returning | yes | extra return values: `TryParse` |
| `in` | yes | no | **no** (read-only) | pass large structs without copying |
| `ref readonly` | yes | no | no | like `in`, but the caller is expected to pass a variable with `ref` or `in` (C# 12) |

```csharp
void Swap(ref int a, ref int b) => (a, b) = (b, a);
int x = 1, y = 2;
Swap(ref x, ref y);                     // x = 2, y = 1; the keyword is required at the call site too

if (int.TryParse(input, out var number))   // out: declare the variable inline
    Console.WriteLine(number);

bool TryFindUser(int id, out User? user)
{
    user = _db.Find(id);                // compile error if any path returns without assigning user
    return user is not null;
}

double Length(in Vector3 v) => Math.Sqrt(v.X * v.X + v.Y * v.Y + v.Z * v.Z);   // no copy, can't modify v
```

**`ref` with a reference type:** without `ref`, the method can change the object but not which object the caller's variable points to. With `ref`, it can replace it.

```csharp
void Reset(ref List<int> list) => list = new List<int>();   // caller's variable now points to a new list
```

**`params`:** lets the caller pass a variable number of arguments, collected into an array (and since C# 13 into other collection types such as `Span<T>` or `IEnumerable<T>`). It must be the last parameter.

```csharp
int Sum(params int[] numbers) => numbers.Sum();
Sum(1, 2, 3);
Sum();                   // empty array
Sum([1, 2, 3]);          // passing a collection directly also works
```

**In practice:** prefer returning a value, a tuple (`(bool ok, User user)`) or a record over many `out` parameters. `ref` and `in` matter mainly in performance code with structs (#593). `async` methods and lambdas can't have `ref`, `out` or `in` parameters.

**Follow-up:** what's `out _`? (A discard: you must pass something for an `out` parameter but don't need the value, e.g. `int.TryParse(s, out _)` just to validate.)
