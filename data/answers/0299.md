## Hints

- Which dev tools would a 2020-era Node project install that current Node versions make optional?
- Can Node run a `.ts` file directly? What does it do with the types?
- Which TypeScript features can't simply be erased?

## Answer

Recent Node releases (22 LTS and 24 LTS) absorb several tools:

- **`node --watch app.js`**: restarts on file changes. It replaces `nodemon` in most setups. `--watch-path` limits what is watched.
- **`node --env-file=.env app.js`**: loads environment variables without `dotenv`. There's also `process.loadEnvFile()` and `--env-file-if-exists`.
- **Global `fetch`, `Request`, `Response`, `FormData`, `WebSocket` client**, built on undici. No `node-fetch` or `axios` needed for simple calls.
- **`node:test`**: built-in test runner with mocks and coverage.
- **TypeScript type stripping**: since Node 22.18 / 23.6 you can run `node app.ts` with no flag. Node erases the type annotations and runs the result.

```ts
// app.ts — runs with plain `node app.ts`
import type { User } from './types.ts';   // note: explicit .ts extension
const greet = (u: User): string => `Hi ${u.name}`;
```

Type-stripping limits:

- It **doesn't type-check**. Keep `tsc --noEmit` in CI.
- Only **erasable syntax** works: no `enum`, `namespace`, or constructor parameter properties (unless you use `--experimental-transform-types`). Enable `erasableSyntaxOnly` in `tsconfig.json` to catch these early.
- It ignores `tsconfig` paths/aliases, and imports need real `.ts` extensions.
- It doesn't work for `.ts` files inside `node_modules`.

Also useful: `node --run <script>` (a faster `npm run`), `import.meta.dirname`, and single executable applications.

**Follow-up:** Would you still use a bundler for a backend? (Sometimes, for cold-start-sensitive serverless functions or to ship one file.)
