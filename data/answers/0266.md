## Hints

- Can a grid track have both a minimum size and a "take what's left" maximum?
- When there are fewer items than would fit in a row, what should happen to the empty space?
- What breaks on a very narrow screen if the minimum track size is a fixed `16rem`?

## Answer

Combining `repeat()`, `auto-fit` or `auto-fill`, and `minmax()` makes the grid choose the number of columns from the available space:

```css
.cards {
  display: grid;
  gap: 1rem;
  grid-template-columns: repeat(auto-fit, minmax(min(16rem, 100%), 1fr));
}
```

This means: "make as many columns as fit, each at least 16rem wide, and share the leftover space equally." The `min(16rem, 100%)` stops overflow when the container is narrower than 16rem.

**`auto-fill` vs `auto-fit`** only matters when there are **fewer items than would fit** in one row:

- **`auto-fill`** keeps creating columns to fill the row, even **empty** ones. Items keep their computed width and the empty tracks reserve space. Use it when cards should look the same size no matter how many there are.
- **`auto-fit`** creates the same tracks, then **collapses the empty ones to 0**, so the `1fr` items **stretch** to fill the row. Use it when a few items should use the full width.

With three items in a container wide enough for five columns:

```text
auto-fill: [item][item][item][    ][    ]
auto-fit:  [  item  ][  item  ][  item  ]
```

When the row is full, the two behave identically.

**Related tools:**

- `grid-auto-flow: dense` back-fills holes left by items that span several tracks. It changes visual order, which can confuse keyboard users.
- **Container queries** help when the *content* of a card should change layout, not just the column count.
- `fr` units share free space only after content minimums. Use `minmax(0, 1fr)` to let tracks shrink below their content (for long words or code blocks).

**Follow-up:** Flexbox with `flex-wrap` can do something similar, but its last row stretches unevenly. Grid keeps the columns aligned.
