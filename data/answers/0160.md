## Hints

- Before `let`/`const` and modules, what was the only way to create a private scope?
- How can a closure keep some functions private while exposing a public API?
- Where do you still see IIFEs today?

## Answer

An **IIFE** (Immediately Invoked Function Expression) is a function that is defined and called in one step:

```js
(function () {
  const secret = 42;   // not visible outside
})();
```

Before ES2015, `var` was function-scoped and every script shared one global scope. An IIFE was the way to create a private scope and avoid polluting or clashing with globals.

The **module pattern** builds on this. The IIFE returns an object with public methods, and closures keep the internal state private:

```js
const counter = (function () {
  let count = 0;                     // private state
  return {
    increment() { return ++count; },
    get value() { return count; },
  };
})();
counter.increment();
counter.count;   // undefined
```

**What replaced it:**

- **ES modules:** each file has its own scope, and you choose what to `export`.
- **`let`/`const`:** block scope, so any `{ }` block can hold private variables.
- **Classes with `#private` fields** for encapsulated state.

**Where IIFEs still appear:**

- **Async IIFE:** `(async () => { await main(); })();` in CommonJS scripts or other places without top-level `await`.
- **Bundler output:** IIFE/UMD builds for `<script>` tags.
- **One-off initialization** inside an expression.

**Gotcha:** if the previous line has no semicolon, a line starting with `(` is parsed as a function call on that line. That's why some codebases write `;(function () { ... })()`.
