## Hints

- If the server prefetches a query and the client hydrates it with `staleTime: 0`, what happens right after hydration?
- What goes wrong if the server uses one `QueryClient` created at module scope?
- On the server there is no browser cookie jar. How does the query function get the user's token?
- If a Server Component renders `user.name` and a Client Component shows the same user from TanStack Query, what happens after a mutation?

## Answer

TanStack Query is a **client** cache. With server rendering the goal is: fetch on the server, send the result inside the HTML, and let the client cache start **already filled**, so there's no loading spinner and no duplicate request.

**App Router pattern**

```ts
// lib/query-client.ts
import { QueryClient, isServer, defaultShouldDehydrateQuery } from '@tanstack/react-query';

function makeQueryClient() {
  return new QueryClient({
    defaultOptions: {
      queries: { staleTime: 60_000 },        // > 0, otherwise the client refetches immediately
      dehydrate: {
        // also send queries that are still pending, for streaming
        shouldDehydrateQuery: (q) => defaultShouldDehydrateQuery(q) || q.state.status === 'pending',
      },
    },
  });
}

let browserClient: QueryClient | undefined;
export function getQueryClient() {
  if (isServer) return makeQueryClient();            // new client per request: no data shared between users
  return (browserClient ??= makeQueryClient());       // one client for the browser tab
}
```

```tsx
// app/providers.tsx
'use client';
export function Providers({ children }: { children: React.ReactNode }) {
  return <QueryClientProvider client={getQueryClient()}>{children}</QueryClientProvider>;
}

// app/orders/page.tsx (Server Component)
export default async function OrdersPage() {
  const qc = getQueryClient();
  await qc.prefetchQuery(ordersQueryOptions());      // same key and options as the client uses
  return (
    <HydrationBoundary state={dehydrate(qc)}>
      <OrdersTable />                                 {/* 'use client', calls useQuery(ordersQueryOptions()) */}
    </HydrationBoundary>
  );
}
```

**Why each piece matters**

- **One `QueryClient` per request on the server.** A module-level client is shared by all concurrent requests, so user A's data can end up in user B's HTML.
- **`staleTime` > 0.** Otherwise the data is "stale" the moment it hydrates and the client fetches it again.
- **Same `queryOptions` on both sides** (#636), so the keys match. If they don't, hydration does nothing and the client fetches anyway.
- **Streaming:** call `prefetchQuery` **without** `await`, dehydrate pending queries (the option above) and use `useSuspenseQuery` under a `<Suspense>` boundary. The shell streams immediately, and the data arrives when it's ready.

**Auth and the query function.** The browser calls `/api/orders` (cookies sent automatically, #632). The server prefetch has no browser, so it must call the backend directly with the token from `auth()`/`getToken()`, or forward the incoming cookies. Keep **one query key and two transport implementations** (server fetcher, client fetcher) behind the same `queryOptions` factory.

**Serialization.** The dehydrated state is JSON in the HTML. `Date`s become strings unless you configure a serializer (`serializeData`/`deserializeData` with superjson), and anything you prefetch is visible in the page source. Failed queries aren't dehydrated by default, so the client retries them.

**Pages Router:** the same idea in `getServerSideProps`: create a client, `await prefetchQuery`, return `{ props: { dehydratedState: dehydrate(qc) } }`, and wrap pages in `_app` with `<HydrationBoundary state={pageProps.dehydratedState}>` (it was called `<Hydrate>` in v4).

**When Server Components alone are enough.** If data is only displayed, has no client-side refetching, polling, pagination or optimistic updates, just `await` it in a Server Component and skip TanStack Query. Use the query cache for **interactive** client data: tables with filters, infinite lists, mutations with optimistic UI, polling. Don't render the same data from both sources: after a mutation TanStack Query refetches, but the Server Component's copy stays old until `router.refresh()`.

**Follow-up:** "Prefetch everything on the server?" No. Prefetch what's above the fold and needed for the first paint. Lazy tabs and dialogs can fetch on the client.
