## Hints

- What does the C# compiler produce: machine code, or something else?
- Who turns that output into instructions your CPU can run, and when?
- Which of the three runs on Linux, and which one is only maintained, not developed?

## Answer

**The pipeline:** C# source → the compiler (Roslyn) → **IL** (Intermediate Language, CPU-independent bytecode) plus metadata, packed in an assembly (`.dll`) → at run time the **CLR** loads it and the **JIT** compiles each method to native machine code the first time it's called.

- **CLR** (Common Language Runtime): the virtual machine. It loads assemblies, checks types, manages memory with the **garbage collector** (#591), handles exceptions and threads, and hosts the JIT.
- **IL**: what every .NET language (C#, F#, VB) compiles to. That's why they can call each other's code.
- **JIT** (Just-In-Time compiler): compiles IL to native code on first call and caches it for the rest of the process. Modern .NET uses tiered compilation: a quick first version, then an optimized one for hot methods (#604). **ReadyToRun** and **Native AOT** compile ahead of time instead (#601).
- **BCL** (Base Class Library): `System.*` types such as `List<T>`, `HttpClient`, `File`.

```csharp
// Program.cs → dotnet build → bin/Debug/net10.0/App.dll (IL, not x64 code)
Console.WriteLine("Hello");   // JIT-compiled to native code the first time Main runs
```

**The three "flavours":**

| | .NET Framework | .NET Core | .NET (5 and later) |
|---|---|---|---|
| Years | 2002 – 4.8.1 (last version) | 2016 – 3.1 | 2020 – today (8, 9, 10…) |
| Platforms | Windows only | Windows, Linux, macOS | Windows, Linux, macOS, containers, mobile |
| Status | supported with Windows, no new features | end of life | where all development happens |
| Web | ASP.NET (`System.Web`), WCF, Web Forms | ASP.NET Core | ASP.NET Core |

.NET Core was a cross-platform rewrite. With version 5 Microsoft dropped "Core" from the name (and skipped 4 to avoid confusion with Framework 4.x): **modern .NET is .NET Core's continuation**. A new major version ships every November; even numbers (8, 10) are **LTS** with 3 years of support, odd numbers (9) are STS with 2 years of support. Production apps usually target the current LTS.

**.NET Standard** was a shared API contract so one library could run on both Framework and Core. New libraries target `net8.0`/`net10.0` directly; `netstandard2.0` is only needed when a library must still load in .NET Framework (#602).

**Follow-up:** is C# interpreted? (No. IL is always compiled to native code before it runs, by the JIT at run time or ahead of time with ReadyToRun or Native AOT.)
