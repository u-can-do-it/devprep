## Hints

- At roughly how many elements does SVG start to struggle?
- D3 wants to manipulate the DOM, and so does React. Who should win?
- Does a chart of 1 million points actually need 1 million points on an 800-pixel-wide screen?

## Answer

**1. Pick the rendering technology by data size and interactivity**

| | SVG | Canvas 2D | WebGL |
|---|---|---|---|
| elements | up to a few thousand | tens to hundreds of thousands | millions |
| interaction | DOM events per element, CSS, easy | manual hit-testing | manual, GPU picking |
| accessibility | can be made accessible | needs a separate accessible layer | same as canvas |
| libraries | Recharts, visx, Nivo, Highcharts | ECharts, Chart.js, uPlot, Highcharts boost | deck.gl, Highcharts boost, PixiJS, Three.js |

**2. Integrating chart libraries with React**

- **D3 for maths, React for rendering:** use `d3-scale`, `d3-shape` and `d3-array` to compute scales and paths, and render `<svg>` elements in JSX. React owns the DOM, so you get normal state, events and testing. That's how visx works.
- **D3 owns a container:** give D3 a `ref` and let it manage everything inside that element in `useEffect`. React must never render children into it, and the effect must clean up. Use this for complex transitions, zoom and brushing.
- **Imperative libraries (Highcharts, ECharts, Chart.js):** use the official wrapper (`highcharts-react-official`) or create the chart once in an effect and call `chart.update()` or `setData()` on changes. Re-creating the whole chart on every render is slow and loses zoom state. Memoise the options object so the wrapper doesn't think it changed.
- Destroy charts on unmount to avoid leaks, and lazy-load chart libraries because they're large.

**3. Large datasets**

- **Reduce before rendering:** aggregate on the server (per minute instead of per second), or **downsample** with algorithms like LTTB that keep the visual shape. You can't show more points than there are pixels.
- Load the detail on zoom instead of everything up front.
- Move heavy transforms to a **Web Worker**, or render with `OffscreenCanvas` in a worker.
- Throttle real-time updates to one per animation frame and append data instead of replacing the whole series.
- Use virtualisation for big data tables next to charts.

**4. Accessibility:** a text title and summary, a data table alternative, keyboard navigation between points (the Highcharts accessibility module does this), and colour schemes that don't rely on colour alone (patterns, labels, colour-blind-safe palettes).
