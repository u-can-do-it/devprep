## Hints

- Who is the caller: your own React UI, or Stripe, a mobile app, or a partner?
- Which HTTP methods can a Server Action respond to?
- How would you return a CSV file or an RSS feed?

## Answer

Both run server code, but they solve different problems.

**Server Actions** (`'use server'` functions) are an **RPC mechanism for your own UI**:

- Called from `<form action>`, `formAction`, or event handlers in your components
- Always **POST**, with an opaque action ID. The URL isn't stable and isn't meant to be public
- Typed end to end and work with progressive enhancement (forms submit before JS loads)
- Integrate with `useActionState`, `useOptimistic`, `revalidatePath`/`updateTag`, and return an updated RSC payload in the same round trip
- Calls from one client run **one at a time**, so they're a poor fit for parallel data fetching

**Route Handlers** (`app/**/route.ts`) are **real HTTP endpoints** using the Web `Request`/`Response` APIs:

```ts
// app/api/webhooks/stripe/route.ts
export async function POST(req: Request) {
  const sig = req.headers.get('stripe-signature')!;
  const event = stripe.webhooks.constructEvent(await req.text(), sig, secret);
  // ...
  return Response.json({ received: true });
}
```

**Use a Route Handler when:**

- A **third party** calls you: webhooks (Stripe, GitHub, a CMS), OAuth callbacks
- You expose a **public or mobile API** that needs a stable URL, versioning, CORS or custom auth headers
- You need **other methods** (GET, PUT, DELETE, OPTIONS) or HTTP caching on GET
- You return **non-React responses**: files, CSV, RSS, images, streams/SSE
- The client is not React, or lives in another app

**Use a Server Action when** your own UI mutates data: forms, buttons, "add to cart".

**For reading data**, use neither. Fetch directly in Server Components. Don't call your own Route Handler from a Server Component: it adds an extra HTTP hop, and at build time there is no server running to call.

**Follow-up:** both are public entry points. Authenticate, authorize and validate input in each one, ideally through a shared data-access layer.
