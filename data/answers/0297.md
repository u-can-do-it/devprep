## Hints

- How does JavaScript represent raw bytes from a file or socket, given that strings are UTF-16?
- How many bytes does the character `é` or an emoji take in UTF-8?
- What happens if a network chunk ends in the middle of a multi-byte character?

## Answer

A `Buffer` is a fixed-length sequence of **raw bytes**, allocated outside the V8 heap. It's a subclass of `Uint8Array`. Node uses it for binary data from files, sockets, crypto and compression.

```js
const buf = Buffer.from('héllo', 'utf8');
buf.length;                 // 6 bytes, though the string has 5 characters
buf.toString('base64');     // 'aMOpbGxv'
buf.toString('hex');        // '68c3a96c6c6f'
Buffer.from('aMOpbGxv', 'base64').toString(); // 'héllo'

Buffer.alloc(10);           // zero-filled, safe
Buffer.allocUnsafe(10);     // faster, may contain old memory: overwrite before use
```

Supported encodings include `utf8`, `utf16le`, `latin1`, `ascii`, `base64`, `base64url` and `hex`.

Encoding pitfalls:

- **Byte length is not string length.** Use `Buffer.byteLength(str)` for `Content-Length` and size limits.
- **Split multi-byte characters**: concatenating `chunk.toString()` per chunk can corrupt characters cut across chunks. Collect the buffers and `Buffer.concat()` them, call `stream.setEncoding('utf8')`, or use `StringDecoder`/`TextDecoder` with `{ stream: true }`.
- Decoding binary data (images, gzip) as UTF-8 destroys it.
- `latin1` vs `utf8` mix-ups produce "mojibake" like `hÃ©llo`.

Avoid the old `new Buffer()` constructor: it is deprecated because it could expose uninitialized memory. Use `Buffer.from`/`Buffer.alloc`.
