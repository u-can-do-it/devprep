## Hints

- What value does `count` hold inside the handler — the one from this render or the next?
- Does `setCount` change the variable immediately?
- Is there a form of `setState` that receives the latest pending value?

## Answer

State in React is a **snapshot per render**. Inside a handler, `count` is a constant captured from the render that created that handler. Calling `setCount` doesn't mutate it — it **queues** an update and schedules a re-render. React also **batches** updates within the same event (and since React 18, in timeouts and promises too).

```jsx
function handleClick() {
  setCount(count + 1); // count is 0 → queue "set to 1"
  setCount(count + 1); // count is still 0 → queue "set to 1"
}
// next render: count === 1
```

Use the **functional updater** when the new value depends on the previous one. React applies queued updaters in order:

```jsx
setCount(c => c + 1);
setCount(c => c + 1); // next render: count === 2
```

Related pitfalls:

- `console.log(count)` right after `setCount` shows the **old** value.
- **Mutating** objects/arrays (`items.push(x); setItems(items)`) doesn't re-render because the reference is the same (`Object.is`). Create new ones: `setItems([...items, x])`.
- Stale closures in `setInterval` or async callbacks — the functional updater fixes those too.

**Follow-up:** if you need the latest value synchronously outside rendering, a `useRef` may be the right tool.
