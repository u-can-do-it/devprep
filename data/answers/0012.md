## Hints

- For a search box, do you want to react after the user stops typing, or at a steady rate while they type?
- For scroll or resize handlers, which one guarantees regular updates?
- What has to be stored between calls so that a timer can be reset?

## Answer

Both limit how often an expensive function runs when events fire rapidly.

- **Debounce:** run only after the events have **stopped** for `wait` ms. Each new event restarts the timer. Typical uses: search-as-you-type, autosave, validating input, resize-end.
- **Throttle:** run **at most once every** `wait` ms while events keep coming. Typical uses: scroll position, mousemove, drag, infinite-scroll checks.

If a user types steadily for 2 seconds with `wait = 300`, debounce fires once (after they stop). Throttle fires about 7 times.

```js
function debounce(fn, wait = 300) {
  let timer;
  function debounced(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), wait);
  }
  debounced.cancel = () => clearTimeout(timer);
  return debounced;
}

function throttle(fn, wait = 100) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= wait) {
      last = now;
      fn.apply(this, args);
    }
  };
}

input.addEventListener('input', debounce(e => search(e.target.value), 300));
```

**Points interviewers check:**

- `this` and arguments are preserved (`apply(this, args)`).
- A `cancel` method exists, for example to call on unmount.
- Leading vs trailing edge: the simple throttle above drops the last call. Production versions such as lodash's add a trailing call.
- In React, create the debounced function once with `useMemo` or `useRef`. Otherwise every render gets a new timer.

**Follow-up:** for animation work, `requestAnimationFrame` is a natural throttle that runs at most once per frame.
