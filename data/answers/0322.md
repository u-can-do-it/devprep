## Hints

- What status code should a successful `POST` that creates something return, and how do you set it?
- How do you return a 404 from deep inside a helper function?
- What does FastAPI return by default when the request body is invalid?

## Answer

**Set the success code on the decorator**, and **raise `HTTPException`** for errors. Raising works from any depth, including dependencies and helpers.

```python
from fastapi import FastAPI, HTTPException, status, Response

app = FastAPI()

@app.post("/items", status_code=status.HTTP_201_CREATED, response_model=ItemOut)
async def create_item(item: ItemIn):
    if await repo.exists(item.sku):
        raise HTTPException(status.HTTP_409_CONFLICT, detail="SKU already exists")
    return await repo.create(item)

@app.get("/items/{item_id}", response_model=ItemOut,
         responses={404: {"description": "Item not found"}})   # documents it in OpenAPI
async def get_item(item_id: int):
    item = await repo.get(item_id)
    if item is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return item

@app.delete("/items/{item_id}", status_code=204)
async def delete_item(item_id: int) -> None:   # 204 must have no body
    await repo.delete(item_id)
```

What FastAPI does for you:

- **422 Unprocessable Entity** with field-level details when path, query or body validation fails.
- **`response_model`** (or the return annotation) validates and filters the output, so internal fields aren't leaked.
- Errors have the shape `{"detail": ...}`. `HTTPException` accepts `headers=`, e.g. `WWW-Authenticate` for a 401.

Choosing codes: 200 read/update, 201 created, 204 no content, 400 bad request, 401 unauthenticated, 403 forbidden, 404 not found, 409 conflict, 422 validation, 429 rate-limited. Use 5xx only for server faults, never for client mistakes.

Use the `status` constants for readability. Inject `response: Response` if the status depends on runtime logic (`response.status_code = 200`).
