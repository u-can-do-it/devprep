## Hints

- Is `JSON.parse` synchronous or asynchronous, and what does that mean for a 200 MB payload?
- How could you process records one by one instead of loading the whole document?
- Would moving the parse into a worker solve the problem completely?

## Answer

`JSON.parse` and `JSON.stringify` are **synchronous and all-or-nothing**: the whole text must be in memory as one string, and the parsed object graph typically needs several times that much memory. On a server, parsing a huge body blocks the event loop for every other request; in a browser, it freezes the UI.

**Options, from simplest:**

1. **Don't send it.** Paginate, filter on the server, return only needed fields, and compress responses (gzip/brotli). JSON compresses very well.
2. **Stream it.** Use a line-delimited format such as **NDJSON / JSON Lines** (one JSON value per line), so each record can be parsed as it arrives:

```js
const res = await fetch('/export.ndjson');
const lines = res.body
  .pipeThrough(new TextDecoderStream())
  .pipeThrough(splitLines()); // small TransformStream that splits on '\n'

for await (const line of lines) {
  if (line) handle(JSON.parse(line)); // memory stays flat
}
```

   For one giant standard JSON document, use a streaming parser (e.g. `stream-json` in Node) that emits values as it reads.
3. **Move work off the main thread.** A Web Worker or Node `worker_threads` can parse without freezing the UI or event loop. The catch: sending the result back is a structured clone, which costs time too, so do the aggregation in the worker and return a small result.
4. **Server side:** limit body size, and for big imports accept a file upload or a streamed body instead of one huge JSON request.

**Other notes:**
- For large static data embedded in a bundle, `JSON.parse('...')` of a string can load faster than an equivalent JS object literal, because the JSON grammar is simpler to parse.
- Formats like MessagePack or Protocol Buffers are smaller and faster but lose human readability and need tooling on both sides.
