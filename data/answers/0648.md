## Hints

- `await page.waitForTimeout(2000)` makes a flaky test pass. What should it be replaced with, and why does `expect(locator).toHaveText()` not need a wait?
- Every test logs in through the UI and the suite takes 20 minutes. How do you log in once and reuse the session?
- Two tests running in parallel both create a customer called "Test". What goes wrong, and how do you design test data?
- A test fails only in CI. What do you turn on to see what happened?
- The row you want to assert on is row 5,000 of a virtualized AG Grid. Why can't you just find it, and how do you get to it?

## Answer

> Locate elements the way users see them (`getByRole`, `getByLabel`) and assert with web-first assertions (`await expect(locator).toBeVisible()`), which retry until a timeout. That replaces sleeps. Put setup in fixtures and page objects, log in once in a setup project that saves `storageState`, and give each test its own data created through the API. Mock the network with `page.route` only for cases that are hard to produce. Turn on traces for retries in CI, and start the app with `webServer`. In a virtualized grid only visible rows exist in the DOM, so filter or scroll the grid to the row first, then locate it by its row id.

**Locators and assertions**

```ts
test('marks an order as paid', async ({ page }) => {
  await page.goto('/orders');
  await page.getByRole('textbox', { name: 'Search' }).fill('ORD-1042');
  const row = page.getByRole('row', { name: /ORD-1042/ });
  await row.getByRole('button', { name: 'Mark as paid' }).click();
  await expect(row.getByRole('gridcell', { name: 'Paid' })).toBeVisible();       // retries until true
  await expect(page.getByRole('alert')).toHaveText('Order updated');
});
```

- Locators are lazy and strict: they're resolved at action time, and fail if they match more than one element.
- Actions auto-wait until the element is attached, visible, stable, enabled and receives events.
- **Web-first assertions** (`toBeVisible`, `toHaveText`, `toHaveCount`, `toHaveURL`) retry. `expect(await locator.textContent()).toBe(…)` doesn't retry, which is a common source of flakiness.
- Priority: `getByRole` > `getByLabel`/`getByPlaceholder` > `getByText` > `getByTestId`. If a role locator is hard to write, the UI is often inaccessible, which is useful feedback (#286).

**Fixtures and page objects**

```ts
// e2e/fixtures.ts
export const test = base.extend<{ ordersPage: OrdersPage; order: Order }>({
  order: async ({ request }, use) => {
    const order = await (await request.post('/api/test/orders', { data: { number: `ORD-${randomUUID()}` } })).json();
    await use(order);                                       // the test runs here
    await request.delete(`/api/test/orders/${order.id}`);   // cleanup, even if the test failed
  },
  ordersPage: async ({ page }, use) => use(new OrdersPage(page)),
});
```

Page objects hold locators and multi-step actions (`ordersPage.filterByStatus('open')`), so a UI change means fixing one file. Keep **assertions in tests**, not hidden inside page objects.

**Logging in once**

```ts
// playwright.config.ts
export default defineConfig({
  webServer: { command: 'yarn build && yarn start', url: 'http://localhost:3000', reuseExistingServer: !process.env.CI },
  use: { baseURL: 'http://localhost:3000', trace: 'on-first-retry' },
  retries: process.env.CI ? 2 : 0,
  projects: [
    { name: 'setup', testMatch: /auth\.setup\.ts/ },
    { name: 'chromium', use: { ...devices['Desktop Chrome'], storageState: 'playwright/.auth/user.json' }, dependencies: ['setup'] },
  ],
});

// e2e/auth.setup.ts
setup('log in', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Username').fill(process.env.E2E_USER!);
  await page.getByLabel('Password').fill(process.env.E2E_PASSWORD!);
  await page.getByRole('button', { name: 'Sign in' }).click();
  await page.waitForURL('/dashboard');
  await page.context().storageState({ path: 'playwright/.auth/user.json' });   // cookies + localStorage
});
```

With NextAuth the saved state includes the session cookie, so every test starts logged in. Behind an OIDC provider (Keycloak, Entra ID), the setup logs in through the provider's test realm. Keep one storage state per role (admin, reviewer, read-only) to test permissions. Add `playwright/.auth` to `.gitignore`.

**Test data and isolation.** Every test gets a fresh browser context (cookies, storage), but **the backend is shared**. Tests running in parallel (`fullyParallel: true`) need unique data (random suffixes) created through the API in fixtures, not by clicking through the UI. Never depend on test order, and never assert "the table has 12 rows" against a shared database.

**Mocking the network.** Prefer a real backend for the happy path. Use `page.route` for states that are hard to produce: a 500, a slow response, an empty list.

```ts
await page.route('**/api/orders*', (route) => route.fulfill({ status: 500, json: { message: 'Boom' } }));
await expect(page.getByRole('alert')).toContainText('Something went wrong');
```

`page.waitForResponse('**/api/orders*')` helps when you must wait for a specific request. Usually an assertion on the UI is enough and is more robust.

**Debugging and CI**

- Locally: `yarn playwright test --ui` (time-travel UI), `--debug`, and `npx playwright codegen` to record locators.
- CI: `trace: 'on-first-retry'`, plus screenshots or video on failure, uploaded as artifacts. Open them with `npx playwright show-trace trace.zip` to see DOM snapshots, network and console for every step.
- Install browsers with `npx playwright install --with-deps`, or use the official Playwright Docker image. Split big suites with `--shard=1/4`.
- Treat retries as a flakiness detector, not a fix. A test that passes only on retry is still flaky; report it and fix it (#137).

**Testing an AG Grid screen**

- Rows are virtualized, so row 5,000 isn't in the DOM. **Narrow first** (type in the grid filter or the page search) so the target row is visible, rather than scrolling.
- AG Grid renders `role="grid"`, `role="row"` and `role="gridcell"`, plus `row-id` (your `getRowId` value) and `col-id` attributes, which make stable locators: `page.locator('.ag-center-cols-container [row-id="ord-1042"] [col-id="amount"]')`. Hide that in the page object.
- Pinned columns render the same row in several containers, so scope to the right one or `getByRole('row')` may match two elements.
- Wait for the loading overlay to disappear, or assert directly on the expected cell text, which retries.
- Editing: double-click the cell, type, press Enter, then assert the saved value after a reload. The grid alone only proves the UI changed.

**Follow-up:** "What do you cover with Playwright and what with Vitest?" Vitest and React Testing Library for logic, schemas, hooks and component states, which is fast and has many cases (#208, #462). Playwright for a small number of critical user journeys end to end: log in, filter, edit, import, export, permissions (#134).
