## Hints

- Who decides the next step: your code or the model?
- What makes agent failures harder to debug and more expensive than a fixed pipeline?
- Which actions should an agent never take without a human approving them?

## Answer

An **AI agent** is an LLM running in a **loop with tools**: it decides which tool to call next, observes the result, and repeats until it judges the goal reached. A **workflow** is a predefined sequence of steps where your **code** controls the flow and the LLM handles individual steps.

**Common workflow patterns** (from Anthropic's "Building effective agents"):

- **Prompt chaining:** fixed steps, each LLM call working on the previous output (outline → draft → translate), with checks in between.
- **Routing:** classify the input, then send it to a specialised prompt or model (billing vs technical support).
- **Parallelisation:** run independent sub-tasks at once, or the same task several times and vote.
- **Orchestrator–workers:** one LLM breaks the task into subtasks dynamically and delegates them.
- **Evaluator–optimiser:** one call generates, another critiques, then repeat.

**Prefer a workflow when** the steps are known in advance, predictability, cost and latency matter, and the task must be auditable (most business processes: document extraction, ticket triage, report generation).

**Use an agent when** the number and order of steps can't be predicted (debugging code, open-ended research, multi-system investigations), the environment gives feedback the model can act on (tests, search results), and mistakes are recoverable.

**Start with the simplest thing that works:** a single well-prompted call with retrieval and tools often beats a multi-agent system.

**Building agents responsibly:**

- **Tools:** few, well-described, least-privilege, with validated arguments and authorization in code.
- **Guardrails:** a maximum number of steps, token and cost budgets, timeouts, and stopping conditions.
- **Human in the loop** for irreversible or external actions (payments, emails, deletes, production changes).
- **State and memory:** persist progress so a long task can resume (LangGraph checkpoints, a durable workflow engine such as Temporal).
- **Observability:** trace every step (prompt, tool call, result, tokens) with Langfuse, LangSmith or OpenTelemetry, so failures can be replayed.
- **Evaluation:** test suites of tasks with success criteria, run on every prompt or model change.
- **Security:** tool results and retrieved content are untrusted and can carry prompt injection; an agent with private data, untrusted input and the ability to send data out is the riskiest combination.

**Frameworks:** LangGraph, the OpenAI Agents SDK, the Claude Agent SDK, the Vercel AI SDK, or a hand-written loop. The loop itself is short; most of the work is tools, guardrails and evaluation.

**Follow-up:** design an agent that triages incoming bug reports: what tools does it get, what may it do on its own, and what needs a human?
