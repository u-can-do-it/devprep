## Hints

- Does `==` compare values or memory identity?
- Why is `x is None` the idiomatic check, and why should `x is 1000` never be used?
- What does `==` call under the hood on a custom class?

## Answer

- **`==`** checks **equality of value**. It calls `__eq__`, so classes decide what "equal" means.
- **`is`** checks **identity**: whether both names refer to the **same object** (same `id()`). It can't be overridden.

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

a == b   # True: same contents
a is b   # False: two different list objects
a is c   # True: same object

x = None
if x is None: ...      # correct: None is a singleton
```

When to use `is`:

- Singletons: `None`, `True`/`False` (rarely needed), sentinel objects (`_MISSING = object()`), and `Ellipsis`.
- Checking whether two references point to the same mutable object.

Pitfall: **don't use `is` for numbers or strings**. CPython caches small ints (-5 to 256) and interns some strings, so `x is 256` may look like it works while `x is 1000` fails. That's an implementation detail, and Python 3.8+ emits a `SyntaxWarning` for `is` with a literal.

Also note that `==` can return `True` for different types (`1 == 1.0 == True`), and NaN breaks reflexivity: `float('nan') == float('nan')` is `False`. Containers check identity first, so `nan in [nan]` with the same object is `True`.

**Follow-up:** If you define `__eq__`, what happens to `__hash__`? (It's set to `None`, making instances unhashable unless you define it too.)
