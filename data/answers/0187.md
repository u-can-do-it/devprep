## Hints

- When a transpiler like esbuild sees `import { User } from './user'` in one file, can it tell whether `User` is a type or a value?
- What could go wrong if an import that's only used as a type stays in the emitted JS?
- What does `verbatimModuleSyntax` promise about your imports?

## Answer

**Type-only imports** are removed from the output entirely:

```ts
import type { User } from './models';           // whole import erased
import { type Order, createOrder } from './orders'; // only `Order` erased
export type { User };
```

**Why it matters:**

- **Single-file transpilers** (esbuild, swc, Babel, oxc, Node's type stripping) compile each file **in isolation**, without type information. They can't know whether `User` is an interface (drop it) or a class (keep it). If they guess wrong, you get runtime errors like "does not provide an export named 'User'", or extra imports.
- **Side effects and cycles:** an import kept only for types still loads the module at runtime. That can trigger side effects, create circular dependencies, or pull server-only code into a client bundle.
- **Readability:** readers see right away which dependencies exist at runtime.

**Related compiler flags:**

- **`isolatedModules`:** reports code that a per-file transpiler can't handle safely, such as re-exporting a type without `export type`, or using `const enum` across files.
- **`verbatimModuleSyntax` (TS 5.0):** a simple rule. Imports and exports **without** `type` are always kept as written, and ones **with** `type` are always dropped. It replaced `importsNotUsedAsValues` and `preserveValueImports`. It also implies the `isolatedModules` checks, and it's the recommended setting for modern ESM projects and runtimes that strip types.

```ts
// with verbatimModuleSyntax:
import { User } from './models';  // error if User is only a type: use `import type`
```

**Tooling:** the `@typescript-eslint/consistent-type-imports` rule plus auto-fix keeps this consistent. Editors add `type` automatically on auto-import when the flag is on.

**Follow-up:** `import type` of a class gives you the type only. You can't call `new` on it.
