## Hints

- Why shouldn't passwords be stored in a way that can be decrypted?
- If a fast hash like SHA-256 runs billions of times per second on a GPU, what does that mean for attackers?
- What is a salt for, and does it need to be secret?

## Answer

Passwords should be stored using a **slow, salted, adaptive password hashing function** – never plaintext, never reversible encryption, never a plain fast hash.

**Why not SHA-256/MD5?** They're designed to be **fast**. With a leaked database, attackers can test billions of guesses per second on GPUs, and unsalted hashes are vulnerable to precomputed rainbow tables.

**What good password hashing provides:**

- **Salt** – a unique random value per password, stored next to the hash. Identical passwords get different hashes; rainbow tables become useless. It doesn't need to be secret.
- **Work factor** – tunable cost to make each guess expensive; increase it as hardware improves.
- **Memory hardness** (Argon2, scrypt) – requires lots of RAM per guess, which defeats GPU/ASIC parallelism.

**Recommended algorithms (2026):**

- **Argon2id** – first choice (OWASP recommendation), tuned by memory, iterations, parallelism.
- **bcrypt** – fine and widely supported; cost ~12+. Note it truncates input at 72 bytes.
- **scrypt** or **PBKDF2** (high iteration count, required in some FIPS contexts).

```python
from argon2 import PasswordHasher

ph = PasswordHasher()               # sensible defaults
hashed = ph.hash("correct horse")    # salt is generated and embedded
ph.verify(hashed, "correct horse")   # raises on mismatch
if ph.check_needs_rehash(hashed):    # upgrade params on next login
    hashed = ph.hash("correct horse")
```

**Also:**

- Use constant-time comparison (libraries do this).
- Optionally add a **pepper** (secret key kept outside the DB, e.g. in a KMS).
- Don't write your own crypto; check passwords against breached-password lists; prefer MFA/passkeys.

**Follow-up:** How do you migrate existing SHA-1 hashes? (Wrap them: `argon2(sha1(pw))` immediately, then rehash properly on next login.)
