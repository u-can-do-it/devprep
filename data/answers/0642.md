## Hints

- What do you have to change in `index.tsx` to get any of React 18's concurrent features?
- In React 17, how many renders did two `setState` calls inside a `setTimeout` cause? And in 18?
- Which React 19 hooks exist because of forms and Actions?
- What did React 19 remove that a five-year-old codebase probably still uses?

## Answer

> React 18 laid the concurrent foundation: `createRoot`, automatic batching of state updates everywhere, transitions for non-urgent updates, and streaming server rendering with Suspense. React 19 added Actions, where async functions in forms handle pending state, errors and optimistic updates, plus the `use` hook, stable Server Components, and `ref` as a regular prop. Upgrading mostly breaks removed legacy APIs like `ReactDOM.render`, string refs and `defaultProps` on function components. Go through 18.3 first and fix its warnings.

A good answer has one line per release, then details on what you've actually used.

**React 18 (2022): the concurrent foundation**

- **`createRoot`** replaces `ReactDOM.render` and turns on the concurrent renderer. Rendering can now be interrupted and prioritized (#40). Apps still using `ReactDOM.render` behave like React 17.
- **Automatic batching everywhere.** Several `setState` calls in a timeout, a promise or a native event handler cause one render, not one each (#34). `flushSync` opts out.
- **Transitions:** `useTransition` / `startTransition` mark an update as non-urgent so typing stays responsive. **`useDeferredValue`** does the same for a value you receive but don't set (#40).
- **New hooks:**
  - **`useId`** gives IDs that match between server and client (#203).
  - **`useSyncExternalStore`** lets external stores (Redux, Zustand) subscribe without tearing (#222).
  - **`useInsertionEffect`** is for CSS-in-JS libraries (#201).
- **Streaming SSR with Suspense:** `renderToPipeableStream`, `hydrateRoot` and selective hydration. The page streams in chunks and hydrates the part the user interacts with first (#219). This is the base for Next.js App Router streaming.
- **StrictMode** in development now mounts, unmounts and re-mounts every component, to expose effects without cleanup (#200).

**React 19 (December 2024): Actions and the server**

- **Actions:** async functions passed to transitions or to `<form action={fn}>`. React tracks the pending state, errors and optimistic updates for you, and resets the form after success.
- **New hooks for Actions** (#39):
  - **`useActionState`**: the action's result, error and pending flag.
  - **`useFormStatus`** (react-dom): the parent form's pending state, readable in a nested submit button.
  - **`useOptimistic`**: show the expected result while the action runs.
- **`use`** reads a promise (suspending until it resolves) or a context, and unlike hooks it can be called conditionally.
- **Server Components and Server Actions** are stable in React itself. You use them through a framework such as Next.js (#43, #45).
- **Smaller API changes:**
  - **`ref` is a regular prop** for function components, so `forwardRef` is no longer needed (#206). Ref callbacks can return a cleanup function.
  - **`<Context>`** works as a provider, replacing `<Context.Provider>`.
  - **`<title>`, `<meta>` and `<link>`** rendered anywhere are hoisted into `<head>`. Stylesheets can be ordered with `precedence`, and resources preloaded with `preload`/`preinit`.
  - **Errors:** hydration errors show a diff, and uncaught render errors are reported once (`onUncaughtError`, `onCaughtError` on the root) instead of being logged twice.
- **19.2 (2025):** `useEffectEvent` (#221), `<Activity mode="hidden">` to keep a hidden subtree's state (#207), and React performance tracks in Chrome DevTools.
- **React Compiler** (stable 1.0 in 2025) ships separately as a build plugin. It memoizes components automatically, so most hand-written `useMemo`/`useCallback` become unnecessary (#215).

**What breaks when upgrading an older app**

| Upgrade | Typical breakage |
|---|---|
| 17 → 18 | `ReactDOM.render` → `createRoot`; `@types/react` 18 removed the implicit `children` from `React.FC`; effects run twice in StrictMode (dev only) and expose missing cleanups; tests need `act` around updates |
| 18 → 19 | Removed: `ReactDOM.render`/`hydrate`, `unmountComponentAtNode`, `findDOMNode`, string refs, legacy context (`contextTypes`), `propTypes` checks, `defaultProps` on function components (use default parameters), `react-test-renderer/shallow`. TypeScript: `useRef` needs an argument, `ReactElement` props default to `unknown`, global `JSX` namespace moved to `React.JSX`. Old libraries that use `findDOMNode` or `forwardRef` internals need updating. |

**How to upgrade safely:** go through **18.3** first. It is 18.2 plus deprecation warnings for everything 19 removes. Fix the warnings, then run the official codemods (`npx codemod react/19/migration-recipe`, `types-react-codemod`), upgrade libraries that pin React (UI kits, form and table libraries, testing tools), and run the test suite and main user flows. In a Next.js app the React version comes with the Next.js version: the App Router uses React 19, and the Pages Router supports both 18 and 19.

**Follow-up:** "Do you need to rewrite anything to benefit from React 18?" No. Switching to `createRoot` gives automatic batching right away. Transitions and Suspense are opt-in, and you add them where the UI feels sluggish.
