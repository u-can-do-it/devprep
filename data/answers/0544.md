## Hints

- What does an agent loop do on each turn, and who decides when it ends?
- What do you get from an agent framework that a 30-line loop over the Messages API doesn't give you?
- Which tools may the agent call on its own, and how do you enforce that in code rather than in the prompt?

## Answer

**The agent loop:** send the conversation and tool definitions to the model; if it answers with tool calls, run them, append the results and call the model again; stop when it answers without tool calls or hits a limit (turns, tokens, time) (#479, #480). Everything else is context management, tools and guardrails.

**Options, from least to most built in:**

1. **A hand-written loop** over the Messages API: full control, a few dozen lines, but you write tools, retries, context trimming and logging yourself.
2. **The SDK's tool runner** (`client.beta.messages.toolRunner` in the Anthropic SDK): the loop over **your** tools, with hooks per turn. Good for product features: a support assistant, a triage bot.
3. **The Claude Agent SDK** (`@anthropic-ai/claude-agent-sdk`, Python `claude-agent-sdk`): Claude Code's harness as a library. Built-in tools (read, edit, bash, grep, web fetch), MCP servers, subagents, hooks, permissions, sessions and automatic context compaction. Good for agents that work on code or files: CI fixers, migration bots, incident investigators.
4. **A hosted agent platform**, when you don't want to run the loop or its sandbox yourself.

**A read-only investigation agent with the Agent SDK:**

```ts
import { query, tool, createSdkMcpServer, type HookCallback } from '@anthropic-ai/claude-agent-sdk';
import { z } from 'zod';

const recentDeploys = tool(
  'recent_deploys',
  'List deploys of a service in the last N hours, newest first.',
  { service: z.string(), hours: z.number().int().max(48) },
  async ({ service, hours }) => ({
    content: [{ type: 'text', text: JSON.stringify(await deploys.list(service, hours)) }],
  }),
  { annotations: { readOnlyHint: true } },
);

const ops = createSdkMcpServer({ name: 'ops', version: '1.0.0', tools: [recentDeploys] });

const blockWrites: HookCallback = async () => ({
  hookSpecificOutput: {
    hookEventName: 'PreToolUse',
    permissionDecision: 'deny',
    permissionDecisionReason: 'This agent only investigates; propose changes in the report instead.',
  },
});

for await (const msg of query({
  prompt: 'Error rate of booking-api doubled at 14:10. Find the likely cause, with evidence.',
  options: {
    systemPrompt: { type: 'preset', preset: 'claude_code', append: 'Cite trace ids and log lines for every claim.' },
    cwd: '/repos/booking-api',
    mcpServers: { ops },
    allowedTools: ['Read', 'Grep', 'Glob', 'mcp__ops__recent_deploys'],
    hooks: { PreToolUse: [{ matcher: 'Write|Edit|Bash', hooks: [blockWrites] }] },
    maxTurns: 30,
  },
})) {
  if (msg.type === 'result') {
    console.log(msg.subtype === 'success' ? msg.result : `Stopped: ${msg.subtype}`);
    console.log(`cost $${msg.total_cost_usd.toFixed(2)}, ${msg.num_turns} turns`);
  }
}
```

What's happening:

- Custom tools are in-process MCP tools named `mcp__<server>__<tool>`.
- `allowedTools` pre-approves calls; a `PreToolUse` **hook** denies writes even if a permission mode would allow them; `canUseTool` is the callback for interactive approval.
- The `claude_code` preset gives you Claude Code's system prompt (the default is minimal); `settingSources` controls whether the repo's `CLAUDE.md` and settings are loaded.
- The final `result` message reports success or the reason it stopped, plus cost and turns. Log them.

**Design decisions interviewers probe:**

- **Workflow or agent?** If the steps are known (fetch the alert, collect the deploys, summarise), a fixed workflow is cheaper and more predictable; an agent pays off when the path depends on what it finds (#480).
- **Context:** give the agent search tools rather than dumping everything into the prompt; return compact tool outputs (#542); delegate wide searches to **subagents** so the main context stays small.
- **Permissions in code, not in the prompt;** read-only by default; human approval for side effects; no production secrets in its environment (#525).
- **Limits:** max turns, budget, timeouts, and what happens when they're hit (a partial report, not silence).
- **Observability:** log every step (tool calls, arguments, results, tokens) so a bad run can be replayed.
- **Evaluation:** a set of past incidents with known causes; measure accuracy, cost and turns per run (#543).

**Agent SDK vs Claude Code vs n8n vs a plain API call:** Claude Code itself (headless with `claude -p`, or the GitHub Action) is enough for many CI tasks without writing an agent. Use the Agent SDK when you need custom tools, your own UI or integration, or tight control of permissions. Use n8n when the flow is fixed and business-owned (#547). Use a single API call for classification, extraction or summaries.

**Follow-up:** your agent sometimes loops calling the same tool with slightly different arguments. How do you diagnose and fix it? (Read the transcripts; usually the tool's output doesn't say what's wrong or what to try next, or two tools overlap. Improve error messages and descriptions, add a turn limit, detect repeated calls in a hook.)
