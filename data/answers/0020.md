## Hints

- Where does an arrow function get its `this` from?
- Can you call an arrow function with `new`? Does it have `arguments`?
- When would an arrow function be the *wrong* choice?

## Answer

Arrow functions are more than shorter syntax. They behave differently:

| | Regular function | Arrow function |
|---|---|---|
| `this` | set dynamically, by how the function is called | **lexical**: taken from the enclosing scope, and can't be changed with `call`/`bind` |
| `arguments` | yes | no (use rest parameters `...args`) |
| `new` / constructor | yes, has `prototype` | **no**: throws a TypeError |
| `super`, `new.target` | own | lexical |
| Hoisting | function declarations are hoisted | follows the variable (`const` → TDZ) |
| Syntax | `function f(a) { return a * 2; }` | `const f = a => a * 2;` (implicit return) |

```js
class Timer {
  seconds = 0;
  start() {
    setInterval(() => this.seconds++, 1000); // arrow: `this` is the instance
    // with function () { this.seconds++ }, `this` would be undefined (classes run in strict mode)
  }
}
```

**When to use arrows:**

- Callbacks (`map`, `then`, timers) where you want the outer `this`.
- Short pure helpers.
- Class fields used as handlers (`handleClick = () => {...}`), so the method stays bound when passed around.

**When not to:**

- **Object methods** that need `this` to be the object: `{ count: 0, inc: () => this.count++ }` doesn't work.
- Prototype methods, and constructors.
- DOM handlers that use `this` as the element. Use `e.currentTarget` instead anyway.
- Functions that need `arguments`.

**Gotcha:** returning an object literal needs parentheses: `() => ({ ok: true })`.
