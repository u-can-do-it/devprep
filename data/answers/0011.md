## Hints

- Which of the three can change the length of the array, and which can change the type of the result?
- What does `reduce` do with the initial value you pass it?
- Do any of them change the original array?

## Answer

All three are **non-mutating** higher-order array methods. Each one takes a callback and returns a new value without changing the original array.

- **`map(fn)`** transforms each element and returns a new array of the **same length**.
- **`filter(fn)`** keeps the elements for which `fn` returns a truthy value. It returns a new array that is **the same length or shorter**.
- **`reduce(fn, initial)`** combines all elements into **one value** of any type: a number, an object, a Map, even another array.

```js
const orders = [
  { id: 1, total: 40, status: 'paid' },
  { id: 2, total: 15, status: 'pending' },
  { id: 3, total: 60, status: 'paid' },
];

const ids = orders.map(o => o.id);                     // [1, 2, 3]
const paid = orders.filter(o => o.status === 'paid');  // ids 1 and 3
const revenue = paid.reduce((sum, o) => sum + o.total, 0); // 100

const byStatus = orders.reduce((acc, o) => {
  (acc[o.status] ??= []).push(o);
  return acc;
}, {});
```

**Tips and pitfalls:**

- Always pass an **initial value** to `reduce`. Without one, `reduce` throws on an empty array, and the first element becomes the accumulator.
- `map` is for transforming. Use `forEach` (or `for...of`) for side effects.
- `arr.map(parseInt)` gives `[1, NaN, NaN]` for `['1','2','3']` because the index is passed as the radix.
- Chaining creates intermediate arrays. That's fine almost always, but for very hot paths a single loop is faster.
- Related methods: `find`, `some`/`every`, `flatMap`, and `Object.groupBy` (ES2024) for grouping.
