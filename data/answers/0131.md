## Hints

- Which command removes commits from history and which one adds a new commit?
- Which is safe to use on a branch that teammates have already pulled?
- What do `--soft`, `--mixed`, and `--hard` change?

## Answer

**`git reset`** moves the current branch pointer to another commit, effectively removing later commits from the branch's history. Modes control what happens to your changes:

- `--soft`: keep changes staged.
- `--mixed` (default): keep changes in the working directory, unstaged.
- `--hard`: discard changes entirely (dangerous).

**`git revert`** creates a **new commit** that applies the inverse of an earlier commit. History is preserved; nothing is rewritten.

```bash
git reset --soft HEAD~1    # undo last commit, keep its changes staged
git reset --hard HEAD~3    # drop last 3 commits and their changes (local only!)
git revert a1b2c3d         # new commit undoing a1b2c3d — safe on main
git revert -m 1 <merge>    # revert a merge commit
```

**Rule of thumb:**

- Local, unpushed mistakes → `reset` is fine.
- Already pushed to a shared branch → use `revert`, so others' history doesn't break.

Recovery tip: commits "lost" by `reset --hard` can usually be found via `git reflog` for a while.

**Follow-up:** "How is `git restore` different?" — it changes files in the working tree or index, not branch history.
