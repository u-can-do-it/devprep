## Hints

- In Python, can a function take another function as an argument and return a new function?
- What does the `@decorator` line above a `def` translate to?
- Why do you need `functools.wraps`, and how do you make a decorator that accepts arguments?

## Answer

A decorator is a **callable that takes a function and returns a replacement** (usually a wrapper). `@timed` above `def f` is just sugar for `f = timed(f)`. It works because functions are first-class objects and closures keep a reference to the original.

```python
import functools
import time

def timed(func):
    @functools.wraps(func)            # keep __name__, __doc__, signature
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            print(f"{func.__name__} took {elapsed:.4f}s")
    return wrapper

@timed
def slow_sum(n: int) -> int:
    return sum(range(n))
```

**Decorators with arguments** need one more level: a factory that returns the decorator.

```python
def retry(times: int):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator

@retry(times=3)
def fetch(): ...
```

Real-world uses: logging, timing, caching (`functools.cache`), auth checks, retries, route registration (`@app.get` in FastAPI), `@property`, `@staticmethod`.

Pitfall: decorating an `async def` with a sync wrapper breaks it; write an `async def wrapper` that `await`s the function.
