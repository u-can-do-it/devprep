## Hints

- What does `new Date(2026, 1, 1)` represent, and why does the month surprise people?
- Can a `Date` represent "10:00 in Warsaw" as opposed to a single moment in time?
- Why is adding "one month" or "one day" with `Date` error-prone?

## Answer

**Problems with `Date`:**

- **Mutable:** `setDate` changes the object in place, which causes shared-reference bugs.
- **Confusing API:** months are 0-based but days are 1-based. `getYear` is deprecated, and there are overflow surprises (Jan 31 + 1 month = Mar 3).
- **Only two time zones:** the user's local zone and UTC. You can't model "an event in New York" in a browser running in Warsaw.
- **Inconsistent parsing:** `new Date('2026-10-04')` is UTC midnight, but `new Date('2026-10-04T00:00')` is *local* midnight. Non-ISO strings depend on the engine.
- **No date-only or time-only types, no durations,** and DST-unsafe arithmetic (adding `24 * 3600 * 1000` is not always "one day").

**Temporal** (reached Stage 4 in 2026, part of ES2026) fixes this with **immutable**, explicit types:

- `Temporal.Instant`: an exact moment (UTC, nanosecond precision).
- `Temporal.ZonedDateTime`: a moment plus an IANA time zone. DST-aware arithmetic.
- `Temporal.PlainDate`, `PlainTime`, `PlainDateTime`: wall-clock values without a zone (birthdays, opening hours).
- `Temporal.Duration` and `Temporal.Now`.

```js
const meeting = Temporal.ZonedDateTime.from('2026-03-28T10:00[Europe/Warsaw]');
const nextWeek = meeting.add({ days: 7 });  // still 10:00 local time across the DST change
const birthday = Temporal.PlainDate.from('1990-02-28');
birthday.add({ years: 1 }).toString();       // '1991-02-28'
```

**Support:** shipped in Firefox and Chromium-based browsers. Safari was still rolling it out in 2026, so production apps often load a polyfill. date-fns and Day.js remain common in existing code.

**Storage advice:** store past moments as UTC instants (ISO 8601 strings). For **future** local events, store the wall-clock time plus the time zone, because time zone rules can change. Format for users with `Intl.DateTimeFormat`.
