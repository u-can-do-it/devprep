## Hints

- Do you need to start a real Uvicorn server to send requests to your app in tests?
- How do you swap the real database or an external API for a fake in one test?
- When do you need an async test client instead of `TestClient`?

## Answer

**`TestClient`** (Starlette, built on httpx) calls the ASGI app **in-process**, with no server or network. It's synchronous, so tests are plain functions:

```python
from fastapi.testclient import TestClient
from app.main import app, get_db, get_payment_client

def test_create_order(db_session):
    app.dependency_overrides[get_db] = lambda: db_session
    app.dependency_overrides[get_payment_client] = lambda: FakePayments()
    try:
        with TestClient(app) as client:          # 'with' runs the lifespan
            r = client.post("/orders", json={"sku": "A1", "qty": 2},
                            headers={"Authorization": "Bearer test"})
        assert r.status_code == 201
        assert r.json()["qty"] == 2
    finally:
        app.dependency_overrides.clear()
```

**Async tests** are needed when the test itself must `await` things, such as an async DB session or async fixtures. Use `httpx.AsyncClient` with `ASGITransport` and `pytest-asyncio` or `anyio`:

```python
import pytest
from httpx import ASGITransport, AsyncClient

@pytest.mark.anyio
async def test_list_orders(seeded_db):
    async with AsyncClient(transport=ASGITransport(app=app), base_url="http://test") as ac:
        r = await ac.get("/orders")
    assert r.status_code == 200
```

`ASGITransport` doesn't run lifespan events. Wrap the app with `asgi-lifespan`'s `LifespanManager` if startup code matters.

**Test database strategies:**

- A real Postgres in Docker or **Testcontainers**, not SQLite, so the SQL dialect matches production.
- Wrap each test in a **transaction that's rolled back**, or truncate tables between tests.
- Run migrations once per session.

What to test: unit-test business logic without HTTP, and use API tests for validation (422s), auth (401/403), status codes and serialization. Mock only at the edges (payment providers, email). Keep overrides in fixtures so they're always cleared.
