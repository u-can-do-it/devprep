## Hints

- What happens to memory if you buffer the whole multipart body before uploading?
- Does the file need to pass through your servers at all?
- How do you validate size and type, survive a dropped connection, and know when the upload has finished?

## Answer

**Option 1 (preferred at scale): don't proxy the bytes.** The API issues **presigned URLs** and the client uploads straight to S3.

1. Client asks `POST /uploads` with filename, size and type. The API checks auth, quotas and allowed types, creates a DB record (`pending`), and returns presigned URLs.
2. For large files, use **S3 multipart upload**: one presigned URL per part (e.g. 64 MB parts) so parts upload in parallel and failed parts retry on their own.
3. Client calls `complete`. Or better, an **S3 event** (via EventBridge/SQS) triggers a worker that verifies the object (size, magic bytes, virus scan), marks it `ready`, and starts processing.

Enforce limits with a presigned POST policy (`content-length-range`) or by checking the parts, and add a lifecycle rule to **abort incomplete multipart uploads**.

**Option 2: stream through Node** (when you must transform, scan inline, or hide S3):

```js
import busboy from 'busboy';
import { Upload } from '@aws-sdk/lib-storage';

app.post('/upload', (req, res, next) => {
  const bb = busboy({ headers: req.headers, limits: { fileSize: 5 * 1024 ** 3, files: 1 } });
  bb.on('file', (name, file, info) => {
    const upload = new Upload({
      client: s3,
      params: { Bucket, Key: crypto.randomUUID(), Body: file, ContentType: info.mimeType },
      queueSize: 4, partSize: 16 * 1024 * 1024,   // memory ≈ queueSize × partSize
    });
    file.on('limit', () => upload.abort());
    upload.done().then(() => res.status(201).end(), next);
  });
  req.pipe(bb);
});
```

Memory stays bounded because the stream's **backpressure** pauses the socket while parts upload.

Also consider: proxy and load-balancer body limits and timeouts, abort when the client disconnects, resumability (tus or multipart with stored part ETags), checksums, never trusting the client's `Content-Type`, and private buckets served via CloudFront signed URLs.

**Follow-up:** How do you show progress to the user? (Track uploaded parts on the client, or `httpUploadProgress` events in option 2.)
