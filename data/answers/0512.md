## Hints

- What does `<Outlet />` render?
- Where should the "is the user logged in?" check live so that every private page gets it for free?
- What's the difference between fetching in `useEffect` after render and fetching in a route loader?
- What does the web server have to do when a user refreshes the page on `/accounts/42`?

## Answer

React Router v7 has a **library ("data") mode**: `createBrowserRouter` with loaders, actions and lazy routes in a normal SPA. It also has a **framework mode**, which is the successor to Remix (file routes, SSR). An enterprise SPA usually uses data mode.

```tsx
const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,          // header, nav, footer and an <Outlet /> for the child route
    errorElement: <RouteError />,     // catches render and loader errors below it
    children: [
      { index: true, element: <Home /> },
      { path: 'login', element: <Login /> },
      {
        element: <RequireAuth />,     // pathless layout route: guards every child
        children: [
          { path: 'accounts', lazy: () => import('./routes/accounts') },
          { path: 'accounts/:accountId', lazy: () => import('./routes/account-details') },
        ],
      },
      { path: '*', element: <NotFound /> },
    ],
  },
]);

createRoot(document.getElementById('root')!).render(<RouterProvider router={router} />);
```

**A lazy route module** exports its component and loader, so the code and the data both load on navigation:

```tsx
// routes/account-details.tsx
export async function loader({ params }: LoaderFunctionArgs) {
  const res = await fetch(`/api/accounts/${params.accountId}`);
  if (res.status === 404) throw new Response('Not found', { status: 404 });
  return res.json() as Promise<Account>;
}

export function Component() {
  const account = useLoaderData() as Account;
  return <AccountDetails account={account} />;
}
```

**Protected routes:**

```tsx
function RequireAuth() {
  const { user, status } = useAuth();
  const location = useLocation();
  if (status === 'loading') return <PageSpinner />;
  if (!user) return <Navigate to="/login" replace state={{ from: location }} />;
  return <Outlet />;
}
// After login: navigate(location.state?.from?.pathname ?? '/', { replace: true })
```

- Matched loaders start **before** any element renders, in parallel. So an element guard alone doesn't stop child loaders from calling the API. Also check auth in loaders (`throw redirect('/login')`), or use route middleware in newer v7 releases.
- **Client-side guards are UX only.** The API must reject unauthenticated and unauthorized requests anyway.
- For role-based pages, use the same pattern with permissions (`<RequirePermission perm="payments:approve" />`).

**Why loaders instead of `useEffect` fetching?** Fetching starts at navigation instead of after render. Nested routes load in parallel instead of in a waterfall, and errors go to `errorElement`. `useNavigation()` gives you a global pending state. Many teams combine loaders with TanStack Query (`queryClient.ensureQueryData` in the loader) to get caching.

**Also mention:**

- **URL state:** keep filters, sort and tabs in `useSearchParams` so views can be shared and bookmarked (#503).
- **Code splitting** per route with `lazy`, and `<ScrollRestoration />`.
- **`basename`** if the app is deployed under a subpath.
- **Server fallback:** the web server must return `index.html` for unknown paths (`try_files $uri /index.html`, #506). Otherwise refreshing a deep link gives a 404.
- **Alternatives:** TanStack Router (fully type-safe params and search params), or a framework (Next.js, React Router framework mode) when you need SSR.
