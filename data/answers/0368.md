## Hints

- After `npm run build`, where does the value of an environment variable used in client code end up?
- Who can open DevTools on your production site?
- How could the browser use a third-party API without ever holding the secret?

## Answer

Everything shipped to the browser is **public**. Bundlers inline client-side env vars at build time (`NEXT_PUBLIC_*`, `VITE_*`), so the value sits in plain text in a JS file. Minification or obfuscation doesn't help: anyone can read the bundle, watch the Network tab, or replay the request with `curl`.

Splitting keys into two kinds helps:

- **Publishable/public keys** are designed to be exposed (Stripe `pk_...`, Firebase web config, map keys). Lock them down with domain/referrer restrictions, quotas and server-side rules.
- **Secret keys** (Stripe `sk_...`, OpenAI/Anthropic keys, DB credentials) must **never** reach the client.

**What to do instead:** call the third-party API from your server, a **backend-for-frontend** (BFF) route, a Server Action or a serverless function. The browser authenticates to *your* backend (session cookie), and the backend adds the secret.

```ts
// app/api/summarize/route.ts (runs on the server only)
export async function POST(req: Request) {
  const user = await requireSession(req);           // your auth
  const { text } = await req.json();
  const res = await fetch('https://api.example-llm.com/v1/messages', {
    method: 'POST',
    headers: { 'x-api-key': process.env.LLM_API_KEY! }, // no NEXT_PUBLIC_ prefix
    body: JSON.stringify({ text }),
  });
  return Response.json(await res.json());
}
```

Then add per-user rate limits so your proxy doesn't become a free API for everyone. In Next.js, `import 'server-only'` makes the build fail if a server module is imported into client code.

**Pitfall:** if a secret has ever been in a bundle or a git commit, assume it is leaked and **rotate** it; deleting the commit is not enough.
