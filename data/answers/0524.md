## Hints

- `GET /api/users/me` and `GET /api/admin/users` live in the same app. What stops a logged-in customer from calling the second one?
- Should authorization be an `if` inside each handler, or something a route can't be registered without?
- How do you find the endpoints that forgot the check?

## Answer

**Broken function-level authorization (BFLA)**, API5:2023 in the OWASP API Security Top 10: an authenticated user can call a *function* they shouldn't, usually an admin or internal endpoint, because the route only checks "is logged in". Typical cases: `/admin/*` protected only by a hidden menu entry; `PUT /users/{id}` accepting a `role` field (mass assignment, #372); checks on `GET /orders/7` but not on `DELETE /orders/7`; internal endpoints reachable through the public gateway; a mobile-only API with weaker rules than the web one.

**Difference from IDOR/BOLA (#371):** BOLA is about *which object* (someone else's invoice), BFLA about *which action or function* (the admin export). Both are "broken access control", A01 in the OWASP Top 10, and both follow the same rule: **deny by default, check on every request, in the backend.**

**Enforcement patterns**

Express: middleware on the router, so handlers can't exist without a policy.

```ts
const requirePermission = (perm: Permission): RequestHandler => (req, res, next) =>
  req.user?.permissions.includes(perm) ? next() : res.sendStatus(req.user ? 403 : 401);

const admin = Router();
admin.use(requireAuth, requirePermission('users:manage'));   // applies to every route below
admin.get('/users', listUsers);
admin.delete('/users/:id', deleteUser);
app.use('/api/admin', admin);
```

FastAPI: dependencies declared on the router.

```python
def require(perm: str):
    def dep(user: User = Depends(current_user)) -> User:
        if perm not in user.permissions:
            raise HTTPException(status_code=403)
        return user
    return dep

admin = APIRouter(prefix="/admin", dependencies=[Depends(require("users:manage"))])

@admin.delete("/users/{user_id}")
async def delete_user(user_id: int, actor: User = Depends(require("users:delete"))): ...
```

- **One authorization layer**, not scattered `if`s: a `can(user, action, resource)` function or a policy engine (Casbin, OPA, Cedar) fed by your RBAC/ABAC data (#379). Object-level checks live in the same place, so BOLA and BFLA are handled together.
- **Deny by default:** a route with no declared policy fails a startup check, or a test walks the router and asserts every route carries auth metadata.
- **Separate admin APIs** by path prefix, and ideally by network (internal gateway, VPN or a separate service) with their own audit log.
- **The server decides roles**, never the client: don't read `role` from the request body or from a client-editable token, and re-check permissions on sensitive actions even when the token says `admin`.
- **`401` for unauthenticated, `403` for forbidden** (or `404` when existence is sensitive), identical for every HTTP method.

**Testing:** an authorization matrix test (every endpoint × every role → expected status) in CI, so a new endpoint without a policy fails the build. Also try other methods (`PATCH`, `OPTIONS`) and path variants (`/Admin/users`, trailing slash, `%2e%2e`) that bypass path-based rules in a proxy.

**Follow-up:** authorization lives in the API gateway as path rules. What breaks when someone adds `/api/v2/admin`? (Path allowlists drift; enforce in the service as well.)
