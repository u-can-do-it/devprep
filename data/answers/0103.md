## Hints

- Which protocol guarantees that bytes arrive, in order, and how?
- What does a protocol give up to have lower latency?
- Which would you pick for a video call, and which for downloading a file?

## Answer

Both are transport-layer protocols on top of IP.

**TCP (Transmission Control Protocol)**

- **Connection-oriented** – three-way handshake before data flows.
- **Reliable and ordered** – sequence numbers, acknowledgments, retransmissions.
- **Flow and congestion control** – adapts to receiver and network capacity.
- **Byte stream** – no message boundaries.
- Higher latency and overhead; a lost packet blocks everything behind it (head-of-line blocking).
- Used by HTTP/1.1, HTTP/2, SSH, databases, SMTP.

**UDP (User Datagram Protocol)**

- **Connectionless** – just send datagrams.
- **No guarantees** – packets may be lost, duplicated or reordered.
- Small header, minimal latency, supports broadcast/multicast.
- Message-oriented – each datagram is a unit.
- Used by DNS, video/voice calls, online games, and **QUIC** (HTTP/3), which builds its own reliability on top of UDP.

| | TCP | UDP |
|---|---|---|
| Delivery | guaranteed, ordered | best effort |
| Setup | handshake | none |
| Speed | slower | faster |
| Use case | web, files, APIs | real-time media, DNS, games |

**Rule of thumb:** use TCP when correctness of every byte matters; UDP when fresh data beats complete data (a late video frame is useless).

**Follow-up:** Why did HTTP/3 move to UDP? (To avoid TCP head-of-line blocking and enable faster handshakes and connection migration via QUIC.)
