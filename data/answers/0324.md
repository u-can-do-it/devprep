## Hints

- How do you turn environment variables (which are all strings) into typed, validated config?
- How do you keep a secret from showing up in logs or error messages?
- How would a test replace the settings without editing environment variables?

## Answer

`pydantic-settings` provides `BaseSettings`: a Pydantic model whose fields are **filled from environment variables** (and optionally `.env` files or secret files), then validated and type-converted. The app **fails at startup** if config is missing or wrong.

```python
from functools import lru_cache
from typing import Annotated
from fastapi import Depends, FastAPI
from pydantic import PostgresDsn, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="APP_", env_file=".env", extra="ignore")

    env: str = "dev"
    database_url: PostgresDsn            # APP_DATABASE_URL, validated as a DSN
    jwt_secret: SecretStr                # repr shows '**********'
    cors_origins: list[str] = []         # parsed from a JSON string
    debug: bool = False                  # "true"/"1"/"yes" -> True

@lru_cache
def get_settings() -> Settings:
    return Settings()

SettingsDep = Annotated[Settings, Depends(get_settings)]

app = FastAPI()

@app.get("/info")
def info(settings: SettingsDep):
    return {"env": settings.env}

# tests
app.dependency_overrides[get_settings] = lambda: Settings(
    database_url="postgresql://test@localhost/test", jwt_secret="x")
```

Practices:

- **Priority**: init arguments, then env vars, then `.env`, then defaults. Real environment variables beat the file.
- `SecretStr` hides values in logs and reprs. Call `.get_secret_value()` only where needed.
- Nested config works with `env_nested_delimiter="__"` (`APP_DB__POOL_SIZE`).
- In production, **inject secrets from a secret manager** (Kubernetes Secrets, AWS Secrets Manager) as env vars or mounted files (`secrets_dir`). Never bake `.env` into the image.
- `@lru_cache` reads config once. Getting it via `Depends` keeps it overridable in tests.

**Follow-up:** Why not just `os.environ["X"]` everywhere? (No types, no validation, late failures at runtime, scattered access and no single place to document the config.)
