## Hints

- What happens if you pass a string to a dataclass field annotated as `int`?
- Which one parses JSON and converts types for you, and what does that cost?
- What tools actually use type hints if the interpreter doesn't check them?

## Answer

> Python type hints aren't checked when the code runs. The interpreter ignores them, and only tools like mypy or libraries that read them, such as Pydantic, use them. Dataclasses generate `__init__`, `__repr__` and `__eq__` from annotated fields, but they don't validate anything, so wrong types get in silently. Pydantic models validate and convert input at runtime, give clear errors and can serialize to JSON. Use dataclasses for internal data you already trust, and Pydantic for data crossing a boundary, like HTTP requests or config.

**Type hints are not enforced at runtime.** The interpreter stores them in `__annotations__` and otherwise ignores them. They're used by **static checkers** (mypy, Pyright), IDEs, and libraries that choose to read them at runtime, like Pydantic and FastAPI.

**`dataclasses`** (standard library) generate `__init__`, `__repr__`, `__eq__` (optionally ordering, `frozen`, `slots`) from annotated fields. No validation or conversion:

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

Point("a", None)  # accepted silently
```

**Pydantic models** (v2, core written in Rust) **validate and coerce** input at runtime, produce clear errors, serialize (`model_dump`, `model_dump_json`) and generate JSON Schema:

```python
from pydantic import BaseModel, Field

class User(BaseModel):
    id: int
    email: str = Field(pattern=r".+@.+")

User(id="42", email="a@b.c").id   # 42 (coerced)
User(id="x", email="a@b.c")       # ValidationError
```

When to use which:

- **Dataclasses** – internal domain objects and data you already trust; zero dependencies, faster to construct.
- **Pydantic** – data crossing a boundary: HTTP requests/responses, config/env (`pydantic-settings`), external APIs, message payloads.

Middle ground: `pydantic.dataclasses.dataclass` adds validation to dataclass syntax; `TypeAdapter` validates arbitrary types.
