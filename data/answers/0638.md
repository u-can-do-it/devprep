## Hints

- MUI components need React context and Emotion. Can you still import a `Button` in a Server Component?
- Where do Emotion's styles go during streaming SSR, and what does the user see if they're missing?
- Why can't you pass a function in `sx` from a Server Component?
- `useMediaQuery` returns `false` on the server. What happens on a phone during hydration?

## Answer

> MUI uses Emotion to generate CSS at run time, which needs extra setup in the App Router. Put the theme provider in a client component and wrap it in `AppRouterCacheProvider`, so the generated CSS reaches the streamed HTML and nothing flashes unstyled. Load fonts with `next/font` and use `next/link` through the `component` prop. To keep it fast, create the theme once, use `styled()` instead of `sx` in hot lists, and prefer CSS breakpoints over `useMediaQuery`, which returns `false` on the server.

**Setup in the App Router**

1. **Client boundary for the theme.** `createTheme` can contain functions, and `ThemeProvider` uses context, so the provider lives in a `'use client'` file:

```tsx
// app/providers.tsx
'use client';
import { AppRouterCacheProvider } from '@mui/material-nextjs/v15-appRouter';   // matches your Next major
import { ThemeProvider, CssBaseline } from '@mui/material';
import { theme } from './theme';

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <AppRouterCacheProvider options={{ enableCssLayer: true }}>
      <ThemeProvider theme={theme}>
        <CssBaseline />
        {children}
      </ThemeProvider>
    </AppRouterCacheProvider>
  );
}
```

2. **`AppRouterCacheProvider`** (from `@mui/material-nextjs`) collects the CSS that Emotion generates while rendering and injects it into the streamed HTML via `useServerInsertedHTML`. Without it you get a flash of unstyled content and class-name hydration mismatches. `enableCssLayer` wraps MUI styles in `@layer mui`, which makes coexistence with Tailwind or global CSS predictable.
3. **Server Components can import MUI components** directly, because MUI marks them `'use client'`. They render as client components, so props must be serializable: `sx={{ p: 2 }}` is fine; `onClick` or `sx={(theme) => …}` must move into your own client component.
4. **Fonts:** load with `next/font` and point `typography.fontFamily` at its CSS variable (`var(--font-roboto)`). Self-hosted fonts also avoid build failures on networks without internet access.
5. **Links:** `<Button component={Link} href="/orders">`, or set it once with `MuiButtonBase.defaultProps.LinkComponent` in the theme.
6. **Pages Router equivalent:** `AppCacheProvider` from `@mui/material-nextjs/v15-pagesRouter` in `_app`, plus `DocumentHeadTags` and `documentGetInitialProps` in `_document`.

**Performance**

- **Imports.** `import { Button } from '@mui/material'` is tree-shaken in production builds. The cost is in **development compile time**: barrel files pull in hundreds of modules. Next.js's `optimizePackageImports` handles `@mui/material` and `@mui/icons-material` by default; in other bundlers, prefer path imports (`@mui/material/Button`). Never `import * as Icons`.
- **Runtime CSS-in-JS.** Emotion serializes styles at render time. `sx` on thousands of cells or list items adds up. For hot paths, define a `styled()` component once at module level (styles are cached), or move the styling into theme overrides. Virtualize long lists (#218); `DataGrid` already does.
- **Theme stability.** Create the theme at module level or memoize it. A new theme object every render re-renders every consumer.
- **Responsive logic.** `useMediaQuery` returns `false` on the server, so mobile users get the desktop markup first, then a re-render or hydration mismatch. Prefer CSS breakpoints (`sx={{ display: { xs: 'none', md: 'flex' } }}`); if you need the hook, think about `noSsr` and a sensible default.
- **Lazy-load heavy parts**: pickers, rich dialogs and charts with `next/dynamic` when they're below the fold.
- **Measure** with `@next/bundle-analyzer` and the React Profiler (#216) before optimizing.

**Zero-runtime option.** MUI's Pigment CSS extracts styles at build time and works with Server Components, but it was opt-in and experimental. Check its current status before betting a migration on it; for most apps Emotion with the setup above is fine.

**Follow-up:** "Why do some MUI styles override yours unpredictably?" Insertion order. Emotion injects styles at runtime, so global CSS loaded earlier loses. CSS layers (`enableCssLayer`) or the `StyledEngineProvider injectFirst` option make the order explicit.
