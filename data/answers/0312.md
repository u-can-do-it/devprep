## Hints

- In what order does Python look up a name inside a nested function?
- Why does `count += 1` inside an inner function raise `UnboundLocalError`?
- What do `[lambda: i for i in range(3)]` return when called?

## Answer

**LEGB** is the name-lookup order:

1. **L**ocal: the current function.
2. **E**nclosing: outer functions, from innermost to outermost.
3. **G**lobal: the module.
4. **B**uilt-in: `len`, `print`, etc.

Scope is decided at **compile time**: if a function **assigns** to a name anywhere, that name is local throughout the function, unless you declare otherwise.

```python
count = 0

def bump():
    global count        # rebind the module-level name
    count += 1

def make_counter():
    n = 0
    def inc():
        nonlocal n      # rebind the enclosing function's name
        n += 1
        return n
    return inc

c = make_counter()
c(), c()                # (1, 2): n lives on in the closure
```

- **`global`** rebinds a module-level variable. It's rarely a good idea (hidden shared state).
- **`nonlocal`** rebinds a variable in the nearest enclosing function. This is how closures keep mutable state.
- Mutating an object (`items.append(x)`) needs neither keyword. Only **rebinding** the name does.

**Late-binding gotcha**: closures capture **variables, not values**. The value is looked up when the function is called.

```python
fns = [lambda: i for i in range(3)]
[f() for f in fns]            # [2, 2, 2]

fns = [lambda i=i: i for i in range(3)]   # bind now via default arg
[f() for f in fns]            # [0, 1, 2]
# or: functools.partial(func, i)
```

The same bug appears when creating callbacks or tasks in a loop.
