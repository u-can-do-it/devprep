## Hints

- Which of `(string)obj` and `obj as string` can throw, and which can return `null`?
- Why doesn't `obj as int` compile?
- Two interfaces both declare `void Save()`. How does one class implement both with different behaviour?

## Answer

**Three ways down the hierarchy**

| | `(T)x` | `x as T` | `x is T t` |
|---|---|---|---|
| On failure | `InvalidCastException` | `null` | `false` |
| Works for | everything: reference types, unboxing, numeric and user-defined conversions | reference types and `Nullable<T>` only | everything |
| User-defined conversions | yes | no | no |
| Use when | you *know* the type and a mismatch is a bug | optional check followed by `null` handling (older style) | the default today: test and bind in one step (#580) |

```csharp
object o = "hello";
var s1 = (string)o;                       // OK; (int)o would throw InvalidCastException
var s2 = o as string;                     // "hello"; `o as int` doesn't compile because int can't be null: use `o as int?`
if (o is string s3 && s3.Length > 3) Console.WriteLine(s3);
if (o is not Order order) return;         // after this line `order` is definitely assigned (#569)
```

- **Upcasts** (derived to base, class to interface) are implicit and always safe. **Downcasts** need an explicit cast and a run-time check.
- The compiler rejects casts between unrelated classes (`(string)new Order()` is a compile error) but allows a cast to any **interface**, because a subclass might implement it; those are checked at run time.
- Unboxing needs the **exact** type (#562): `(long)(object)42` throws, `(long)(int)(object)42` works.
- Numeric conversions: widening is implicit (`int` → `long` → `double`), narrowing needs a cast and **truncates** (`(int)3.99 == 3`), and `long` → `double` is implicit but can lose precision. `Convert.ToInt32` rounds instead of truncating; `int.Parse`/`TryParse` are for strings (#608).

**`typeof`, `GetType()`, `nameof`**

```csharp
Type t1 = typeof(List<int>);            // compile time, from a type name; typeof(List<>) for the open generic
Type t2 = order.GetType();              // run time: the object's actual type, which may be a subclass or an EF proxy
string n = nameof(order.Customer);      // "Customer": refactor-safe names for logs, exceptions and binding
throw new ArgumentException("Must be positive", nameof(amount));
```

`is` and `as` respect inheritance; `x.GetType() == typeof(T)` is an exact match that excludes subclasses.

**Explicit interface implementation**

A member written as `void ISaveable.Save()` has no access modifier, isn't part of the class's public surface, and can be called **only through the interface**:

```csharp
public sealed class Document : ISaveable, IArchivable
{
    void ISaveable.Save() => SaveToDisk();              // only reachable as ((ISaveable)doc).Save()
    void IArchivable.Save() => MoveToArchive();         // same name, a different contract
    public void SaveToDisk() { }
    private void MoveToArchive() { }
}

public sealed class Catalog : IEnumerable<Product>
{
    private readonly List<Product> _items = [];
    public IEnumerator<Product> GetEnumerator() => _items.GetEnumerator();
    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();     // the non-generic one, kept out of the way
}
```

Use it when:

- two interfaces declare the **same member** with different meanings;
- a member only makes sense through the interface and would clutter the class API: the non-generic `IEnumerable.GetEnumerator`, `ICollection<T>.IsReadOnly` on `List<T>`;
- you want to **discourage** a direct call, e.g. a framework hook on your type that users shouldn't call themselves.

Caveats: explicit members can't be `virtual` or `abstract` and a derived class can't override them (it can re-implement the interface); inside the class you call them as `((ISaveable)this).Save()`; and calling one on a **struct** through the interface boxes it (#562).

**Follow-up:** `object a = 1; object b = 1; Console.WriteLine(a == b);` prints `False`. Why? (Both sides are `object`, so `==` is reference equality, and the two boxed ints are different objects (#562). Use `a.Equals(b)`, which `Int32` overrides to compare values, or unbox first.)
