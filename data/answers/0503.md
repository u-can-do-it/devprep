## Hints

- Is the data 200 rows or 2 million? Where should sorting and filtering happen?
- Should you store the sorted, filtered rows in state, or compute them?
- Which table state should survive a page reload or be shareable as a link?
- How does a screen reader user know which column is sorted?

## Answer

**Store only the inputs** (rows, sort, filter, page) and **derive** the visible rows with `useMemo`. Never copy sorted rows into state, because they go out of sync.

```tsx
type Column<T> = { key: keyof T & string; header: string; sortable?: boolean; numeric?: boolean };
type Sort<T> = { key: keyof T; dir: 'asc' | 'desc' } | null;

const collator = new Intl.Collator(undefined, { numeric: true, sensitivity: 'base' });
function compare(a: unknown, b: unknown) {
  if (a == null || b == null) return a == null ? (b == null ? 0 : 1) : -1;
  if (typeof a === 'number' && typeof b === 'number') return a - b;
  if (a instanceof Date && b instanceof Date) return a.getTime() - b.getTime();
  return collator.compare(String(a), String(b));
}

export function DataTable<T extends { id: string }>({ rows, columns, pageSize = 20 }: {
  rows: T[]; columns: Column<T>[]; pageSize?: number;
}) {
  const [sort, setSort] = useState<Sort<T>>(null);
  const [filter, setFilter] = useState('');
  const [page, setPage] = useState(0);

  const view = useMemo(() => {
    const q = filter.trim().toLowerCase();
    const filtered = q
      ? rows.filter((r) => columns.some((c) => String(r[c.key] ?? '').toLowerCase().includes(q)))
      : rows;
    if (!sort) return filtered;
    const dir = sort.dir === 'asc' ? 1 : -1;
    return filtered.toSorted((a, b) => compare(a[sort.key], b[sort.key]) * dir);
  }, [rows, columns, filter, sort]);

  const pageCount = Math.max(1, Math.ceil(view.length / pageSize));
  const current = Math.min(page, pageCount - 1);
  const visible = view.slice(current * pageSize, (current + 1) * pageSize);

  function toggleSort(key: keyof T) {
    // asc -> desc -> unsorted
    setSort((s) => (s?.key !== key ? { key, dir: 'asc' } : s.dir === 'asc' ? { key, dir: 'desc' } : null));
    setPage(0);
  }

  return (
    <>
      <label>
        Filter <input value={filter} onChange={(e) => { setFilter(e.target.value); setPage(0); }} />
      </label>
      <table>
        <caption className="sr-only">Transactions</caption>
        <thead>
          <tr>
            {columns.map((c) => (
              <th key={c.key} scope="col"
                  aria-sort={sort?.key === c.key ? (sort.dir === 'asc' ? 'ascending' : 'descending') : undefined}>
                {c.sortable ? <button onClick={() => toggleSort(c.key)}>{c.header}</button> : c.header}
              </th>
            ))}
          </tr>
        </thead>
        <tbody>
          {visible.length === 0 ? (
            <tr><td colSpan={columns.length}>No results</td></tr>
          ) : visible.map((row) => (
            <tr key={row.id}>
              {columns.map((c) => <td key={c.key} className={c.numeric ? 'num' : undefined}>{String(row[c.key] ?? '')}</td>)}
            </tr>
          ))}
        </tbody>
      </table>
      <nav aria-label="Pagination">
        <button disabled={current === 0} onClick={() => setPage(current - 1)}>Previous</button>
        <span aria-live="polite">Page {current + 1} of {pageCount} ({view.length} rows)</span>
        <button disabled={current >= pageCount - 1} onClick={() => setPage(current + 1)}>Next</button>
      </nav>
    </>
  );
}
```

**Client-side or server-side?**

- **Client-side** works for up to a few thousand rows that are already loaded. It's instant and simple.
- **Server-side** is for large or growing data. Send `sort`, `filter` and `page` (or a cursor, see #95) as query params, debounce the filter, and keep the previous page visible while the next one loads (TanStack Query `placeholderData: keepPreviousData`). Totals and "page X of Y" then come from the API.
- **Thousands of rows on one screen:** virtualize the rows (#218) instead of paginating.

**URL state:** put sort, filter and page in the query string (`useSearchParams`). Users can then bookmark, share and refresh the view, and the back button works. Keep transient UI state, like which row is hovered, in component state.

**Accessibility:** use a real `<table>` with `scope="col"` headers. Put `aria-sort` on the sorted `<th>` and make the sort control a `<button>` inside it. Add a caption, and announce result changes through a live region.

**Banking and enterprise details:** right-align numbers with `font-variant-numeric: tabular-nums`, format amounts and dates with `Intl.NumberFormat` and `Intl.DateTimeFormat`, use sticky headers, and add column visibility and CSV export.

**Libraries:** TanStack Table (headless: you own the markup), AG Grid or MUI Data Grid (feature-rich enterprise grids). Say why you'd hand-roll it or pick a library.
