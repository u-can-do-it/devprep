## Hints

- How do you attach each child to its parent in one pass if the parent may appear later in the list?
- What does recursion cost on a very deep structure, and what replaces it?
- Which input would make a naive implementation loop forever?

## Answer

Menus, comments, file trees, org charts and category pickers all arrive as a **flat list with `parentId`** and have to be rendered as a tree (and sometimes sent back flat). This is the single most common "real" data-shaping task in frontend interviews.

**Flatten a nested array:** recursive, then iterative, then the built-in.

```js
const flattenRec = (arr) => arr.reduce((acc, x) => acc.concat(Array.isArray(x) ? flattenRec(x) : x), []);

function flattenIter(arr) {                 // explicit stack: no recursion-depth limit
  const out = [], stack = [...arr].reverse();
  while (stack.length) {
    const x = stack.pop();
    if (Array.isArray(x)) stack.push(...x.slice().reverse()); else out.push(x);
  }
  return out;
}

arr.flat(Infinity);                         // ES2019, use this in real code
```

**Flatten an object to dot paths** (`{a:{b:1}}` → `{'a.b': 1}`) is the same recursion with a prefix; mention that arrays and `null` need a decision (`typeof null === 'object'`).

**Build a tree from a flat list in O(n):** index every node by id first, then link children to parents. Two passes avoid the "parent not seen yet" problem.

```ts
type Flat = { id: string; parentId: string | null; name: string };
type Node = Flat & { children: Node[] };

function buildTree(items: Flat[]): Node[] {
  const byId = new Map<string, Node>(items.map((i) => [i.id, { ...i, children: [] }]));
  const roots: Node[] = [];
  for (const node of byId.values()) {
    const parent = node.parentId === null ? undefined : byId.get(node.parentId);
    if (parent) parent.children.push(node);
    else roots.push(node);                  // root, or orphan whose parent is missing
  }
  return roots;
}
```

Input order no longer matters. Sort `children` afterwards if the UI needs a stable order (by `position` or name).

**Tree back to a flat list** (for a table, a virtualized list (#218), or saving): depth-first with depth, iterative to be safe.

```ts
function flattenTree(roots: Node[]) {
  const out: (Node & { depth: number })[] = [];
  const stack = roots.map((n) => ({ node: n, depth: 0 })).reverse();
  while (stack.length) {
    const { node, depth } = stack.pop()!;
    out.push({ ...node, depth });
    for (let i = node.children.length - 1; i >= 0; i--) stack.push({ node: node.children[i], depth: depth + 1 });
  }
  return out;
}
```

**Rendering in React:** a component that renders itself for each child is fine; the recursion depth equals the tree depth, which is small. Use the node id as `key` (#32). Lazy-load deep subtrees or virtualize when there are thousands of rows.

**Edge cases interviewers probe:**

- **Orphans** (parent id points to nothing): treat as roots, drop them, or report; say which.
- **Cycles** (`a → b → a`): the one-pass build above cannot loop, but any walk over the result can. Guard traversals with a `visited` set when the data comes from users.
- **Deep recursion:** JavaScript has no tail-call optimization in practice; ten-thousand-deep recursion throws `RangeError: Maximum call stack size exceeded`. Use the iterative versions.
- **Mutating the input:** `{ ...i, children: [] }` creates new objects so the original list stays untouched, which matters for React state (#199).
- **Complexity:** both directions are O(n) time and O(n) extra space; the naive `items.filter(i => i.parentId === id)` per node is O(n²).

On the backend the equivalent is a recursive CTE (#336); for big trees you may ask the API for a subtree instead of the whole forest.

**Follow-up:** find the path of names from the root to a given id. (Walk up with the `byId` map and `parentId` in O(depth); no tree needed.)
