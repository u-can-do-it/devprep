## Hints

- Do the middle components actually use the prop, or do they just pass it along?
- Could the component that owns the data render the deep child itself and hand it down as `children`?
- When does Context become the better tool?

## Answer

**Prop drilling** means passing a prop through several intermediate components that don't use it, just so a deep descendant can read it. It's verbose, it couples the middle layers to data they don't care about, and it makes refactoring painful.

Often the fix is **composition**. Instead of passing *data* down, the owner renders the deep component itself and passes the finished *element* down through `children` or a named slot prop:

```jsx
// Drilling: Layout and Sidebar must forward `user`
<Layout user={user} />

// Composition: Layout just places what it receives
function Page({ user }) {
  return (
    <Layout
      sidebar={<Sidebar><UserCard user={user} /></Sidebar>}
    >
      <Feed userId={user.id} />
    </Layout>
  );
}

function Layout({ sidebar, children }) {
  return <div className="grid">{sidebar}<main>{children}</main></div>;
}
```

`Layout` no longer knows about `user`. It's simpler, more reusable, and it doesn't need to re-render when the user changes.

**Other solutions, in order of escalation:**

1. **Composition** (above). Try it first.
2. **Context** for values many distant components need: theme, locale, current user.
3. **A store** (Zustand, Redux Toolkit) or a **server-state cache** (TanStack Query) for shared, frequently changing data.

**Follow-up:** passing a prop down two levels is fine. Don't reach for Context just to save a couple of props, because it hides where data comes from.
