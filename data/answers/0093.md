## Hints

- What does each leading digit (1xx–5xx) tell the client?
- Who is at fault for a 4xx versus a 5xx?
- What's the difference between "I don't know who you are" and "I know who you are, but no"?

## Answer

**Classes:**

- **1xx** informational (`101 Switching Protocols` for WebSockets)
- **2xx** success
- **3xx** redirection (`301`, `302`, `304 Not Modified`)
- **4xx** client error – the request is wrong, retrying unchanged won't help
- **5xx** server error – the server failed on a valid request

**Common codes:**

- `200 OK` – successful `GET`, or update returning a body.
- `201 Created` – resource created by `POST`; include a `Location` header.
- `204 No Content` – success with no body (typical `DELETE`).
- `400 Bad Request` – malformed syntax, invalid JSON.
- `401 Unauthorized` – actually means *unauthenticated*: missing or invalid credentials.
- `403 Forbidden` – authenticated, but not allowed.
- `404 Not Found` – resource doesn't exist (also used to hide existence from unauthorized users).
- `409 Conflict` – state conflict: duplicate email, version mismatch.
- `422 Unprocessable Content` – syntactically valid but fails validation (FastAPI uses this for Pydantic errors).
- `500 Internal Server Error` – unhandled exception; never leak stack traces.

```http
HTTP/1.1 201 Created
Location: /users/42
Content-Type: application/json

{"id": 42, "email": "ana@example.com"}
```

Also worth knowing: `429 Too Many Requests` (rate limiting, with `Retry-After`), `502/503/504` (gateway and availability issues).

**Pitfall:** returning `200` with `{"error": "..."}` in the body breaks clients, monitoring and caching. Use proper codes plus a consistent error body (e.g. RFC 9457 Problem Details).
