## Hints

- What does each first digit (1xx–5xx) mean?
- 401 vs 403: which one means "who are you?" and which means "I know who you are, and no"?
- Which errors should you retry, and which never?
- What `status` do you see when the request is blocked by CORS?

## Answer

**The classes:** 2xx means it worked, 3xx means go somewhere else, **4xx means the client made a mistake**, and **5xx means the server failed**. (1xx are informational and you rarely see them.)

| Code | Meaning | What the frontend does |
|---|---|---|
| **200** OK | success, with a body | use the data |
| **201** Created | a resource was created (often with a `Location` header) | show success, navigate to or insert the new item |
| **204** No Content | success, **no body** | don't call `res.json()`, because it throws |
| **301 / 302 / 307 / 308** | redirect | `fetch` follows these automatically |
| **304** Not Modified | your cached copy is still valid | the browser handles it. You see a 200 from cache |
| **400** Bad Request | malformed request | a bug on your side, or show a generic error |
| **401** Unauthorized | **not authenticated**: missing or expired login | refresh the token once, or redirect to login |
| **403** Forbidden | **authenticated but not allowed** | "You don't have access". Don't retry, don't log out |
| **404** Not Found | the resource doesn't exist | a not-found page or message |
| **405** Method Not Allowed | wrong HTTP method | a bug on your side |
| **409** Conflict | conflicts with the current state (duplicate, edited by someone else) | "Already exists" or "Changed by someone else, reload" |
| **413** Content Too Large | upload too big | tell the user the size limit |
| **422** Unprocessable Content | validation failed | show the field errors next to the inputs |
| **429** Too Many Requests | rate limited | wait (`Retry-After` header), then retry |
| **500** Internal Server Error | server bug | "Something went wrong, try again" and log it |
| **502 / 503 / 504** | bad gateway / unavailable / gateway timeout | retry with backoff, show "service unavailable" |

**Handling them with plain `fetch`:**

```js
class HttpError extends Error {
  constructor(status, body) {
    super(`HTTP ${status}`);
    this.status = status;
    this.body = body;
  }
}

async function request(url, options) {
  const res = await fetch(url, options);           // rejects only on network/CORS errors
  const isJson = res.headers.get('Content-Type')?.includes('application/json');
  const body = res.status === 204 ? null : isJson ? await res.json() : await res.text();
  if (!res.ok) throw new HttpError(res.status, body);
  return body;
}

try {
  await request('/api/transfers', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(form) });
} catch (err) {
  if (!(err instanceof HttpError)) showError('Network error. Check your connection.');
  else if (err.status === 401) redirectToLogin();
  else if (err.status === 403) showError("You don't have permission to do this.");
  else if (err.status === 404) showError('Not found.');
  else if (err.status === 409) showError('This was changed by someone else. Reload and try again.');
  else if (err.status === 400 || err.status === 422) setFieldErrors(err.body?.errors);
  else if (err.status === 429) showError('Too many attempts. Wait a moment and try again.');
  else showError('Something went wrong on our side. Try again later.');
}
```

**Retry rules:** retry network errors, **429** and **502/503/504** with exponential backoff. Only retry **idempotent** requests (GET, PUT, DELETE), or a POST that carries an idempotency key. Never retry 400, 401, 403, 404, 409 or 422 unchanged: they'll fail the same way again.

**CORS gotcha:** a request blocked by CORS doesn't give you a status at all. `fetch` rejects with `TypeError: Failed to fetch`, and the details only appear in the DevTools console (#110).

**Memory aid:** 401 asks "who are you?" (log in). 403 says "I know who you are, and no." 404 is "nothing here." 422 is "I understood you, but the data is invalid."
