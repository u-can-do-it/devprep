## Hints

- If you "modify" a string, do you change the object or create a new one?
- When is a function's default argument value evaluated: at definition or at each call?
- What sentinel value is commonly used to work around it?

## Answer

> Python names point to objects, so two names can share one object. Immutable types like `int`, `str` and `tuple` can't change after creation, while mutable ones like `list`, `dict` and `set` change in place, so a change through one name shows up through the other. Default argument values are created only once, when the function is defined. A mutable default like `items=[]` is therefore shared across every call and collects data between them. Use `None` as the default and create a new list inside the function.

**Immutable** objects can't change after creation: `int`, `float`, `str`, `tuple`, `frozenset`, `bytes`, `None`. Operations return new objects. **Mutable** objects can be changed in place: `list`, `dict`, `set`, `bytearray`, most custom class instances.

Variables are just names bound to objects, so two names can point to the same mutable object and see each other's changes:

```python
a = [1, 2]
b = a
b.append(3)
print(a)  # [1, 2, 3]
```

Only hashable (typically immutable) objects can be dict keys or set members.

**Mutable default arguments:** defaults are evaluated **once, when the function is defined**, and the same object is reused on every call:

```python
def add_item(item, items=[]):  # bug
    items.append(item)
    return items

add_item(1)  # [1]
add_item(2)  # [1, 2]  <- state leaked between calls

def add_item(item, items: list | None = None):  # fix
    if items is None:
        items = []
    items.append(item)
    return items
```

The same trap applies to `dict` and `set` defaults, and to dataclass fields (use `field(default_factory=list)`, which dataclasses actually enforce).

Linters like Ruff (`B006`) flag this automatically.
