## Hints

- What happens to clicks and scrolling while JavaScript runs a 500 ms computation on the main thread?
- Is data sent with `postMessage` shared or copied, and what does copying a 200 MB buffer cost?
- Why did browsers lock `SharedArrayBuffer` behind extra security headers?

## Answer

**When to use a Web Worker**

The main thread does JavaScript, style, layout, paint and input handling, all in one queue. CPU-heavy work there blocks interactions (poor INP). A **dedicated worker** runs JavaScript on a **separate thread** with no DOM access. Good candidates:

- Parsing or transforming large data (CSV/JSON, diffing, search indexing)
- Image, audio and video processing, compression, encryption, WebAssembly
- Rendering with `OffscreenCanvas`
- Syntax highlighting or linting in editors, and local databases (SQLite WASM)

Not worth it for small tasks. Message passing and worker startup have overhead, and the DOM must still be updated on the main thread. For splitting up *many small* main-thread tasks, yielding (`scheduler.yield()`) is often enough.

```js
// main.js
const worker = new Worker(new URL('./parse.worker.js', import.meta.url), { type: 'module' });
worker.postMessage({ buffer }, [buffer]); // transfer, don't copy
worker.onmessage = (e) => render(e.data);

// parse.worker.js
self.onmessage = ({ data }) => self.postMessage(heavyParse(data.buffer));
```

**Passing data efficiently**

- `postMessage` uses the **structured clone** algorithm, a deep copy. It's fine for small objects and expensive for large ones.
- **Transferables** (`ArrayBuffer`, `MessagePort`, `ImageBitmap`, `OffscreenCanvas`, streams) move **ownership** at zero copy cost. The sender's buffer becomes detached (length 0).
- Libraries such as **Comlink** turn message passing into RPC-style `await api.method()` calls.

**`SharedArrayBuffer`** lets threads share **the same memory**. You coordinate it with `Atomics` (wait/notify, atomic operations). It's needed for multithreaded WebAssembly. After the **Spectre** attacks it requires **cross-origin isolation**, so a page can't load cross-origin data into its own process and read it with high-precision timers:

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

(`credentialless` is a softer COEP option.) Check `self.crossOriginIsolated`. Isolation can break third-party embeds, popups such as OAuth flows, and cross-origin resources that don't send CORP/CORS headers. Plan that rollout carefully.

**Other worker types:** **shared workers** are shared across tabs of the same origin. **Service workers** are a network proxy, not a place for computation.

**Follow-up:** in Next.js or React apps, lazy-create workers on first use and terminate them when idle, so they don't use memory needlessly.
