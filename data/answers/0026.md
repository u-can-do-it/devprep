## Hints

- How would you type the payload of a PATCH request where every field is optional?
- How do you build a type from only some keys of another type, or from all keys except some?
- How would you type a dictionary whose keys are a fixed set of strings?

## Answer

Utility types build **new types from existing ones**, so you don't repeat definitions and the types stay in sync when the original changes.

```ts
interface User {
  id: string;
  name: string;
  email: string;
  role: 'admin' | 'user';
  createdAt: Date;
}
```

**`Partial<T>`** makes every property optional. Useful for updates and patches:

```ts
function updateUser(id: string, patch: Partial<User>) { /* ... */ }
updateUser('1', { name: 'Ann' });
```

**`Pick<T, K>`** keeps only the listed keys:

```ts
type UserPreview = Pick<User, 'id' | 'name'>;
```

**`Omit<T, K>`** keeps every key except the listed ones. Useful for create DTOs:

```ts
type CreateUserInput = Omit<User, 'id' | 'createdAt'>;
```

**`Record<K, V>`** is an object type with keys `K` and values `V`:

```ts
const permissions: Record<User['role'], string[]> = {
  admin: ['read', 'write', 'delete'],
  user: ['read'],              // a missing key would be an error
};
type Cache = Record<string, User>;
```

They combine well:

```ts
type UserUpdate = Partial<Omit<User, 'id'>> & Pick<User, 'id'>;
```

**Other useful ones:** `Required`, `Readonly`, `Exclude`/`Extract` (for unions), `NonNullable`, `ReturnType`, `Parameters`, `Awaited`.

**Pitfalls:**

- `Omit` doesn't check that the keys exist: `Omit<User, 'typo'>` compiles fine. `Pick` does check.
- `Partial` is **shallow**. Nested objects stay required.
- `Record<string, V>` claims every key exists. Turn on `noUncheckedIndexedAccess` to get `V | undefined` when reading.

**Follow-up:** "How is `Partial` implemented?" As a mapped type: `{ [K in keyof T]?: T[K] }`.
