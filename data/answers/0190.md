## Hints

- Why would the TypeScript team port the compiler to another language instead of optimizing the existing JS code?
- Which tools depend on TypeScript's programmatic API rather than the `tsc` command line?
- Which `tsconfig` options deprecated in TS 6.0 now fail in TS 7?

## Answer

**What changed:** TypeScript 7 (GA in summer 2026) is a **native port of the compiler and language service to Go** (codenamed "Corsa"). It's a port, not a redesign, so type-checking behavior is meant to match TS 6. The gains come from native code and **shared-memory parallelism**: parsing and checking run on multiple threads. Reported full-build speedups are typically around **8–12×**, with much lower memory use and much faster editor startup and responsiveness on large monorepos.

TS 6.0 was a bridge release. It deprecated old options, and **those deprecations are hard errors in 7.0**. Examples: `target: es5`, `moduleResolution: node10`/`classic`, AMD/UMD/System module output, `outFile`, `baseUrl`. Defaults also moved forward, for example **`strict` is on** and `module` defaults to `esnext`.

**Ecosystem caveat:** 7.0 shipped **without a stable programmatic API**, which is expected in 7.1. Tools built on the JS compiler API need the old compiler for now: typescript-eslint's type-aware rules, Vue/Svelte/Astro/Angular language tooling, and custom transformers. A compatibility package (`@typescript/typescript6`, which provides a `tsc6` binary) lets the two run side by side.

**Migration plan for a large codebase:**

1. **Upgrade to TS 6.0 first** and fix every deprecation warning. Modernize `target`, `module` and `moduleResolution` (`nodenext` or `bundler`), and replace `baseUrl`-based imports with `paths` or package `imports`.
2. **Run TS 7 alongside TS 6 in CI** as a type-check-only job (`tsc --noEmit`) and compare the errors. Expect a few differences, such as changed ordering of union types in error messages.
3. **Inventory API consumers:** lint rules, codegen, framework plugins. Keep `tsc6` for those until 7.1.
4. **Switch builds** once the results match, then use the speed: stricter flags, more type-aware checks in pre-commit.

**Bigger picture:** the toolchain is splitting roles. **Transpiling** is done by fast tools (esbuild, swc, oxc, Node's built-in type stripping, which needs `erasableSyntaxOnly`-style code). **`tsc` is mainly the type checker and `.d.ts` emitter** (helped by `isolatedDeclarations`). TS 7 makes that type-checking step fast enough to run constantly.

**Follow-up:** "Why Go and not Rust?" The team said Go's structure and garbage collector map closely onto the existing codebase's patterns. That made a faithful, line-by-line port practical, rather than a rewrite.
