## Hints

- In a diamond `D(B, C)` where both `B` and `C` inherit from `A`, how many times should `A.__init__` run?
- Does `super()` always call the parent class?
- How do you see the order Python will search?

## Answer

Python supports multiple inheritance. To decide which method wins, each class has a **Method Resolution Order (MRO)**, computed with the **C3 linearization** algorithm. It guarantees that:

- a class comes before its parents;
- the order of the bases you listed is respected;
- each class appears exactly once.

```python
class A:
    def save(self): print("A")

class B(A):
    def save(self):
        print("B"); super().save()

class C(A):
    def save(self):
        print("C"); super().save()

class D(B, C):
    def save(self):
        print("D"); super().save()

D.__mro__   # (D, B, C, A, object)
D().save()  # D B C A
```

**`super()` doesn't mean "my parent".** It means "the **next class in the MRO of the instance's type**". Inside `B`, `super()` goes to `C` (not `A`) when the object is a `D`. That's why `A.save` runs exactly once, which solves the diamond problem.

For this to work, **cooperative** classes must:

- always call `super().method(...)`, even if the parent seems to be `object`;
- have compatible signatures. A common pattern is accepting `**kwargs` and passing the rest along.

```python
class Base:
    def __init__(self, **kwargs):
        super().__init__(**kwargs)

class TimestampMixin(Base):
    def __init__(self, *, created=None, **kwargs):
        self.created = created
        super().__init__(**kwargs)
```

If the bases can't be ordered consistently, class creation fails with `TypeError: Cannot create a consistent method resolution order`.

In practice: use multiple inheritance mainly for **mixins** (small, stateless behavior classes listed before the main base). Prefer composition otherwise. Calling `Parent.__init__(self)` directly in a diamond runs shared bases twice.
