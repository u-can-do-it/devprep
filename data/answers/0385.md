## Hints

- Whose side is each one on: the client's or the server's?
- Who configures a forward proxy, and does the server know it's there?
- What does an API gateway add on top of "routing requests to backends"?

## Answer

All three sit in the middle of HTTP traffic; the difference is **who they act for** and **how much logic** they carry.

**Forward proxy**: acts for **clients**. Clients are configured to send outbound traffic through it (corporate proxy, `HTTPS_PROXY` env var, egress proxy in a cluster). Uses: filtering and auditing outbound traffic, caching, hiding client IPs, controlling which external hosts servers may call (a useful SSRF control). The destination server sees the proxy, not the client.

**Reverse proxy**: acts for **servers**. Clients think they're talking to the origin; the proxy forwards to one or more backends (Nginx, Caddy, Envoy, HAProxy, Traefik, cloud load balancers). Uses: TLS termination, load balancing, compression, caching static files, serving multiple apps on one domain, hiding internal topology, adding security headers.

```nginx
location /api/ {
  proxy_pass http://api_upstream;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

**API gateway**: a reverse proxy specialized for **APIs**, with cross-cutting API logic: authentication (JWT/API key validation), rate limiting and quotas per client, request/response transformation, versioning, routing to microservices, analytics, sometimes a developer portal (Kong, AWS API Gateway, Apigee, Envoy-based gateways).

Rules of thumb: a single app usually needs just a reverse proxy/load balancer; many services or public APIs with multiple consumers justify a gateway. Avoid putting **business logic** in the gateway, it becomes a hard-to-test bottleneck.

**Pitfall:** behind a proxy, your app sees the proxy's IP. Read the client IP from `X-Forwarded-For`/`Forwarded`, but only **trust it from known proxies** (e.g. Express `trust proxy`, Uvicorn `--forwarded-allow-ips`), or attackers can spoof it to bypass IP rate limits.

**Follow-up:** Where does a service mesh fit? Sidecar or ambient proxies handle service-to-service traffic (mTLS, retries) inside the cluster, while the gateway handles traffic coming in.
