## Hints

- What happens to the rest of an expression once `?.` meets `null` or `undefined`?
- Which values does `||` treat as "missing" that `??` does not?
- Is there a short form for "assign only if missing"?

## Answer

**Optional chaining (`?.`)** stops the evaluation and returns `undefined` when the value on its left is `null` or `undefined`, instead of throwing a TypeError. It has three forms:

```js
user?.address?.city;      // property
user?.[key];              // computed property
user.onSave?.(data);      // call only if the method exists
```

It **short-circuits** the whole chain: in `a?.b.c.d`, if `a` is nullish, nothing after it runs.

**Nullish coalescing (`??`)** returns the right side only when the left side is `null` or `undefined`. **`||`** returns the right side for any **falsy** value: `0`, `''`, `false`, `NaN`, `null` and `undefined`.

```js
const page = 0;
page || 1;   // 1  (bug: 0 is a valid page)
page ?? 1;   // 0

const title = '';
title ?? 'Untitled'; // ''
title || 'Untitled'; // 'Untitled'
```

Use `??` for defaults whenever `0`, `''` or `false` are valid values.

**Logical assignment** operators combine the check with an assignment:

```js
opts.retries ??= 3;    // set only if null/undefined
cache.hits ||= 0;
user.active &&= isValid(user);
```

**Gotchas:**

- You can't mix `??` with `||` or `&&` without parentheses. `a || b ?? c` is a SyntaxError.
- `?.` can't be used on the left side of an assignment (`a?.b = 1` is invalid).
- Overusing `?.` can hide bugs. If a value should always exist, let the code fail loudly instead of quietly passing `undefined` along.
