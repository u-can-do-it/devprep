## Hints

- What is the difference between no dependency array, `[]`, and `[userId]`?
- If an effect starts a timer or subscription, what happens when the component unmounts?
- Why might an effect run twice on mount in development?

## Answer

`useEffect(fn, deps)` runs `fn` **after** React commits the render to the screen. The dependency array controls when it re-runs:

- **No array** — after every render.
- **`[]`** — only after the first mount.
- **`[a, b]`** — after mount and whenever `a` or `b` changes (compared with `Object.is`).

The function you return is the **cleanup**. It runs **before the effect runs again** (with the old values) and **when the component unmounts**.

```jsx
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${userId}`, { signal: controller.signal })
    .then(r => r.json())
    .then(setUser)
    .catch(() => {});
  return () => controller.abort(); // cancel stale request
}, [userId]);
```

**Common pitfalls:**

- **Missing dependencies** → stale closures reading old props/state. Trust the `exhaustive-deps` lint rule.
- **Objects/functions created during render** as dependencies change every render → infinite loops.
- **Forgetting cleanup** for intervals, listeners, sockets → leaks and race conditions.
- Using effects for things that aren't side effects, like deriving state from props — compute it during render instead.

In development, **Strict Mode** mounts, unmounts and re-mounts components to check that your cleanup is correct, so effects run twice.

**Follow-up:** for data fetching, prefer a library (TanStack Query) or Server Components over hand-rolled effects.
