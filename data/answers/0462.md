## Hints

- Why does `vi.mock` or `jest.mock` work even though you write it below the imports?
- What's the difference between replacing a module and spying on one method?
- What happens to a `setTimeout(…, 5000)` in a test when fake timers are on?

## Answer

**Vitest** is a test runner built on Vite with a **Jest-compatible API** (`describe`, `it`, `expect`, `vi` instead of `jest`). **Jest** is the long-standing standard, with its own transform pipeline (Babel or `ts-jest`).

| | Jest (30) | Vitest |
|---|---|---|
| TypeScript, JSX, ESM | needs a transform setup; native ESM still experimental | out of the box through Vite |
| config | separate `jest.config` | reuses `vite.config` (aliases, plugins) |
| speed | good | usually faster, especially watch mode |
| browser testing | jsdom or happy-dom | jsdom or happy-dom, plus **Browser Mode** (real Chromium, Firefox, WebKit via Playwright) |
| ecosystem | largest, many existing projects | growing, the default for Vite projects |

Choose Vitest for Vite or modern ESM projects; stay on Jest when a large existing suite and its config work fine, or the framework expects it (React Native).

**Mocks, spies and fake timers** (the same idea in both; Vitest shown):

```ts
import { vi } from 'vitest';
import { sendEmail } from './mailer';
import { registerUser } from './register';

// 1. Module mock: replace a whole module. It's hoisted above the imports.
vi.mock('./mailer', () => ({ sendEmail: vi.fn().mockResolvedValue({ ok: true }) }));

test('sends a welcome email', async () => {
  await registerUser('ana@example.com');
  expect(sendEmail).toHaveBeenCalledWith(expect.objectContaining({ to: 'ana@example.com' }));
});

// 2. Spy: keep the real object, watch or override one method, restore afterwards
const spy = vi.spyOn(console, 'error').mockImplementation(() => {});
afterEach(() => vi.restoreAllMocks());

// 3. Fake timers: control time instead of waiting
test('debounces search', async () => {
  vi.useFakeTimers();
  const onSearch = vi.fn();
  const search = debounce(onSearch, 300);
  search('a'); search('ab');
  await vi.advanceTimersByTimeAsync(300);
  expect(onSearch).toHaveBeenCalledOnce();
  vi.useRealTimers();
});
```

- **`vi.fn()` / `jest.fn()`** creates a standalone mock function that records calls.
- **`mockResolvedValue`, `mockImplementationOnce`** script its behaviour.
- **`vi.mocked(fn)`** gives a typed mock in TypeScript.
- **Hoisting:** `vi.mock` and `jest.mock` are moved to the top of the file, so the factory can't use variables declared later unless you use `vi.hoisted()` (or names prefixed `mock` in Jest).
- Use the **async** timer helpers when promises are involved, otherwise awaited code after the timer never runs.
- Restore mocks between tests (`restoreMocks: true` in config) so they don't leak.

**Rule of thumb:** mock at the edges you don't control (network, time, randomness, third-party SDKs), not your own modules. Over-mocking produces tests that pass while the app is broken.

**Follow-up:** a test passes alone but fails when run with the full suite. What would you check first?
