## Hints

- How did you handle pending, error and optimistic states for a form submit before React 19?
- What can you pass to `<form action>` in React 19 besides a URL?
- How can a component read a promise or a Context conditionally?

## Answer

> Submitting a form or saving data usually means tracking pending flags, errors and race conditions by hand. React 19 Actions handle that: any async function run in a transition, which you can pass straight to `<form action>`. `useActionState` gives you the action's last result and a pending flag. `useOptimistic` shows the expected result right away and reverts automatically when the action finishes or fails. `use` reads a promise or a Context, and unlike other hooks it can be called inside conditions.

React 19 makes **async mutations** a first-class concept.

**Actions** — any async function run inside a transition. React tracks pending state, errors and ordering for you. You can pass a function directly to `<form action={...}>`; React calls it with the `FormData` and resets uncontrolled fields on success.

**`useActionState`** — wraps an action and gives you its last result plus a pending flag:

```jsx
const [state, submit, isPending] = useActionState(
  async (prev, formData) => {
    const res = await saveName(formData.get('name'));
    return res.ok ? { error: null } : { error: res.message };
  },
  { error: null }
);

<form action={submit}>
  <input name="name" />
  <button disabled={isPending}>Save</button>
  {state.error && <p role="alert">{state.error}</p>}
</form>
```

**`useFormStatus`** (react-dom) — lets a child like a submit button read the parent form's pending state without prop drilling.

**`useOptimistic`** — shows an optimistic value while an action runs, then automatically reverts to real state when it finishes or fails.

**`use(resource)`** — reads a **promise** (suspending until it resolves) or a **Context**. Unlike other hooks, it may be called inside conditions and loops.

Other notable changes: **Server Components and Server Actions** are stable in the React API (used through frameworks like Next.js), `ref` is a normal prop (no `forwardRef`), `<Context>` works as a provider, and you can render `<title>`/`<meta>`/stylesheets anywhere — React hoists them into `<head>`.

**Follow-up:** don't create the promise passed to `use()` inside a Client Component's render — it gets recreated every render; create it in a Server Component or cache it.
