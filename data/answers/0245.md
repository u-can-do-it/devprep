## Hints

- Is checking the session in a layout enough to protect every page and Server Action under it?
- What can `proxy.ts` cheaply check, and what shouldn't it do?
- Where is the one place every data read and mutation goes through?

## Answer

**Pieces of a typical setup:**

1. **Sign-in**: a library (Auth.js, Better Auth, Clerk, WorkOS…) or your own flow, using a Server Action for credentials and a Route Handler for OAuth callbacks.
2. **Session**: either a **stateless** encrypted or signed cookie (JWT via `jose`), or a **database session** with only an ID in the cookie (easy to revoke). The cookie should be `HttpOnly`, `Secure`, `SameSite=Lax`, with a sensible expiry. Don't keep tokens in `localStorage`.
3. **Checks in several layers:**

| Layer | What to do |
|---|---|
| `proxy.ts` | **Optimistic** check only: does a session cookie exist? Redirect to `/login`. No DB calls. |
| **Data Access Layer** | The **real** check: `verifySession()` plus authorization (role, ownership) before every query or mutation |
| Server Components / pages | Call the DAL; `redirect('/login')` if there's no session |
| Server Actions and Route Handlers | Check again inside **each** one, because they are public endpoints |
| Client Components | Only for UX (hiding buttons), never for security |

```ts
// lib/dal.ts
import 'server-only';
import { cache } from 'react';

export const verifySession = cache(async () => {
  const token = (await cookies()).get('session')?.value;
  const session = await decrypt(token);
  if (!session?.userId) redirect('/login');
  return { userId: session.userId, role: session.role };
});
```

**Why not just a layout or middleware check?**

- **Layouts don't re-render on client navigation** (partial rendering), and pages, Server Actions and Route Handlers are separate entry points. A check in the layout doesn't protect them.
- **Proxy alone isn't enough.** Matchers can miss routes, and CVE-2025-29927 (2025) allowed bypassing middleware with a crafted header on self-hosted apps.

**Also:** `React.cache` keeps per-request checks cheap; rotate sessions on login and privilege change; add CSRF protection to Route Handlers that change state (Server Actions already check `Origin`); rate-limit login.

**Follow-up:** distinguish **authentication** (who are you) from **authorization** (may you touch *this* record). Most real bugs are IDOR, not missing logins.
