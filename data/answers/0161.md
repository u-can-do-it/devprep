## Hints

- What happens in sloppy mode when you assign to a variable you never declared?
- What is `this` inside a plain function call in strict mode?
- Do you need to write `'use strict'` in an ES module or a class?

## Answer

Strict mode is an opt-in, stricter version of JavaScript. It turns silent mistakes into errors and removes some confusing features. You enable it with `'use strict';` at the top of a script or function. It is **on automatically** in **ES modules** and inside **class bodies**, so most modern code already runs in strict mode.

**Main changes:**

- **Assigning to an undeclared variable throws** a ReferenceError instead of creating a global.
- **`this` is `undefined`** in a plain function call, instead of `globalThis`.
- **Writes that fail silently now throw:** to a non-writable or getter-only property, to a frozen object, or adding a property to a non-extensible object.
- **Removed syntax:** `with`, legacy octal literals (`010`), duplicate parameter names, and `delete` on a plain variable.
- **`arguments`** no longer stays in sync with named parameters, and `eval` can't create variables in the surrounding scope.
- **More reserved words:** `implements`, `interface`, `package`, `private`, `protected`, `public`, `static`, `let`, `yield`.

```js
'use strict';
function setup() { total = 0; }  // ReferenceError: total is not defined
function show() { return this; }
show();                          // undefined
```

**Gotchas:**

- `'use strict'` must be the first statement. It can't be used inside a function that has default, rest or destructured parameters.
- Mixing strict and sloppy code when concatenating files (an old bundling issue) could change behavior.

TypeScript emits `"use strict"` for non-module output when `alwaysStrict` is on (part of `strict`), so in TS projects you rarely write it by hand.
