## Hints

- What do you need to install to run tests with `node:test`?
- Which features (mocking, coverage, watch mode, snapshots) does it ship with?
- What do Jest or Vitest still do better?

## Answer

Since Node 20 the **built-in test runner** is stable. You import it from `node:test`, and assertions come from `node:assert`. Nothing to install.

```js
// math.test.js
import { describe, it, mock } from 'node:test';
import assert from 'node:assert/strict';
import { total } from './cart.js';

describe('total', () => {
  it('sums item prices', () => {
    assert.equal(total([{ price: 2 }, { price: 3 }]), 5);
  });

  it('calls the tax service once', async (t) => {
    const getTax = t.mock.fn(async () => 0.2);
    await total([{ price: 10 }], { getTax });
    assert.equal(getTax.mock.callCount(), 1);
  });
});
```

```bash
node --test                          # finds *.test.js, test/** etc.
node --test --watch                  # rerun on change
node --test --experimental-test-coverage
node --test --test-reporter=junit --test-reporter-destination=report.xml
```

It includes `describe`/`it`/`test`, hooks (`before`, `afterEach`…), function and module mocks, **mock timers**, snapshots, subtests, parallel files, filtering with `--test-name-pattern`, and reporters (spec, TAP, JUnit).

**Choose it** for libraries, backend services and CLIs where you want zero dependencies, fast startup and no transform step. With type stripping it can run `.ts` tests directly.

**Choose Vitest/Jest** when you need a rich ecosystem: jsdom/browser environments for front-end code, bundler integration (Vite aliases, CSS imports), a mature watch UI, or many existing tests. Vitest is the usual choice for front-end and Vite projects.

**Follow-up:** How do you mock a module import in `node:test`? (`t.mock.module()`, still experimental, so many teams prefer dependency injection.)
