## Hints

- When state changes, what re-runs in React, and what re-runs in Vue or in an Angular signal?
- Which of the three is a library, and which is a full framework with routing, forms and DI built in?
- What are signals, and why have so many frameworks adopted them?

## Answer

**React** is a UI **library**. Components are functions that return JSX. When state changes, React **re-runs the component** (and by default its children), builds a new virtual DOM tree and reconciles it with the old one. Updates are coarse-grained; you optimise with memoisation, and the React Compiler now does much of it automatically. Routing, forms and data fetching come from the ecosystem or a framework (Next.js, React Router).

**Vue** is a progressive framework with **fine-grained reactivity**. `ref()` and `reactive()` are tracked through Proxies; components use HTML-like templates (or JSX) compiled into optimised render functions, and only components that read the changed state re-render. Vapor mode is bringing compiled, virtual-DOM-free output, similar to Solid. Single-file components (`.vue`) hold template, script and styles. Nuxt is the meta-framework.

**Angular** is a **full framework**: TypeScript-first, with dependency injection, a router, forms, an HTTP client, i18n and a CLI built in. Historically it used **zone.js** to detect async events and then checked the component tree for changes. Modern Angular uses **signals** (`signal`, `computed`, `effect`), standalone components and **zoneless change detection** (the default for new projects since v21), plus new control flow in templates (`@if`, `@for`). RxJS is still used for streams and the HTTP client.

| | React | Vue | Angular |
|---|---|---|---|
| type | library | progressive framework | full framework |
| templates | JSX | templates (or JSX) | templates |
| reactivity | re-render and diff | tracked refs, fine-grained | signals (formerly zone.js plus tree checks) |
| state management | many choices | Pinia | services with signals, NgRx |
| learning curve | small core, big ecosystem | gentle | steepest, most opinionated |
| typical fit | product teams, wide hiring pool | small to large apps | large enterprise apps with consistent structure |

**Signals** are reactive values that know who reads them. When one changes, only the computations and DOM bindings that depend on it update, without re-running whole components. Solid, Vue, Preact, Svelte 5 (runes) and Angular all use them; React instead re-runs components and relies on the compiler to skip work.

**For a React developer working in an Angular codebase:** components with inputs and outputs replace props and callbacks, services with DI replace Context and custom hooks, signals replace `useState` plus `useMemo`, and the async pipe or `toSignal` replace data-fetching hooks.
