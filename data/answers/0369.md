## Hints

- How would you stop the browser from ever making a plain HTTP request to your domain again?
- What can go wrong if a browser guesses the content type of a user-uploaded file?
- Which headers control what other origins can do with your windows and resources?

## Answer

A solid baseline for HTML responses (alongside CSP, which deserves its own rollout plan):

```http
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; object-src 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
```

- **HSTS** tells the browser to use HTTPS only for this host for `max-age` seconds, stopping SSL-stripping downgrade attacks. `preload` gets you into browsers' built-in list so even the first visit is safe. Be sure every subdomain supports HTTPS before adding `includeSubDomains`.
- **`X-Content-Type-Options: nosniff`** stops MIME sniffing, so an uploaded "image" that contains HTML/JS isn't executed as a script or page.
- **`Referrer-Policy`** limits how much of the URL leaks to other sites (tokens or IDs in paths and query strings).
- **`Permissions-Policy`** disables powerful features (camera, geolocation, payment) for your page and embedded iframes.
- **COOP** puts your page in its own browsing context group, so cross-origin popups can't hold a reference to it (helps against XS-Leaks and tabnabbing). Together with **COEP: require-corp** it enables `crossOriginIsolated`, which `SharedArrayBuffer` and high-precision timers require.
- **CORP** stops other origins from embedding your resources.
- **CSP `frame-ancestors`** replaces `X-Frame-Options` for clickjacking.

Also remove headers that fingerprint your stack (`X-Powered-By`). Don't bother with `X-XSS-Protection`; modern browsers ignore it.

Set headers in one place (reverse proxy, framework config such as `headers()` in `next.config.ts`, or Helmet for Express) and check them in CI or with a scanner.

**Follow-up:** Why is HSTS dangerous to roll out carelessly? A long `max-age` can't be revoked for clients that already cached it, so start low.
