## Hints

- What do the `req` and `res` objects passed to `createServer` represent?
- How do you get the JSON body when `req` is a stream?
- What would you have to write yourself that Express or Fastify gives you for free?

## Answer

`node:http` gives you a request listener with a readable `req` stream and a writable `res` stream. Everything else is up to you.

```js
import { createServer } from 'node:http';

const server = createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);

  if (req.method === 'GET' && url.pathname === '/health') {
    res.writeHead(200, { 'content-type': 'application/json' });
    return res.end(JSON.stringify({ ok: true }));
  }

  if (req.method === 'POST' && url.pathname === '/echo') {
    let body = '';
    for await (const chunk of req) body += chunk;   // read the stream
    res.writeHead(201, { 'content-type': 'application/json' });
    return res.end(body);
  }

  res.writeHead(404).end();
});

server.listen(3000);
```

What a framework adds on top:

- **Routing** with path params (`/users/:id`) and method matching.
- **Body parsing** with size limits, plus content-type handling.
- **Validation and serialization** (Fastify uses JSON Schema).
- **Middleware/hooks**, centralized **error handling**, async error support.
- Cookies, CORS, compression, static files and a plugin ecosystem.

Raw `http` is fine for tiny services, health endpoints or learning. For a real API, a framework avoids reinventing (and getting wrong) things like body limits, which otherwise let a client send an unbounded body and exhaust memory.

**Follow-up:** What happens if the handler throws and nothing catches it? (The request hangs or the process crashes, depending on where it throws.)
