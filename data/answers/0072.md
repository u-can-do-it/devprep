## Hints

- What happens to a function's local state when it hits `yield` instead of `return`?
- How much memory does a generator over a billion items use compared to a list?
- Can you iterate the same generator twice?

## Answer

A **generator** is a function containing `yield`. Calling it doesn't run the body; it returns a generator object (an iterator). Each `next()` runs until the next `yield`, hands out a value, and **pauses with its local state preserved**. When the function returns, `StopIteration` is raised and the loop ends.

```python
def read_lines(path):
    with open(path) as f:
        for line in f:
            yield line.rstrip("\n")

def errors(lines):
    return (l for l in lines if "ERROR" in l)   # generator expression

for line in errors(read_lines("app.log")):     # lazy pipeline, constant memory
    print(line)
```

Why use them:

- **Memory efficiency** – values are produced lazily, one at a time, so you can process huge files or infinite sequences.
- **Composable pipelines** – chain generators like Unix pipes.
- **Cleaner iterators** – no need to write a class with `__iter__`/`__next__`.

Gotchas:

- Generators are **single-use**; once exhausted they yield nothing.
- No `len()` or indexing; convert with `list()` if needed (losing the memory benefit).
- `yield from other_gen()` delegates to a sub-generator.
- `send()`/`throw()` exist but are rarely needed; `async` generators (`async def` + `yield`) are the async counterpart, used for streaming responses.
