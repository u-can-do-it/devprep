## Hints

- Can a script inside a cross-origin iframe read the parent page's DOM?
- When you receive a message, how do you know who sent it?
- What should an embedded third-party widget be allowed to do by default?

## Answer

**Communication: `window.postMessage`**

The same-origin policy blocks direct DOM access across origins. The supported channel is `postMessage`:

```js
// parent → iframe
const frame = document.querySelector('iframe');
frame.contentWindow.postMessage({ type: 'theme', value: 'dark' }, 'https://widget.example');

// iframe side
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://app.example') return; // always check the sender
  if (event.data?.type === 'theme') applyTheme(event.data.value);
});
```

Rules:

- **Always pass an explicit `targetOrigin`.** Never use `'*'` for sensitive data.
- **Always check `event.origin`** when receiving, and validate the shape of `event.data`. Any window can send you messages.
- Data is copied with the structured clone algorithm, so functions and DOM nodes can't be sent.
- For ongoing two-way traffic, a `MessageChannel` gives you a dedicated port pair.

**`sandbox` attribute**

`sandbox` with no value applies **every restriction**: no scripts, no forms, no popups, no top-level navigation. The frame is also treated as a unique opaque origin. You then add back only what's needed:

```html
<iframe src="https://widget.example/embed"
        sandbox="allow-scripts allow-forms allow-popups"
        allow="fullscreen; clipboard-write"
        referrerpolicy="strict-origin-when-cross-origin"
        loading="lazy" title="Payment widget"></iframe>
```

Never combine `allow-scripts` and `allow-same-origin` for **same-origin** content: the framed script could simply remove its own sandbox.

**`allow` attribute**

This is the iframe's **Permissions Policy**. It controls access to powerful features: camera, microphone, geolocation, fullscreen, payment. If you don't delegate a feature, the frame can't use it.

**Also remember:**

- Give every iframe a `title` for screen readers.
- Use `loading="lazy"` for embeds below the fold.
- To stop **your** site from being framed (clickjacking), the server sends a CSP `frame-ancestors` directive. That's the counterpart to sandboxing others.
