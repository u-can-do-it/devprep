## Hints

- Should a failed form validation be thrown, or returned?
- Which error boundary catches an error thrown inside the root layout?
- `redirect()` works by throwing. What happens if you call it inside `try { } catch { }`?

## Answer

Split errors into **expected** and **unexpected**.

**Expected errors** (validation failures, "not found", "no permission") are part of normal flow:

- In Server Actions, **return** them as values and render them with `useActionState`. Don't throw.
- For missing resources, call **`notFound()`**. It renders the nearest `not-found.tsx` with a 404 status.
- **`redirect('/login')`** sends a 307 (a 303 when called from a Server Action). **`permanentRedirect()`** sends a 308.

```tsx
const post = await getPost(slug);
if (!post) notFound();
if (!canView(user, post)) redirect('/login');
```

**Unexpected errors** (bugs, a crashed DB) are thrown and caught by **`error.tsx`**, a Client Component Error Boundary for that segment and its children:

```tsx
'use client';
export default function Error({ error, retry }: { error: Error & { digest?: string }; retry: () => void }) {
  useEffect(() => { reportError(error); }, [error]);
  return <button onClick={() => retry()}>Try again</button>;
}
```

- `retry()` (stable in 16.3) re-fetches and re-renders the segment. `reset()` only clears the error state.
- In production, errors from Server Components reach the client as a **generic message plus a `digest`**, so secrets don't leak. Match the digest against server logs.
- `error.tsx` doesn't catch errors from the `layout.tsx` in the same folder. The parent boundary does.
- **`global-error.tsx`** handles errors in the root layout. It replaces the whole document, so it must render its own `<html>` and `<body>`.
- Error boundaries don't catch errors in event handlers or async callbacks. Handle those with `try/catch` and state.

**The `try/catch` trap:** `redirect()` and `notFound()` throw special errors that Next.js intercepts. If you wrap them in `try/catch`, you swallow the navigation:

```ts
try {
  await save();
  redirect('/done'); // BAD: swallowed by the catch below
} catch (e) { return { error: 'Failed' }; }
// FIX: call redirect() after the try/catch, or rethrow with unstable_rethrow(e)
```

**Follow-up:** add `instrumentation.ts` with `onRequestError` to send server errors to Sentry or OpenTelemetry.
