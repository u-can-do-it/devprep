## Hints

- How would you ship one widget that works in React, Vue and plain HTML?
- Why don't the page's global styles leak into a native `<video>` element's controls?
- How could a custom element render on the server before any JavaScript runs?

## Answer

**Web Components** is a set of native browser standards for building reusable, encapsulated elements that work with any framework or none.

**1. Custom Elements** let you define your own tag with lifecycle callbacks:

```js
class UserBadge extends HTMLElement {
  static observedAttributes = ['name'];

  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }
  connectedCallback() { this.render(); }        // added to the DOM
  disconnectedCallback() { /* cleanup */ }       // removed
  attributeChangedCallback() { this.render(); }  // observed attribute changed

  render() {
    this.shadowRoot.innerHTML = `
      <style>:host { display: inline-flex; gap: .5rem } ::slotted(img) { border-radius: 50% }</style>
      <slot name="avatar"></slot><span part="label">${this.getAttribute('name') ?? ''}</span>`;
  }
}
customElements.define('user-badge', UserBadge); // the name must contain a hyphen
```

(In real code, escape `name` instead of interpolating it into `innerHTML`.)

**2. Shadow DOM** is an encapsulated subtree:

- Outside styles don't reach in and inner styles don't leak out.
- Inherited properties and **CSS custom properties** do cross the boundary. That's how you theme components.
- Consumers can style chosen internals through `::part()`. The component styles itself with `:host`, and styles projected children with `::slotted()`.
- **Slots** project the user's light-DOM children into the template.

**3. `<template>`** holds inert markup that is parsed but not rendered, ready to clone (`template.content.cloneNode(true)`).

**Declarative Shadow DOM** (`<template shadowrootmode="open">`) lets the server render a shadow root in HTML, so components can be SSR'd without JavaScript.

**Tradeoffs:**

- Pros: framework-agnostic and long-lived. A good fit for design systems shared across many apps (Shoelace/Web Awesome, Lit, Salesforce, Adobe Spectrum).
- Cons: you write a lot by hand (Lit helps). Forms need `static formAssociated = true` and `attachInternals()`. ARIA references (`aria-labelledby`) don't cross shadow boundaries. SSR is harder. Global styles and utility classes can't reach inside.

**Follow-up:** React 19 supports custom elements fully: it sets properties instead of stringifying them to attributes, and supports custom events. That removed the main pain of using them in React.
