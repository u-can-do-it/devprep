## Hints

- How many states does the UI have before, during and after the request?
- Why can't the `useEffect` callback itself be `async`?
- What do you do with `res` before you can use the data?
- What happens if the component unmounts before the response arrives?

## Answer

This is the most common React warm-up task. Practise writing it **from memory, without autocomplete**, in under 10 minutes.

```jsx
import { useEffect, useState } from 'react';

export default function Users() {
  const [users, setUsers] = useState([]);
  const [status, setStatus] = useState('loading');   // 'loading' | 'error' | 'success'
  const [error, setError] = useState(null);
  const [attempt, setAttempt] = useState(0);          // bump it to retry

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        const res = await fetch('https://jsonplaceholder.typicode.com/users', { signal: controller.signal });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);   // fetch doesn't reject on 404/500
        const data = await res.json();                         // the body is a second await
        setUsers(data);
        setStatus('success');
      } catch (err) {
        if (err.name === 'AbortError') return;                 // unmounted or re-run: ignore
        setError(err);
        setStatus('error');
      }
    }

    load();                                  // the effect itself can't be async: it must return a cleanup, not a Promise
    return () => controller.abort();
  }, [attempt]);

  if (status === 'loading') return <p>Loading…</p>;
  if (status === 'error') {
    return (
      <div role="alert">
        <p>Couldn't load users: {error.message}</p>
        <button onClick={() => { setStatus('loading'); setAttempt((a) => a + 1); }}>Try again</button>
      </div>
    );
  }
  if (users.length === 0) return <p>No users yet.</p>;

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>
          {user.name} ({user.email})
        </li>
      ))}
    </ul>
  );
}
```

**Checklist the interviewer is watching for:**

1. `await res.json()`: the data isn't in `res`
2. Checking `res.ok`
3. **Loading, error and empty** states, not just the happy path
4. A stable `key` (`user.id`, not the index)
5. Cleanup with `AbortController`. It also handles `<StrictMode>` running the effect twice in development (#200)
6. A correct dependency array

**Likely follow-ups:**

- *"Load one user when `id` changes."* Use `[id]` as the dependency, and the abort cleanup prevents stale responses (#496).
- *"Show a details panel on click."* Store `selectedId` in state, and derive the selected user from the list.
- *"How would you do this in production?"* TanStack Query: caching, deduplication, retries, background refetch and less code (#212). Say it, but show you can do it without the library.
- *"Add TypeScript."* `useState<User[]>([])`, and validate the response if it matters (#182).
