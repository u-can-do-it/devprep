## Hints

- Which states can a promise be in, and can it change state once it has settled?
- When should the `then` callbacks run: right away, or later? Which queue do they go into?
- What should happen when a `then` callback returns another promise, or throws?

## Answer

The core ideas: a promise is a state machine (`pending` → `fulfilled` | `rejected`, settled **once**). `then` returns a **new** promise that settles with the callback's result. Callbacks always run **asynchronously as microtasks**, even if the promise is already settled.

```js
class MyPromise {
  #state = 'pending';
  #value;
  #callbacks = [];

  constructor(executor) {
    let called = false; // resolve/reject only work the first time
    const resolve = (v) => { if (!called) { called = true; this.#resolve(v); } };
    const reject = (e) => { if (!called) { called = true; this.#settle('rejected', e); } };
    try { executor(resolve, reject); } catch (e) { reject(e); }
  }

  #resolve(v) {
    if (v === this) return this.#settle('rejected', new TypeError('Chaining cycle'));
    if (v && typeof v.then === 'function') {
      // adopt the state of a promise or thenable
      return v.then((x) => this.#resolve(x), (e) => this.#settle('rejected', e));
    }
    this.#settle('fulfilled', v);
  }

  #settle(state, value) {
    this.#state = state;
    this.#value = value;
    this.#callbacks.forEach((cb) => queueMicrotask(cb));
    this.#callbacks = [];
  }

  then(onFulfilled, onRejected) {
    return new MyPromise((resolve, reject) => {
      const run = () => {
        const ok = this.#state === 'fulfilled';
        const handler = ok ? onFulfilled : onRejected;
        if (typeof handler !== 'function') return ok ? resolve(this.#value) : reject(this.#value);
        try { resolve(handler(this.#value)); } catch (e) { reject(e); }
      };
      this.#state === 'pending' ? this.#callbacks.push(run) : queueMicrotask(run);
    });
  }

  catch(onRejected) { return this.then(undefined, onRejected); }
  static resolve(v) { return v instanceof MyPromise ? v : new MyPromise((r) => r(v)); }
}
```

**What makes it (closer to) spec-compliant:**

- **Settle once:** later `resolve`/`reject` calls are ignored.
- **Asynchronous callbacks** through microtasks, never synchronous, even for already-settled promises. This avoids "sometimes sync, sometimes async" bugs.
- **Pass-through:** a missing handler forwards the value or reason to the next promise, which is why `.catch` at the end of a chain works.
- **Thenable adoption:** returning a promise from `then` makes the chain wait for it. A self-resolution cycle is rejected with a TypeError.
- **Throwing in a handler** rejects the derived promise.

**Gaps compared with full Promises/A+:** thenables whose `then` getter throws or that call their callbacks several times need extra guards, and real promises adopt thenables in a separate microtask job (which explains the extra ticks in output puzzles). Unhandled-rejection tracking is also missing.

**Follow-ups:** implement `finally` (run the callback, then pass the original result through), and `Promise.withResolvers()`, which returns `{ promise, resolve, reject }`.
