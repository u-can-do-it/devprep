## Hints

- In React 17, once rendering a big tree started, could a keystroke interrupt it?
- What's the difference between an urgent update and a non-urgent one from the user's point of view?
- What is "tearing", and why is it a risk for external stores?

## Answer

Before React 18, rendering was **synchronous**: a big update blocked the main thread until done. **Concurrent rendering** makes rendering **interruptible**. React renders in small units of work (fibers), yields to the browser between them, and can **pause, resume, or throw away** an in-progress render if a more urgent update comes in. Updates get priorities (internally "lanes"): typing and clicks are urgent; transitions are not. Only the finished tree gets committed, so the user never sees a half-rendered UI.

**`useTransition`** — mark a state update as non-urgent when you own the setter:

```jsx
const [isPending, startTransition] = useTransition();

function onTabClick(tab) {
  startTransition(() => setTab(tab)); // heavy render, can be interrupted
}
```

The old UI stays interactive (and visible instead of a Suspense fallback) while the new one renders; `isPending` lets you show a subtle indicator. In React 19 the callback can be async (that's what Actions build on).

**`useDeferredValue`** — when you only receive a value (e.g. a prop) and want a lagging copy for expensive work:

```jsx
const deferredQuery = useDeferredValue(query);
const results = useMemo(() => filter(items, deferredQuery), [deferredQuery]);
```

The input updates immediately; the list re-renders with the deferred value in the background. Pair with `React.memo` so the slow child actually skips urgent renders.

**Caveats:**

- Transitions don't make code faster; they keep the UI responsive. Real fixes (virtualization, less work) still matter.
- Controlled text input updates must not be in a transition.
- **Tearing**: if a render is paused and an external mutable store changes, different components could show different values. `useSyncExternalStore` prevents this; state libraries use it.

**Follow-up:** Suspense, streaming SSR and selective hydration are all built on the same concurrent engine.
