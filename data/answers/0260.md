## Hints

- What happens if you set `width` and `height` on a `<span>`?
- Which elements start on a new line, and which sit inside a line of text?
- How would you make a row of links that also have padding and a fixed height?

## Answer

`display` sets the box's **outer** behavior (how it sits among its siblings) and **inner** behavior (how its children are laid out).

| | `block` | `inline` | `inline-block` |
|---|---|---|---|
| Starts on a new line | Yes | No, flows inside text | No |
| Default width | Fills its container | Fits its content | Fits its content |
| `width` / `height` | Respected | **Ignored** | Respected |
| Vertical `margin` | Applies | **Ignored** (no effect on layout) | Applies |
| Vertical `padding` | Applies | Painted, but doesn't push lines apart | Applies |
| Examples | `div`, `p`, `h1`, `section`, `ul` | `span`, `a`, `strong`, `em` | `button`, `input`, `img` behave like this |

```css
.tag {
  display: inline-block; /* stays in the text flow but can be sized */
  padding: 0.25rem 0.5rem;
  height: 1.75rem;
}
```

**Gotchas:**

- `inline-block` items have whitespace gaps between them (the spaces in the HTML) and line up on the text baseline. Both make them awkward for layout.
- Images are inline by default, which leaves a small gap under them. `display: block` or `vertical-align: middle` fixes it.

**Other values to know:**

- `none` removes the element from layout and from the accessibility tree.
- `flex` / `grid` make a block-level box whose children use flex or grid layout. `inline-flex` / `inline-grid` do the same but sit inline.
- `contents` removes the element's own box and promotes its children. Useful for grid layouts, but older browsers had accessibility bugs with it.
- `flow-root` creates a new block formatting context, which contains floats and stops margins collapsing through.

**Follow-up:** CSS now defines `display` as two keywords (`display: inline flex` = `inline-flex`). In modern layouts, use Flexbox or Grid instead of `inline-block`.
