## Hints

- Which is harder to build correctly: the look of a combobox, or its keyboard and screen-reader behaviour?
- What happens when your brand doesn't look like Material Design?
- With shadcn/ui, who owns the component code after you install it?

## Answer

**Styled libraries** (MUI, Ant Design, Chakra, Mantine) ship behaviour **and** a visual design. **Headless libraries** (Radix Primitives, React Aria, Base UI, Ark UI, Headless UI) ship only behaviour and accessibility: state, keyboard interaction, focus management, ARIA, positioning. You bring all the styling.

| | styled (MUI) | headless (Radix, React Aria) |
|---|---|---|
| time to first screen | fastest | slower: you style everything |
| custom brand | fight the theme system, overrides, specificity | full control |
| accessibility | built in | built in (the hard part) |
| bundle and runtime | heavier, often CSS-in-JS or theme runtime | small, style with anything |
| upgrades | the library's visual changes affect you | only behaviour changes |
| consistency | enforced by the library | enforced by your own design system |

**shadcn/ui** is a third model. It's not a dependency but a **CLI that copies component source code** (Radix or Base UI plus Tailwind and `cva` variants) into your repo. You own and edit the code. That's ideal as a starting point for your own design system, but you also own the maintenance, and upstream fixes don't arrive automatically.

**How to choose for a design system:**

- **Strong custom brand, long-lived product, several apps:** headless primitives + your tokens + your styling. The design system owns the look, and accessibility comes from battle-tested primitives.
- **Internal tools and admin panels, speed matters more than brand:** a styled library such as MUI with a theme is pragmatic.
- **Startup wanting both speed and ownership:** shadcn/ui, then evolve the copied components into your own library.
- **Strict accessibility requirements (banking, public sector):** React Aria has the most thorough cross-screen-reader behaviour, including i18n and touch.

**What not to do:** build a combobox, date picker or menu from scratch with `div`s and `onClick`. Getting focus management, `aria-activedescendant`, typeahead, scroll locking and mobile screen readers right is months of work. Use a primitive.

**Follow-up:** your company already has MUI everywhere but a new brand looks nothing like Material. Do you theme MUI, switch to headless, or run both during a migration?
