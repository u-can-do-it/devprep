## Hints

- What does a screen reader announce when you focus an input that only has a `placeholder`?
- How does the choice of `type` change the keyboard on a phone?
- How would you tell the browser or password manager what a field contains?

## Answer

**1. Every control needs a programmatic label**

```html
<label for="email">Email</label>
<input id="email" name="email" type="email" autocomplete="email" required>

<!-- or wrap the control -->
<label><input type="checkbox" name="terms"> I accept the terms</label>
```

A label gives the field its accessible name and also makes the label text clickable, which gives a bigger hit area. A `placeholder` is **not** a label: it disappears as you type, often has poor contrast, and isn't reliably announced. Use `aria-label` or `aria-labelledby` only when a visible label really isn't possible, such as a search field with an icon button.

**2. Use the right input type and `inputmode`**

- `email`, `tel`, `url`, `number`, `date`, `search` and `password` give the right mobile keyboard and built-in validation.
- For numeric codes (ZIP, OTP) use `type="text" inputmode="numeric"`. `type="number"` adds spinners and changes values when you scroll.

**3. Add `autocomplete` tokens**

`name`, `given-name`, `email`, `street-address`, `postal-code`, `cc-number`, `current-password`, `new-password` and `one-time-code` let browsers and password managers fill the form correctly. WCAG 2.1 requires this for fields that collect the user's own personal data (1.3.5).

**4. Group related controls**

```html
<fieldset>
  <legend>Shipping method</legend>
  <label><input type="radio" name="ship" value="std"> Standard</label>
  <label><input type="radio" name="ship" value="exp"> Express</label>
</fieldset>
```

Screen readers announce the `legend` together with each option.

**5. Other basics**

- Mark required fields visibly and with the `required` attribute.
- Link hints to their fields with `aria-describedby`.
- Use a real `<button type="submit">`. A `<button>` inside a form defaults to `submit`, so give other buttons `type="button"`.

**Follow-up:** error messages need the same care, using `aria-invalid`, linked messages and focus management.
