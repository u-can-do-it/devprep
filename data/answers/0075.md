## Hints

- What does the `with` statement guarantee happens even if an exception is raised inside the block?
- Which two dunder methods does an object need to work with `with`?
- How can `contextlib` let you write one with a single generator function?

## Answer

A context manager sets something up and **guarantees cleanup** when the `with` block exits, whether normally or via an exception. Classic examples: files, locks, DB transactions, temporary changes to state.

```python
with open("data.txt") as f:   # file is closed even if parsing raises
    data = parse(f.read())
```

**Class-based:** implement `__enter__` (its return value is bound by `as`) and `__exit__(exc_type, exc, tb)`. If `__exit__` returns `True`, the exception is suppressed.

```python
class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        return False  # don't swallow exceptions
```

**Generator-based** with `contextlib.contextmanager`: code before `yield` is setup, after it is teardown. Use `try/finally` so cleanup runs on errors.

```python
from contextlib import contextmanager

@contextmanager
def transaction(conn):
    tx = conn.begin()
    try:
        yield tx
        tx.commit()
    except Exception:
        tx.rollback()
        raise
```

Related tools: `async with` / `@asynccontextmanager` (used by FastAPI's lifespan), `contextlib.suppress`, `ExitStack` for a dynamic number of resources, and parenthesized multiple managers in one `with` (3.10+).
