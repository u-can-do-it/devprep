## Hints

- Does the model execute the function itself?
- How does the model know what arguments a tool takes?
- If five AI apps each want access to GitHub, Slack and your database, how many integrations do you write without a standard protocol?

## Answer

**Tool calling** (function calling) lets a model **ask your code to do something**: look up an order, search documents, call an API. The model never executes anything itself.

1. You send the conversation plus **tool definitions**: a name, a description and a **JSON Schema** for the arguments.
2. If a tool would help, the model replies with a **tool call** (`get_order_status` with `{"orderId": "A-123"}`) instead of text.
3. **Your code** validates the arguments, checks permissions, runs the function and sends the result back as a tool result message.
4. The model continues: it answers the user or calls another tool. Repeating this is the basic **agent loop**.

```ts
const tools = [{
  name: 'get_order_status',
  description: 'Get the current status of a customer order by its id.',
  input_schema: {
    type: 'object',
    properties: { orderId: { type: 'string', description: 'Order id, e.g. A-123' } },
    required: ['orderId'],
  },
}];

// on a tool call from the model:
const args = OrderArgs.parse(call.input);                         // never trust model-generated arguments
if (!canAccessOrder(user, args.orderId)) return toolError('forbidden');
const result = await orders.getStatus(args.orderId);
```

**Good practice:** clear names and descriptions (the model chooses tools from them), few tools with narrow scopes, validation of every argument, authorization done in code for the **current user** (not the model's judgement), human confirmation for actions with side effects (sending, paying, deleting), and timeouts and useful error messages the model can recover from. The same mechanism gives **structured output**: a schema the reply must match.

**Model Context Protocol (MCP)** is an open standard, introduced by Anthropic in 2024 and now supported across the major AI tools, for connecting AI applications to tools and data. Instead of every app writing its own integration for every system, a service exposes an **MCP server** once, and any **MCP client** (Claude, ChatGPT, Cursor, VS Code, your own agent) can use it.

- An MCP server provides **tools** (actions), **resources** (readable data such as files or records) and **prompts** (reusable templates).
- It speaks JSON-RPC over **stdio** (local servers) or **Streamable HTTP** (remote servers, with OAuth for authorization).
- The host application decides which servers are connected and asks the user to approve tool calls.

**Risks:** an MCP server is code with your permissions. Only install trusted servers, give them least privilege, and remember that tool results are untrusted input that can contain prompt injection.

**Follow-up:** you're exposing your product's API to AI agents. Would you build an MCP server, publish an OpenAPI spec, or both?
