## Hints

- What happens if the response for "re" arrives after the response for "react"?
- Which role and ARIA attributes does a screen reader need to announce the suggestions?
- While the user arrows through the list, where does focus stay?

## Answer

This is a classic live-coding task because it tests several skills at once: state, effects, async race conditions, events and accessibility.

```tsx
function useDebouncedValue<T>(value: T, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

type Item = { id: string; label: string };

export function Autocomplete({ label, onSelect }: { label: string; onSelect: (item: Item) => void }) {
  const [query, setQuery] = useState('');
  const [items, setItems] = useState<Item[]>([]);
  const [open, setOpen] = useState(false);
  const [active, setActive] = useState(-1);
  const [status, setStatus] = useState<'idle' | 'loading' | 'error'>('idle');
  const debounced = useDebouncedValue(query.trim());
  const id = useId();

  useEffect(() => {
    if (debounced.length < 2) { setItems([]); setOpen(false); setStatus('idle'); return; }
    const ctrl = new AbortController();
    setStatus('loading');
    fetch(`/api/search?q=${encodeURIComponent(debounced)}`, { signal: ctrl.signal })
      .then((r) => { if (!r.ok) throw new Error(`HTTP ${r.status}`); return r.json(); })
      .then((data: Item[]) => { setItems(data); setActive(-1); setOpen(true); setStatus('idle'); })
      .catch((e) => { if (e.name !== 'AbortError') setStatus('error'); });
    return () => ctrl.abort();   // a newer query cancels the older request: no stale results
  }, [debounced]);

  function choose(item: Item) {
    onSelect(item);
    setQuery(item.label);
    setOpen(false);
  }

  function onKeyDown(e: React.KeyboardEvent) {
    if (e.key === 'ArrowDown') { e.preventDefault(); setOpen(true); setActive((i) => Math.min(i + 1, items.length - 1)); }
    else if (e.key === 'ArrowUp') { e.preventDefault(); setActive((i) => Math.max(i - 1, 0)); }
    else if (e.key === 'Enter' && open && active >= 0) { e.preventDefault(); choose(items[active]); }
    else if (e.key === 'Escape') setOpen(false);
  }

  return (
    <div className="autocomplete">
      <label htmlFor={`${id}-input`}>{label}</label>
      <input
        id={`${id}-input`}
        role="combobox"
        aria-expanded={open}
        aria-controls={`${id}-list`}
        aria-autocomplete="list"
        aria-activedescendant={open && active >= 0 ? `${id}-opt-${active}` : undefined}
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        onKeyDown={onKeyDown}
        onBlur={() => setOpen(false)}
      />
      {open && (
        <ul id={`${id}-list`} role="listbox">
          {items.map((item, i) => (
            <li
              key={item.id}
              id={`${id}-opt-${i}`}
              role="option"
              aria-selected={i === active}
              // mousedown fires before the input's blur; preventDefault keeps focus in the input
              onMouseDown={(e) => { e.preventDefault(); choose(item); }}
            >
              {item.label}
            </li>
          ))}
        </ul>
      )}
      <div aria-live="polite" className="sr-only">
        {status === 'loading' ? 'Loading' : status === 'error' ? 'Search failed' : open ? `${items.length} results` : ''}
      </div>
    </div>
  );
}
```

**Points to mention out loud:**

- **Debounce** so you don't send a request on every keystroke. Also set a minimum query length.
- **Race conditions:** aborting in the effect cleanup guarantees that only the latest query can set state. An "ignore" flag also works if the API can't be cancelled.
- **Focus stays in the input.** `aria-activedescendant` tells assistive technology which option is "active" without moving DOM focus. This is the [combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).
- **Announce** the result count and loading or error state through an `aria-live` region.
- **States:** loading, error, no results, and a highlighted matched substring.
- **In production:** cache results per query with TanStack Query (`placeholderData: keepPreviousData` keeps the old list visible while typing). Don't hand-roll the a11y: use Downshift, React Aria `useComboBox` or the design system's component.

**Follow-up:** how would you test it? Use React Testing Library with `userEvent.type`, fake timers for the debounce, MSW for the API, and assertions with `getByRole('option')`.
