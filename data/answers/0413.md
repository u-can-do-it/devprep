## Hints

- Which of the two can never change the files you're working on?
- What are remote-tracking branches like `origin/main`?
- What extra step does one of them do after downloading, and can that step cause conflicts?

## Answer

- **`git fetch`** downloads new commits, branches and tags from the remote and updates your **remote-tracking branches** (`origin/main`). It **does not touch** your local branches or working directory, so it's always safe.
- **`git pull`** is `git fetch` **plus integrating** the remote branch into your current branch, by default with a **merge** (or a rebase if configured). This changes your branch and can produce merge conflicts.

```bash
git fetch origin
git log --oneline main..origin/main   # what's new on the remote?
git diff main origin/main             # inspect before integrating
git merge origin/main                 # or: git rebase origin/main

git pull --rebase                     # fetch + rebase local commits on top
git config --global pull.rebase true  # make that the default
git pull --ff-only                    # refuse if a real merge would be needed
```

**When to use which:**
- `fetch` when you want to see what changed before deciding how to integrate, or to update `origin/*` before a rebase or comparison.
- `pull` for the everyday "bring my branch up to date".

Many developers prefer `pull --rebase` (or `--ff-only`) to avoid noisy "Merge branch 'main' of ..." commits in feature branches.

**Follow-up:** "What does `git push` do if the remote has new commits?" It's rejected as non-fast-forward. Fetch and integrate first. Never fix it with a plain `--force`.
