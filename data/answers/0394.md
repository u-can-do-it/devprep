## Hints

- Instead of choosing inputs yourself, what if you described rules that must hold for all inputs?
- What's a property of `decode(encode(x))`, or of sorting a list, that is always true?
- When a random input fails, how do you make it small enough to debug?

## Answer

**Example-based tests** check specific inputs you thought of. **Property-based tests** state a **property**, an invariant that must hold for **all** valid inputs, and the framework generates hundreds of random inputs to try to break it. Libraries: **Hypothesis** (Python), **fast-check** (JS/TS).

```python
from hypothesis import given, strategies as st

@given(st.lists(st.integers()))
def test_sort_properties(xs):
    out = my_sort(xs)
    assert len(out) == len(xs)
    assert all(a <= b for a, b in zip(out, out[1:]))
    assert sorted(out) == sorted(xs)       # same elements
```

```ts
fc.assert(fc.property(fc.string(), (s) => decode(encode(s)) === s));
```

**Shrinking** is the key feature: when a failure is found, the library minimizes the input to the simplest failing case (e.g. `[0, -1]` instead of a 50-element list) and records it in a database, so it is rerun next time.

**Common property patterns:**

- **Round-trip**: `parse(serialize(x)) == x` (JSON, URL encoding, codecs).
- **Invariants**: output is sorted, totals are never negative, balances sum to zero.
- **Oracle**: compare with a simple, slow reference implementation, or the old version during a refactor.
- **Idempotence**: `normalize(normalize(x)) == normalize(x)`.
- **Stateful testing**: generate random sequences of operations against a system (a cache, a state machine) and compare with a model.

**Where it finds bugs that examples miss:** edge cases nobody thinks of: empty strings, Unicode and emoji, `NaN`, `-0`, huge numbers, duplicates, unusual orderings. Examples encode the cases you already imagined; properties explore the ones you didn't.

**Costs:** finding good properties takes thought, tests run slower, and constrained input generators can get complex. Use it for parsers, serializers, financial calculations, data transformations and algorithms, alongside readable example tests that document typical behavior.

**Follow-up:** How does this relate to fuzzing? Both generate inputs; fuzzing usually targets crashes and security bugs with coverage feedback, while property tests assert functional correctness.
