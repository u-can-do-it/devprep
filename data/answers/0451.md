## Hints

- Reducers must be pure, so where do API calls go?
- What three actions does `createAsyncThunk` dispatch for one request?
- If the data comes from the server, should you be writing reducers for it at all?

## Answer

Reducers can't contain side effects, so async work happens in **middleware**. Redux Toolkit gives you three main tools.

**1. Thunks.** A thunk is a function you dispatch instead of an action. The thunk middleware calls it with `dispatch` and `getState`. `createAsyncThunk` wraps a promise and dispatches `pending`, `fulfilled` and `rejected` actions:

```ts
export const fetchUser = createAsyncThunk('user/fetch', async (id: string, { signal }) => {
  const res = await fetch(`/api/users/${id}`, { signal });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return (await res.json()) as User;
});

const userSlice = createSlice({
  name: 'user',
  initialState: { data: null as User | null, status: 'idle' as 'idle' | 'loading' | 'failed' },
  reducers: {},
  extraReducers: (b) => {
    b.addCase(fetchUser.pending, (s) => { s.status = 'loading'; })
     .addCase(fetchUser.fulfilled, (s, a) => { s.status = 'idle'; s.data = a.payload; })
     .addCase(fetchUser.rejected, (s) => { s.status = 'failed'; });
  },
});
```

It's good for one-off workflows (checkout, a multi-step save), but you still write loading flags, caching and refetching yourself.

**2. Listener middleware** (`createListenerMiddleware`) reacts to actions or state changes: "when `cart/itemAdded` happens, debounce and save the cart", or "when the user logs out, cancel polling". It covers most of what people used **redux-saga** or **redux-observable** for, with plain `async`/`await` and built-in cancellation (`listenerApi.cancelActiveListeners()`, `delay`, `take`).

**3. RTK Query** treats server data as a **cache**, not as hand-written state:

```ts
export const api = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['Order'],
  endpoints: (b) => ({
    getOrders: b.query<Order[], void>({ query: () => 'orders', providesTags: ['Order'] }),
    cancelOrder: b.mutation<void, string>({
      query: (id) => ({ url: `orders/${id}/cancel`, method: 'POST' }),
      invalidatesTags: ['Order'],     // getOrders refetches automatically
    }),
  }),
});
export const { useGetOrdersQuery, useCancelOrderMutation } = api;
```

It handles deduplication, caching with expiry, `isLoading`/`isFetching`, refetch on focus or reconnect, polling, optimistic updates (`onQueryStarted` + `updateQueryData`) and generated hooks. It can also generate endpoints from an OpenAPI spec.

**Which to choose:**

- Fetching and caching server data → **RTK Query** (or TanStack Query if you're not on Redux).
- A complex, one-off async workflow → **`createAsyncThunk`**.
- Reacting to actions with side effects (autosave, sync, analytics) → **listener middleware**.
- **Sagas** only if the codebase already uses them heavily; new code rarely needs generators.
