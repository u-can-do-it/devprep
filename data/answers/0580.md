## Hints

- How would you replace a chain of `if (x is A a) ... else if (x is B b) ...` with one expression?
- Which patterns let you check a property's value, or a numeric range, without extra `if`s?
- What does the compiler warn about when a `switch` expression doesn't cover every possible input?

## Answer

**Pattern matching** tests a value against a shape and, if it matches, can extract parts of it into variables. It works in `is` expressions, `switch` statements and **`switch` expressions** (an expression that returns a value).

**The main patterns**

| Pattern | Example | Matches when |
|---|---|---|
| Type / declaration | `o is string s` | `o` is a `string` (and not `null`); binds `s` |
| Constant | `x is null`, `status is 404` | equal to the constant (`is null` ignores overloaded `==`) |
| Relational | `x is > 0 and <= 100` | comparison with a constant |
| Logical | `not null`, `A or B`, `> 0 and < 10` | combines patterns |
| Property | `order is { Status: Status.Paid, Total: > 1000 }` | properties match nested patterns |
| Extended property | `{ Customer.Country: "PL" }` | nested property path (C# 10) |
| Positional | `point is (0, 0)` | `Deconstruct` results match |
| List | `args is [var first, .., var last]` | array or list shape (C# 11) |
| Discard | `_` | anything |

**A `switch` expression**

```csharp
public decimal Shipping(Order order) => order switch
{
    { Total: >= 200 }                         => 0m,                 // free shipping
    { Customer.Country: "PL", Weight: < 5 }  => 9.99m,
    { Customer.Country: "PL" }               => 19.99m,
    { IsExpress: true }                       => 49m,
    _                                         => 29m,
};
```

Arms are checked **top to bottom**, so put specific cases first. The compiler reports an error if an arm can never match because an earlier one already covers it.

**List patterns**

```csharp
string Describe(int[] xs) => xs switch
{
    []              => "empty",
    [var only]      => $"one: {only}",
    [1, ..]         => "starts with 1",
    [.., var last]  => $"ends with {last}",
};
```

**Exhaustive handling**

If a `switch` expression doesn't handle every possible input, the compiler warns (CS8509), and at runtime an unmatched value throws `SwitchExpressionException`. This lets you model a closed set of cases and get a warning when you add a case and forget a branch:

```csharp
public abstract record PaymentResult;
public sealed record Approved(string TransactionId) : PaymentResult;
public sealed record Declined(string Reason) : PaymentResult;
public sealed record RequiresAction(Uri RedirectUrl) : PaymentResult;

IResult ToHttp(PaymentResult r) => r switch
{
    Approved a       => Results.Ok(a.TransactionId),
    Declined d       => Results.UnprocessableEntity(d.Reason),
    RequiresAction x => Results.Accepted(x.RedirectUrl.ToString()),
    _                => throw new UnreachableException(),   // still needed: C# can't prove the hierarchy is closed
};
```

Limits to know:

- For **enums**, the compiler knows the named values and warns when one is missing, but any `int` can be cast to an enum, so it still wants a `_` arm (or warns about unnamed values).
- For **class hierarchies**, C# (as of C# 14) has no closed/sealed hierarchies or discriminated unions, so you need the `_` arm and lose the "you forgot a case" check. Analyzers or libraries (OneOf, Dunet) fill the gap; real unions are a long-standing language proposal.
- **Bool and other finite inputs** are fully checked (`true`/`false`, or covering ranges like `< 0`, `0`, `> 0`).

**Follow-up:** `if (obj is not string s) return; Console.WriteLine(s.Length);` compiles. Why is `s` in scope? (The compiler tracks definite assignment: after the early return, the only way to reach the next line is that the pattern matched, so `s` is definitely assigned there.)
