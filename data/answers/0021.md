## Hints

- Which of the two does the language give you by default, and which one is set on purpose?
- What do `typeof null` and `typeof undefined` return?
- How do `||` and `??` behave differently for `0` or `''`?

## Answer

**`undefined`** means "no value has been assigned". The language produces it on its own:

- a declared but unassigned variable,
- a missing object property or array element,
- a parameter that wasn't passed,
- a function that doesn't return anything.

**`null`** is a value a developer assigns **on purpose** to mean "empty" or "no object".

```js
let a;                 // undefined
const o = {}; o.x;     // undefined
typeof undefined;      // 'undefined'
typeof null;           // 'object'  (a historical bug)
null == undefined;     // true
null === undefined;    // false
JSON.stringify({ a: undefined, b: null }); // '{"b":null}'
```

Default parameters apply only for `undefined`: `f(null)` keeps `null`.

**Falsy values.** There are exactly eight: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`. Everything else is truthy, including `'0'`, `'false'`, `[]`, `{}` and `new Boolean(false)`.

**Practical consequences:**

```js
const count = 0;
count || 10;     // 10 (wrong if 0 is a valid value)
count ?? 10;     // 0  (?? only falls back for null/undefined)
user?.address?.city; // optional chaining stops at null/undefined
```

- `if (arr.length)` works, but `if (value)` will skip valid `0` and `''`. Check for `null`/`undefined` explicitly when those are valid values.
- Check for "nullish" with `x == null` or `x === null || x === undefined`.
- APIs and teams often pick one convention. A common one: `null` for "intentionally empty" (as in JSON or databases), and `undefined` for "not set". TypeScript's `strictNullChecks` makes the difference explicit.

**Follow-up:** "How do you check whether a variable is an array or a plain object?" Use `Array.isArray`, and remember that `typeof null === 'object'`.
