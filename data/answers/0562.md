## Hints

- What has to happen to an `int` when you store it in a variable of type `object`?
- Which old collection types caused boxing for every item, and what replaced them?
- Can calling an interface method on a struct cause an allocation?

## Answer

**Boxing** converts a value type to `object` (or to an interface it implements): the runtime **allocates an object on the heap** and **copies** the value into it. **Unboxing** is the explicit cast back: it checks the type and copies the value out.

```csharp
int n = 42;
object o = n;        // boxing: heap allocation + copy
int m = (int)o;      // unboxing: type check + copy
long l = (long)o;    // InvalidCastException: unbox to the exact type only, then convert: (long)(int)o
n = 7;               // o still holds 42; the box is a separate copy
```

**Where it happens without you noticing:**

- Non-generic collections: `ArrayList`, `Hashtable` store `object`, so every `int` added is boxed. Generic `List<int>` and `Dictionary<int, T>` store values directly (one of the main reasons generics exist).
- Calling a method through an **interface** on a struct: `IComparable c = 5;` boxes.
- `params object[]` APIs and old-style formatting: `string.Format("{0}", 42)` boxes the `int`. String interpolation with modern compilers uses a handler that avoids it.
- Calling `object` methods a struct doesn't override, e.g. `GetHashCode()` or `Equals(object)` on a struct without overrides.
- Casting a generic `T` to an interface (`(IComparable<T>)value`) when `T` is a struct; a constraint like `where T : IComparable<T>` lets you call the method without a box.

**Why it matters:** each box is a small heap allocation. In a hot loop that means millions of short-lived objects, more GC work (#591) and cache misses. It's also a correctness trap: mutating the box doesn't change the original, and two boxes of the same value aren't `ReferenceEquals`.

```csharp
var list = new ArrayList();
for (int i = 0; i < 1_000_000; i++) list.Add(i);      // 1,000,000 allocations

var better = new List<int>();
for (int i = 0; i < 1_000_000; i++) better.Add(i);    // no boxing, values stored inline in the array
```

**How to find it:** allocation profilers (Visual Studio, `dotnet-trace`, #594), BenchmarkDotNet's `[MemoryDiagnoser]`, or looking for `box` instructions in the IL.

**Follow-up:** does `int` have methods if it's not an object? (Yes. `int` is `System.Int32`, a struct that inherits from `ValueType`/`object`. Calling `42.ToString()` doesn't box, because `Int32` overrides `ToString`.)
