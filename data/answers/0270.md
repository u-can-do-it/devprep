## Hints

- How would you style a card differently depending on whether it contains an image, without JavaScript?
- If a library's reset uses `:where()`, how hard is it for you to override?
- What happens to a selector list when one of its selectors is invalid?

## Answer

**`:is()`** matches if **any** selector in its list matches. It shortens repetitive selectors:

```css
:is(h1, h2, h3):hover { color: var(--brand); }
/* same as h1:hover, h2:hover, h3:hover */
```

**`:where()`** works exactly like `:is()` but always has **zero specificity**. Use it for resets, base styles and library defaults that consumers should override easily:

```css
:where(ul, ol)[role="list"] { list-style: none; padding: 0; }
```

**`:has()`** is the "parent" (or relational) selector. It matches an element **if something relative to it matches**:

```css
.card:has(img) { grid-template-rows: auto 1fr; }   /* card containing an image */
label:has(+ input:invalid) { color: crimson; }     /* label followed by an invalid input */
form:has(:user-invalid) .submit { opacity: 0.5; }
html:has(dialog[open]) { overflow: hidden; }       /* lock scroll while a modal is open */
```

Before `:has()`, these patterns needed JavaScript to toggle classes.

**Specificity:**

| Selector | Specificity |
|---|---|
| `:is(.a, #b)` | That of its **most specific** argument, here an ID (1-0-0), even when it matches through `.a` |
| `:not(...)`, `:has(...)` | Same rule as `:is()`: the most specific argument |
| `:where(...)` | Always **0-0-0** |

This catches people out: `:is(#main, .x) p` has ID-level specificity everywhere.

**Forgiving selector lists:** `:is()` and `:where()` skip invalid selectors in their list instead of invalidating the whole rule. `:has()` does **not** forgive invalid arguments.

**`:has()` caveats:**

- It can't be nested inside another `:has()`, and pseudo-elements aren't allowed inside it.
- Browsers optimize it well, but broad patterns such as `body:has(.x *)` that re-evaluate on every DOM change can be costly. Anchor it to a specific element.
- It's supported in all modern browsers (Baseline since late 2023).

**Follow-up:** `:not()` now accepts complex selector lists too: `a:not(.btn, [aria-current])`.
