## Hints

- Why is `textContent` the default and `innerHTML` the exception when inserting user text?
- You have 1,000 items to render. Why would you build them in a `DocumentFragment` first?
- How do you handle a click on any of 1,000 delete buttons with one listener?

## Answer

"No React, no libraries: build a small todo list / searchable table / tabs in plain HTML and JavaScript." It checks whether you understand what the framework does for you. The winning approach is still **state → render**, just done by hand.

```html
<form id="add"><input name="title" required autocomplete="off" /><button>Add</button></form>
<input id="filter" placeholder="Filter" />
<ul id="list"></ul>
<template id="item">
  <li><label><input type="checkbox" /> <span class="title"></span></label> <button type="button" data-action="delete">×</button></li>
</template>
<script type="module" src="/app.js"></script>
```

```js
// app.js — runs after parsing because it's a module (defer by default, #47)
const state = { todos: [], filter: '' };
const list = document.querySelector('#list');
const tpl = document.querySelector('#item');

function render() {
  const frag = document.createDocumentFragment();          // build off-DOM, one reflow at the end (#55)
  for (const t of state.todos) {
    if (!t.title.toLowerCase().includes(state.filter)) continue;
    const li = tpl.content.firstElementChild.cloneNode(true);
    li.dataset.id = t.id;                                   // data-* attributes for identity (#252)
    li.querySelector('input').checked = t.done;
    li.querySelector('.title').textContent = t.title;       // never innerHTML with user text (#108)
    li.classList.toggle('done', t.done);
    frag.append(li);
  }
  list.replaceChildren(frag);                               // clears and inserts in one step
}

document.querySelector('#add').addEventListener('submit', (e) => {
  e.preventDefault();                                       // no page reload
  const data = new FormData(e.currentTarget);               // #515
  state.todos.push({ id: crypto.randomUUID(), title: String(data.get('title')).trim(), done: false });
  e.currentTarget.reset();
  render();
});

list.addEventListener('click', (e) => {                     // event delegation: one listener for all rows (#13)
  const li = e.target.closest('li');
  if (!li) return;
  const todo = state.todos.find((t) => t.id === li.dataset.id);
  if (e.target.matches('[data-action="delete"]')) state.todos = state.todos.filter((t) => t !== todo);
  else if (e.target.matches('input[type=checkbox]')) todo.done = e.target.checked;
  else return;
  render();
});

document.querySelector('#filter').addEventListener('input', (e) => {
  state.filter = e.target.value.toLowerCase();
  render();
});

render();
```

**APIs you are expected to know cold:** `querySelector`/`querySelectorAll` (static `NodeList`), `createElement`, `append`/`prepend`/`before`/`after`/`remove`, `replaceChildren`, `cloneNode(true)`, `classList.add/remove/toggle`, `dataset`, `closest`/`matches`, `addEventListener` with `{ once, passive, signal }`, `FormData`, `<template>`.

**Things to say out loud:**

- **`textContent` vs `innerHTML` vs `innerText`:** `textContent` sets text safely and fast; `innerHTML` parses HTML and is an XSS hole with user data (use it only for trusted static markup, or sanitize with DOMPurify); `innerText` is layout-aware and slow because it triggers reflow.
- **Delegation** scales to any number of rows and survives re-renders, since the listener sits on the stable parent. `e.target` is the clicked element, `e.currentTarget` the listener's element.
- **Full re-render vs patching:** rebuilding the whole list is simplest and fine for hundreds of items; it loses focus and scroll inside the list. For bigger lists, update the changed `li` only, which is the job React's reconciler does for you (#32).
- **Batching:** build in a `DocumentFragment` or a detached element, then insert once. Reading layout (`offsetHeight`) between writes causes layout thrashing (#55).
- **Lifecycle:** with `type="module"` or `defer` you don't need `DOMContentLoaded`. Remove listeners you add to `window` or `document` when the widget goes away, or pass an `AbortSignal` to `addEventListener` and abort once.
- **Forms:** `required`, `type="email"` and `e.preventDefault()` on submit; read values with `FormData`, not by walking inputs (#48, #253).
- **Persistence:** `localStorage.setItem('todos', JSON.stringify(state.todos))` after each change, wrapped in `try/catch` (#56).
