## Hints

- Ten requests fail with 401 at the same moment. How many token refreshes should run, and what happens to the other nine requests?
- How do you stop a request from retrying its refresh forever?
- `fetch` resolves on a 500. What does Axios do, and which option controls it?
- `CancelToken` appears in an old codebase. What replaced it, and how does TanStack Query plug in?
- `axios.get<User>('/me')`: does the generic validate anything?

## Answer

> Create one Axios instance with `baseURL`, a timeout and shared headers. A request interceptor attaches the token. A response interceptor turns a 401 into a single shared refresh (other requests wait for the same promise), retries the original request once, and signs the user out if the refresh fails. Cancel with an `AbortController` `signal`, which TanStack Query provides. Axios rejects on non-2xx responses, so narrow errors with `axios.isAxiosError`. The generic on `get<T>` is only a cast, so validate important responses with Zod. Pick Axios for interceptors, upload progress and its error model. Pick `fetch` in Server Components, where Next.js caching is built on it.

**The instance**

```ts
// lib/http.ts
import axios, { AxiosError, type InternalAxiosRequestConfig } from 'axios';

export const http = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL,
  timeout: 15_000,
  headers: { 'Content-Type': 'application/json' },
  paramsSerializer: { indexes: null },     // status=open&status=paid instead of status[]=open
});
```

**Attaching the token.** Where the token comes from depends on the auth setup. With NextAuth the safest pattern keeps tokens server-side and calls the API through a route handler or BFF (#632, #641). If the client must send the token, read it from a small in-memory store that is filled from the session. Don't call `getSession()` on every request, because each call is a network round trip.

```ts
http.interceptors.request.use((config) => {
  const token = tokenStore.get();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

**Refreshing on 401 without a storm**

```ts
let refreshing: Promise<string> | null = null;

http.interceptors.response.use(
  (res) => res,
  async (error: AxiosError) => {
    const original = error.config as InternalAxiosRequestConfig & { _retry?: boolean };
    if (error.response?.status !== 401 || !original || original._retry || original.url?.includes('/auth/refresh')) {
      return Promise.reject(error);
    }
    original._retry = true;                                     // retry each request once at most
    try {
      refreshing ??= refreshToken().finally(() => { refreshing = null; });   // one refresh for everybody
      const token = await refreshing;
      original.headers.Authorization = `Bearer ${token}`;
      return http(original);
    } catch (e) {
      tokenStore.clear();
      signOut();                                                 // e.g. NextAuth signOut({ callbackUrl: '/login' })
      return Promise.reject(e);
    }
  },
);
```

Key points: a single in-flight refresh promise, a `_retry` flag, never refreshing on the refresh endpoint itself, and clearing the query cache on sign-out (#636). Refreshing a little before expiry (from the token's `exp`) avoids most 401s.

**Interceptor details**

- Request interceptors run in **reverse** order of registration, and response interceptors in order.
- `http.interceptors.request.eject(id)` removes one, which is useful in tests.
- Keep interceptors about transport (auth, correlation ids, error normalization). Toasts belong in TanStack Query's global `onError`, so you don't show a toast for a query that is allowed to fail quietly (#636).

**Errors.** Axios rejects for any status outside 2xx (configurable with `validateStatus`). Narrow before using:

```ts
try {
  await http.post('/orders', payload);
} catch (e) {
  if (axios.isAxiosError<{ errors?: Record<string, string> }>(e)) {
    if (e.code === 'ERR_CANCELED') return;                      // cancelled, not a failure
    if (!e.response) return showOffline();                      // network error or timeout (ECONNABORTED)
    if (e.response.status === 422) return form.setErrors(e.response.data.errors ?? {});   // #644
  }
  throw e;
}
```

For TanStack Query's `retry`, don't retry 4xx: `retry: (n, e) => !(isAxiosError(e) && (e.response?.status ?? 500) < 500) && n < 2`.

**Cancellation.** `CancelToken` is deprecated. Use `AbortController`:

```ts
useQuery({
  queryKey: ['orders', filters],
  queryFn: ({ signal }) => http.get<Page<Order>>('/orders', { params: filters, signal }).then((r) => r.data),
});
```

When the key changes or the component unmounts, the query aborts the stale request. This matters for search-as-you-type and grid filters (#502).

**Typing is not validation.** `http.get<User>()` only casts `response.data`. For data you rely on, parse it: `UserSchema.parse(res.data)` (#182). Generating clients and types from the backend's OpenAPI spec (orval, openapi-typescript) keeps types in sync without hand-writing them.

**Files**

- Upload with progress (something `fetch` can't report for uploads): `http.post('/imports', formData, { onUploadProgress: (e) => setProgress(e.progress ?? 0) })`. Don't set `Content-Type` yourself; Axios adds the multipart boundary.
- Download: `http.get('/exports/123', { responseType: 'blob' })`, then build an object URL and read the filename from `Content-Disposition`. For very large files a plain link to an authenticated endpoint streams better, because nothing is buffered in JS memory (#651).

**Axios vs `fetch`**

| | Axios | `fetch` |
|---|---|---|
| Rejects on 4xx/5xx | yes | no; check `res.ok` |
| Interceptors | built in | write a wrapper |
| Upload progress | yes | no (download progress via streams) |
| JSON | automatic | `res.json()` |
| Timeout | `timeout` option | `AbortSignal.timeout(ms)` |
| Next.js Data Cache and `revalidate` | not used | built on `fetch` |
| Bundle | ~13 kB gzipped | 0 |

In a Next.js App Router project a common split is `fetch` in Server Components and Route Handlers, and Axios in client components that talk to the API, which is where the interceptors pay off.

**Follow-up:** "How do you test code that uses Axios?" Mock the network, not Axios. MSW intercepts requests from both Axios and `fetch`, so the interceptors and error handling run for real in the test (#461).
