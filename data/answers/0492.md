## Hints

- Does Googlebot run JavaScript? Does LinkedIn's link-preview scraper?
- What status code does a client-side "Page not found" screen return?
- How does a search engine know that `/shoes?sort=price` and `/shoes` are the same page?

## Answer

**Why client-rendered SPAs struggle:** the initial HTML is an empty `<div id="root">`. Google does render JavaScript, but rendering is deferred and costs crawl budget, and errors or slow API calls during rendering mean missing content. Many other crawlers (Bing to a degree, social preview scrapers for Slack, LinkedIn and Facebook, AI crawlers) don't run JavaScript at all. And every route has the same `<title>` unless JavaScript changes it.

**What to do:**

1. **Render HTML on the server** for public pages: SSR, SSG or ISR with Next.js, Remix/React Router, or Astro. Content, links and metadata are in the first response. Keep pure SPAs for logged-in apps where SEO doesn't matter.
2. **Unique metadata per page:** `<title>`, meta description, canonical URL, Open Graph and Twitter tags. In the Next.js App Router use `metadata` or `generateMetadata`.
3. **Crawlable links:** real `<a href="/products/42">` elements, not `onClick` navigation, and path-based routes instead of `#/hash` routes.
4. **Correct status codes:** return a real **404** (Next's `notFound()`) and **301** redirects for moved pages. An SPA "not found" screen served with 200 is a *soft 404*.
5. **Canonical URLs** for duplicates (filters, sorting, tracking parameters), and `noindex` for pages that shouldn't rank (internal search results, carts).
6. **`sitemap.xml` and `robots.txt`** (`app/sitemap.ts`, `app/robots.ts` in Next.js). Don't block JS and CSS files that are needed for rendering.
7. **Structured data** (JSON-LD with schema.org `Product`, `Article`, `BreadcrumbList`, `FAQPage`) for rich results.
8. **Performance:** Core Web Vitals are part of Google's page-experience signals, and fast pages also get crawled more efficiently.
9. **International sites:** `hreflang` alternates and a separate URL per language (`/pl/…`), not language switching by cookie.
10. **Semantic HTML:** one `h1`, a logical heading structure, `alt` text, and content that isn't hidden behind clicks or tabs that load data lazily.

**Checking it:** Google Search Console (URL Inspection shows the rendered HTML), Lighthouse's SEO audit, view the page source (not DevTools' live DOM) to see what crawlers get first, and Rich Results Test for structured data.

**Follow-up:** a product listing has filters for colour, size and price, creating millions of URL combinations. Which should be indexable, and how do you control it?
