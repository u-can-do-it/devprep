## Hints

- Why doesn't `{...register('email')}` on an MUI `TextField` attach the ref to the `<input>`?
- `Autocomplete`'s `onChange` has a different signature from a native input. What does it pass?
- In server-side mode, which `DataGrid` props become controlled, and what goes into the query key?
- Why should `rowCount` not drop to `0` while the next page loads?

## Answer

**React Hook Form + MUI.** MUI inputs are controlled components with their own refs, so the clean integration is `Controller` (or `useController`) wrapped in reusable field components:

```tsx
function FormTextField<T extends FieldValues>({ name, control, ...props }: { name: Path<T>; control: Control<T> } & TextFieldProps) {
  return (
    <Controller
      name={name}
      control={control}
      render={({ field, fieldState }) => (
        <TextField
          {...field}
          {...props}
          inputRef={field.ref}                       // focus on error goes to the real <input>
          error={!!fieldState.error}
          helperText={fieldState.error?.message ?? props.helperText}
        />
      )}
    />
  );
}
```

`register` returns a `ref` that `TextField` would attach to its root `div`; if you use `register`, pass the ref explicitly as `inputRef`. Validate with a Zod resolver shared with the backend (#625). Show server errors with `setError('field', { message })` after a failed mutation. MUI's `helperText` is linked to the input through `aria-describedby`, so errors are announced.

**`Autocomplete` with server search**

```tsx
const [input, setInput] = useState('');
const debounced = useDebounce(input, 300);
const { data = [], isFetching } = useQuery({
  queryKey: ['customers', 'search', debounced],
  queryFn: ({ signal }) => api<Customer[]>(`/customers?q=${encodeURIComponent(debounced)}`, { signal }),
  enabled: debounced.length >= 2,
  placeholderData: keepPreviousData,
});

<Autocomplete
  options={data}
  loading={isFetching}
  filterOptions={(x) => x}                         // the server already filtered
  getOptionLabel={(c) => c.name}
  isOptionEqualToValue={(a, b) => a.id === b.id}   // objects from different fetches aren't ===
  onInputChange={(_e, value) => setInput(value)}
  onChange={(_e, value) => field.onChange(value)}  // (event, value), not event.target.value
  renderInput={(params) => <TextField {...params} label="Customer" />}
/>
```

**Date pickers** come from MUI X (`@mui/x-date-pickers`): wrap the app in `LocalizationProvider` with an adapter (`AdapterDayjs`, `AdapterDateFns`) and a locale (`pl`), and decide whether the form holds a date object or an ISO string. Time zones are where bugs hide (#630).

**`DataGrid` with server-side data.** The free `DataGrid` is MIT-licensed (page size capped at 100). `DataGridPro` and `DataGridPremium` (column pinning, tree data, grouping, Excel export) need a commercial licence key, so check which one the project pays for.

```tsx
const [paginationModel, setPaginationModel] = useState({ page: 0, pageSize: 25 });
const [sortModel, setSortModel] = useState<GridSortModel>([]);
const [filterModel, setFilterModel] = useState<GridFilterModel>({ items: [] });

const { data, isFetching } = useQuery({
  ...orderQueries.list({ paginationModel, sortModel, filterModel }),   // all three in the key
  placeholderData: keepPreviousData,                                    // keep old rows while loading
});

const rowCountRef = useRef(0);
if (data?.total !== undefined) rowCountRef.current = data.total;       // stable while loading

<DataGrid
  rows={data?.items ?? []}
  columns={columns}                              // defined outside the component or memoized
  getRowId={(r) => r.orderId}                    // when rows have no `id` field
  rowCount={rowCountRef.current}
  loading={isFetching}
  paginationMode="server" sortingMode="server" filterMode="server"
  paginationModel={paginationModel} onPaginationModelChange={setPaginationModel}
  sortModel={sortModel} onSortModelChange={setSortModel}
  filterModel={filterModel} onFilterModelChange={setFilterModel}
  pageSizeOptions={[25, 50, 100]}
/>
```

Consider keeping page, sort and filter in the URL (`useSearchParams`) so a view can be shared and survives a refresh (#503). Debounce text filters. Map the grid's filter model to what the API actually supports, and hide filter operators the backend can't handle.

**Around the data:** `Dialog` for confirmations (focus trap and Escape handled for you; give `DialogTitle` an id for `aria-labelledby`), `Snackbar`/`Alert` for mutation results, `Skeleton` for first loads, and `aria-label` on every `IconButton`.

**Follow-up:** "Client-side or server-side grid?" Client-side is simpler and fine up to a few thousand rows that load quickly. Beyond that, or when data is permission-filtered on the backend, go server-side.
