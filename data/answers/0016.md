## Hints

- When can the garbage collector reclaim an object, in terms of reachability?
- Which everyday patterns keep objects reachable by accident?
- Why are `WeakMap` keys restricted to objects, and why can't you iterate a `WeakMap`?

## Answer

JS engines use **reachability-based GC** (mark-and-sweep, with generations in V8). An object is freed once nothing can reach it from the roots: globals, the stack, and active closures. A **leak** is memory that stays reachable even though you no longer need it.

**Common causes:**

- Event listeners, `setInterval`s and subscriptions that are never removed. They keep their closures and everything those closures reference.
- Detached DOM nodes still referenced from JS variables or caches.
- Unbounded caches or Maps keyed by objects.
- Closures holding large data longer than needed.
- Accidental globals.
- In SPAs: forgetting cleanup in `useEffect`. Return a cleanup function, or use `AbortController` to remove listeners.

**Weak references:**

- **`WeakMap` / `WeakSet`:** the keys must be objects (or non-registered symbols) and are held **weakly**. When the key object is no longer reachable from anywhere else, the entry disappears. That's why they can't be iterated and have no `size`. The contents depend on the GC.

```js
const meta = new WeakMap();
function track(el) { meta.set(el, { clicks: 0 }); }
// When `el` is removed from the DOM and dereferenced, its metadata can be collected too.
```

Typical uses: private data for objects, metadata attached to DOM nodes, memoizing by object identity.

- **`WeakRef`:** holds a weak reference to a single object. `ref.deref()` returns the object, or `undefined` if it was collected. **`FinalizationRegistry`** runs a callback at some point after an object is collected. Both are non-deterministic. Use them only for caches and optimizations, never for program logic or required cleanup.

**Finding leaks:** Chrome DevTools Memory tab. Compare heap snapshots before and after repeating an action, and look for "Detached" nodes and retainer paths. In Node, use `--inspect` or `node --heapsnapshot-signal`.

**Follow-up:** "Why not use a `Map` keyed by DOM nodes?" Because the `Map` keeps the nodes alive forever.
