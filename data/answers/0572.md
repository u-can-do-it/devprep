## Hints

- `Where` isn't a method of `List<T>`. So how can you call `list.Where(...)`?
- When does `var q = users.Where(u => u.Active);` actually look at the users?
- If a query is enumerated twice, how many times does it run, and why does that matter for a database query?

## Answer

**LINQ** (Language Integrated Query) is a set of query operators (`Where`, `Select`, `OrderBy`, `GroupBy`, `Any`, `Sum`, `Join`…) that work over any `IEnumerable<T>` (in memory) or `IQueryable<T>` (translated to SQL by EF Core, #579).

```csharp
var names = users
    .Where(u => u.IsActive)
    .OrderBy(u => u.LastName)
    .Select(u => u.FullName)
    .ToList();

// query syntax: compiles to the same method calls
var names2 = (from u in users where u.IsActive orderby u.LastName select u.FullName).ToList();
```

**Extension methods make it work.** A `static` method in a `static` class whose first parameter has `this` can be called as if it were an instance method. LINQ operators are extension methods on `IEnumerable<T>` in `System.Linq.Enumerable`.

```csharp
public static class StringExtensions
{
    public static bool IsBlank(this string? s) => string.IsNullOrWhiteSpace(s);
}

"  ".IsBlank();     // compiles to StringExtensions.IsBlank("  ")
```

They can't access private members and are only in scope when their namespace is imported. C# 14 adds `extension` blocks, which also allow extension properties.

**Deferred execution:** most operators (`Where`, `Select`, `OrderBy`) don't run when called; they build a pipeline that runs when you **enumerate** it (`foreach`, `ToList`, `Count`, `First`). Each enumeration runs it **again**.

```csharp
var active = users.Where(u => { Console.WriteLine("check"); return u.IsActive; });
// nothing printed yet
var count = active.Count();      // runs the filter
var first = active.First();      // runs it again: multiple enumeration
var list = active.ToList();      // materialize once if you need the result several times
```

Multiple enumeration is a performance bug with expensive sources (a database query runs twice) and a correctness bug with sources that change or can be read only once. `ToList()`, `ToArray()`, `Count()`, `Sum()`, `First()` execute immediately.

**`First`, `FirstOrDefault`, `Single`, `SingleOrDefault`:**

| Method | 0 matches | 1 match | 2+ matches |
|---|---|---|---|
| `First` | throws | returns it | returns the first |
| `FirstOrDefault` | `default` (`null`/`0`) | returns it | returns the first |
| `Single` | throws | returns it | **throws** |
| `SingleOrDefault` | `default` | returns it | **throws** |

Use `Single` when more than one result means a bug (lookup by unique key); use `First` with `OrderBy` when you want "the newest". `Single` must check for a second element, so in SQL it fetches up to 2 rows. Use `Any()` rather than `Count() > 0` to check for existence.

**Follow-up:** what's wrong with `list.Where(x => x.Id == id).FirstOrDefault()`? (Nothing incorrect, but `list.FirstOrDefault(x => x.Id == id)` is shorter; for repeated lookups by id use a `Dictionary` instead, #571.)
