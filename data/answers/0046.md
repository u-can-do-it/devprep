## Hints

- How does a screen reader user jump straight to the main content or the list of headings?
- What does a search engine or link preview read to describe your page?
- What does `<button>` give you that `<div onclick>` doesn't?

## Answer

**Semantic HTML** means using elements for their meaning, not their look: `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<footer>`, a logical `<h1>`–`<h6>` outline, `<button>` for actions, `<a href>` for navigation, `<ul>`/`<ol>` for lists, `<table>` for tabular data.

Why it matters:

- **Accessibility** — landmarks and headings let screen reader users navigate; native elements come with roles, keyboard support and focus for free (`<button>` is focusable and activates on Enter/Space; a `<div>` is not).
- **SEO** — crawlers understand structure and the main content better.
- **Maintainability** — the markup documents itself; less CSS and JS to fake behavior.

```html
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Trail Running Shoes – Acme Store</title>
  <meta name="description" content="Lightweight trail shoes with free returns.">
  <link rel="canonical" href="https://acme.example/shoes/trail">
  <meta property="og:title" content="Trail Running Shoes">
  <meta property="og:image" content="https://acme.example/og/trail.jpg">
</head>
```

Key SEO tags: a unique, descriptive **`<title>`**; **`meta description`** (affects the snippet, not ranking directly); **`canonical`** to avoid duplicate content; **`viewport`** for mobile-first indexing; **Open Graph / Twitter** tags for link previews; `robots` meta for `noindex`; `lang` on `<html>`; `hreflang` for translations; and **JSON-LD** structured data for rich results.

**Follow-up:** `meta keywords` is ignored by Google; in Next.js these are set through the `metadata` API rather than by hand.
