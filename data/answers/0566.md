## Hints

- What does "assembly" mean in `internal`, and what's the default access of a class and of a class member?
- Which modifier stops other classes from inheriting from yours, and why might that be the safer default?
- Can you create an instance of an `abstract` class or a `static` class?

## Answer

**Access modifiers:**

| Modifier | Visible to |
|---|---|
| `public` | everyone |
| `private` | only the containing type (default for **members**) |
| `protected` | the containing type and **derived** types |
| `internal` | any code in the **same assembly** (project / `.dll`) (default for top-level **types**) |
| `protected internal` | same assembly **or** derived types (union) |
| `private protected` | derived types **in the same assembly** (intersection) |
| `file` (C# 11) | only the same source file (mostly for source generators) |

```csharp
public class Account
{
    private decimal _balance;                       // only Account
    protected void Log(string msg) { }              // Account and subclasses
    internal void Recalculate() { }                 // the whole project, not consumers of the DLL
    public decimal Balance => _balance;
}
```

Use the most restrictive access that works. `internal` is a good default for classes in a library: it's not part of your public API, so you can change it freely. `[InternalsVisibleTo("MyApp.Tests")]` exposes internals to a test project.

**`static`:** the member belongs to the **type**, not an instance (`Math.Max`, a shared counter). A `static class` can't be instantiated or inherited and has only static members: used for helpers and extension methods (#572). Static mutable state is shared by all threads and requests, so treat it carefully (#592).

**`sealed`:** a sealed class can't be inherited (`string` is sealed). On an `override` method it stops further overriding. Sealing classes not designed for inheritance prevents fragile subclassing, and the JIT can devirtualize calls on sealed types (#604). Many teams seal by default.

**`abstract`:** an abstract class **can't be instantiated** and may declare abstract members with no body that derived classes **must** override (#567).

```csharp
public abstract class Shape
{
    public abstract double Area();                  // no body: subclasses must implement
    public override string ToString() => $"Area {Area():F2}";
}

public sealed class Circle(double r) : Shape        // primary constructor, can't be subclassed
{
    public override double Area() => Math.PI * r * r;
}

var s = new Shape();                                // compile error: abstract
```

**Follow-up:** can a `static` class implement an interface? (No. It has no instances, so there's nothing to treat as that interface. Interfaces can declare `static abstract` members, which non-static types implement.)
