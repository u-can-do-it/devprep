## Hints

- What types can be keys in an object, and what types can be keys in a `Map`?
- What could go wrong if user input becomes an object key such as `__proto__`?
- How fast is checking whether an array contains a value, compared with a `Set`?

## Answer

**`Map` vs plain object:**

| | Object | Map |
|---|---|---|
| Key types | strings and symbols (numbers become strings) | any value, including objects |
| Order | mostly insertion order, but integer-like keys come first | always insertion order |
| Size | `Object.keys(o).length` | `map.size` |
| Iteration | `Object.entries(o)` | directly iterable |
| Prototype keys | inherited keys like `constructor`, `__proto__` can clash | none |
| JSON | native | needs `Object.fromEntries(map)` |

Use a **`Map`** for dictionaries built at runtime: keys from user input, frequent adds and deletes, or object keys (for example, metadata per DOM node or per request). Use an **object** for records with a fixed, known shape that you serialize to JSON.

```js
const visits = new Map();
visits.set(userObj, (visits.get(userObj) ?? 0) + 1);
```

**`Set` vs array:** a `Set` holds unique values, compared with SameValueZero (so `NaN` equals `NaN`). `set.has(x)` takes O(1) on average, while `array.includes(x)` is O(n). That matters inside loops.

```js
const unique = [...new Set(ids)];
const allowed = new Set(['admin', 'editor']);
if (allowed.has(role)) { /* ... */ }

const a = new Set([1, 2, 3]), b = new Set([2, 3, 4]);
a.intersection(b);  // Set {2, 3}  (ES2025 set methods)
a.difference(b);    // Set {1}
```

Keep using arrays when order and duplicates matter, or when you need index access and `map`/`filter`.

**Follow-up:** `WeakMap`/`WeakSet` hold their keys weakly, so they suit caches keyed by objects whose lifetime you don't control.
