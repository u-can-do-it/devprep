## Hints

- A component must return one root. What if you don't want an extra `<div>` in the DOM?
- Where would an extra wrapper break valid HTML or a CSS layout?
- Inside a `.map()`, what attribute does each returned item need, and can the short syntax accept it?

## Answer

A **Fragment** groups multiple children without adding a DOM node:

```jsx
function Columns() {
  return (
    <>
      <td>Name</td>
      <td>Email</td>
    </>
  );
}
```

**Why not just wrap in a `<div>`?**

- **Valid HTML:** a `<div>` inside `<tr>`, `<ul>`, `<dl>` or `<select>` is invalid. It can break table layout and screen-reader semantics, and on the server it can cause hydration errors.
- **CSS layout:** in flex and grid layouts, the children must be direct children of the container. A wrapper div breaks that.
- **Less DOM:** fewer nodes and cleaner DevTools.

**`<>` vs `<Fragment key>`:** the short syntax can't take attributes. When you return a group of siblings from `.map()`, each group needs a `key`, so you must use the long form:

```jsx
import { Fragment } from 'react';

<dl>
  {terms.map(t => (
    <Fragment key={t.id}>
      <dt>{t.word}</dt>
      <dd>{t.definition}</dd>
    </Fragment>
  ))}
</dl>
```

`key` is the only prop `Fragment` accepts.

**Follow-up:** Fragments also affect state. If you switch between `<><Child /></>` and `[<Child />]`, React treats them as the same position. Wrapping the child in a real element would reset its state.
