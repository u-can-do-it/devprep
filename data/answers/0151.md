## Hints

- Which of the three runs the function right away, and which one gives you a new function?
- How does each one take the arguments for the target function?
- What should happen when someone calls a bound function with `new`?

## Answer

All three let you set `this` explicitly for a regular function.

- **`fn.call(thisArg, a, b)`** calls `fn` right away, with the arguments listed one by one.
- **`fn.apply(thisArg, [a, b])`** calls `fn` right away, with the arguments passed as an array (or array-like).
- **`fn.bind(thisArg, a)`** does **not** call anything. It returns a new function with `this` fixed and, optionally, some arguments preset (partial application). Once bound, `this` can't be changed by another `bind`/`call`.

```js
function greet(greeting, mark) { return `${greeting}, ${this.name}${mark}`; }
const ann = { name: 'Ann' };
greet.call(ann, 'Hi', '!');      // 'Hi, Ann!'
greet.apply(ann, ['Hi', '?']);   // 'Hi, Ann?'
const hiAnn = greet.bind(ann, 'Hi');
hiAnn('.');                      // 'Hi, Ann.'
```

Typical uses: borrowing methods (`Array.prototype.slice.call(arrayLike)`), fixing lost `this` in callbacks (`button.addEventListener('click', this.onClick.bind(this))`). With spread syntax, `apply` is rarely needed: `Math.max(...nums)` replaces `Math.max.apply(null, nums)`.

A simple `bind`:

```js
Function.prototype.myBind = function (ctx, ...preset) {
  const fn = this;
  return function bound(...args) {
    // `new` ignores the bound this, like the native bind
    if (new.target) return new fn(...preset, ...args);
    return fn.apply(ctx, [...preset, ...args]);
  };
};
```

**Pitfalls:** arrow functions ignore the `thisArg` entirely. In strict mode, passing `null` keeps `this` as `null` instead of switching to `globalThis`.

**Follow-up:** "Why can't you re-bind a bound function?" The bound function ignores its own `this` and always calls the target with the stored one.
