## Hints

- How would you match `/blog/hello-world` and `/blog/2026/10/hello` with one file?
- Which of the three also matches `/docs` with no extra segments?
- In Next.js 15+, do you read `params` directly or do you `await` it?

## Answer

Wrap a folder name in square brackets to make it a **dynamic segment**. The matched value arrives in the `params` prop.

| Folder | Matches | `params` |
|---|---|---|
| `app/blog/[slug]/page.tsx` | `/blog/a` | `{ slug: 'a' }` |
| `app/shop/[...slug]/page.tsx` (catch-all) | `/shop/a`, `/shop/a/b/c` (not `/shop`) | `{ slug: ['a', 'b', 'c'] }` |
| `app/docs/[[...slug]]/page.tsx` (optional catch-all) | `/docs`, `/docs/a/b` | `{ slug: undefined }` or `['a', 'b']` |

Since Next.js 15, `params` (and `searchParams`) is a **Promise**. Next.js 16 removed synchronous access, so you must `await` it:

```tsx
// app/blog/[slug]/page.tsx
export default async function Post({ params }: PageProps<'/blog/[slug]'>) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) notFound();
  return <article>{post.title}</article>;
}
```

`PageProps<'/blog/[slug]'>` is a globally generated type helper, so you don't type params by hand. In Client Components, read params with the `useParams()` hook.

**Things to know:**

- Static segments win over dynamic ones: `app/blog/new/page.tsx` matches before `[slug]`.
- Use `generateStaticParams` to prerender known values at build time.
- Params are **user input**. Validate them before you put them in a query.

**Follow-up:** catch-all routes are common for CMS-driven pages and docs sites, where the URL depth isn't known ahead of time.
