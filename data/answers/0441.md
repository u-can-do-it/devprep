## Hints

- What are the three states a Promise can be in, and can it change state twice?
- What does `.then()` return, and what happens if a callback inside it throws?
- When does the code inside `new Promise((resolve) => ...)` run, and when do `.then()` callbacks run?

## Answer

A **Promise** is an object representing the eventual result of an asynchronous operation. Instead of passing callbacks into a function, the function returns a Promise you can attach handlers to.

**States.** A promise is `pending`, then **settles** exactly once to `fulfilled` (with a value) or `rejected` (with a reason). After that it never changes, and late subscribers still get the result.

```js
const p = new Promise((resolve, reject) => {
  // the executor runs synchronously, right now
  setTimeout(() => resolve(42), 100);
});

p.then((v) => v * 2)          // returns a NEW promise
 .then((v) => console.log(v)) // 84
 .catch((err) => console.error(err)) // catches a rejection from any step above
 .finally(() => console.log('done'));
```

**Chaining rules:**
- `.then()` always returns a new promise. Returning a value fulfills it; returning a promise makes it **adopt** that promise's result; throwing rejects it.
- A rejection skips `.then` fulfillment handlers until it reaches a `.catch` (or a `.then(_, onRejected)`).
- Handlers run asynchronously as **microtasks**, after the current synchronous code, even if the promise is already settled.

**Useful statics:** `Promise.resolve`/`reject`, the combinators (`all`, `allSettled`, `race`, `any`), `Promise.withResolvers()` (ES2024) and `Promise.try()` (ES2025) for running a function that may throw synchronously or return a promise.

**Common mistakes:**
- Forgetting to `return` inside `.then`, which breaks the chain (the next step gets `undefined` and errors escape).
- Nesting `.then` inside `.then` instead of returning and chaining.
- Wrapping an existing promise in `new Promise(...)` (the "explicit construction" anti-pattern).
- No `.catch` at the end, which produces an unhandled rejection (in Node this crashes the process by default).

`async`/`await` is syntax on top of promises: an `async` function always returns a promise, and `await` unwraps one.
