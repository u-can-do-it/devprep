## Hints

- What does `const user = await res.json() as User` actually check at runtime?
- Where are the "trust boundaries" in a typical app?
- How can you avoid writing both a TypeScript type and a separate validator for the same shape?

## Answer

TypeScript types are **erased** when the code is compiled. `res.json()` returns `any` (or `unknown`), so `as User` is an **assertion, not a check**. If the backend renames a field, your code compiles fine and crashes, or silently corrupts data, later and far from the cause.

**Validate at trust boundaries:** HTTP responses and request bodies, `localStorage`, URL params, env variables, `postMessage`, webhooks, file uploads and third-party SDKs. Inside the boundary, rely on the types.

**Schema-first validation:** define a runtime schema and **infer** the static type from it, so there is one source of truth. "Parse, don't validate": turn `unknown` into a typed value or fail.

```ts
import { z } from 'zod';

const User = z.object({
  id: z.string(),
  email: z.email(),
  role: z.enum(['admin', 'user']),
  createdAt: z.coerce.date(),
});
type User = z.infer<typeof User>;

async function getUser(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  const result = User.safeParse(await res.json());
  if (!result.success) throw new Error('Invalid user payload', { cause: result.error });
  return result.data;
}
```

Alternatives: Valibot (smaller bundle), ArkType, TypeBox (JSON Schema). Many tools accept any library that implements the shared **Standard Schema** interface. On the server, frameworks validate request bodies from the same schemas.

**Complementary approaches:**

- **Code generation** from OpenAPI or GraphQL schemas, or end-to-end typed RPC (tRPC, Server Actions), keeps client and server types in sync. Data from outside is still untrusted.
- **Type guards** (`x is User`) for small, hand-written checks.

**Trade-offs:** validation costs CPU and bundle size, so validate once at the edge, not in every function. Decide how to fail: reject the request, use a fallback, or log the error and continue.
