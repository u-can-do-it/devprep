## Hints

- Why is `<div onClick>` worse than `<button>` for keyboard and screen-reader users?
- How do you connect a `<label>` or an error message to an input in a reusable component that might appear twice on a page?
- When content changes without a page load, how does a screen-reader user find out?

## Answer

React renders regular DOM, so accessibility is mostly **HTML done right**, plus handling dynamic updates that a single-page app introduces.

**Core practices:**

- **Semantic elements first:** `<button>`, `<a href>`, `<nav>`, `<main>`, `<ul>`, `<dialog>`. These give you focus, keyboard support and roles for free. A clickable `<div>` gives you none of them.
- **Labels and descriptions:** every input needs an accessible name. Error text should be linked with `aria-describedby`, and the field marked with `aria-invalid`.
- **Announce dynamic changes:** use an `aria-live` region or `role="status"`/`role="alert"` for toasts, validation and async results.
- **Manage focus:** on client-side route changes, move focus to the new heading. After deleting an item, focus something sensible. Trap focus in modals.
- **Use accessible primitives:** React Aria, Radix or Ariakit for complex widgets like comboboxes, menus and tabs, instead of building ARIA patterns by hand.
- **Tooling:** `eslint-plugin-jsx-a11y`, axe checks in tests (`vitest-axe`, `@axe-core/playwright`), and testing with `getByRole`.

**`useId`** generates a unique ID that is **stable between the server and client render**. That makes it safe for `htmlFor`/`id`/`aria-*` links without hydration mismatches, even when the component appears many times:

```jsx
function Field({ label, error, ...props }) {
  const id = useId();
  return (
    <>
      <label htmlFor={id}>{label}</label>
      <input id={id} aria-invalid={!!error}
             aria-describedby={error ? `${id}-err` : undefined} {...props} />
      {error && <p id={`${id}-err`}>{error}</p>}
    </>
  );
}
```

**Don't** use `useId` for list `key`s, and don't depend on the format of the generated ID.
