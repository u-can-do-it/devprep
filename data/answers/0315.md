## Hints

- How does a test function receive a database connection without creating it itself?
- How does a fixture clean up after the test, even when the test fails?
- Where do you put fixtures shared by many test files, and how do you avoid recreating expensive ones for every test?

## Answer

A **fixture** is a function decorated with `@pytest.fixture`. Tests request it by **naming it as a parameter**, and pytest builds it (plus any fixtures it depends on) and injects the result. It's dependency injection for tests.

```python
# conftest.py — fixtures here are visible to all tests in this directory tree
import pytest

@pytest.fixture(scope="session")
def engine():
    eng = create_engine(TEST_DB_URL)
    yield eng                     # value given to tests
    eng.dispose()                 # teardown after the last test

@pytest.fixture
def db(engine):                   # function scope (default): fresh per test
    conn = engine.connect()
    tx = conn.begin()
    yield Session(bind=conn)
    tx.rollback()                 # every test starts clean
    conn.close()

@pytest.fixture
def make_user(db):                # factory fixture
    def _make(**kw):
        user = User(email=kw.get("email", "a@b.c"))
        db.add(user); db.flush()
        return user
    return _make

# test_users.py
@pytest.mark.parametrize("email", ["x@y.z", "q@w.e"])
def test_user_email(make_user, email):
    assert make_user(email=email).email == email
```

Key concepts:

- **Scopes**: `function` (default), `class`, `module`, `package`, `session`. Use wider scopes for expensive setup, but beware of state leaking between tests.
- **`yield` fixtures**: code after `yield` is teardown and runs even if the test fails.
- **`conftest.py`**: shared fixtures, discovered automatically without imports.
- **Built-ins**: `tmp_path`, `monkeypatch`, `capsys`, `caplog`.
- `autouse=True` applies a fixture without requesting it. Use it sparingly, since it's invisible.
- Async fixtures and tests need a plugin such as `pytest-asyncio` or `anyio`.
