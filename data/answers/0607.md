## Hints

- Why does `{ "FirstName": "Ann" }` bind to a `FirstName` property while the response comes back as `firstName`?
- What does a client see for an enum property by default, and why is that fragile?
- What happens when you return an `Order` whose `Customer` has a list of `Orders`?

## Answer

**The defaults in ASP.NET Core.** Minimal APIs, MVC and `HttpClient.GetFromJsonAsync` use **System.Text.Json** (STJ) with `JsonSerializerDefaults.Web`: property names are written in **camelCase**, matching on input is **case-insensitive**, and numbers may be read from strings. A bare `JsonSerializer.Serialize(x)` outside ASP.NET Core uses neither (names as written, case-sensitive), which is why the same model behaves differently in a console tool.

```csharp
public sealed record OrderDto(
    int Id,
    [property: JsonPropertyName("customer_ref")] string CustomerRef,      // rename one property
    decimal Total,
    [property: JsonIgnore] string InternalNote,                           // never written, never bound
    [property: JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)] string? Coupon);

builder.Services.ConfigureHttpJsonOptions(o =>             // MVC: AddControllers().AddJsonOptions(...)
{
    o.SerializerOptions.Converters.Add(new JsonStringEnumConverter());
    o.SerializerOptions.DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull;
});
```

**What STJ reads and writes**

- Public properties with a public getter are written. To read, it needs a setter or `init`, a constructor whose parameters match the properties (records), or `[JsonConstructor]`. Private setters and fields need `[JsonInclude]`.
- A missing property gives `default` silently, even with nullable reference types on. `required` members (C# 11) or `[JsonRequired]` turn that into a `JsonException`; `RespectNullableAnnotations` (.NET 9, off by default) rejects `null` for non-nullable properties.
- `DateTime` and `DateTimeOffset` are ISO 8601 (#609); `decimal` is a JSON number, so JavaScript clients lose precision above 2^53 (some money APIs send strings for that reason).
- `JsonSerializerOptions` caches type metadata and is expensive to build: create one, keep it in a `static readonly` field and reuse it. `new JsonSerializerOptions()` per call is a classic performance bug.

**Enums as strings.** By default an enum is its number: `"status": 2`. That's unreadable, breaks if you reorder members (#614) and tells the client nothing. Register `JsonStringEnumConverter` globally (above) or per enum with `[JsonConverter(typeof(JsonStringEnumConverter<OrderStatus>))]`; .NET 9 adds `[JsonStringEnumMemberName("in_progress")]` for custom names.

**Custom converters** for types that need a different JSON shape than their C# shape: a `Money` value object as `"12.50 EUR"`, a legacy date format, a type with a private constructor.

```csharp
public sealed class MoneyConverter : JsonConverter<Money>
{
    public override Money Read(ref Utf8JsonReader reader, Type type, JsonSerializerOptions options) =>
        Money.Parse(reader.GetString()!);
    public override void Write(Utf8JsonWriter writer, Money value, JsonSerializerOptions options) =>
        writer.WriteStringValue(value.ToString());
}
// options.Converters.Add(new MoneyConverter()), or [JsonConverter(typeof(MoneyConverter))] on Money
```

**Polymorphism (.NET 7+).** A property typed as a base class serializes only the base members and can't be read back as the right subtype. Declare the hierarchy and a discriminator:

```csharp
[JsonPolymorphic(TypeDiscriminatorPropertyName = "type")]
[JsonDerivedType(typeof(CardPayment), "card")]
[JsonDerivedType(typeof(BankTransfer), "transfer")]
public abstract record Payment(decimal Amount);
public sealed record CardPayment(decimal Amount, string Last4) : Payment(Amount);
public sealed record BankTransfer(decimal Amount, string Iban) : Payment(Amount);

// {"type":"card","amount":10,"last4":"4242"} round-trips as a CardPayment
```

The discriminator must be the first property in the JSON unless you set `AllowOutOfOrderMetadataProperties` (.NET 9).

**Object cycles when you return entities.** `order.Customer.Orders[0].Customer...` never ends, and STJ throws `JsonException: A possible object cycle was detected`. `ReferenceHandler.IgnoreCycles` writes `null` at the cycle and `ReferenceHandler.Preserve` emits `$id`/`$ref` metadata, but both are patches for the real problem: the API is exposing the data model. Return **DTOs** projected with `Select` (#585); that also stops leaking columns (#599) and loads only what the response needs.

**STJ vs Newtonsoft.Json**

| | System.Text.Json | Newtonsoft.Json |
|---|---|---|
| Speed | faster, UTF-8 and `Span` based, source generation for AOT (#601) | reflection based |
| Strictness | strict: comments, trailing commas, single quotes and `NaN` are errors unless enabled | lenient by default |
| Private setters and fields | need `[JsonInclude]` | used with `[JsonProperty]` |
| Dynamic JSON | `JsonDocument`/`JsonElement` (read-only, pooled), `JsonNode` (mutable DOM) | `JObject`, `dynamic` |
| Customization | converters, `JsonTypeInfo` contract customization | contract resolvers, many more knobs |
| In ASP.NET Core | default | `AddNewtonsoftJson()` switches MVC |

Use STJ for new code. Keep Newtonsoft where an app depends on its leniency or exposes `JObject` in its own API.

**Follow-up:** `JsonSerializer.Deserialize<OrderDto>("{}")` succeeds. Is that a bug? (By default a missing property just leaves its default value: `0`, `null`, `false`. Mark members that must be present as `required` or `[JsonRequired]`, and validate the rest at the edge (#587).)
