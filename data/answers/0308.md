## Hints

- How would you rewrite a `for` loop that appends to a list as a single expression?
- What is the difference in memory between `[x*x for x in data]` and `(x*x for x in data)`?
- When does a comprehension hurt readability?

## Answer

Comprehensions build a collection from an iterable in one expression, with an optional filter:

```python
nums = range(10)

squares = [n * n for n in nums if n % 2 == 0]   # list
unique  = {w.lower() for w in words}             # set
by_id   = {u.id: u for u in users}               # dict
pairs   = [(x, y) for x in "ab" for y in (1, 2)] # nested loops, left to right

total = sum(n * n for n in nums)                 # generator expression
```

**Generator expressions** use parentheses and are **lazy**: they produce items one at a time and never build the full collection. A list comprehension materializes everything immediately.

| | List comprehension | Generator expression |
|---|---|---|
| Memory | whole list | one item at a time |
| Reusable | yes, iterate many times | single pass, then exhausted |
| Indexing / `len()` | yes | no |
| Best for | results you reuse or index | feeding `sum`, `any`, `max`, `"".join`, or huge or infinite streams |

Notes:

- Comprehensions are usually faster than an equivalent loop with `.append`. Python 3.12 inlined them (PEP 709), making them faster still.
- The loop variable doesn't leak into the enclosing scope in Python 3.
- `any(x > 10 for x in data)` short-circuits. `any([x > 10 for x in data])` builds the whole list first.
- Readability limit: with more than two `for`s, or complex conditions, use a plain loop or a helper function. Don't use a comprehension just for side effects (`[print(x) for x in xs]`).

**Follow-up:** Why does the second `sum(gen)` on the same generator return 0? (It's already exhausted.)
