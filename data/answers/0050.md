## Hints

- If two rules target the same element with different colors, how does the browser decide which wins?
- How many class selectors does it take to beat one ID selector?
- What tools do modern CSS give you to control priority other than writing longer selectors?

## Answer

When rules conflict, the cascade considers, in order: **origin and `!important`**, **cascade layers**, **specificity**, and finally **source order** (later wins). Inline `style` attributes beat any selector.

**Specificity** is a three-part score **(IDs, classes, elements)**, compared left to right:

| Selector | Score |
|---|---|
| `p` | 0-0-1 |
| `.card p` | 0-1-1 |
| `.card .title:hover` | 0-3-0 (pseudo-classes and attribute selectors count as classes) |
| `#nav a` | 1-0-1 |

One ID beats any number of classes. The universal selector `*` and combinators add nothing. `:is()` and `:not()` take the specificity of their most specific argument; **`:where()` always has zero specificity**.

**Avoiding specificity wars:**

- Style mostly with **single classes**, avoid IDs and deep nesting (BEM, CSS Modules or utility classes like Tailwind keep it flat).
- Don't fight with `!important` — it escalates the problem.
- Use **`@layer`** to set priority explicitly: unlayered styles beat layered ones, and later layers beat earlier ones regardless of specificity.
- Use `:where()` in libraries and resets so they're easy to override.

```css
@layer reset, base, components, utilities;

@layer components {
  .btn { background: var(--brand); }
}
@layer utilities {
  .bg-red { background: red; } /* wins even against more specific component rules */
}
```

**Follow-up:** `!important` inverts layer order — an important declaration in an earlier layer beats one in a later layer.
