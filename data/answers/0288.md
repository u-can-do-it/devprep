## Hints

- Which of these fetches a file, and which only warms up the connection?
- Is the resource needed for the current page or for the next navigation?
- What happens if you preload something the page never uses, or preload a font without `crossorigin`?

## Answer

Resource hints tell the browser about work it would otherwise discover late.

| Hint | What it does | Priority | Use for |
|---|---|---|---|
| `dns-prefetch` | DNS lookup only | Low cost | Many third-party origins; fallback for old browsers |
| `preconnect` | DNS + TCP + TLS handshake | Early | **2–4 critical** third-party origins: font CDN, image CDN, API |
| `preload` | **Fetches** a resource for the **current page** | High | Late-discovered critical resources: LCP image, fonts, CSS background hero |
| `modulepreload` | Fetches **and parses** an ES module (and can include its dependencies) | High | Critical JS module graph |
| `prefetch` | Fetches a resource for a **likely next navigation** into the HTTP cache | **Lowest**, when idle | Next route's JS or data |

```html
<link rel="preconnect" href="https://cdn.example.com" crossorigin>
<link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" href="/hero.avif" as="image" fetchpriority="high">
<link rel="modulepreload" href="/assets/app.js">
<link rel="prefetch" href="/assets/checkout.js">
```

**Rules and pitfalls:**

- **`as` is required** for preload. It sets the priority, the `Accept` header and the CSP checks. Without it the browser may download the file twice.
- **Fonts must be preloaded with `crossorigin`**, even from your own origin. Otherwise the preload doesn't match the real request and the font is fetched twice.
- Unused preloads waste bandwidth, and Chrome warns after a few seconds. **Preloading too much** reduces the priority of everything else.
- Too many `preconnect`s waste sockets and CPU. Unused connections close after about 10 seconds.

**Related tools:**

- **`fetchpriority="high|low"`** on `<img>`, `<link>`, `<script>` and `fetch()`. For example, raise the LCP image and lower carousel images.
- **Speculation Rules API** (Chromium) can **prefetch or fully prerender** likely next pages, making navigations near-instant:

```html
<script type="speculationrules">
{ "prerender": [{ "where": { "href_matches": "/products/*" }, "eagerness": "moderate" }] }
</script>
```

- **103 Early Hints** send preload and preconnect headers before the final response.
- Frameworks do much of this for you. Next.js `<Link>` prefetches routes in the viewport, and `next/font` preloads fonts.

**Follow-up:** check the effect in the DevTools Network panel's Priority column and the LCP breakdown. A hint that doesn't move a metric is just noise.
