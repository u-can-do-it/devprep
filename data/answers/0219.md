## Hints

- What does a component do to "suspend," and which data sources actually support it?
- If one slow widget is inside the same boundary as the whole page, what does the user see?
- When a transition causes a component to suspend again, does React show the fallback or keep the old UI?

## Answer

`<Suspense fallback={...}>` shows a fallback while **any component inside it is waiting**. A component waits by suspending, which in practice means reading a promise that isn't resolved yet. When the data arrives, React retries and reveals the content.

**What triggers Suspense:**

- `lazy()` components
- `use(promise)` in React 19
- `async` Server Components
- Suspense-enabled libraries, such as TanStack Query's `useSuspenseQuery` and framework loaders

Fetching in `useEffect` does **not** suspend.

```jsx
<Suspense fallback={<PageSkeleton />}>
  <Header />
  <Suspense fallback={<ChartSkeleton />}>
    <RevenueChart />          {/* slow */}
  </Suspense>
  <Suspense fallback={<FeedSkeleton />}>
    <ActivityFeed />
  </Suspense>
</Suspense>
```

**Streaming SSR:** with `renderToPipeableStream` or `renderToReadableStream`, the server sends the **shell** (everything outside pending boundaries) right away, with fallbacks in place. As each boundary's data resolves, it streams the HTML plus a small inline script that swaps it in. The client then hydrates **selectively**, boundary by boundary, and handles the region the user interacts with first. Users see content sooner, and slow data no longer blocks time to first byte.

**Placing boundaries:**

- Wrap **independent, slow regions** so they load in parallel and don't block the rest.
- Avoid too many tiny spinners. Group content that should appear together, and design skeletons that reserve space to prevent layout shift.
- Pair boundaries with **error boundaries** at the same level.
- Start fetches early (parent, loader or server) to avoid **waterfalls** where a child only starts fetching after its parent resolves.

**Transitions:** if an update is wrapped in `startTransition`, React **keeps showing the already-revealed UI** instead of replacing it with a fallback. That's how navigation avoids flashing skeletons.
