## Hints

- What do the `g`, `i`, `m`, `s`, `u`/`v`, `y` and `d` flags change?
- How do you name a capture group and use it in a replacement?
- Why can a short regex take seconds on a 30-character input?

## Answer

**Flags:** `g` (global, find all matches), `i` (case-insensitive), `m` (`^`/`$` match at each line), `s` (`.` also matches newlines), `u` (Unicode code points), `v` (an improved Unicode mode with set operations), `y` (sticky: match only at `lastIndex`), `d` (return match indices).

**Groups and lookarounds:**

```js
const re = /(?<year>\d{4})-(?<month>\d{2})/;
'2026-10'.match(re).groups.year;               // '2026'
'2026-10'.replace(re, '$<month>/$<year>');     // '10/2026'
/(?:https?):\/\//;                             // non-capturing group
/\d+(?=px)/;     // lookahead: digits followed by 'px'
/(?<=\$)\d+/;    // lookbehind: digits preceded by '$'
[...text.matchAll(/#(\w+)/g)].map((m) => m[1]); // every hashtag
```

**Gotcha:** a regex with `g` or `y` is stateful. Calling `re.test()` repeatedly continues from `lastIndex`, so it alternates between `true` and `false`.

**ReDoS (Regular expression Denial of Service):** JavaScript engines mostly use **backtracking** matchers. Nested or overlapping quantifiers can take exponential time on input that *almost* matches:

```js
/^(a+)+$/.test('a'.repeat(30) + '!'); // can hang
```

On a server, one such request blocks the event loop and stalls every user. That makes it a real DoS vector, and it has hit popular npm packages.

**Prevention:**

- Avoid nested quantifiers (`(a+)+`, `(.*)*`) and alternatives that overlap (`(a|aa)+`). Anchor your patterns.
- **Limit input length** before matching.
- Never build a regex from user input without escaping it (`RegExp.escape()` in modern engines).
- Use linear-time engines (RE2 bindings) for user-supplied patterns.
- Lint with `eslint-plugin-regexp` and test patterns with ReDoS checkers.
- Prefer a real parser (`URL`, a schema validator) over clever regexes.
