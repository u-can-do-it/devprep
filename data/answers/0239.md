## Hints

- Which package should these hooks be imported from in the App Router: `next/router` or `next/navigation`?
- Can a page that's prerendered at build time know what `?q=` a future visitor will type?
- How can a Server Component page read the query string without any hook?

## Answer

All three come from **`next/navigation`** (not `next/router`, which is Pages Router) and only work in **Client Components**:

- **`useRouter()`** – navigate in code: `push(href)`, `replace(href)`, `back()`, `forward()`, `prefetch(href)`, and `refresh()`. `refresh()` re-fetches the current route's Server Components without losing client state.
- **`usePathname()`** – the current path, e.g. `/blog/hello`. Handy for "active link" styling.
- **`useSearchParams()`** – a **read-only** `URLSearchParams` for the query string.
- Related: `useParams()` and `useSelectedLayoutSegment()`.

To update the query string, build a new string and navigate:

```tsx
'use client';
export function SortSelect() {
  const router = useRouter();
  const pathname = usePathname();
  const params = useSearchParams();

  function onChange(sort: string) {
    const next = new URLSearchParams(params.toString());
    next.set('sort', sort);
    router.replace(`${pathname}?${next}`, { scroll: false });
  }
  // ...
}
```

**Why `useSearchParams` needs `<Suspense>`:** if the route is **prerendered**, the query string doesn't exist at build time. Next.js therefore renders the Client Component tree up to the nearest Suspense boundary **only in the browser**. Without a boundary, that would de-optimize the whole page, so the production build fails with "Missing Suspense boundary with useSearchParams". In dev, everything renders on demand, so the problem only appears at build time.

```tsx
<Suspense fallback={<SortSelectSkeleton />}>
  <SortSelect />
</Suspense>
```

**Alternatives:**

- In a Server Component page, read the **`searchParams` prop** (a Promise) and pass values down. Layouts don't receive it.
- If the route is dynamic anyway (it reads cookies, or calls `await connection()`), the hook gets real values during server rendering.

**Follow-up:** for complex URL state (filters, pagination), libraries like `nuqs` give typed, parsed search params on top of these hooks.
