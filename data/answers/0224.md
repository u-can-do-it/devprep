## Hints

- If every WebSocket message calls `setState` at the top of the tree, how many components re-render per second?
- Does the screen need to update more often than the display refreshes?
- Which work could leave the main thread, or leave React entirely?

## Answer

The goal is to **decouple the update rate of the data from the render rate of the UI**, and to make each render touch as little as possible.

**1. Ingest outside React.** Keep the socket in a module or store, not in component state. Parse messages, which can be large JSON or binary, in a **Web Worker** if it's expensive.

**2. Buffer and batch.** Apply incoming messages to a mutable buffer, then flush to the store **once per animation frame**, or every 100–250 ms for numbers people read. A thousand updates become about 60 store changes per second, or fewer:

```ts
let pending = new Map<string, Tick>();
socket.onmessage = e => { const t = decode(e.data); pending.set(t.symbol, t); };
function flush() {
  if (pending.size) { store.applyBatch(pending); pending = new Map(); }
  requestAnimationFrame(flush);
}
requestAnimationFrame(flush);
```

**3. Fine-grained subscriptions.** Normalize state by ID and subscribe per cell or row with selectors (Zustand, Jotai atoms, `useSyncExternalStore`), so a price change re-renders only that cell. Don't push live data through Context, and don't keep it in one large array that changes reference on every update.

**4. Prioritize.** Input, filters and navigation stay urgent. Heavy derived views (sorting 10k rows, aggregations) go through `useDeferredValue`/`startTransition` or are precomputed in the worker.

**5. Render less DOM.** Virtualize tables. Draw high-frequency charts with **Canvas or WebGL** (uPlot, ECharts, deck.gl) and feed them imperatively through a ref instead of re-rendering SVG with React. For extreme cases, a ticker cell can update `textContent` directly through a ref.

**6. Resilience and measurement:**

- Backpressure: drop intermediate values (keep only the latest per key) and throttle offscreen or hidden tabs.
- Reconnect with resync.
- Profile with the React Profiler and Performance panel, and track INP and long tasks in production.

**Follow-up:** ask about the product requirement. Humans can't read 500 updates a second. Often the right answer is to aggregate on the server and send fewer, coarser updates.
