## Hints

- Where does the TypeScript type of a query result come from if nobody writes it by hand?
- What happens in CI if a backend change removes a field the frontend still queries?
- Why might you prefer types inferred at compile time over a separate generation step?

## Answer

Because a GraphQL schema is strongly typed, tools can produce **exact TypeScript types for each operation** – only the fields you selected, with correct nullability. This removes hand-written API types and catches schema mismatches at build time.

**GraphQL Code Generator (client preset):**

```ts
// codegen.ts
import type { CodegenConfig } from "@graphql-codegen/cli";
const config: CodegenConfig = {
  schema: "https://api.example.com/graphql",
  documents: ["src/**/*.tsx"],
  generates: { "src/gql/": { preset: "client" } },
};
export default config;
```

```tsx
import { graphql } from "@/gql";
import { useQuery } from "@apollo/client";

const ProductQuery = graphql(`
  query Product($id: ID!) { product(id: $id) { id name price } }
`);

const { data } = useQuery(ProductQuery, { variables: { id } });
// data?.product?.price is typed as number; variables are type-checked
```

The `graphql()` function returns a **`TypedDocumentNode`** that carries result and variable types; Apollo Client, urql and TanStack Query wrappers infer from it. The preset also supports **fragment masking** and can emit **persisted query** manifests.

**Alternatives:**

- **gql.tada** – infers types directly from the schema with TypeScript's type system, with no codegen watch step.
- **Relay compiler** – generates types and optimized artifacts, enforces fragment colocation.
- Server side: resolver type generation for schema-first servers.

**Workflow tips:**

- Run codegen in CI and **validate operations against the schema**; combine with schema registry checks so a backend can't remove a field that clients still use.
- Commit the schema snapshot or fetch it from a registry, so builds are reproducible.
- Custom scalars (`DateTime`, `Decimal`) need explicit type mappings, or they become `any`/`unknown`.
