## Hints

- What actually gets copied when you assign an object to a new variable?
- Does the spread operator copy nested objects?
- Which built-in deep-copies data, and what can't it copy?

## Answer

**Primitives** (string, number, boolean, null, undefined, bigint, symbol) are copied **by value**. **Objects**, including arrays and functions, are accessed through a **reference**. Assigning an object copies the reference, so both variables point to the same object.

```js
let a = 1; let b = a; b++;        // a is still 1
const o1 = { n: 1 }; const o2 = o1;
o2.n = 2;                          // o1.n is 2 as well
```

Strictly speaking, JS always passes **by value**. For objects, the value being passed is the reference. That's why reassigning a parameter inside a function doesn't affect the caller, but mutating it does.

**Shallow copy** copies only the top level. Nested objects are still shared:

```js
const user = { name: 'Ann', address: { city: 'Oslo' } };
const copy = { ...user };            // or Object.assign({}, user)
copy.address.city = 'Rome';          // also changes user.address.city
const arr2 = [...arr];               // or arr.slice(), Array.from(arr)
```

**Deep copy** options:

- **`structuredClone(obj)`** is built-in (browsers and Node 17+). It handles nested objects, `Date`, `Map`, `Set`, typed arrays and circular references. It **throws** on functions and DOM nodes, and it doesn't keep class prototypes or getters.
- `JSON.parse(JSON.stringify(obj))` is the old trick. It drops `undefined` and functions, turns `Date` into strings, fails on `Map`/`Set`, and throws on circular references.
- A library helper such as lodash's `cloneDeep`, or a custom recursive function.

**Follow-up:** React and Redux rely on **immutable updates**: create new objects (`{ ...state, x }`) so reference equality can detect changes.
