## Hints

- During a network partition, what two choices does a node have when it receives a write?
- Is "C" in CAP the same as "C" in ACID?
- What does a system trade off when there is no partition — and which theorem captures that?

## Answer

**CAP theorem:** in a distributed data store, when a **network Partition** happens you must choose between:

- **Consistency (linearizability):** every read sees the latest write, or the request fails.
- **Availability:** every non-failed node returns a response, possibly stale.

Partitions are unavoidable in real networks, so the practical choice is **CP vs AP during a partition**. CP systems (etcd, ZooKeeper, Spanner, typical leader-based SQL setups) refuse or block some requests; AP systems (Cassandra, DynamoDB in default mode, DNS) keep serving and reconcile later. CAP's "C" is *not* ACID's "C" (constraint validity).

**PACELC** extends it: if Partition → A or C; **E**lse → **L**atency or **C**onsistency. Even without failures, strong consistency costs latency (cross-replica coordination).

**Consistency models (strongest → weakest):**

- **Linearizable / strong:** behaves like a single copy; operations appear instantaneous in real-time order.
- **Sequential:** all nodes see operations in the same order, but not necessarily real-time order.
- **Causal:** causally related operations (a reply after a post) are seen in order by everyone; concurrent ones may differ.
- **Session guarantees:** read-your-writes, monotonic reads, monotonic writes — what users typically notice.
- **Eventual:** replicas converge if writes stop; reads may be stale meanwhile.

**Tunable consistency:** with N replicas, write quorum W and read quorum R, `R + W > N` makes reads overlap the latest write (e.g. N=3, W=2, R=2). Cassandra and DynamoDB expose this per request.

**Conflict handling in AP systems:** last-write-wins (risks lost updates), version vectors, or CRDTs.

**Interview angle:** pick per use case — bank balances and inventory reservations need strong consistency; likes counters, feeds, and analytics are fine with eventual consistency.
