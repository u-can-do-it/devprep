## Hints

- Which one answers "who are you?" and which answers "what are you allowed to do?"
- Which one has to happen first?
- Which HTTP status codes map to failures of each?

## Answer

- **Authentication (AuthN)** – verifying **identity**: is this user really who they claim to be? Passwords, passkeys/WebAuthn, MFA, SSO via OIDC, API keys, client certificates.
- **Authorization (AuthZ)** – deciding **permissions**: is this authenticated identity allowed to perform this action on this resource?

Authentication comes first; authorization uses its result.

**HTTP mapping:**

- `401 Unauthorized` – authentication missing or failed (misleading name: means *unauthenticated*).
- `403 Forbidden` – authenticated, but not permitted.

**Authorization models:**

- **RBAC** – permissions via roles (`admin`, `editor`).
- **ABAC / policy-based** – rules on attributes (owner, department, time).
- **ReBAC** – based on relationships (Google Zanzibar style: "user is member of team that owns doc").

```python
@app.delete("/posts/{post_id}")
def delete_post(post_id: int, user: User = Depends(current_user)):   # authN
    post = get_post(post_id)
    if post.author_id != user.id and "admin" not in user.roles:     # authZ
        raise HTTPException(status_code=403)
    ...
```

**Pitfall:** checking only authentication ("logged in") and forgetting per-object authorization leads to **IDOR / broken access control** – e.g. `GET /invoices/124` returns someone else's invoice. Broken access control is #1 on the OWASP Top 10.

Also: hiding a button in the UI is not authorization – always enforce on the server.
