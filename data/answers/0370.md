## Hints

- Can you trust the file name, extension or `Content-Type` the client sends?
- What happens if an uploaded file is served from your main domain and contains HTML?
- How would you keep a 5 GB upload from taking down your API server?

## Answer

> Every uploaded file could be an attack, so treat it as hostile. Limit file size, and check the real type from the file's content, not its name or `Content-Type`. Store it under a random name in private object storage, never using the client's file name as a path. Serve user files from a separate domain with `nosniff` and `Content-Disposition: attachment`, because an HTML or SVG file on your main domain is stored XSS. Process files in a sandbox, and check permissions on every download.

Treat every uploaded file as hostile. Defenses, roughly in order:

1. **Limit size and count** at the proxy and the app (`client_max_body_size`, framework limits) to prevent DoS.
2. **Allow-list types** by checking the **magic bytes**/content, not only the extension or client-supplied `Content-Type`. Reject everything else.
3. **Never use the client's file name for storage.** Generate a random ID; store the original name only as metadata. This prevents path traversal (`../../app.py`) and overwrites.
4. **Store outside the web root**, ideally in object storage (S3/GCS) with a private bucket. Let clients upload directly using short-lived **presigned URLs** with size/type conditions, so big files never pass through your API.
5. **Serve safely:** from a separate, cookieless domain (e.g. `usercontent.example.net`) with `X-Content-Type-Options: nosniff`, the right `Content-Type`, and `Content-Disposition: attachment` for anything not meant to render. An SVG or HTML file served from your main origin is stored XSS.
6. **Process carefully:** re-encode images (which also strips EXIF/GPS metadata), scan with antivirus for document workflows, and run parsers (ImageMagick, PDF, archive extraction) in sandboxed workers with resource limits. Watch for zip bombs and zip-slip paths.
7. **Authorize access** to files like any other resource. An unguessable URL is not access control.

```python
ALLOWED = {"image/png", "image/jpeg", "image/webp"}

async def upload(file: UploadFile, user=Depends(current_user)):
    head = await file.read(2048)
    kind = magic.from_buffer(head, mime=True)  # python-magic
    if kind not in ALLOWED:
        raise HTTPException(415, "Unsupported file type")
    key = f"uploads/{user.id}/{uuid4()}"
    ...
```

**Follow-up:** How do you handle uploads that must be scanned before use? Store as "pending", scan asynchronously, and only then mark them available.
