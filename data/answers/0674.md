## Hints

- When you push a details screen on top of a list screen, is the list screen unmounted?
- What should you pass as a route param: the whole object or its id?
- How do you stop a logged-out user from reaching the home screen with the back button?

## Answer

> There is no URL bar or browser history. A navigation library keeps a tree of navigators and their state. With React Navigation you combine stack, tab and drawer navigators. The native stack uses the platform's own navigation views, so transitions and gestures feel right. Screens stay mounted while they are in the stack, so use focus events instead of mount and unmount. For auth, render different screens depending on the session instead of redirecting by hand.

**Navigators**

| Navigator | What it is | Typical use |
|---|---|---|
| Native stack | `UINavigationController` on iOS, fragments on Android | the default: push details, modals |
| JS stack | implemented in JS with Reanimated | fully custom transitions |
| Bottom tabs | tab bar | top-level sections |
| Drawer | side menu | many sections, settings |

They nest. A common shape is a root stack containing the tabs, with detail and modal screens above the tabs so that they cover the tab bar.

**Navigating and params**

```tsx
type RootStackParamList = {
  Tabs: undefined;
  Order: { orderId: string };
  SignIn: undefined;
};

navigation.navigate('Order', { orderId: order.id });

function OrderScreen({ route }: NativeStackScreenProps<RootStackParamList, 'Order'>) {
  const { data } = useOrder(route.params.orderId);
  // ...
}
```

Pass ids, not whole objects. Params should be small and serialisable, so that deep links (#684) and state restoration work, and the screen always shows fresh data from the cache or the API.

**Screen lifecycle**

- Pushing screen B on top of A does **not** unmount A. Going back to A does not remount it, so its `useEffect` doesn't run again.
- A tab screen mounts on first visit and then stays mounted.
- To react to a screen becoming visible, use `useFocusEffect` or `useIsFocused`:

```tsx
useFocusEffect(
  useCallback(() => {
    const sub = startLocationUpdates();
    return () => sub.remove();          // runs when the screen loses focus
  }, []),
);
```

- For data, let the query library refetch stale data on focus (#682).

**Auth flow**

```tsx
function RootNavigator() {
  const { status } = useSession();      // 'loading' | 'signedIn' | 'signedOut'
  if (status === 'loading') return <SplashScreen />;

  return (
    <Stack.Navigator>
      {status === 'signedIn' ? (
        <>
          <Stack.Screen name="Tabs" component={Tabs} options={{ headerShown: false }} />
          <Stack.Screen name="Order" component={OrderScreen} />
        </>
      ) : (
        <Stack.Screen name="SignIn" component={SignInScreen} />
      )}
    </Stack.Navigator>
  );
}
```

When the session changes, the navigator removes the screens that no longer exist. The user can't go "back" into the app after logout, and you don't call `navigate` yourself.

**Other points**

- **Android back:** the navigator handles the system back button and gesture. Custom handling goes through `BackHandler` or the `beforeRemove` event (for "discard changes?").
- **Modals:** `presentation: 'modal'` on a stack screen gives the native sheet.
- **Headers:** configure with `options`. The native header gives large titles and search bars on iOS.
- **Type safety:** declare param lists, and register the root type globally so `useNavigation()` is typed.
- **Deep links:** a `linking` config maps URL paths to screens (#684).
- **Expo Router** builds on React Navigation and derives all of this from files (#675).

**Follow-up:** after a user edits an order on the details screen and goes back, the list shows old data. How do you fix it? (Invalidate the list query in the mutation's `onSuccess` (#530), or update the cache directly. Don't rely on the list remounting.)
