## Hints

- After `b = a.copy()`, if `a` contains lists, are the inner lists copied too?
- What does `grid = [[0] * 3] * 3` actually create?
- How does `deepcopy` cope with an object that references itself?

## Answer

- **Assignment** (`b = a`) copies nothing: both names point to the same object.
- A **shallow copy** creates a new outer container but **reuses the same inner objects**.
- A **deep copy** recursively copies the container **and everything inside it**.

```python
import copy

a = [[1, 2], [3, 4]]
shallow = a.copy()          # also list(a), a[:], copy.copy(a)
deep = copy.deepcopy(a)

a[0].append(99)
shallow[0]   # [1, 2, 99]: inner list is shared
deep[0]      # [1, 2]: fully independent

a.append([5])
shallow      # unaffected: the outer list is a different object
```

Classic bug:

```python
grid = [[0] * 3] * 3      # three references to ONE row
grid[0][0] = 1            # [[1,0,0],[1,0,0],[1,0,0]]
grid = [[0] * 3 for _ in range(3)]   # correct: three rows
```

Notes:

- `deepcopy` keeps a **memo** dictionary, so shared and circular references are copied correctly.
- Classes can customize copying with `__copy__` / `__deepcopy__`.
- Some objects can't or shouldn't be deep-copied: open files, sockets, locks, DB connections.
- Deep copies are slow for large structures. Often a better design is **immutable data** (tuples, frozen dataclasses) or building new values instead of mutating them. Python 3.13's `copy.replace()` creates a modified copy of a dataclass or namedtuple.
- Copying only matters for mutable contents. A shallow copy of a list of ints or strings is effectively independent.

**Follow-up:** Is `dict(d)` shallow or deep? (Shallow. Nested dicts are still shared.)
