## Hints

- If a list has 20,000 rows but only 30 fit on screen, how many need to exist in the DOM?
- What does the scrollbar need to know to stay correct when most rows aren't rendered?
- What does the browser's Ctrl+F do with rows that aren't in the DOM?

## Answer

**Virtualization** renders only the items in or near the viewport, plus a small **overscan** buffer, and fills the rest of the scroll height with spacers or absolute positioning. As the user scrolls, rows are swapped in and out. DOM size stays constant, whatever the data size, so initial render, memory, style recalculation and scroll performance all improve.

Use it when you have **hundreds to thousands of complex rows**: tables, feeds, chat logs, log viewers, large selects. Below roughly 100 simple rows it's usually not worth it.

```tsx
import { useVirtualizer } from '@tanstack/react-virtual';

function BigList({ rows }: { rows: Row[] }) {
  const parentRef = useRef<HTMLDivElement>(null);
  const v = useVirtualizer({
    count: rows.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 40,
    overscan: 8,
  });
  return (
    <div ref={parentRef} style={{ height: 600, overflow: 'auto' }}>
      <div style={{ height: v.getTotalSize(), position: 'relative' }}>
        {v.getVirtualItems().map(item => (
          <div key={item.key} style={{ position: 'absolute', top: 0, width: '100%',
               transform: `translateY(${item.start}px)` }}>
            <RowView row={rows[item.index]} />
          </div>
        ))}
      </div>
    </div>
  );
}
```

Libraries: TanStack Virtual (headless), react-window, react-virtuoso (dynamic heights, chat-style lists).

**Downsides:**

- **Dynamic heights** need measuring and can cause scroll jumps.
- **Find-in-page** and anchor links can't see unrendered rows.
- **Accessibility:** screen readers see only part of the list. Use `aria-rowcount`/`aria-rowindex` or `aria-setsize`/`aria-posinset`, and keep keyboard focus stable while rows unmount.
- More complex scroll restoration, sticky headers and SSR.

**Alternatives:** pagination or "load more", or CSS `content-visibility: auto`, which skips rendering offscreen content while keeping it in the DOM.
