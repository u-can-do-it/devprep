## Hints

- How would you avoid recomputing an expensive pure function for the same arguments?
- What breaks if an argument is a list, or if the cached function is a method?
- When you write a decorator, why does the wrapped function lose its name and docstring?

## Answer

**`lru_cache` / `cache`: memoization.**

```python
from functools import cache, lru_cache

@cache                         # unbounded (3.9+)
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

@lru_cache(maxsize=1024)       # keeps the 1024 most recently used results
def get_country(code: str) -> Country: ...

get_country.cache_info()       # hits, misses, size
get_country.cache_clear()
```

Pitfalls:

- Arguments must be **hashable**, so a list argument raises `TypeError`.
- Only cache **pure** functions. Results never expire, so it's wrong for data that changes (DB rows, config). Use a TTL cache or Redis for those.
- `@cache` on **methods** includes `self` in the key and keeps every instance alive, which is a **memory leak**. Use `cached_property` for per-instance values, or a module-level function.
- The cache is per process. Workers don't share it.
- Mutable return values are shared. A caller that mutates the result corrupts the cache.

**`partial`: pre-fill arguments.**

```python
from functools import partial
parse_hex = partial(int, base=16)
parse_hex("ff")                # 255
callbacks = [partial(handle, i) for i in range(3)]   # avoids late binding
```

**`wraps`: write correct decorators.**

```python
from functools import wraps

def retry(fn):
    @wraps(fn)                 # copies __name__, __doc__, __wrapped__, etc.
    def wrapper(*args, **kwargs):
        ...
        return fn(*args, **kwargs)
    return wrapper
```

Without `@wraps`, logs, tracebacks, documentation tools and frameworks like FastAPI (which inspects signatures) see `wrapper` instead of the real function.

Also worth knowing: `singledispatch` (overloading by argument type), `reduce` and `cached_property`.

**Follow-up:** How do you cache an `async` function? (`lru_cache` would cache the coroutine object, which can only be awaited once. Use a library such as `async-lru`, or cache the awaited result manually.)
