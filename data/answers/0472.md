## Hints

- Why is `"You have " + n + " messages"` impossible to translate correctly?
- How many plural forms does Polish have, compared to English?
- Should a French user download your Japanese translations?

## Answer

**Internationalisation (i18n)** prepares the app for any language and region. **Localisation (l10n)** is adding a specific one.

**1. Externalise strings into message catalogs** with keys or source-text ids, using a library: **react-intl (FormatJS)**, **i18next/react-i18next**, **Lingui**, or `next-intl` for Next.js.

```tsx
const t = useTranslations('inbox');
<p>{t('unread', { count })}</p>
```

**2. Use ICU MessageFormat for plurals, gender and selects.** Never build sentences by concatenation: word order and grammar differ between languages.

```
unread = {count, plural,
  =0   {No new messages}
  one  {# new message}
  other {# new messages}}

# Polish needs more categories: 1 plik, 2 pliki, 5 plików, 22 pliki, 1,5 pliku
files = {count, plural, one {# plik} few {# pliki} many {# plików} other {# pliku}}
```

The categories come from CLDR, which `Intl.PluralRules` exposes: English has `one`/`other`, Polish `one`/`few`/`many`/`other`, Arabic six.

**3. Format with the built-in `Intl` API**, never by hand:

```ts
new Intl.NumberFormat('pl-PL', { style: 'currency', currency: 'PLN' }).format(1234.5); // "1234,50 zł"
new Intl.DateTimeFormat('en-GB', { dateStyle: 'long', timeZone: 'Europe/Warsaw' }).format(date);
new Intl.RelativeTimeFormat('de', { numeric: 'auto' }).format(-1, 'day');               // "gestern"
new Intl.ListFormat('en', { type: 'conjunction' }).format(['React', 'Vue', 'Angular']);
```

Also `Intl.Collator` for locale-aware sorting and `Intl.DisplayNames` for country and language names.

**4. Load only the active locale:** split catalogs per language (and per route for big apps) and load them with `import()`. On the server, render with the user's locale to avoid hydration mismatches.

**5. Layout and markup**

- Set `<html lang>` and `dir="rtl"` for Arabic and Hebrew; use logical CSS properties (`margin-inline-start`, `padding-block`).
- Leave room for text expansion (German is often 30% longer than English) and test with **pseudo-localisation** (`[!!! Ŝéţţîñĝš !!!]`) to find hard-coded strings and overflow.
- Don't put text in images; translate `alt`, `aria-label` and page titles too.

**6. Process:** extract keys automatically, sync with a translation platform (Crowdin, Lokalise, Phrase), fail CI on missing keys, and give translators context (screenshots, descriptions, character limits).

**Follow-up:** where do you store the user's chosen locale (URL, cookie, profile), and how does that affect caching and SEO?
