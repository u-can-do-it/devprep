## Hints

- What does the assistant know about your codebase's conventions unless you tell it?
- How do you know AI-generated code is correct, beyond "it compiles"?
- What must never be pasted into, or generated by, an AI tool without checking?

## Answer

Interviewers now expect you to use AI tools **and** to stay accountable for the result. Show a concrete workflow, not "I use Copilot sometimes".

**How to use them effectively:**

- **Give context:** project instruction files (`CLAUDE.md`, `AGENTS.md`, Cursor rules) with conventions, commands and architecture; point the tool at the relevant files and existing examples ("follow the pattern in `features/orders/api`").
- **Plan before code** for anything non-trivial: ask for a plan, review it, then implement in small steps. Break work into tasks with clear acceptance criteria. Agents do well on well-specified, verifiable tasks.
- **Make the result verifiable:** write or ask for tests first, then let the agent iterate until tests, type checks and lint pass. Agents with tool access (Claude Code, Cursor agent, Copilot agent) can run the commands themselves.
- **Good uses:** boilerplate and scaffolding, tests for existing code, refactors across many files, explaining unfamiliar code, writing scripts and migrations, debugging with logs, first drafts of docs.
- **Extend the tools** where it pays off: MCP servers for internal systems (issue tracker, database schema, docs), reusable skills or prompts for repeated workflows, hooks that run formatters and tests automatically.
- Run several agents on independent tasks in parallel (separate branches or worktrees) when the work splits cleanly.

**How to review AI-generated code:** treat it like a pull request from a fast, confident junior who hasn't read the whole codebase.

- **Read every line of the diff.** You own it; "the AI wrote it" isn't an excuse in an incident review.
- Check **edge cases and error handling** (empty, null, concurrency, timeouts), not just the happy path.
- **Security:** injection, missing authorization checks, secrets in code, unsafe `dangerouslySetInnerHTML`, overly broad permissions.
- **Hallucinations:** APIs or options that don't exist, wrong library versions, and invented package names (attackers register them: "slopsquatting"). Verify new dependencies.
- **Fit:** does it duplicate an existing utility, ignore conventions, or add unnecessary abstraction? Do the tests actually test behaviour, or just mirror the implementation?

**Rules and risks:** follow company policy on which tools may see which code and data; never paste secrets, customer data or credentials; check licensing for large generated snippets; and watch for skills atrophying, so stay able to write and debug the code yourself.

**Follow-up:** describe a time an AI tool produced plausible but wrong code. How did you catch it, and what did you change in your workflow?
