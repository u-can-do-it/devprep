## Hints

- Which file makes a folder publicly reachable as a URL?
- Which of these files stays mounted when you navigate between sibling pages?
- Which ones are React Suspense or Error Boundaries under the hood?

## Answer

In the App Router, **folders define URL segments** and a few **special files** inside a folder define the UI for that segment:

- **`page.tsx`** – the UI for the route. A folder is only routable if it has a `page` (or a `route.ts`).
- **`layout.tsx`** – UI shared by a segment and its children. It receives `children`, **persists across navigation** (state is kept, it doesn't re-render) and can nest. The root `app/layout.tsx` is required and must render `<html>` and `<body>`.
- **`loading.tsx`** – an instant loading state. Next.js wraps the page in `<Suspense fallback={<Loading />}>`, so it shows while the segment's data streams in.
- **`error.tsx`** – a **Client Component** used as a React Error Boundary for the segment. It gets the `error` and a `retry()` function.
- **`not-found.tsx`** – rendered when you call `notFound()` in that segment (and at the root, for unmatched URLs).

Rendering order inside one segment:

```tsx
<Layout>
  <Template>
    <ErrorBoundary fallback={<Error />}>
      <Suspense fallback={<Loading />}>
        <NotFoundBoundary fallback={<NotFound />}>
          <Page />
        </NotFoundBoundary>
      </Suspense>
    </ErrorBoundary>
  </Template>
</Layout>
```

Other conventions: `template.tsx` (like a layout but re-mounts on every navigation), `route.ts` (API endpoint), `default.tsx` (fallback for parallel routes) and `global-error.tsx` (errors in the root layout).

Any other file in the folder (components, utils, tests) is **not** routable, so you can colocate code safely.

**Follow-up:** `error.tsx` does not catch errors thrown by the `layout.tsx` in the *same* folder, because the boundary sits inside that layout. The parent segment's `error.tsx` catches them.
