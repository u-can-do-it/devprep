## Hints

- What does an object need to have for `for...of` or spread to work with it?
- What happens to a generator function's local state between two `next()` calls?
- How could you represent an infinite sequence without building an infinite array?

## Answer

**Iteration protocols**

- An **iterator** is an object with a `next()` method. `next()` returns `{ value, done }`.
- An **iterable** is an object with a `[Symbol.iterator]()` method that returns an iterator. Arrays, strings, `Map`, `Set` and `NodeList` are all iterable. `for...of`, spread, destructuring, `Array.from` and `Promise.all` all work with any iterable.

**Generators** (`function*`) are the easiest way to write iterators. Calling one returns a generator object without running the body. Each `next()` runs the body until the next `yield`, then **pauses** while keeping its local state.

```js
function* range(start, end, step = 1) {
  for (let i = start; i < end; i += step) yield i;
}
[...range(0, 5)]; // [0, 1, 2, 3, 4]

function* ids() { let id = 0; while (true) yield ++id; } // infinite but lazy
const gen = ids();
gen.next().value; // 1

class Tree {
  *[Symbol.iterator]() { yield this.value; for (const c of this.children) yield* c; }
}
```

**Use cases:**

- **Lazy or infinite sequences.** Values are computed only when requested, which saves memory for large data.
- **Custom iterable data structures** such as trees, graphs and paginated collections.
- **Two-way communication:** `gen.next(value)` sends a value back in, which is how coroutines and libraries like redux-saga work.
- **Async generators** (`async function*` with `for await...of`) are a good fit for streams, paginated APIs and Node readable streams.

```js
async function* pages(url) {
  while (url) { const r = await (await fetch(url)).json(); yield r.items; url = r.next; }
}
for await (const items of pages('/api/items')) render(items);
```

**Follow-up:** `return()` and `throw()` on a generator. Iterator helpers (`.map`, `.filter`, `.take` on iterators) are part of ES2025.
