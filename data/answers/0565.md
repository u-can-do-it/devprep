## Hints

- What does a property compile to, and why does a public field break encapsulation later?
- What's the difference between a value fixed at compile time and one fixed when the object or type is created?
- How do `init` and `required` help you build immutable objects without long constructors?

## Answer

**Fields vs properties:** a **field** is a variable stored in the object. A **property** looks like a field to callers but is a pair of **methods** (`get_Name`, `set_Name`). Properties let you add validation, lazy loading or change notifications later without changing the public API. Convention: fields `private`, expose data through properties.

```csharp
public class User
{
    private string _email = "";                 // field
    public string Email                         // property with a backing field
    {
        get => _email;
        set => _email = value.Contains('@') ? value : throw new ArgumentException("Invalid email");
    }

    public int Age { get; set; }                // auto-property: compiler generates the field
    public DateTime CreatedAt { get; private set; }   // read-only from outside
    public string FullName => $"{First} {Last}";       // computed, no storage
}
```

C# 14 adds the `field` keyword so you can add logic without declaring the backing field: `public string Name { get; set => field = value.Trim(); }`.

**`init` and `required`:**

- `init` accessor: the property can be set only in the constructor or an **object initializer**, then it's read-only.
- `required` (C# 11): the caller **must** set it in the initializer, or the code doesn't compile.

```csharp
public class Order
{
    public required Guid Id { get; init; }
    public required string Customer { get; init; }
    public decimal Total { get; init; }
}

var o = new Order { Id = Guid.NewGuid(), Customer = "Ann" };   // OK
o.Total = 5;                     // compile error: init-only
var bad = new Order { Total = 1 };   // compile error: Id and Customer are required
```

**`const`, `readonly`, `static readonly`:**

| | `const` | `readonly` | `static readonly` |
|---|---|---|---|
| Value fixed | at **compile time** | in the constructor | in the static constructor / initializer |
| Per | type (implicitly static) | **instance** | type |
| Allowed types | primitives, `string`, enums, `null` | any | any |
| Example | `const int MaxRetries = 3;` | `readonly ILogger _log;` | `static readonly TimeSpan Timeout = TimeSpan.FromSeconds(30);` |

The `const` trap: the value is **copied into every assembly that uses it**. If library A changes `public const int Version = 2` and app B isn't recompiled, B still sees the old value. Use `static readonly` for public values that might change.

`readonly` on a reference type field makes the **reference** read-only, not the object: a `readonly List<int>` can still be added to.

**Follow-up:** can a property be passed as a `ref` argument? (No, because it's a method call, not a storage location; copy it into a local first.)
