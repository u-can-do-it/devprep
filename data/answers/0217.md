## Hints

- How does a component subscribe to Context, and does `memo` look at it?
- If the Provider's `value` is a new object every render, what do all consumers see?
- Can Context subscribe to just one field of its value?

## Answer

> `React.memo` only compares props, so it can't stop a component from re-rendering when a Context it reads changes. Every consumer re-renders when the Provider's value changes, and Context has no way to subscribe to just one field. To limit that, memoize the value object, split contexts by how often they change, and keep Providers low in the tree. For state that changes often, use a store with selectors like Zustand, so components re-render only when their slice changes. Context suits rarely changing values like theme or locale.

**No.** `React.memo` only compares **props**. A component that calls `useContext(Ctx)` or `use(Ctx)` re-renders whenever the Provider's value changes (by `Object.is`), however deep it is and whether or not memoized parents sit in between. The React Compiler doesn't change this either.

Context also has **no selectors**. A consumer that only needs `user.name` re-renders when `user.cart` changes.

**Techniques, roughly in order:**

1. **Stabilize the value.** Don't create a new object on every Provider render:
   ```jsx
   const value = useMemo(() => ({ user, login, logout }), [user]);
   <AuthContext value={value}>{children}</AuthContext>
   ```
2. **Split contexts** by update frequency. Separate state from dispatch: `dispatch` never changes, so components that only dispatch never re-render.
   ```jsx
   <TodosDispatch value={dispatch}><TodosState value={todos}>…</TodosState></TodosDispatch>
   ```
3. **Keep Providers low.** Wrap only the subtree that needs the value, and pass the rest as `children` so it isn't re-created.
4. **Read Context in a small leaf component**, not in a large component that also renders heavy children.
5. **Use a store with selectors** for fast-changing shared state: Zustand, Jotai, Redux Toolkit, or your own `useSyncExternalStore` store. Put the *store instance* in Context, which never changes, and let components subscribe to slices:
   ```jsx
   const count = useStore(s => s.cart.count); // re-renders only when count changes
   ```

**Rule of thumb:** Context is great for low-frequency values (theme, locale, auth, feature flags, dependency injection). It's a poor transport for high-frequency state like mouse position, form keystrokes or live data.

**Follow-up:** `use-context-selector` and similar libraries add selectors to Context, but a real store is usually simpler.
