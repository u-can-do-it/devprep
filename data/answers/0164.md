## Hints

- If you call a function twice with the same arguments, does it always return the same result?
- Besides returning a value, what else could a function change or read in the outside world?
- Why does React expect components to be pure during rendering?

## Answer

A **pure function** has two properties:

1. **Deterministic:** the same inputs always give the same output.
2. **No side effects:** it doesn't change anything outside itself or depend on hidden state.

**Side effects** include: mutating arguments or globals, network or database calls, writing to the DOM or `localStorage`, logging, timers, and reading changing values such as `Date.now()` or `Math.random()`.

```js
// impure: mutates its input and depends on the clock
function addItem(cart, item) {
  cart.items.push({ ...item, addedAt: Date.now() });
  return cart;
}

// pure: returns a new value, and the time is passed in explicitly
function addItem(cart, item, now) {
  return { ...cart, items: [...cart.items, { ...item, addedAt: now }] };
}
```

**Why it matters:**

- **Testability:** pure functions need no mocks or setup. Inputs go in, you assert the output.
- **Predictability:** you can understand them in isolation (referential transparency), and they are safe to reuse.
- **Caching:** only pure functions can be memoized safely.
- **UI frameworks:** React assumes rendering is pure. It may render a component several times, pause or throw away renders, and StrictMode renders twice in development to catch impurities. The React Compiler's automatic memoization also relies on this. Side effects belong in event handlers, effects or Server Actions.
- **Concurrency and undo:** immutable updates make time-travel debugging and change detection by reference cheap.

You can't avoid side effects entirely, because programs exist to have them. The usual design is a **functional core with an imperative shell**: keep the business logic pure, and push I/O to the edges (route handlers, effects, command handlers).

**Follow-up:** "Is a function that uses a local mutable variable pure?" Yes, if the mutation can't be seen from outside. Purity is about observable behavior.
