## Hints

- How would you write "if `T` is a function, give me its return type, otherwise `never`" at the type level?
- What happens when a conditional type receives a union, and how do you stop that?
- How can a mapped type iterate over `keyof T`, rename keys, and recurse?

## Answer

**Conditional types** work like a type-level ternary: `T extends U ? X : Y`. Inside the `extends` clause, **`infer`** declares a type variable that the compiler fills in by pattern matching:

```ts
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type MyAwaited<T> = T extends PromiseLike<infer V> ? MyAwaited<V> : T; // recursive
type ElementOf<T> = T extends readonly (infer E)[] ? E : never;
type FirstArg<F> = F extends (first: infer A, ...rest: any[]) => any ? A : never;

type R = MyReturnType<() => Promise<number>>;  // Promise<number>
type A = MyAwaited<Promise<Promise<string>>>;  // string
```

**Distribution:** if the checked type is a bare type parameter and it receives a union, the conditional is applied to **each member separately**. That's how `Exclude<T, U> = T extends U ? never : T` works. To turn distribution off, wrap both sides in a tuple: `[T] extends [U] ? ...`. That's also how you test for `never` safely: `[T] extends [never]`.

**Mapped types** loop over keys: `{ [K in keyof T]: ... }`. They support:

- modifiers: `readonly`, `?`, and removing them with `-readonly` / `-?`,
- **key remapping** with `as` (TS 4.1+), which can be combined with template literal types,
- filtering keys by remapping them to `never`.

```ts
type DeepReadonly<T> =
  T extends (...args: any[]) => any ? T :
  T extends Map<infer K, infer V> ? ReadonlyMap<DeepReadonly<K>, DeepReadonly<V>> :
  T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } :
  T;

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};
type G = Getters<{ name: string; age: number }>;
// { getName: () => string; getAge: () => number }

type PickByValue<T, V> = { [K in keyof T as T[K] extends V ? K : never]: T[K] };
```

Arrays and tuples work in `DeepReadonly` because homomorphic mapped types (`[K in keyof T]`) keep the array or tuple shape.

**Real-world uses:**

- typed event emitters (`on<E extends keyof Events>`),
- extracting route params from a string (`'/users/:id'` → `{ id: string }`),
- deriving form or validation types, typed API clients, ORM query builders.

**Pitfalls:**

- Deep recursion slows the compiler or hits "Type instantiation is excessively deep".
- Very clever types are hard to read and maintain. Document them and test them with `expectTypeOf` or `// @ts-expect-error`.
- Prefer the built-ins (`ReturnType`, `Awaited`, `Parameters`) in real code.
