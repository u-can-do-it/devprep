## Hints

- How do core objects like HTTP servers and streams tell you something happened?
- Are listeners called synchronously or asynchronously when you call `emit`?
- What happens if an `'error'` event is emitted and nobody listens for it?

## Answer

`EventEmitter` (from `node:events`) is Node's implementation of the **observer pattern**. An object emits named events and any number of listeners react. Many core APIs extend it: `http.Server`, streams, `process`, child processes.

```js
import { EventEmitter, once } from 'node:events';

class OrderService extends EventEmitter {
  place(order) {
    // ...save order
    this.emit('placed', order);
  }
}

const orders = new OrderService();
orders.on('placed', (o) => console.log('send email for', o.id));
orders.once('placed', () => console.log('first order ever!'));

orders.place({ id: 1 });

// Promise-based: wait for a single event
const [order] = await once(orders, 'placed');
```

Key points:

- `emit()` calls listeners **synchronously**, in registration order. A slow listener blocks the emitter.
- Remove listeners with `off()` / `removeListener()`. A **MaxListenersExceededWarning** (more than 10 listeners for one event by default) usually signals a leak, for example adding a listener on every request.
- The **`'error'` event is special**: if it is emitted with no listener, Node throws and the process may crash. Always handle `'error'` on streams and sockets.
- `events.on(emitter, name)` returns an async iterator, so you can consume events with `for await`.

Use it for in-process decoupling. For events between services, use a message queue instead.
