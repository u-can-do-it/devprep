## Hints

- What would the browser have to guess if a page didn't say which rules it was written for?
- Why would browsers keep old, buggy rendering behavior around at all?
- Is there a way to check from JavaScript which mode a page ended up in?

## Answer

`<!DOCTYPE html>` is not an HTML element. It's an instruction to the browser to render the page in **standards mode**, following the current HTML and CSS specs.

Browsers have three rendering modes:

- **Standards mode**: modern, spec-compliant behavior. You get this with `<!DOCTYPE html>`.
- **Quirks mode**: imitates late-1990s browsers so very old pages still render as they did back then. You get it when the doctype is **missing** or malformed.
- **Limited-quirks ("almost standards") mode**: triggered by some old transitional doctypes. It differs from standards mode only in how images inside table cells are sized.

Things that behave differently in quirks mode:

- Percentage `height` resolves differently, and `body` fills the viewport.
- Some CSS values are accepted without units (`width: 100` is treated as `100px`).
- Tables don't inherit font sizes the usual way, and inline images leave different gaps.
- Some legacy box-model behavior can show up.

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Page</title>
  </head>
```

The doctype must be the **very first thing** in the document. In old browsers even a comment before it could trigger quirks mode. It is case-insensitive.

You can check the mode with `document.compatMode`: it returns `"CSS1Compat"` in standards mode and `"BackCompat"` in quirks mode.

**Follow-up:** the old HTML 4 and XHTML doctypes pointed to DTDs. HTML5 dropped them because the doctype's only job is to switch modes.
