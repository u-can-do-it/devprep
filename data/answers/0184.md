## Hints

- What happens when you declare the same `interface` name twice?
- How can you add a property to a third-party library's types without forking it?
- What goes inside a `.d.ts` file, and when do you need to write one?

## Answer

**Declaration merging:** TypeScript combines several declarations with the same name into one.

- **Interfaces merge:** their members are combined. This is a key difference from `type` aliases, which can't be redeclared.
- **Namespaces** can merge with classes, functions and enums to add static members.

```ts
interface Box { width: number }
interface Box { height: number }
const b: Box = { width: 1, height: 2 }; // both properties are required
```

**Module augmentation:** you can reopen a library's module and add to its interfaces. This is the standard way to type plugin-added properties:

```ts
// types/fastify.d.ts
import 'fastify';
declare module 'fastify' {
  interface FastifyInstance { db: DatabaseClient }
}
```

**Global augmentation** works from inside a module file:

```ts
export {};
declare global {
  interface Window { __APP_CONFIG__: { apiUrl: string } }
}
```

**`.d.ts` files** contain only **declarations**, never implementation. You use them to:

- **Type untyped JS libraries:** `declare module 'legacy-lib' { export function init(opts: { key: string }): void; }`, or the shorthand `declare module 'legacy-lib';` (everything becomes `any`).
- **Type non-JS imports:** `declare module '*.svg' { const url: string; export default url; }`
- **Publish types for your package:** generated with `declaration: true` and referenced via `types` in `package.json` `exports`. **`isolatedDeclarations`** (TS 5.5) requires explicit types on exports, so fast tools can generate `.d.ts` files without full type checking.

Before writing your own, check whether the package ships its own types or has `@types/*` from DefinitelyTyped.

**Gotchas:**

- A file with no `import`/`export` is a global script, so `declare module 'x'` there *declares* a new module instead of *augmenting* the existing one. Add `export {}` or an import.
- The file must be part of the compilation (`include`, or `types` in `tsconfig`).
- Merging can surprise teammates: an interface may be quietly extended elsewhere.
