## Hints

- What do you get from calling `Symbol('id')` twice with the same description?
- Do symbol-keyed properties show up in `Object.keys`, `for...in` or `JSON.stringify`?
- How does `for...of` know how to iterate a custom object?

## Answer

A **Symbol** is a primitive that is guaranteed to be unique. Every `Symbol('desc')` call creates a new one; the description is only a debugging label.

```js
const id = Symbol('id');
const user = { name: 'Ann', [id]: 42 };
Object.keys(user);          // ['name']
JSON.stringify(user);       // '{"name":"Ann"}'
user[id];                   // 42
```

**Uses:**

- **Collision-free property keys.** Libraries can attach metadata to objects they don't own without clashing with other keys. Symbol keys are skipped by `for...in`, `Object.keys` and JSON. They are not private, though: `Object.getOwnPropertySymbols` and `Reflect.ownKeys` still return them. For real privacy, use `#private` fields.
- **Global registry.** `Symbol.for('app.key')` returns the same symbol everywhere, even across realms.

**Well-known symbols** let your objects plug into built-in language behavior:

- `Symbol.iterator`: makes an object work with `for...of` and spread.
- `Symbol.asyncIterator`: makes it work with `for await...of`.
- `Symbol.toPrimitive`: controls conversion to a number or string.
- `Symbol.toStringTag`: changes what `Object.prototype.toString` reports.
- `Symbol.hasInstance`: customizes `instanceof`.
- `Symbol.dispose` / `Symbol.asyncDispose`: cleanup for `using` declarations (explicit resource management).

```js
class Range {
  constructor(from, to) { Object.assign(this, { from, to }); }
  *[Symbol.iterator]() { for (let i = this.from; i <= this.to; i++) yield i; }
}
[...new Range(1, 3)]; // [1, 2, 3]
```

**Follow-up:** "Why is `typeof Symbol()` not `'object'`?" It is a primitive, and `new Symbol()` throws.
