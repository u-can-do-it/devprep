## Hints

- Two different queries return the same `User:42`. How many copies are in the cache?
- A mutation renames a todo and returns `{ id, title }`. Do you have to do anything for the list to update?
- A mutation creates a new todo. Why doesn't the list update by itself?

## Answer

Apollo Client's **`InMemoryCache`** is a **normalized** store. When a query result arrives, Apollo splits it into individual objects and stores each one under a **cache id**, by default `__typename:id` (for example `Todo:7`). Fields that hold objects become **references** to those entries.

```ts
// query result
{ todos: [{ __typename: 'Todo', id: '7', title: 'Write tests', owner: { __typename: 'User', id: '1', name: 'Ana' } }] }

// stored as
ROOT_QUERY: { todos: [{ __ref: 'Todo:7' }] }
'Todo:7':   { id: '7', title: 'Write tests', owner: { __ref: 'User:1' } }
'User:1':   { id: '1', name: 'Ana' }
```

So every query that includes `User:1` reads the **same** entry. Update it once and every component showing Ana re-renders.

**Customising identity:** `typePolicies` in the cache config, e.g. `Product: { keyFields: ['sku'] }`. Types without an id are stored inside their parent, not normalized.

**Updating after a mutation:**

1. **Updating existing entities is automatic** if the mutation returns the changed object **with its `id` and `__typename`** and the changed fields:

```graphql
mutation Rename($id: ID!, $title: String!) {
  renameTodo(id: $id, title: $title) { id title }
}
```

2. **Adding or removing items** isn't automatic, because Apollo can't know which lists the new object belongs to. Options:
   - `update(cache, { data })` with `cache.modify` or `cache.updateQuery` to insert the new reference or remove one (and `cache.evict` plus `cache.gc()` for deletes).
   - `refetchQueries: ['GetTodos']`: simplest, costs a request.
3. **`optimisticResponse`**: write the expected result into the cache immediately, then replace it with the server's answer or roll back on error.

```ts
const [addTodo] = useMutation(ADD_TODO, {
  update(cache, { data }) {
    cache.modify({
      fields: {
        todos: (existing = []) => [...existing, cache.writeFragment({ data: data.addTodo, fragment: TODO_FIELDS })],
      },
    });
  },
});
```

**Other pieces:** **fetch policies** (`cache-first` by default, `cache-and-network`, `network-only`, `no-cache`), **field policies** with `merge` and `keyArgs` for paginated lists, and `client.resetStore()` on logout.

**Common bugs:** forgetting `id` in a query's selection (that object isn't normalized and won't update), lists that never update after create or delete, and stale data after logout.
