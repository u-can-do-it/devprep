## Hints

- In which direction do props travel through the component tree?
- If a child can't modify props, what can it receive from the parent that lets it ask for a change?
- How is this different from two-way binding like Angular's `[(ngModel)]`?

## Answer

In React, data flows **down** the tree through props. The component that owns a piece of state is the single source of truth, and children receive read-only copies. A child can't reach up and change its parent's state directly.

To change parent data, the parent passes a **callback** as a prop. The child calls it, and the parent updates its own state. The new value then flows back down on the next render. In short: data down, events up.

```jsx
function Parent() {
  const [name, setName] = useState('');
  return <NameInput value={name} onChange={setName} />;
}

function NameInput({ value, onChange }) {
  return <input value={value} onChange={e => onChange(e.target.value)} />;
}
```

**Benefits:**

- **Predictability:** for any value on screen, you can trace exactly which component owns it and where it changes.
- **Easier debugging:** state changes happen in one place, not through hidden two-way bindings.
- **Easier refactoring:** components are pure functions of their props.

**Cost:** passing callbacks through many layers (prop drilling). You fix that with composition, Context, or a store. All of these still keep the one-way model.

**Follow-up:** two sibling components that need the same data? Lift the state up to their closest common parent and pass it down to both.
