## Hints

- What is `addEventListener` an example of?
- How would you replace a `switch` over five payment providers so adding a sixth doesn't touch existing code?
- Why might you wrap a third-party analytics SDK instead of calling it everywhere?

## Answer

Classic design patterns appear in frontend code, often as functions and modules rather than class hierarchies.

**Observer (publish/subscribe):** subjects notify subscribers of changes. DOM events (`addEventListener`), `EventTarget`, RxJS, and every store (`store.subscribe`, Zustand, `useSyncExternalStore`) are observers.

```ts
function createStore<T>(initial: T) {
  let state = initial;
  const listeners = new Set<() => void>();
  return {
    get: () => state,
    set: (next: T) => { state = next; listeners.forEach((l) => l()); },
    subscribe: (l: () => void) => (listeners.add(l), () => listeners.delete(l)),
  };
}
```

**Strategy:** interchangeable algorithms behind one interface, often a map of functions instead of a `switch`. Examples: validation rules, sorting modes, pricing or payment providers.

```ts
const shippingCost: Record<Method, (order: Order) => number> = {
  standard: (o) => (o.total > 200 ? 0 : 15),
  express: () => 30,
  pickup: () => 0,
};
const cost = shippingCost[order.method](order);
```

**Factory:** a function that creates configured objects and hides construction: `createApiClient({ baseUrl, getToken })`, `createSlice`, `createStore`, or picking a component by type (`const Field = fieldComponents[field.type]`).

**Adapter:** converts one interface into the one your code expects, for example mapping API DTOs (`snake_case`, nullable fields) to UI models, or wrapping a chart or map library behind your own component API so you can swap it later.

**Facade:** a simple front for a complex subsystem, such as an `analytics.track(event)` module hiding GTM, consent checks and batching, or an API client hiding fetch, retries and auth refresh.

**Decorator:** adds behaviour without changing the original: higher-order functions (`withRetry(fetchUser)`, `memoize`, `debounce`) and higher-order components.

**Composite:** the component tree itself; also menus and file trees where an item and a group share an interface.

**Command:** actions as objects that can be queued, logged, undone or replayed. Redux actions and undo/redo stacks use it.

**Singleton:** in JS, just a module-level instance. Be careful: in SSR (Next.js) a module singleton is **shared across all users' requests**, which can leak data between them.

**Dependency injection:** passing dependencies in (props, Context, function arguments) instead of importing them directly, which makes components testable and lets you swap implementations.

**In an interview:** name the pattern, show where it appears in code you've written, and give the trade-off. Patterns are vocabulary, not a goal; adding a factory and an adapter to a 20-line feature is over-engineering.

**Follow-up:** which pattern do React hooks such as `useContext` plus a provider resemble, and what are their testing benefits?
