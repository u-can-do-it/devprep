## Hints

- Does an `enum` exist after compilation? What about a union type?
- What does a numeric enum generate at runtime, and which values does it accept?
- How can you get both a runtime list of values and a union type without using `enum`?

## Answer

**Enums** are one of the few TypeScript features that **generate runtime code**:

```ts
enum Status { Active = 'active', Banned = 'banned' }
// emits an object: { Active: 'active', Banned: 'banned' }
```

Drawbacks:

- **Numeric enums** also emit a reverse mapping, and they were historically loose about which numbers they accept.
- **Nominal for string enums:** you can't pass the literal `'active'` where `Status` is expected, which is awkward with API data.
- **Not erasable syntax.** Node's built-in type stripping and the `erasableSyntaxOnly` flag (TS 5.8) reject enums, because they can't just be removed.
- **`const enum`** is inlined but doesn't work well with `isolatedModules` or single-file transpilers (esbuild, swc).

**A union of string literals** has no runtime cost, narrows nicely, and accepts plain strings from JSON:

```ts
type Status = 'active' | 'banned';
function ban(s: Status) {}
ban('active'); // ok
```

**If you also need the values at runtime** (for a dropdown or validation), use an `as const` object or array:

```ts
const STATUS = { Active: 'active', Banned: 'banned' } as const;
type Status = (typeof STATUS)[keyof typeof STATUS]; // 'active' | 'banned'

const ROLES = ['admin', 'editor', 'viewer'] as const;
type Role = (typeof ROLES)[number];
```

**When enums are still fine:** existing codebases, bit flags with numeric enums, or teams that like the `Status.Active` namespace style. Most modern style guides prefer unions or `as const` objects, especially now that projects run TS directly in Node and use fast transpilers.

**Follow-up:** "How do you check exhaustiveness?" Use a `switch` with a `never` check in the `default` branch.
