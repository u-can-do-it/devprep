## Hints

- Is there a DOM in a React Native app?
- How do you style a component without CSS files and the cascade?
- What does Expo give you over a bare React Native project?

## Answer

React Native uses the **same React** (components, hooks, state, Context, most state libraries) but renders **native platform views** instead of DOM elements. It runs JavaScript on a JS engine (Hermes by default) and draws real iOS and Android UI.

**Main differences from React DOM:**

- **Primitives instead of HTML:** `<View>` instead of `div`, `<Text>` (all text must be inside it), `<Image>`, `<Pressable>`, `<TextInput>`, `<ScrollView>`, and `<FlatList>` (virtualised by default).
- **Styling:** JavaScript style objects (`StyleSheet.create`) with a subset of CSS. There's no cascade or inheritance except text inside `<Text>`, no class names or media queries, and values are unitless density-independent pixels. Layout is **Flexbox only**, with `flexDirection: 'column'` as the default. NativeWind brings Tailwind-style classes.
- **Navigation:** no URL bar or History API. Use React Navigation or **Expo Router** (file-based, similar to Next.js) with native stack and tab navigators.
- **Platform APIs:** camera, push notifications, secure storage and biometrics come from native modules. Platform-specific code uses `Platform.OS` or `.ios.tsx`/`.android.tsx` files.
- **Architecture:** the **New Architecture** (default since 0.76) replaces the old async JSON bridge with **JSI**, so JS can call native code directly, plus **Fabric** (renderer) and **TurboModules**.
- **Performance:** keep the JS thread free, use `FlatList` with stable keys, run animations on the UI thread (Reanimated), and avoid big re-renders, much like on the web.
- **Delivery:** builds go through App Store and Play Store review. **EAS Build/Update** (Expo) builds in the cloud and pushes JS-only updates over the air.

**Expo** is the recommended way to start: a framework and toolchain with a large set of maintained native modules, Expo Router, development builds, config plugins instead of editing native projects by hand, and EAS for building and submitting. A bare project gives full native control but you maintain Xcode and Gradle setup yourself.

**Code sharing with the web:** business logic, API clients, validation and state can live in shared packages in a monorepo. UI usually differs, though `react-native-web` or `react-strict-dom` can share some components.
