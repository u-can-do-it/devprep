## Hints

- How many different image sizes does a phone need compared with a 4K monitor?
- What causes the page to "jump" when an image finishes loading?
- Which image on the page should *not* be lazy-loaded?

## Answer

`next/image` wraps `<img>` and automates most image-performance best practices:

- **Resizing and modern formats on demand.** The optimizer serves a resized WebP (or AVIF, if configured) version that fits the device, and caches it. You don't have to export many sizes by hand.
- **Responsive `srcset`.** Together with the `sizes` prop, the browser downloads the smallest image that still looks sharp.
- **No layout shift (CLS).** You must give `width`/`height` (or `fill` with a sized parent), so space is reserved before the image loads. Static imports read the dimensions for you.
- **Lazy loading by default.** Off-screen images aren't downloaded until the user scrolls near them.
- **Placeholders.** `placeholder="blur"` shows a blurred preview, which is automatic for static imports.
- **Security.** Remote images must match `images.remotePatterns`, so your optimizer can't be abused to fetch any URL.

```tsx
import Image from 'next/image';
import hero from './hero.jpg';

<Image src={hero} alt="Team at work" preload placeholder="blur" />

<div style={{ position: 'relative', aspectRatio: '16/9' }}>
  <Image src={post.coverUrl} alt="" fill sizes="(max-width: 768px) 100vw, 50vw" />
</div>
```

**Pitfalls:**

- Leaving the **LCP/hero image** lazy-loaded hurts LCP. Mark it with `preload` (Next.js 16; replaces the deprecated `priority`), or with `loading="eager"` / `fetchPriority="high"`.
- `fill` without `sizes` makes the browser assume `100vw` and download a huge file.
- An empty `alt` is only correct for decorative images.

**Follow-up:** in Next.js 16 the allowed `quality` values default to `[75]` and the cache TTL went up to 4 hours. For SVGs or a dedicated image CDN, use `unoptimized` or a custom `loader`.
