## Hints

- What three arguments does a typical Express middleware receive?
- What happens if a middleware neither sends a response nor calls `next()`?
- How is an error-handling middleware different from a normal one?

## Answer

Middleware is a **chain of functions** that each receive the request, the response and `next`. Each one can read/modify `req`/`res`, end the request by sending a response, or call `next()` to pass control to the next function. Order of registration = order of execution.

```js
import express from 'express';
const app = express();

app.use(express.json());                 // built-in: parse JSON bodies
app.use((req, res, next) => {            // custom logger
  const start = Date.now();
  res.on('finish', () => console.log(req.method, req.url, Date.now() - start, 'ms'));
  next();
});
app.get('/admin', requireAuth, (req, res) => res.send('ok')); // route-level middleware

app.use((err, req, res, next) => {       // error handler: 4 args, registered last
  res.status(err.status ?? 500).json({ error: err.message });
});
```

Key points:

- Forgetting `next()` (and not responding) leaves the request **hanging**.
- `next(err)` skips normal middleware and jumps to error handlers.
- Typical uses: body parsing, auth, logging, CORS, rate limiting, compression.

**Fastify** differs: it uses a **hook lifecycle** (`onRequest`, `preHandler`, `onSend`, …) and an encapsulated **plugin system** instead of one linear chain, has built-in JSON-schema validation and fast serialization, and handlers can simply `return` a value or a promise. It's generally faster than Express.
