## Hints

- When Node runs the compiled output, which file does `import './utils.js'` load, and does TypeScript rewrite import paths?
- What does a bundler like Vite accept that Node's ESM loader rejects?
- How does `package.json` `exports` affect which `.d.ts` file TypeScript picks?

## Answer

`moduleResolution` tells TypeScript **how the runtime or bundler will find modules**, so the type checker resolves imports the same way. The important modes:

- **`nodenext` / `node16`:** for code that **Node runs directly**. It follows Node's rules. A file is ESM or CJS based on `package.json` `"type"` or the extension (`.mts`/`.cts`), package `exports` and `imports` are respected, and **relative ESM imports need a file extension**.
- **`bundler`** (usually with `module: "preserve"` or `"esnext"`): for code processed by **Vite, webpack, Next.js, esbuild**. Extensionless imports and directory `index` files are allowed, and `exports` conditions are respected.
- **`node10`/`classic`:** legacy modes. They were deprecated in TS 6.0 and removed in TS 7.

**Why `.js` in a `.ts` file?** By default TypeScript **doesn't rewrite import paths**. You write the path that will exist **at runtime**:

```ts
// src/index.ts  (moduleResolution: nodenext)
import { sum } from './math.js';  // resolves to math.ts at type-check time, math.js at runtime
```

Alternatives: `rewriteRelativeImportExtensions` (TS 5.7) lets you write `./math.ts` and rewrites it to `.js` on emit. That also suits **Node's built-in type stripping**, which runs `.ts` files directly and requires real `.ts` extensions (together with `allowImportingTsExtensions` and erasable-only syntax).

**Publishing a package:** expose types through `exports`, with the `types` condition listed **first**:

```json
{
  "type": "module",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js", "require": "./dist/index.cjs" }
  }
}
```

**Common pitfalls:**

- **`paths` aliases** affect only type checking. The bundler or runtime needs matching config, or you can use `package.json` `"imports"` (`#src/*`), which both Node and TS understand.
- **Dual ESM/CJS packages** need separate `.d.ts`/`.d.cts` files, or types resolve with the wrong format. Check with "Are the Types Wrong?".
- **Mismatches:** using `bundler` for a Node library compiles fine and then fails at runtime on missing extensions.
- Node 22+ can `require()` ESM, which eases interop but doesn't change how TypeScript resolves imports.
