## Hints

- Which parts of a modern phone screen can cover your content?
- What does "edge-to-edge" mean for where your app is allowed to draw?
- On iOS, what happens to a text field at the bottom of the screen when the keyboard opens?

## Answer

> A screen is not a clean rectangle: notches, the status bar, the home indicator, system navigation bars and the keyboard all cover content. Read the safe area insets from `react-native-safe-area-context` and pad the content that must stay visible. On current Android versions apps draw edge-to-edge, behind the system bars, so insets matter on both platforms. For the keyboard, move or resize the content with a keyboard-aware component, and test every form on both platforms.

**Safe areas**

```tsx
// App root
<SafeAreaProvider>
  <App />
</SafeAreaProvider>

function Screen() {
  const insets = useSafeAreaInsets();          // { top, bottom, left, right }
  return (
    <View style={{ flex: 1, paddingTop: insets.top, backgroundColor: '#0a5' }}>
      <ScrollView contentContainerStyle={{ paddingBottom: insets.bottom + 16 }}>
        {/* ... */}
      </ScrollView>
    </View>
  );
}
```

- Backgrounds should fill the whole screen, and only the content gets padding. That is why the hook is often better than wrapping everything in a `SafeAreaView`.
- The library's `SafeAreaView` takes `edges={['top']}` when you want only some sides.
- The core `SafeAreaView` from `react-native` is deprecated and worked only on iOS.
- Navigators already apply insets to their headers and tab bars. Apply your own only on screens without a header, in modals, and for floating buttons and bottom bars.

**Edge-to-edge on Android**

Android 15 made edge-to-edge the default for apps that target it, and Android 16 removed the opt-out. The app draws behind a transparent status bar and navigation bar. Current React Native and Expo versions enable this for you. In practice:

- Bottom buttons and tab bars need `insets.bottom`, or they sit under the gesture bar.
- Setting a status bar background colour no longer has an effect. Draw a view behind it instead.
- Old code that assumed "the window ends above the navigation bar" breaks after an upgrade (#701).

**Status bar**

You control the icon style, not much else:

```tsx
<StatusBar style="light" />   // expo-status-bar: light icons on a dark header
```

Set it per screen when headers have different colours.

**Keyboard**

The keyboard covers the lower part of the screen. Your layout must react.

- **`KeyboardAvoidingView`** (core): wraps the screen and adds padding or changes height. `behavior="padding"` is the usual iOS setting. Android behaviour depends on the window's resize mode, and with edge-to-edge it often needs the same treatment as iOS.
- **`react-native-keyboard-controller`**: the more reliable choice today. It gives identical behaviour on both platforms, a `KeyboardAwareScrollView` that scrolls the focused input into view, a toolbar with next/previous/done, and frame-by-frame keyboard animation values.
- Put forms in a scroll view, so the user can reach every field on a small screen.

Useful props on scroll views and lists:

```tsx
<ScrollView
  keyboardShouldPersistTaps="handled"   // a tap on a button works without first closing the keyboard
  keyboardDismissMode="on-drag"         // dragging the list closes the keyboard
/>
```

`Keyboard.dismiss()` closes it from code, for example when the user taps outside a field.

**Checklist for a form screen**

1. Is every input visible while focused, on a small phone, on both platforms?
2. Is the submit button reachable with the keyboard open?
3. Does the bottom content clear the home indicator and gesture bar?
4. Does it still work in landscape and with a larger system font?

**Follow-up:** a chat screen has an input bar fixed at the bottom. How do you keep it above the keyboard and the message list scrolled to the end? (Wrap the screen in a keyboard-avoiding view or use the keyboard library's sticky view, add `insets.bottom` when the keyboard is closed, and use an inverted list so the newest messages stay at the bottom.)
