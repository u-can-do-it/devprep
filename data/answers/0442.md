## Hints

- What does the second argument of `JSON.stringify` do, and the third?
- What happens to `undefined`, functions, `Date`, `Map` and `BigInt` when you stringify them?
- Which syntax is valid in a JavaScript object literal but invalid in JSON?

## Answer

**JSON** (JavaScript Object Notation) is a text format for data: objects, arrays, strings, numbers, booleans and `null`. It's stricter than JS: keys and strings need **double quotes**, and there are **no comments, trailing commas, `undefined`, `NaN` or functions**.

```js
const text = JSON.stringify({ id: 1, tags: ['js'] });   // '{"id":1,"tags":["js"]}'
const obj = JSON.parse(text);                           // a brand-new object

JSON.stringify(obj, null, 2);         // pretty-print with 2-space indent
JSON.stringify(user, ['id', 'name']); // replacer array: only these keys
JSON.parse("{'a': 1}");               // SyntaxError: single quotes aren't JSON
```

**What doesn't survive a round trip:**

| Value | `JSON.stringify` gives |
|---|---|
| `undefined`, functions, symbols | property dropped (in arrays: `null`) |
| `NaN`, `Infinity` | `null` |
| `Date` | ISO string (via `toJSON`), comes back as a **string**, not a Date |
| `Map`, `Set` | `{}` |
| `BigInt` | throws `TypeError` |
| circular reference | throws `TypeError` |
| class instance | plain object, prototype and methods lost |

**Customizing:**
- An object's `toJSON()` method controls how it's serialized (that's how `Date` works).
- A **replacer** function `(key, value) => ...` can transform or drop values on the way out.
- A **reviver** function in `JSON.parse(text, reviver)` can transform values on the way in, e.g. turn ISO strings back into `Date`s.

```js
const data = JSON.parse(text, (key, value) =>
  key.endsWith('At') ? new Date(value) : value,
);
```

`JSON.parse(JSON.stringify(x))` is an old deep-clone trick, but it silently loses the types above. Use `structuredClone` instead.
