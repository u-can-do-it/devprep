## Hints

- When you `reset --hard` or rebase, are the old commits deleted right away?
- Which record does Git keep every time `HEAD` or a branch tip moves?
- Is that record shared with your teammates through the remote?

## Answer

The **reflog** is a local log of every position `HEAD` (and each branch) has pointed to: commits, checkouts, resets, rebases, merges, amends. Commits that are "lost" from branches are usually still in the object database, and the reflog tells you their hashes.

```bash
git reflog
# 3f9c2a1 HEAD@{0}: reset: moving to HEAD~3
# 8d41b7e HEAD@{1}: commit: add payment webhook handler
# ...

git reset --hard HEAD@{1}           # move the branch back to before the reset
# or more carefully:
git branch rescue 8d41b7e           # create a branch at the lost commit
```

**Common rescues:**
- **Bad `reset --hard`:** find the entry before the reset and reset back to it.
- **Botched rebase:** find `rebase (start)` in `git reflog`, or the branch's own log (`git reflog show feature`), and reset to the commit just before it. Right after the rebase, `ORIG_HEAD` also points to the old tip.
- **Deleted branch:** find the last commit you had checked out on it and `git branch <name> <sha>`.
- **Amended a commit by mistake:** the pre-amend commit is in the reflog.

**Limits:**
- The reflog is **local only**. It's not pushed, and a fresh clone has none.
- Entries expire (by default 90 days, or 30 days for unreachable commits), after which `git gc` may delete the objects.
- **Uncommitted** changes lost through `reset --hard` are **not** recoverable this way, because they were never committed. (Staged files can sometimes be found with `git fsck --lost-found`.)

**Takeaway:** commit often. Almost anything committed can be recovered.
