## Hints

- What code runs for every request, before and after the endpoint?
- Where should you create a database pool or load an ML model once, and close it on shutdown?
- Why were `@app.on_event("startup")` handlers deprecated?

## Answer

**Middleware** wraps every request/response. It receives the request, can modify it, calls the next layer, and can modify the response. Use it for cross-cutting concerns: request IDs, timing, logging, CORS, GZip, trusted hosts.

```python
import time, uuid
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_request_id(request: Request, call_next):
    request_id = request.headers.get("x-request-id", str(uuid.uuid4()))
    start = time.perf_counter()
    response = await call_next(request)
    response.headers["x-request-id"] = request_id
    response.headers["x-process-time"] = f"{time.perf_counter() - start:.4f}"
    return response
```

Built-ins via Starlette: `app.add_middleware(CORSMiddleware, ...)`, `GZipMiddleware`. Middleware runs in reverse order of addition (last added = outermost). For performance-critical paths, pure ASGI middleware beats `@app.middleware("http")`. Note middleware can't use `Depends`; per-route concerns (auth) usually fit better as dependencies.

**Lifespan** is an async context manager that runs **once at startup and shutdown** of the app. Code before `yield` initializes shared resources; code after cleans up. It replaced the deprecated `on_event` handlers because setup and teardown live together and can share local variables.

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.db = await create_pool(DATABASE_URL)
    app.state.http = httpx.AsyncClient()
    yield
    await app.state.http.aclose()
    await app.state.db.close()

app = FastAPI(lifespan=lifespan)
```
