## Hints

- A promise can't be cancelled by itself. How do you tell the work behind it to stop?
- How would you give an outgoing HTTP call a 3-second timeout?
- How do you cancel work when the client disconnects or the server is shutting down?

## Answer

`AbortController` is the standard cancellation primitive, shared with browsers. A controller owns a **`signal`**. You pass the signal to cancellable APIs. When you call `controller.abort()`, the signal fires and those APIs reject with an `AbortError`.

```js
// timeout: no controller needed
const res = await fetch(url, { signal: AbortSignal.timeout(3000) });

// cancel when the client goes away OR after a timeout
app.get('/search', async (req, res) => {
  const ac = new AbortController();
  req.on('close', () => ac.abort());
  const signal = AbortSignal.any([ac.signal, AbortSignal.timeout(5000)]);

  try {
    const data = await fetch(searchUrl, { signal }).then((r) => r.json());
    res.json(data);
  } catch (err) {
    if (err.name === 'AbortError' || err.name === 'TimeoutError') return;
    throw err;
  }
});
```

Many Node APIs accept `{ signal }`: `fetch`, `fs/promises` `readFile`, `timers/promises` `setTimeout`, `events.once`, `stream.pipeline`, `child_process.spawn`, `addEventListener`.

To make **your own** function cancellable, accept a `signal`, call `signal.throwIfAborted()` between steps, and listen for the `'abort'` event to clean up.

Pitfalls:

- Aborting only stops what listens to the signal. A DB query or CPU loop that ignores it keeps running.
- Don't leave listeners on long-lived signals. Use `{ once: true }` or remove them.
- Distinguish `TimeoutError` (from `AbortSignal.timeout`) from a user abort when reporting errors.

**Follow-up:** How would you propagate one shutdown signal to all in-flight work? (A process-wide controller aborted on `SIGTERM`, combined with per-request signals via `AbortSignal.any`.)
