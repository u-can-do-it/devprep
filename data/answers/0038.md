## Hints

- What makes a function a "hook" as opposed to a regular helper?
- Each time a component calls `useState`, does it get a new piece of state or a shared one?
- How would you share actual state between components that use the same hook?

## Answer

A custom hook is a function whose name starts with `use` and that **calls other hooks**. It lets you extract and reuse **stateful logic** (not UI) across components.

```jsx
function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try { return JSON.parse(localStorage.getItem(key)) ?? initial; }
    catch { return initial; }
  });
  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);
  return [value, setValue];
}

const [theme, setTheme] = useLocalStorage('theme', 'light');
```

**Do they share state? No.** A custom hook shares *logic*, not *state*. Every component that calls it gets its own independent state, exactly as if it had written the `useState`/`useEffect` calls itself. Two components calling `useLocalStorage('theme')` have two separate states (they won't even sync with each other unless you add a `storage` event listener).

To share state, put it in a common place: lift it to a parent, put it in Context, or use an external store and subscribe with `useSyncExternalStore` (which is how Zustand works).

**Good practices:**

- The `use` prefix is required so lint rules and the React Compiler treat it as a hook.
- Return a stable, minimal API (tuple or object).
- Test them with `renderHook` from React Testing Library.
- Don't wrap a single `useState` in a hook just for the sake of it.

**Follow-up:** examples worth mentioning — `useDebounce`, `useMediaQuery`, `useOnClickOutside`, `useFetch`.
