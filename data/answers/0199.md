## Hints

- How does React decide whether a state update actually changed anything?
- If you `push` into an array and call `setItems(items)`, what does that comparison see?
- Which array methods return a new array, and which modify the original?

## Answer

React compares the old and new state with `Object.is`, which is a **reference** check. If you mutate an object and pass the same reference back, React sees "no change" and may skip the re-render. Mutation also breaks other things:

- `React.memo`, `useMemo` and the React Compiler rely on reference changes.
- Earlier renders' snapshots get silently changed, which breaks undo and history.
- Concurrent rendering assumes state is immutable.

Always create **new** objects and arrays:

```jsx
// objects
setUser(u => ({ ...u, name: 'Ada' }));
setUser(u => ({ ...u, address: { ...u.address, city: 'Oslo' } })); // nested

// arrays
setItems(items => [...items, newItem]);                    // add
setItems(items => items.filter(i => i.id !== id));          // remove
setItems(items => items.map(i =>
  i.id === id ? { ...i, done: !i.done } : i));              // update one
setItems(items => items.toSorted((a, b) => a.rank - b.rank)); // sort
```

**Avoid on state:** `push`, `pop`, `splice`, `sort`, `reverse`, and assigning to an index. These mutate in place. Use the ES2023 non-mutating versions instead: `toSorted`, `toReversed`, `toSpliced`, `with(index, value)`.

**Deep updates:** spreading many levels gets noisy. Either flatten or normalize the state shape, or use **Immer** (`produce`, or the `useImmer` hook), which lets you write "mutating" code against a draft and produces an immutable result.

**Pitfall:** spread is shallow. `{ ...u }` still shares nested objects with the original, so mutating `copy.address.city` mutates the original too.
