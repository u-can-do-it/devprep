## Hints

- Which data structure gives O(1) lookups so you don't nest two loops?
- For brackets, what tells you that `([)]` is invalid even though every bracket has a partner?
- What key would make all anagrams of a word collide in a `Map`?

## Answer

These are the warm-up tasks in most frontend coding rounds. The point is clean code, correct complexity and talking through edge cases, not cleverness.

**1. Valid brackets** `"{[()]}"` → `true`, `"([)]"` → `false`. A **stack**: push openers, pop and compare on closers.

```js
function isValid(s) {
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];
  for (const ch of s) {
    if (ch in pairs) {
      if (stack.pop() !== pairs[ch]) return false;   // wrong closer or empty stack
    } else {
      stack.push(ch);
    }
  }
  return stack.length === 0;                          // unclosed openers
}
```

O(n) time, O(n) space. Edge cases: empty string (valid), a lone closer, leftover openers.

**2. Two sum** (indices of two numbers adding up to a target). One pass with a `Map` from value to index: for each number check whether `target - num` was seen.

```js
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return null;
}
```

O(n) instead of the O(n²) double loop. Checking **before** inserting avoids using the same element twice (`[3], target 6`).

**3. Group anagrams** `['eat','tea','tan','ate','nat']` → `[['eat','tea','ate'], ['tan','nat']]`. Build a key that is identical for anagrams: the sorted word, or a 26-letter count.

```js
function groupAnagrams(words) {
  const groups = new Map();
  for (const w of words) {
    const key = [...w].sort().join('');            // or a char-count key for O(k) instead of O(k log k)
    (groups.get(key) ?? groups.set(key, []).get(key)).push(w);
  }
  return [...groups.values()];
}
```

O(n · k log k) with sorting, O(n · k) with counting, where k is the word length. `Object.groupBy(words, key)` does the same since ES2024 (#516).

**4. First non-repeating character** `"swiss"` → `"w"`. Count, then scan again in order. `Map` keeps insertion order, so one scan of the map entries also works.

```js
function firstUnique(s) {
  const counts = new Map();
  for (const ch of s) counts.set(ch, (counts.get(ch) ?? 0) + 1);
  for (const [ch, n] of counts) if (n === 1) return ch;
  return null;
}
```

O(n). Mention Unicode: `for...of` and `[...s]` iterate code points, `s[i]` iterates UTF-16 units and splits emoji (#153 area).

**5. Frequency counting in general** (most common element, is `b` a permutation of `a`, word count) is the same pattern: one pass to count into a `Map`, one pass to decide. Interviewers want to hear "hash map, O(n)" and then see you handle the empty input.

**How to talk through it:** restate the task with an example, name the brute force and its complexity, say which data structure removes the inner loop, write it, then walk one example through the code by hand and list edge cases (empty, one element, all identical, case sensitivity, Unicode). See #509 for complexities of the built-ins you use (`includes` is O(n), `Set.has` is O(1), `sort` is O(n log n)).

**Follow-up:** two sum on a **sorted** array without extra memory? (Two pointers from both ends, O(n) time, O(1) space.)
