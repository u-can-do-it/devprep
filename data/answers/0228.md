## Hints

- What happens to the JavaScript state of your header when you click a plain `<a>` to another page?
- What could the app download before the user even clicks?
- Does prefetching happen in development?

## Answer

`<Link>` renders a real `<a href>` (so SEO, accessibility, middle-click and "open in new tab" all work), but adds two things:

**1. Client-side navigation.** A normal click is intercepted: there is no full page reload. The router fetches only the **RSC payload** for the segments that change and keeps shared layouts mounted, along with their state (open menus, input values, scroll in a sidebar). A plain `<a>` reloads the whole document, re-downloads and re-runs JS, and loses all client state.

**2. Prefetching.** When a `<Link>` enters the viewport (and again on hover), Next.js loads the target route in the background, so the click feels instant. The `prefetch` prop controls it:

- `"auto"` / `null` (default) – static routes are prefetched fully. Dynamic routes are prefetched down to the nearest `loading.tsx`, so the loading state can show at once.
- `true` – prefetch the full route, dynamic ones too.
- `false` – never prefetch (e.g. a huge list of rarely used links).

Prefetching **only runs in production builds**.

```tsx
import Link from 'next/link';

<Link href={`/products/${id}`}>Details</Link>
<Link href="/settings" replace scroll={false}>Settings</Link>
<Link href="/admin" prefetch={false}>Admin</Link>
```

Other useful props: `replace` (no new history entry), `scroll={false}`, and `onNavigate` (can cancel navigation, e.g. for unsaved changes). For programmatic navigation use `useRouter()` from `next/navigation`.

**Follow-up:** use a plain `<a>` for external URLs and file downloads. Next.js 16 made prefetching cheaper: shared layouts are downloaded once rather than once per link.
