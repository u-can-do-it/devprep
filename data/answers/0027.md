## Hints

- How does TypeScript know which member of a union you have inside an `if` block?
- What does a shared literal property such as `type` or `status` let the compiler do?
- How can you make the compiler fail when someone adds a new variant and forgets to handle it?

## Answer

**Narrowing** is how TypeScript refines a broad type to a more specific one inside a branch, using **control-flow analysis**. The built-in narrowing tools:

- `typeof x === 'string'`, `x instanceof Date`, `'key' in x`
- equality checks (`x === null`), truthiness checks, `Array.isArray`
- **user-defined type guards:** `function isUser(x: unknown): x is User`
- **assertion functions:** `function assert(x: unknown): asserts x is User`
- since TS 5.5, the compiler **infers type predicates** for simple guards such as `arr.filter(x => x !== undefined)`

A **discriminated (tagged) union** is a union of object types that all share a property with a **literal type**, called the discriminant. Checking that property narrows the value to exactly one variant:

```ts
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error };

function render(s: RequestState<User[]>) {
  switch (s.status) {
    case 'success': return s.data.length;    // data is available only here
    case 'error':   return s.error.message;
    case 'idle':
    case 'loading': return null;
    default: {
      const _never: never = s;               // exhaustiveness check
      throw new Error(`Unhandled: ${JSON.stringify(_never)}`);
    }
  }
}
```

**Why it's a strong pattern:**

- It **makes impossible states impossible to represent**. You can't have `data` and `error` at the same time, or `loading: true` together with data, which boolean flags would allow.
- The compiler enforces exhaustive handling. Adding a variant makes every unhandled `switch` fail to compile.
- It fits reducers and actions, API results, state machines, and event types.

**Gotchas:**

- Narrowing can be **lost inside callbacks** for `let` variables or mutable properties. TS 5.4 improved this for closures created after the last assignment.
- Destructuring the discriminant into a separate variable used to break narrowing. TS 4.6+ handles destructured `const`s.
- `in` checks on non-discriminated unions are less precise than checking a discriminant.
