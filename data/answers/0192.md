## Hints

- When you write `<Avatar user={u} />`, is anything rendered yet, or is it just a description?
- Which of these holds state: the function you wrote, or something React creates per use?
- What can a component return besides JSX?

## Answer

- **Component**: a function (or class) that takes props and returns UI. It's the blueprint: `function Avatar({ user }) { ... }`.
- **Element**: the plain, immutable object you get from JSX, `<Avatar user={u} />`. It describes what you want on screen (`type`, `props`, `key`). Creating one is cheap and renders nothing by itself.
- **Node** (`ReactNode`): anything React can render: elements, strings, numbers, `null`/`undefined`/booleans (render nothing), arrays of nodes, and portals.

React calls your component with the element's props, gets back more elements, and repeats until it reaches host elements like `'div'`. Each place a component appears in the tree gets its own internal **instance** (a Fiber), and that is where hooks state lives. That's why two `<Counter />` elements have separate counts.

```jsx
function Avatar({ user }) {            // component
  return <img src={user.photo} alt="" />;
}
const el = <Avatar user={u} />;        // element
const nodes = [el, 'text', null, 42];  // all valid ReactNodes
```

**Pitfall:** calling a component as a function (`{Avatar({ user })}`) instead of rendering it as an element. React no longer sees a separate component. Its hooks attach to the parent, and it can't be memoized or keyed on its own.

**Follow-up:** in TypeScript, type `children` as `React.ReactNode`, not `JSX.Element`. `JSX.Element` rejects strings and `null`.
