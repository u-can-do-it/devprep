## Hints

- What type does TypeScript infer for `let x = 'a'` versus `const x = 'a'`?
- Why does `{ method: 'GET' }` get the type `{ method: string }`?
- How can you derive a union type from an array of values?

## Answer

**Literal widening:** TypeScript widens literal values to their general type when they can change later:

```ts
const a = 'GET';            // type 'GET'   (a const can't change)
let b = 'GET';              // type string
const req = { method: 'GET' }; // { method: string }: properties are mutable
const arr = ['a', 'b'];     // string[]
```

**`as const`** tells the compiler to infer the **narrowest** type and make everything **readonly**:

```ts
const req = { method: 'GET', retries: 3 } as const;
// { readonly method: 'GET'; readonly retries: 3 }

const ROLES = ['admin', 'editor'] as const;
// readonly ['admin', 'editor'], a tuple instead of string[]
type Role = (typeof ROLES)[number]; // 'admin' | 'editor'
```

**Common uses:**

- **One source of truth for a union:** keep a runtime array and a type in sync (a better option than an enum in many cases).
- **Literal discriminants** in returned objects, so discriminated unions narrow correctly.
- **Tuple returns:** `return [value, setValue] as const;` keeps the position types, instead of producing `(T | Setter)[]`.
- **Typed config** together with `satisfies`: `const routes = { ... } as const satisfies Record<string, Route>;` checks the shape and keeps the literal types.

**Pitfalls:**

- The result is readonly, so you can't pass it to a parameter typed `string[]`. Accept `readonly string[]` in your functions instead.
- `as const` only affects types. At runtime the object is still mutable (use `Object.freeze` for that).
- It works only on literal expressions, not on variables: `x as const` is an error.

**Follow-up:** `const` type parameters (TS 5.0) give the same narrow inference at the call site without the caller writing `as const`.
