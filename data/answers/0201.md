## Hints

- Does `useEffect` run before or after the browser paints the screen?
- If you measure an element and then reposition it in a regular effect, what might the user briefly see?
- What does a blocking, synchronous effect cost?

## Answer

Both run after React updates the DOM. The difference is **timing relative to paint**:

- **`useEffect`** runs **after the browser paints**, usually asynchronously. It doesn't block the frame. Use it by default: subscriptions, logging, syncing with external systems.
- **`useLayoutEffect`** runs **synchronously after DOM mutations but before paint**. The browser waits for it. State updates made inside it are applied before the user sees anything.

Use `useLayoutEffect` when you need to **read layout and then change it** without a visible flicker. Tooltip positioning is the classic example:

```jsx
function Tooltip({ anchorRect, children }) {
  const ref = useRef(null);
  const [top, setTop] = useState(0);

  useLayoutEffect(() => {
    const { height } = ref.current.getBoundingClientRect();
    setTop(anchorRect.top - height - 8); // re-render happens before paint
  }, [anchorRect]);

  return <div ref={ref} style={{ position: 'fixed', top }}>{children}</div>;
}
```

With `useEffect`, the tooltip would first paint at `top: 0` and then jump.

**Costs and caveats:**

- It blocks painting. Heavy work inside it hurts responsiveness (INP).
- It doesn't run during server rendering, so the server HTML shows the "unmeasured" state.
- Layout reads like `getBoundingClientRect` can force synchronous reflow.

**Follow-up:** check whether CSS can do the job first. CSS anchor positioning, container queries, and `position: sticky` remove many reasons to measure in JavaScript. `useInsertionEffect` is a third variant meant only for CSS-in-JS libraries that inject styles.
