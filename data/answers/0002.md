## Hints

- Which of the three is limited to the nearest `{ }` block?
- What happens if you declare the same `var` twice, or reassign a `const`?
- Does `const` make an object immutable?

## Answer

**Scope**

- `var` is **function-scoped**. It ignores blocks like `if` and `for`. At the top level of a script it also becomes a property of `window`/`globalThis`.
- `let` and `const` are **block-scoped**. They exist only inside the nearest `{ ... }`.

```js
function demo() {
  if (true) {
    var a = 1;
    let b = 2;
  }
  console.log(a); // 1
  console.log(b); // ReferenceError
}
```

**Redeclaring and reassigning**

| | redeclare | reassign | hoisted & initialized |
|---|---|---|---|
| `var` | yes | yes | yes, as `undefined` |
| `let` | no | yes | no (TDZ) |
| `const` | no | no | no (TDZ) |

**`const` ≠ immutable.** `const` only stops you from rebinding the variable. The object it points to can still change:

```js
const user = { name: 'Ann' };
user.name = 'Bob'; // fine
user = {};         // TypeError
```

Use `Object.freeze` for shallow immutability.

**Classic loop pitfall:** `for (var i = 0; i < 3; i++) setTimeout(() => console.log(i))` logs `3 3 3`, because every callback shares one `i`. With `let`, each iteration gets a fresh binding, so it logs `0 1 2`.

**Modern practice:** use `const` by default, `let` when you need to reassign, and never `var`.
