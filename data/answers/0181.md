## Hints

- How do you get a different return type depending on the type of the argument?
- Which signature does the caller see: the overload signatures or the implementation signature?
- What happens when a caller passes a union type that each overload accepts only half of?

## Answer

**Overloads** declare several call signatures for one function, followed by a single implementation that handles all of them. Callers see only the overload signatures. The implementation signature is hidden.

```ts
function parse(input: string): Config;
function parse(input: Uint8Array, encoding: 'utf-8' | 'latin1'): Config;
function parse(input: string | Uint8Array, encoding = 'utf-8'): Config {
  const text = typeof input === 'string' ? input : new TextDecoder(encoding).decode(input);
  return JSON.parse(text);
}

parse('{}');                         // ok
parse(bytes, 'utf-8');               // ok
// parse(bytes);                     // error: no overload matches
```

**Rules:**

- TypeScript tries the overloads **top to bottom** and uses the first match, so put the most specific ones first.
- The implementation must be compatible with every overload, and it isn't checked against each one precisely, so overloads can hide bugs.
- In interfaces or types, write several call signatures: `{ (x: string): A; (x: number): B }`.

**When to use what:**

- **A union parameter** when the return type doesn't depend on the input: `format(x: string | number): string`.
- **Generics** when the output follows the input's type: `first<T>(arr: T[]): T`.
- **Overloads** when the parameter lists differ (different counts or combinations), or when specific inputs map to specific outputs, as with DOM-style `createElement('div') → HTMLDivElement`.
- **Conditional return types** are an alternative, but the implementation usually needs casts.

**Pitfall:** a caller holding a `string | Uint8Array` value can't call `parse` above, because no single overload accepts the union. Add an overload for the union if that case matters.
