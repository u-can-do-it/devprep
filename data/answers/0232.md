## Hints

- How could `/login` and `/dashboard` use completely different layouts without `/auth` appearing in the URL?
- Where would you put a `Button.tsx` that is used only by one route?
- What happens when you navigate between two different root layouts?

## Answer

**Route groups** – a folder name in parentheses, like `(marketing)`, is **left out of the URL**. You use it to organize routes and give groups different layouts:

```text
app/
  (marketing)/
    layout.tsx        -> public header and footer
    page.tsx          -> /
    pricing/page.tsx  -> /pricing
  (app)/
    layout.tsx        -> sidebar, requires login
    dashboard/page.tsx -> /dashboard
  (auth)/
    login/page.tsx    -> /login
```

Common uses:

- Different layouts for parts of the site without changing URLs.
- Applying a `loading.tsx` or `layout.tsx` to only some routes at the same level.
- **Multiple root layouts**: put `layout.tsx` with `<html>` and `<body>` in each group instead of at `app/`. Navigating between root layouts triggers a **full page load**.
- Team ownership: one folder per product area.

Avoid two groups resolving to the same URL (e.g. `(a)/about` and `(b)/about`). That's a build error.

**Private folders** – a folder starting with an underscore, like `_components` or `_lib`, is **never routable**, even if it contains a `page.tsx`. It marks implementation details clearly and avoids clashes with future Next.js file conventions.

**Colocation** – only `page` and `route` files are public, so you *can* keep components, tests and styles next to routes even without `_`. Private folders just make the intent obvious. Many teams use `src/app` for routes and keep shared code in `src/components`, `src/lib`, etc.

**Follow-up:** groups affect layout nesting only, not URLs. If you need a URL prefix, use a normal folder.
