## Hints

- How can the URL change without the browser fetching a new page from the server?
- Which event fires when the user presses Back, and does `pushState` fire it?
- What happens when someone opens a deep link like `/settings/billing` directly?

## Answer

The **History API** lets an SPA change the URL and add history entries **without a full page load**. The app intercepts link clicks, updates the URL, and renders the matching view itself.

```js
// navigate
function navigate(url) {
  history.pushState({ scrollY: 0 }, '', url); // new entry; does NOT fire popstate
  render(location.pathname);
}

// Back / Forward
window.addEventListener('popstate', (e) => {
  render(location.pathname);                  // e.state holds what you pushed
});

// intercept same-origin link clicks
document.addEventListener('click', (e) => {
  const a = e.target.closest('a[href]');
  if (!a || a.origin !== location.origin || e.metaKey || e.ctrlKey || a.target) return;
  e.preventDefault();
  navigate(a.href);
});
```

- `pushState` adds an entry. `replaceState` updates the current one (good for filter or query changes that shouldn't flood history).
- `popstate` fires only on **history traversal** (Back/Forward, `history.back()`), not on push or replace.

**Pitfalls to handle:**

1. **Deep links and refresh:** the server must return the app shell for unknown paths (SPA fallback / rewrites). Otherwise users get a 404.
2. **Scroll restoration:** restore scroll on Back and reset it on new navigations. `history.scrollRestoration = 'manual'` gives you control.
3. **Focus and announcements (accessibility):** after a route change, move focus to the new page's `<h1>` or main region and update `document.title`. Screen readers otherwise don't notice anything changed.
4. **Modifier clicks:** let Ctrl/Cmd+click, middle click, `target="_blank"` and downloads behave natively.
5. **State size:** `history.state` is serialized with structured clone and has size limits. Store ids, not big objects.
6. **Race conditions:** cancel stale data fetches when the user navigates again (AbortController).

**Modern alternative: the Navigation API.** A single `navigation.addEventListener('navigate', e => e.intercept({ handler }))` catches links, form submissions and Back/Forward in one place, with built-in abort signals and focus and scroll handling. It now has broad browser support. Routers such as React Router, TanStack Router and the Next.js App Router hide all of this from you.

**Follow-up:** hash routing (`#/path`) needs no server configuration, but it gives ugly URLs, and the hash part is never sent to the server.
