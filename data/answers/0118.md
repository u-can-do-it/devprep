## Hints

- What is the OWASP Top 10 based on, and how often does it change?
- Which category covers "user A can read user B's data by changing an ID in the URL"?
- Why have dependencies and build pipelines become their own category?

## Answer

The **OWASP Top 10** is an awareness document listing the most critical web application security risk categories, based on real-world data and community surveys. It's updated every few years; the current edition is **2025**:

1. **Broken Access Control** – IDOR, missing server-side checks, privilege escalation, CORS misconfig. SSRF is now folded in here.
2. **Security Misconfiguration** – default credentials, verbose errors, open cloud buckets, missing security headers.
3. **Software Supply Chain Failures** – vulnerable or malicious dependencies, compromised build pipelines.
4. **Cryptographic Failures** – plaintext data, weak algorithms, poor key management, missing TLS.
5. **Injection** – SQL/NoSQL/OS command injection and XSS.
6. **Insecure Design** – missing threat modeling and abuse cases, flaws no implementation fix can solve.
7. **Authentication Failures** – credential stuffing, weak passwords, broken session handling, no MFA.
8. **Software or Data Integrity Failures** – unsigned updates, insecure deserialization, trusting unverified data.
9. **Security Logging & Alerting Failures** – attacks go unnoticed.
10. **Mishandling of Exceptional Conditions** – failing open, leaking info in errors, unhandled edge cases.

**What matters most for a typical web app:**

- **Access control** – enforce authorization on every endpoint and object, server-side, deny by default.
- **Injection** – parameterized queries, output encoding, CSP.
- **Dependencies** – lockfiles, `npm audit`/Dependabot/Renovate, pinned CI actions, SBOMs.
- **Configuration** – secure headers, no secrets in repos, least-privilege cloud IAM.
- **Authentication** – rate limiting, MFA/passkeys, proper password hashing.

**Tip:** don't recite the list mechanically – connect items to concrete practices you've applied (code review checklists, SAST/DAST in CI, threat modeling).

**Follow-up:** OWASP also publishes an **API Security Top 10**, where Broken Object Level Authorization (BOLA) is #1.
