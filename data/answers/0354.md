## Hints

- Does the file really need to pass through your application servers?
- What happens to a 4 GB upload if the connection drops at 90%?
- Why shouldn't you trust the file name or `Content-Type` sent by the client?

## Answer

**Small files (a few MB): `multipart/form-data`** directly to the API. Simple, but the app server buffers or streams the bytes, holds a connection open, and is limited by request size and timeouts.

**Preferred for anything sizeable: direct-to-storage with presigned URLs.**

1. Client asks the API for an upload: `POST /uploads { "filename": "cv.pdf", "size": 812345, "contentType": "application/pdf" }`.
2. API checks auth, quota and allowed types, creates an `upload` record (`pending`), and returns a **short-lived presigned URL** (S3, GCS, R2, Azure SAS) scoped to one object key it chooses.
3. Client `PUT`s the bytes straight to object storage.
4. Client calls `POST /uploads/{id}/complete` (or a storage event notification triggers processing).
5. A background job validates and processes the file, then marks it `ready`.

```ts
import { PutObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const key = `uploads/${userId}/${crypto.randomUUID()}`;
const url = await getSignedUrl(s3, new PutObjectCommand({
  Bucket: "user-uploads", Key: key, ContentType: "application/pdf",
}), { expiresIn: 300 });
```

**Large files:** use **multipart upload** (S3 parts uploaded in parallel and retried individually) or a resumable protocol like **tus**, so a dropped connection resumes instead of restarting.

**Security checklist:**

- Generate the storage key yourself; never use the client's filename as a path.
- Enforce max size (presigned POST policies support `content-length-range`).
- Verify the real type by inspecting content (magic bytes), not the extension or header.
- Scan for malware; strip metadata from images; re-encode images if you display them.
- Keep the bucket private; serve downloads via short-lived signed URLs or a CDN with `Content-Disposition: attachment` for untrusted types.
- Clean up abandoned `pending` uploads with lifecycle rules.

**Follow-up:** How would you show upload progress and let the user cancel?
