## Hints

- Which data structure maps an event name to its listeners, and why a `Set` rather than an array?
- What goes wrong if a listener removes itself (or adds another) while `emit` is iterating?
- How do you implement `once` without a special case inside `emit`?

## Answer

A classic 15-minute task. The goal is a small, correct observer implementation (#468) and a conversation about the edge cases.

```ts
type Listener<A extends unknown[]> = (...args: A) => void;

export class EventEmitter<Events extends Record<string, unknown[]>> {
  #listeners = new Map<keyof Events, Set<Listener<any>>>();

  on<K extends keyof Events>(event: K, fn: Listener<Events[K]>): () => void {
    let set = this.#listeners.get(event);
    if (!set) this.#listeners.set(event, (set = new Set()));
    set.add(fn);
    return () => this.off(event, fn);          // unsubscribe function, like addEventListener + AbortSignal
  }

  off<K extends keyof Events>(event: K, fn: Listener<Events[K]>): void {
    const set = this.#listeners.get(event);
    set?.delete(fn);
    if (set?.size === 0) this.#listeners.delete(event);   // don't leak empty sets
  }

  once<K extends keyof Events>(event: K, fn: Listener<Events[K]>): () => void {
    const wrapper: Listener<Events[K]> = (...args) => {
      this.off(event, wrapper);
      fn(...args);
    };
    return this.on(event, wrapper);
  }

  emit<K extends keyof Events>(event: K, ...args: Events[K]): boolean {
    const set = this.#listeners.get(event);
    if (!set || set.size === 0) return false;
    for (const fn of [...set]) fn(...args);    // copy: listeners may add/remove during emit
    return true;
  }

  listenerCount(event: keyof Events): number {
    return this.#listeners.get(event)?.size ?? 0;
  }
}

// usage
const bus = new EventEmitter<{ login: [user: { id: string }]; logout: [] }>();
const stop = bus.on('login', (user) => console.log(user.id));
bus.emit('login', { id: '42' });
stop();
```

**Points to make while coding:**

- **`Set` instead of array:** `off` is O(1) and the same function can't be registered twice. Node's `EventEmitter` allows duplicates; say which behaviour you chose.
- **Copy before iterating:** a listener that calls `off` on itself (what `once` does) would otherwise be skipped or cause the next listener to be missed. Spreading the set means listeners added during `emit` run on the next emit, which is the usual contract.
- **`once` as a wrapper:** keeps `emit` simple. Returning the wrapper's unsubscribe lets the caller cancel a `once` before it fires.
- **Errors:** if a listener throws, the loop stops and later listeners never run. Node behaves the same. Options: let it propagate (simplest), or `try/catch` each listener and report errors on an `'error'` event. Don't swallow silently.
- **Async listeners:** `emit` is synchronous and ignores returned promises. If you need to wait for handlers, make an `emitAsync` that `await`s `Promise.all` of the results.
- **Memory leaks:** a long-lived emitter holding listeners from components that were unmounted is the classic leak (#16). Always return or provide `off`; in React, unsubscribe in the effect cleanup (#33).
- **Typing:** the generic event map gives autocomplete for event names and typed payloads; `any` in the private map is fine because the public methods enforce the types.

**Alternatives:** in browsers and in Node 15+ `EventTarget` and `CustomEvent` exist natively, and Node has `node:events` (#293). You would use this hand-written one for a tiny bus, a store (#222), or when you want typed events without a dependency.

**Follow-up:** how would you add wildcard events (`'*'`) or namespaces (`'user:*'`)? (Keep a second set of pattern listeners and match on emit; or key by prefix.)
