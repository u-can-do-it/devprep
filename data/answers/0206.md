## Hints

- Before React 19, why couldn't a function component just accept `ref` like any other prop?
- What can a ref callback return in React 19?
- Should a parent get the raw DOM node, or a small API like `focus()` and `scrollToBottom()`?

## Answer

**React 19: `ref` is a normal prop for function components.** You no longer need `forwardRef`:

```tsx
function TextInput({ ref, ...props }: React.ComponentProps<'input'>) {
  return <input ref={ref} {...props} />;
}

// parent
const inputRef = useRef<HTMLInputElement>(null);
<TextInput ref={inputRef} />;
```

`forwardRef` still works, but it's on the path to deprecation, and a codemod can remove it. Class components still don't receive `ref` as a prop. For them it refers to the instance.

**Ref callbacks can return a cleanup function** (React 19). This makes it easy to attach observers to a node:

```jsx
<div ref={node => {
  const ro = new ResizeObserver(onResize);
  ro.observe(node);
  return () => ro.disconnect();   // runs when the node is removed
}} />
```

In TypeScript, a ref callback that implicitly returns something (`ref={n => (x = n)}`) is now a type error. Use a block body. Also, `useRef` now requires an initial argument.

**`useImperativeHandle`** is still useful when you want to expose a **limited API** instead of the raw DOM node. This hides implementation details and prevents parents from changing styles directly:

```tsx
function VideoPlayer({ ref }: { ref?: React.Ref<{ play(): void; pause(): void }> }) {
  const videoRef = useRef<HTMLVideoElement>(null);
  useImperativeHandle(ref, () => ({
    play: () => videoRef.current?.play(),
    pause: () => videoRef.current?.pause(),
  }), []);
  return <video ref={videoRef} src="/clip.mp4" />;
}
```

**Guideline:** refs are an escape hatch. Use them for focus, scrolling, measuring, media, and third-party widgets. For data, prefer props and state.
