## Hints

- Will a `try/catch` around `setTimeout(() => { throw ... })` catch the error? Why not?
- What happens to a rejected promise that nobody handles?
- How do you handle a failure of one item when running many requests in parallel?

## Answer

**Promises:** add `.catch()` at the end of the chain, or `.then(onOk, onErr)`. An error thrown inside any `then` turns into a rejection that travels down to the next `catch`.

**`async`/`await`:** wrap the `await` in `try/catch`. This only catches the rejection if you actually `await` the promise, or `return await` it inside the `try`.

```js
async function getUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`); // fetch doesn't reject on 4xx/5xx
    return await res.json();
  } catch (err) {
    throw new Error('Failed to load user', { cause: err }); // keep the original error
  } finally {
    hideSpinner();
  }
}
```

**Callbacks and timers:** `try/catch` only covers the *synchronous* part. An error thrown later inside a `setTimeout` callback or an event handler must be handled inside that callback. Node-style callbacks pass the error as the first argument.

**Unhandled rejections:** a promise that rejects with no handler attached.

- Browser: fires an `unhandledrejection` event on `window`.
- Node 15+: by default **crashes the process**. Use `process.on('unhandledRejection', ...)` only for logging, not for recovery.

**Good practices:**

- Throw `Error` objects, not strings. Use `cause` to chain errors.
- Use `Promise.allSettled` when you want partial results instead of failing everything.
- Use `AbortController` for cancellation and timeouts, and handle `AbortError` separately.
- Don't swallow errors with an empty `catch {}`. Handle the error, or log it and rethrow.
- Add a global safety net (error boundary, error tracking such as Sentry).
