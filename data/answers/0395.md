## Hints

- If you change `>` to `>=` in the code and every test still passes, what does that say about the tests?
- Coverage tells you a line ran. What would tell you a test would fail if that line were wrong?
- Why might running this on every commit of a large codebase be impractical?

## Answer

**Mutation testing** evaluates the **quality of your tests**. A tool makes many small, deliberate bugs (**mutants**) in your code, one at a time, and runs the tests against each:

- tests fail: the mutant is **killed** (good, your tests detect that bug),
- tests pass: the mutant **survived**, so a real bug like it would go unnoticed.

Typical mutations: `>` to `>=`, `+` to `-`, `&&` to `||`, `true` to `false`, removing a function call, returning `null`/empty, deleting a statement.

```ts
// Source
export const isAdult = (age: number) => age >= 18;

// Test (100% coverage)
expect(isAdult(30)).toBe(true);
expect(isAdult(5)).toBe(false);

// Mutant: age > 18  -> both tests still pass: SURVIVED
// Fix: add the boundary case
expect(isAdult(18)).toBe(true);
```

**Mutation score** = killed / (total − equivalent mutants). Unlike coverage, which only proves code **executed**, mutation score shows whether your **assertions** would catch changes in behavior. A suite with 100% coverage and no assertions has a mutation score near 0.

**Tools:** StrykerJS (JS/TS), mutmut or cosmic-ray (Python), PIT (Java), Stryker.NET.

**Costs and caveats:**

- **Slow**: it runs the test suite (or the relevant subset) once per mutant. Use incremental mode, run only on changed files in PRs, or run nightly.
- **Equivalent mutants**: some changes don't alter behavior (e.g. in dead code or redundant conditions) and can never be killed; they need manual review.
- Don't chase 100%: focus on core business logic, and treat surviving mutants as **review prompts**: missing boundary test, weak assertion, or actually unnecessary code.

**Follow-up:** When is it worth adopting? For critical domains (pricing, permissions, financial calculations) or to evaluate whether a high coverage number is real.
