## Hints

- What should happen to your layout when a user sets a larger default font size in the browser?
- What is `em` relative to, and why does nesting make it hard to predict?
- Why does `100vh` sometimes overflow on mobile browsers?

## Answer

| Unit | Relative to | Good for |
|---|---|---|
| `px` | A CSS pixel (not a device pixel) | Borders, hairlines, shadows |
| `rem` | The **root** (`html`) font size | Font sizes, spacing, layout. Respects the user's font setting |
| `em` | The element's **own** font size (for `font-size`, the parent's) | Spacing that should scale with the component's text, such as button padding |
| `%` | Usually the parent / containing block (`padding` and `margin` % are relative to its **width**) | Fluid widths |
| `vw` / `vh` | 1% of the viewport | Full-bleed sections |
| `svh` / `lvh` / `dvh` | Small, large or dynamic viewport height | Mobile full-height layouts |
| `ch` | Width of the "0" glyph | Readable line length: `max-width: 65ch` |
| `cqi` / `cqw` | 1% of a query container | Component-relative sizing |

**Key points:**

- **Use `rem` for font sizes.** If users raise their browser's default font size, `px` text ignores it (zoom still works), which is an accessibility problem.
- **`em` compounds.** A list nested in a list with `font-size: 0.8em` shrinks at every level. That's why `rem` is the default for type, with `em` for local, proportional spacing.
- **`100vh` on mobile** equals the *large* viewport, so content goes under the browser toolbar. Use `100dvh` (it changes as the toolbar shows and hides) or `100svh` (the stable, smallest height).

**`clamp(min, preferred, max)`** gives fluid values without media queries:

```css
h1 {
  /* at least 1.75rem, grows with viewport width, at most 3rem */
  font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem);
}
.container { width: min(100% - 2rem, 70rem); }
```

Keep a `rem` term in the preferred value. Pure `vw` font sizes don't respond to user zoom, which fails WCAG resize-text requirements.

**Follow-up:** `min()` and `max()` are the one-sided versions. `lh` and `rlh` units are relative to line height, which helps with vertical rhythm.
