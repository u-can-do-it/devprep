## Hints

- Without an error boundary, what happens to the whole app when one component throws during render?
- Does an error thrown in an `onClick` handler happen during rendering?
- Which lifecycle methods does an error boundary rely on, and is there a hook equivalent?

## Answer

An **error boundary** is a component that catches errors thrown while rendering its subtree, in lifecycle methods or in constructors. It shows a fallback UI instead of unmounting the whole app. Without one, an uncaught render error removes the entire root.

They still need to be **class components**, because they rely on `static getDerivedStateFromError` (to render a fallback) and `componentDidCatch` (to log the error). No hook equivalent exists yet. In practice, most teams use the **`react-error-boundary`** package:

```jsx
import { ErrorBoundary } from 'react-error-boundary';

<ErrorBoundary
  fallbackRender={({ error, resetErrorBoundary }) => (
    <div role="alert">
      <p>Something went wrong.</p>
      <button onClick={resetErrorBoundary}>Retry</button>
    </div>
  )}
  onError={(error, info) => reportToSentry(error, info.componentStack)}
  resetKeys={[userId]}
>
  <Profile userId={userId} />
</ErrorBoundary>
```

**Not caught:**

- Errors in **event handlers**. These don't happen during render, so use `try/catch` and set error state.
- **Async code** such as `setTimeout` or unawaited promises in effects.
- **Server-side rendering** errors.
- Errors thrown **inside the boundary itself**.

Errors in React 19 **Actions** (transitions) and rejected promises read with `use()` **do** go to the nearest boundary.

**Placement:** put one at the top level as a last resort, plus more granular ones around independent widgets, so a broken chart doesn't take down the page. In React 19, `createRoot` also accepts `onCaughtError` and `onUncaughtError` for centralized reporting.

**Follow-up:** in Next.js, an `error.tsx` file is an error boundary for a route segment.
