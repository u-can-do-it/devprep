## Hints

- When does a child component re-render if its parent re-renders?
- Why does passing a new arrow function as a prop defeat `React.memo`?
- What does memoization itself cost, and how do you know it's worth it?

## Answer

All three avoid recomputing or re-rendering by caching based on dependencies:

- **`useMemo(() => compute(a), [a])`** — caches a computed **value**.
- **`useCallback(fn, [a])`** — caches a **function reference** (same as `useMemo(() => fn, [a])`).
- **`React.memo(Component)`** — skips re-rendering a component if its props are shallowly equal to last time.

They work together: `React.memo` is useless if the parent passes a new object or function every render.

```jsx
const Row = React.memo(function Row({ item, onSelect }) { /* ... */ });

function List({ items }) {
  const [selected, setSelected] = useState(null);
  const onSelect = useCallback(id => setSelected(id), []);
  const sorted = useMemo(() => [...items].sort(byName), [items]);
  return sorted.map(i => <Row key={i.id} item={i} onSelect={onSelect} />);
}
```

**Use them when:**

- A calculation is genuinely expensive (measured, not guessed).
- A value/function is passed to a memoized child or used as an effect dependency.
- Rendering a big list or heavy subtree that receives unchanged props.

**Don't use them when:**

- The computation is cheap — comparing deps costs about as much as recomputing.
- The child isn't memoized anyway.
- You could fix the problem structurally: move state down, or pass children as props so they don't re-render.

Measure with the React DevTools Profiler first.

**Follow-up:** the **React Compiler** (stable since late 2025) auto-memoizes components and hooks, making most manual `useMemo`/`useCallback` unnecessary in projects that adopt it.
