## Hints

- What identifies one specific TCP connection between two machines?
- What's the difference between listening on `127.0.0.1` and on `0.0.0.0`?
- What does `EADDRINUSE` tell you?

## Answer

An **IP address** identifies a machine (or a network interface); a **port** (0–65535) identifies a specific **process/service** on it. Ports below 1024 are well-known (80 HTTP, 443 HTTPS, 22 SSH, 5432 Postgres) and need extra privileges to bind on Linux; clients use random **ephemeral ports** for their side of a connection.

A **socket** is the OS endpoint a program uses to send and receive data: protocol + IP + port. A server creates a **listening socket**; each accepted client gets its own connected socket. A TCP connection is uniquely identified by the **4-tuple** (client IP, client port, server IP, server port), which is why one server port can handle thousands of clients.

```js
import http from 'node:http';
http.createServer((req, res) => res.end('ok'))
  .listen(3000, '127.0.0.1');   // only reachable from this machine
// .listen(3000, '0.0.0.0')     // all IPv4 interfaces: reachable from the network
```

**Why `localhost:3000` works but others can't reach it:**

- The app is bound to **`127.0.0.1`** (loopback), which only accepts local connections. Many dev servers default to this; pass `--host 0.0.0.0` (Vite, `uvicorn --host 0.0.0.0`) to expose it.
- In **Docker**, the app inside the container must listen on `0.0.0.0`, and the port must be published (`-p 3000:3000`), otherwise nothing outside the container reaches it.
- A **firewall** or security group blocks the port.

**`EADDRINUSE`**: another process already listens on that IP/port. Find it with `lsof -i :3000` or `ss -ltnp`.

**Follow-up:** What's a Unix domain socket? A socket addressed by a file path instead of IP/port, used for fast local communication (e.g. Nginx to a local app server, Docker daemon).
