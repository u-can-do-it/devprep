## Hints

- What does Figma's auto layout map to in CSS?
- The design shows a card with a short title. What happens with a 120-character title, or in German?
- Which states does a static mockup usually not show?

## Answer

**1. Read the design as a system, not as pixels**

- Use **Dev Mode** to inspect, but map values to **tokens** and existing components, not raw hex and pixel values. `#2563EB` should become `var(--color-bg-action)`, and a 16px gap should become a spacing token.
- **Auto layout maps to Flexbox:** direction → `flex-direction`, gap → `gap`, padding → `padding`, "hug contents" → intrinsic width, "fill container" → `flex: 1` or `width: 100%`. Fixed frames often mean `max-width`, not `width`.
- Check whether the component **already exists** in the library (Code Connect links Figma components to code). A new variant is better than a near-duplicate component.

**2. Make it responsive and robust**

- Find out which breakpoints were designed and what should happen *between* them. Use fluid layouts (`flex-wrap`, Grid `auto-fit`, `clamp()`, container queries) instead of a fixed layout per breakpoint.
- Test with **real content**: long names, missing images, 0 and 1,000 items, translated text 30% longer, 200% browser zoom, a narrow 320px viewport.
- Use `rem` for type and spacing so user font settings work.

**3. Fill in the states the mockup doesn't show** (and ask the designer to confirm them):

- hover, focus-visible, active, disabled
- loading (skeleton or spinner), empty, error, partial data
- validation messages and long error text
- overflow: truncation with a tooltip, or wrapping
- keyboard focus order and screen-reader labels for icon-only buttons
- dark mode and RTL if supported

**4. Verify the result**

- Compare side by side, or use an overlay tool, at the designed widths. "Pixel-accurate" means matching the **spacing, type and token values**, not 1px rendering differences between Figma and browsers.
- Run an axe check and check contrast ratios. If the design fails WCAG contrast or has tiny targets, raise it early instead of shipping it.
- Add a Storybook story for each state so design review happens on the real component.

**When the design is unclear or not feasible:** ask early and show options ("this will wrap like this on mobile, or we truncate"), propose using an existing component, and record the decision in the ticket. Don't silently invent UX.

**Follow-up:** the design uses a font weight and a shadow that aren't in the token set. What do you do?
