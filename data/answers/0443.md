## Hints

- What does `JSON.parse` (or `response.json()`) do with malformed input, and what type does it return?
- After parsing succeeds, what guarantees do you have about the shape of the data?
- What can go wrong if you deep-merge parsed JSON into an existing object?

## Answer

Parsing is two separate problems: **is it valid JSON**, and **is it the data I expect**.

**1. Syntax errors.** `JSON.parse` throws a `SyntaxError`, and `await res.json()` rejects with one. Handle it at the boundary and check the response first:

```ts
const res = await fetch('/api/user');
if (!res.ok) throw new Error(`HTTP ${res.status}`);
if (!res.headers.get('content-type')?.includes('application/json')) {
  throw new Error('Expected JSON'); // e.g. an HTML error page from a proxy
}
const raw: unknown = await res.json();
```

**2. Shape validation.** `JSON.parse` returns `any`, and a TypeScript type annotation or `as User` checks nothing at runtime. Treat the result as `unknown` and validate it with a schema library (Zod, Valibot, ArkType) or, in Python, Pydantic:

```ts
const User = z.object({ id: z.number(), email: z.string().email() });
const user = User.parse(raw); // throws with a readable error if the shape is wrong
```

Validate **everything that crosses a trust boundary**: request bodies, third-party APIs, `localStorage`, message queues, files.

**3. Security pitfalls:**
- **Never `eval`** JSON or build it by string concatenation; use `JSON.parse` and `JSON.stringify`.
- **Prototype pollution:** `JSON.parse('{"__proto__": {"isAdmin": true}}')` creates a harmless own key, but a naive recursive `merge(target, parsed)` then writes into `Object.prototype`. Use schema validation that strips unknown keys, or reject `__proto__`/`constructor`/`prototype` keys.
- **Size limits:** cap request body size on the server (e.g. Express `express.json({ limit: '100kb' })`), because parsing is synchronous and a huge payload can block the event loop.

**4. Precision.** JSON numbers become JS `number`s, so integers above `Number.MAX_SAFE_INTEGER` (2^53 − 1) silently lose precision. APIs usually send large IDs as **strings** for this reason.
