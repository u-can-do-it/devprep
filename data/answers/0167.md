## Hints

- What has to be true about a function for caching its results to be safe?
- How do you build a cache key from several arguments, and what goes wrong when arguments are objects?
- What happens to memory if the cache never removes anything?

## Answer

Memoization caches a function's result for given inputs so that repeated calls skip the work. It is safe only for **pure** functions: the same inputs always give the same output, and there are no side effects.

A version with a configurable key and a bounded LRU cache. A `Map` remembers insertion order, so the oldest entry comes first:

```js
function memoize(fn, { key = (...args) => JSON.stringify(args), max = 500 } = {}) {
  const cache = new Map();
  return function (...args) {
    const k = key(...args);
    if (cache.has(k)) {
      const v = cache.get(k);
      cache.delete(k); cache.set(k, v);       // mark as recently used
      return v;
    }
    const v = fn.apply(this, args);
    cache.set(k, v);
    if (cache.size > max) cache.delete(cache.keys().next().value); // evict oldest
    return v;
  };
}

const slowSquare = (n) => { /* expensive */ return n * n; };
const fastSquare = memoize(slowSquare);
```

**Pitfalls:**

- **Cache keys:** `JSON.stringify` is slow for large arguments. It also mixes some values up (`undefined` and `null` in arrays both become `null`) and ignores functions. For a single object argument, key on identity with a `WeakMap` so entries can be garbage-collected.
- **Unbounded growth:** caching every input leaks memory. Add a size limit (LRU) or a TTL.
- **Async functions:** caching the promise deduplicates concurrent calls, which is good. But remove rejected promises, or one failure stays cached forever.
- **Recursion:** for something like `fib`, the inner recursive calls must go through the memoized version.
- **Stale data:** results that depend on outside state (time, the database) need invalidation.

Measure before memoizing. Hashing the key plus the cache lookup can cost more than a cheap computation.

**Follow-up:** React's `useMemo` and the React Compiler memoize per component render, which is a different scope from a module-level cache.
