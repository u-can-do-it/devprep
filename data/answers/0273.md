## Hints

- How could the browser animate between two DOM states it never shows at the same time?
- What does the browser capture before your update runs, and what does it render after?
- How do you make one element (a thumbnail) appear to morph into another (a hero image)?

## Answer

The **View Transitions API** animates between two UI states with very little code. The browser:

1. **Captures a snapshot** of the current state.
2. **Runs your DOM update.**
3. Builds a tree of pseudo-elements holding the **old** and **new** views, and **animates between them** with CSS (a cross-fade by default).

**Same-document (SPA) transitions**

```js
function showDetail(item) {
  if (!document.startViewTransition) return render(item); // fallback
  document.startViewTransition(() => render(item));       // can be async
}
```

**Morphing shared elements:** give matching elements the same `view-transition-name` in the old and new states. The browser animates their position and size between the two:

```css
.thumb.active, .hero-image { view-transition-name: product-image; }

::view-transition-old(root),
::view-transition-new(root) { animation-duration: 250ms; }
```

Each name must be **unique** on the page at any moment. `view-transition-class` lets you style many named elements together, and newer browsers can generate names automatically (`match-element`).

**Cross-document (MPA) transitions** work between full page loads on the same origin, with no JavaScript:

```css
@view-transition { navigation: auto; } /* add to both pages */
```

Events such as `pageswap` and `pagereveal` let you customize the transition per navigation. This gives multi-page sites SPA-like transitions.

**Support:** same-document transitions work in all major engines. Cross-document support is in Chromium and Safari, and is newer elsewhere. Treat both as **progressive enhancement**: without support, the update still happens, just without animation.

**Framework integration:** React has an experimental `<ViewTransition>` component and Next.js has an opt-in for it. Astro and SvelteKit have built-in helpers.

**Pitfalls:**

- During the transition the page shows snapshots and isn't interactive. Keep transitions short.
- Respect `prefers-reduced-motion`.
- Duplicate `view-transition-name`s make the transition fail.

**Follow-up:** `transition.finished`, `ready` and `updateCallbackDone` promises let you coordinate focus management after the swap.
