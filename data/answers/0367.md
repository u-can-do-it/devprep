## Hints

- How many keys are involved in each approach, and who is allowed to know them?
- Why doesn't HTTPS just use asymmetric encryption for the whole connection?
- If you sign something with a private key, who can verify it and what does that prove?

## Answer

**Symmetric encryption** uses **one shared secret key** for both encryption and decryption (AES-256-GCM, ChaCha20-Poly1305). It is very fast and suited to bulk data, but both sides need the same key, so key distribution is the hard part.

**Asymmetric (public-key) cryptography** uses a **key pair**: a public key you can share with anyone and a private key you keep. Depending on the algorithm it supports key exchange (ECDH/X25519), encryption (RSA-OAEP) and signatures (ECDSA, Ed25519, RSA-PSS). It solves key distribution but is much slower.

Real systems are **hybrid**. TLS uses asymmetric crypto to authenticate the server (certificate signature) and agree on a shared secret (ECDHE), then switches to fast symmetric encryption for the data. Modern browsers already negotiate a post-quantum hybrid key exchange (X25519 + ML-KEM) for this step.

**Digital signature:** the signer computes a hash of the message and signs it with their **private key**; anyone with the **public key** can verify it. It proves **integrity** (not modified) and **authenticity** (made by the key holder), and gives non-repudiation. It does **not** hide the content.

```python
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey

priv = Ed25519PrivateKey.generate()
sig = priv.sign(b"release-1.4.2.tar.gz digest")
priv.public_key().verify(sig, b"release-1.4.2.tar.gz digest")  # raises if tampered
```

Where you meet them: JWT `HS256` (symmetric HMAC) vs `RS256`/`ES256` (asymmetric, so many services can verify without being able to issue tokens), SSH keys, signed commits and package provenance.

**Follow-up:** Encryption in transit (TLS) vs at rest (disk/DB/KMS envelope encryption) — you need both, and at-rest encryption doesn't help if the app itself is compromised.
