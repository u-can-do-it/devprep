## Hints

- What does `({}).__proto__` point to, and what happens if you write a property onto it?
- What does a naive recursive `merge(target, JSON.parse(body))` do with a key named `__proto__`?
- Which data structures don't inherit from `Object.prototype` at all?

## Answer

In JavaScript almost every object inherits from `Object.prototype`. **Prototype pollution** is when an attacker gets code to write properties onto that shared prototype (or another built-in one), usually through `__proto__`, `constructor.prototype` or `prototype` keys in user-controlled input. After that, **every object** in the process "has" the injected property.

```js
function merge(target, src) {
  for (const key in src) {
    if (typeof src[key] === 'object') merge(target[key] ??= {}, src[key]);
    else target[key] = src[key];
  }
}
merge({}, JSON.parse('{"__proto__": {"isAdmin": true}}'));
({}).isAdmin; // true, for every object in the process
```

Impact depends on "gadgets" in the code: auth bypass (`if (user.isAdmin)`), DoS, changed options in libraries (template engines, `child_process` `shell`/`env` options), sometimes **remote code execution** on the server. On the client it can lead to DOM XSS via polluted config objects.

Typical sinks: deep merge/clone/set-by-path helpers, query-string parsers that support nested keys (`?a[__proto__][x]=1`), and config loaders.

Defenses:

- **Validate input with a schema** (Zod, Ajv with `additionalProperties: false`) before merging it anywhere.
- **Block dangerous keys** (`__proto__`, `constructor`, `prototype`) in any recursive merge/set helper, and keep libraries (lodash, qs, etc.) patched.
- Use **`Map`** for user-keyed data, or **`Object.create(null)`** objects with no prototype.
- Check own properties with `Object.hasOwn(obj, key)`, not `obj[key]` or `in`.
- **Harden the runtime**: `Object.freeze(Object.prototype)` early at startup (test first, some libraries break), or Node's `--disable-proto=delete` flag to remove the `__proto__` accessor.

**Follow-up:** Why doesn't `JSON.parse` itself pollute? It creates an own property literally named `__proto__`; the damage happens when a later merge assigns it through the setter.
