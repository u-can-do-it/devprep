## Hints

- Which collection would you use to check "have I seen this ID already?" a million times?
- What happens inside a `List<T>` when it runs out of capacity?
- If a method returns `List<T>`, what can the caller do to your data that it couldn't with `IReadOnlyList<T>`?

## Answer

**The main collections:**

| Collection | What it is | Lookup | Add | Remove | Use for |
|---|---|---|---|---|---|
| `T[]` | fixed-size array | O(1) by index | can't grow | can't | fixed data, hot paths |
| `List<T>` | resizable array | O(1) by index, O(n) `Contains` | O(1) amortized at end | O(n) (shifts items) | default ordered list |
| `Dictionary<TKey, TValue>` | hash table | O(1) average by key | O(1) average | O(1) average | lookup by key |
| `HashSet<T>` | hash table of keys only | O(1) average `Contains` | O(1) average | O(1) average | uniqueness, membership tests |
| `Queue<T>` / `Stack<T>` | FIFO / LIFO | — | O(1) | O(1) | BFS, work lists, undo |
| `SortedDictionary<K, V>` | balanced tree | O(log n) | O(log n) | O(log n) | keys always sorted |
| `LinkedList<T>` | doubly linked list | O(n) | O(1) at a known node | O(1) at a known node | rarely the right choice |

`List<T>` doubles its internal array when full: most adds are O(1), an occasional one copies everything. Pass a capacity (`new List<T>(1000)`) when you know the size. Dictionaries and sets need a good `GetHashCode` and `Equals` on the key (#578); never mutate an object while it's a key.

```csharp
var seen = new HashSet<int>();
foreach (var id in ids)
    if (!seen.Add(id)) Console.WriteLine($"duplicate {id}");     // Add returns false if present

var byEmail = users.ToDictionary(u => u.Email, StringComparer.OrdinalIgnoreCase);
if (byEmail.TryGetValue(email, out var user)) { }                 // one lookup, no KeyNotFoundException
```

Thread-safe variants live in `System.Collections.Concurrent` (#592); immutable ones in `System.Collections.Immutable` and the faster read-only `FrozenDictionary`/`FrozenSet`.

**Which interface to expose:**

| Interface | Gives the caller |
|---|---|
| `IEnumerable<T>` | iteration only; may be lazy (a LINQ query, #572), so it may run each time it's enumerated |
| `IReadOnlyCollection<T>` | iteration + `Count` |
| `IReadOnlyList<T>` | + index access; the materialized, read-only result |
| `ICollection<T>` | iteration + `Count`, plus `Add`, `Remove`, `Clear` (no index access) |
| `IList<T>` | + insert and remove at an index |

Guidelines: **accept** the most general type you need (`IEnumerable<T>` if you only loop once); **return** something specific and honest. Return `IReadOnlyList<T>` for a finished result so callers can't modify your internal list and know it won't re-run a query. Don't return `null` collections; return an empty one (`[]` collection expression, `Array.Empty<T>()`).

**Follow-up:** why can't you remove items from a `List<T>` inside a `foreach` over it? (The enumerator detects the change and throws `InvalidOperationException`. Use `RemoveAll(predicate)`, or loop backwards with an index.)
