## Hints

- What does `await fetch(url)` give you: your data, or something else?
- How many `await`s do you need to get parsed JSON?
- Does a 404 response make the promise reject?
- What happens if you call `res.json()` on a `204 No Content` response?

## Answer

`fetch` happens in **two steps**. It resolves to a **`Response` object** as soon as the headers arrive. The body is a stream that you read with a second async call:

```js
const res = await fetch('/api/users');   // 1. headers: status, ok, headers
const users = await res.json();          // 2. body, parsed as JSON
```

**What the `Response` gives you:**

| Property / method | What it is |
|---|---|
| `res.ok` | `true` for status 200–299 |
| `res.status`, `res.statusText` | `404`, `"Not Found"` |
| `res.headers.get('Content-Type')` | read a response header |
| `res.json()`, `res.text()`, `res.blob()`, `res.formData()`, `res.arrayBuffer()` | read the body. Each returns a Promise |

The body can be read **only once**: a second `res.json()` throws. Use `res.clone()` if you need it twice.

**`fetch` doesn't reject on HTTP errors.** A 404 or 500 is still a successful *HTTP exchange*, so the promise resolves with `res.ok === false`. It only rejects on a **network failure, a CORS error, or an abort**. You have to check `res.ok` yourself:

```js
async function getJson(url, options) {
  const res = await fetch(url, options);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.status === 204 ? null : res.json();   // 204 has no body: res.json() would throw
}
```

**Sending data:**

```js
await fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Ann' }),         // fetch doesn't stringify for you
});
```

**Other options you'll use:**

- `signal: controller.signal` to cancel the request, or `AbortSignal.timeout(5000)` for a timeout
- `credentials: 'include'` to send cookies cross-origin (the default is `'same-origin'`)
- `cache: 'no-store'`
- When the body is `FormData`, **don't** set `Content-Type`: the browser adds the multipart boundary itself.

**What your libraries did for you:**

| | `fetch` | axios | React Query `queryFn` |
|---|---|---|---|
| Parse JSON | you call `res.json()` | automatic: `res.data` | whatever your `queryFn` returns |
| Reject on 4xx/5xx | **no**, check `res.ok` | yes | only if your `queryFn` throws |
| Stringify the body | you call `JSON.stringify` | automatic | — |

A common React Query bug follows from this: `queryFn: () => fetch(url).then((r) => r.json())`. With that code, a 404 lands in `data` instead of `error`. Throw when `!res.ok`.

**Same thing with `.then()`:**

```js
fetch('/api/users')
  .then((res) => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();             // return it, so the next .then gets the parsed data
  })
  .then((users) => console.log(users))
  .catch((err) => console.error(err));
```
