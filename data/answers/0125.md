## Hints

- What happens to the build cache when you change one line of source code?
- Why does the order of `COPY` and `RUN` instructions matter?
- Does the production image need the compiler and dev dependencies?

## Answer

Each filesystem-changing instruction (`RUN`, `COPY`, `ADD`) creates a **layer**. Layers are cached and reused: if an instruction and its inputs haven't changed, Docker reuses the cached layer — but once one layer changes, **all later layers rebuild**.

So order from least to most frequently changing: copy dependency manifests and install first, then copy source code. That way editing code doesn't re-run `npm ci`.

**Multi-stage builds** use several `FROM` stages; you build in a heavy stage and copy only the output into a minimal runtime image. Benefits: much smaller images, no build tools or source in production (smaller attack surface), and one Dockerfile for the whole flow.

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node
CMD ["node", "dist/server.js"]
```

Other tips: use a `.dockerignore` (exclude `node_modules`, `.git`), combine related `RUN` commands and clean caches in the same layer, and run as a non-root user.

**Pitfall:** deleting a file in a later layer doesn't shrink the image — it still exists in the earlier layer.
