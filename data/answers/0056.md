## Hints

- Which of these is sent to the server automatically with every request?
- Which one survives closing the tab, and which one is shared across tabs?
- Where would you store an auth token so that injected JavaScript can't read it?

## Answer

| | Cookies | `localStorage` | `sessionStorage` | IndexedDB |
|---|---|---|---|---|
| Capacity | ~4 KB per cookie | ~5–10 MB per origin | ~5 MB per origin | Large (a share of disk) |
| Lifetime | Until `Expires`/`Max-Age`, or session | Until cleared | Until the tab closes | Until cleared |
| Scope | Domain/path; sent to server | Origin, all tabs | Origin **and** single tab | Origin, all tabs |
| Sent with requests | **Yes, automatically** | No | No | No |
| API | `document.cookie` / `Set-Cookie` header | Sync, strings only | Sync, strings only | **Async**, structured data, indexes, transactions |
| Available in workers | No (except via headers) | No | No | Yes |

**When to use:**

- **Cookies** — session identifiers and anything the server must see. Set `HttpOnly` (JS can't read it — protects against XSS theft), `Secure`, and `SameSite=Lax/Strict` (CSRF protection).
- **`localStorage`** — small, non-sensitive preferences: theme, UI state, last-viewed tab.
- **`sessionStorage`** — per-tab, temporary state: multi-step form drafts.
- **IndexedDB** — larger structured data and offline apps (with a Service Worker), caching API data. Use a wrapper like `idb` or Dexie.

```js
localStorage.setItem('theme', JSON.stringify({ mode: 'dark' }));
const theme = JSON.parse(localStorage.getItem('theme') ?? 'null');
```

**Security pitfall:** don't store auth tokens (JWTs) in `localStorage` — any XSS can read them. An `HttpOnly` cookie is safer.

**Follow-up:** Web Storage is synchronous and blocks the main thread; browsers may evict storage under pressure unless you call `navigator.storage.persist()`.
