## Hints

- What React component does Next.js wrap around your `page` when you add `loading.tsx`?
- Why can the loading state appear *instantly* on click, before the server has responded?
- Does a `loading.tsx` help if the slow query lives in the `layout.tsx` of the same folder?

## Answer

`loading.tsx` is a file convention that gives a route segment an **instant loading state**. Next.js wraps that segment's `page` (and its child segments) in a Suspense boundary:

```tsx
<Layout>
  <Suspense fallback={<Loading />}>
    <Page />
  </Suspense>
</Layout>
```

**What you get:**

- **Streaming:** the layout and fallback are sent first, and the page's HTML streams in when its data resolves.
- **Instant navigation:** for dynamic routes, `<Link>` prefetches the route *down to the nearest `loading.tsx`*. On click, the router shows the layout and skeleton right away, with no server round trip, then swaps in the page.
- **Interruptible navigation:** shared layouts stay interactive while the new segment loads, and the user can navigate away.
- With Cache Components, the fallback becomes part of the route's static shell.

**Limitations (where manual `<Suspense>` is better):**

- **Coarse:** the whole page is one fallback. If the page has fast and slow parts, the fast parts wait too. Wrap only the slow components in your own `<Suspense>`, so critical content (title, price) renders immediately.
- **Doesn't cover its own layout:** the boundary sits *inside* `layout.tsx` of the same folder, so slow data in that layout blocks the segment. Move the fetch into the page, or into a component with its own boundary.
- **Status code:** once streaming starts, the response is already `200`. A `notFound()` or `redirect()` thrown later is handled client-side, not as a real 404 or 3xx.
- **Same-route updates:** changing only `searchParams` may not show the fallback again. Use `<Suspense key={query}>` or `useTransition` pending state.
- **Infrastructure:** a buffering reverse proxy (nginx default) delivers everything at once, so the benefit disappears.

**Good practice:** make the skeleton match the final layout (no CLS), keep it light, and add `loading.tsx` at the segments users navigate between most.

**Follow-up:** bots get the fully rendered HTML, so streaming doesn't hurt SEO.
