## Hints

- Besides its value, which hidden flags does every property have?
- What are the defaults when you create a property with `Object.defineProperty` instead of assigning it?
- When is a getter a better fit than a stored value?

## Answer

Every property has a **descriptor**. There are two kinds:

- **Data descriptor:** `{ value, writable, enumerable, configurable }`
- **Accessor descriptor:** `{ get, set, enumerable, configurable }`

What the flags control:

- `writable`: whether the value can be changed.
- `enumerable`: whether the property appears in `for...in`, `Object.keys`, spread and JSON.
- `configurable`: whether the property can be deleted, or its descriptor changed.

Properties created by normal assignment have all flags `true`. Properties created with `Object.defineProperty` default every flag to **`false`**.

```js
const cfg = {};
Object.defineProperty(cfg, 'version', { value: '1.0', enumerable: true });
cfg.version = '2.0';   // silently ignored (TypeError in strict mode)
Object.getOwnPropertyDescriptor(cfg, 'version');
// { value: '1.0', writable: false, enumerable: true, configurable: false }
```

**Getters and setters** run code when a property is read or written. They are useful for derived values, validation, lazy computation and backward-compatible APIs:

```js
class Temperature {
  #c = 0;
  get fahrenheit() { return this.#c * 9 / 5 + 32; }
  set celsius(v) {
    if (typeof v !== 'number') throw new TypeError('number expected');
    this.#c = v;
  }
}
```

**Pitfalls:**

- A getter that reads its own name (`get x() { return this.x; }`) recurses forever. Store the value under another name or in a private field.
- A property with a setter but no getter reads as `undefined`.
- Getters should be cheap and free of side effects. Code that reads a property doesn't expect it to do heavy work.

Frameworks have used descriptors for change tracking (Vue 2 reactivity was built on `defineProperty`; Vue 3 moved to `Proxy`).
