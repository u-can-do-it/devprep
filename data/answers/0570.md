## Hints

- After `catch (Exception ex) { throw ex; }`, where does the stack trace say the error happened?
- Does `finally` run when the `try` block returns early?
- What does the compiler turn a `using` declaration into, and why does a file handle or database connection need it?

## Answer

**The basics:**

```csharp
try
{
    var text = File.ReadAllText(path);
    return Parse(text);
}
catch (FileNotFoundException ex)                       // most specific first
{
    _log.LogWarning(ex, "Config {Path} missing", path);
    return Config.Default;
}
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)   // exception filter
{
    return null;
}
finally
{
    // always runs: after success, after a catch, after return, after an unhandled throw
}
```

- Catch blocks are checked **top to bottom**; put specific types before general ones.
- **Exception filters** (`when`) decide whether to catch without unwinding the stack first, so a filter that returns `false` leaves the original stack intact for debugging.
- Catch only what you can **handle**. Don't swallow exceptions with an empty `catch`; let unexpected ones bubble up to a global handler (#587).
- Don't use exceptions for normal control flow (e.g. "user not found" in a hot path); they're relatively expensive. Use `TryParse`-style methods or results.

**`throw` vs `throw ex`:**

```csharp
catch (Exception ex)
{
    _log.LogError(ex, "Failed");
    throw;        // rethrows, keeps the original stack trace
    // throw ex;  // resets the stack trace to this line: you lose where it really failed
    // throw new OrderException("Could not save order", ex);   // wrap: keep the original as InnerException
}
```

**`IDisposable` and `using`:** the GC frees **memory**, but not unmanaged resources like file handles, sockets, database connections or locks, and it frees memory only at some later point. Types holding such resources implement `IDisposable.Dispose()` to release them **deterministically**. `using` guarantees `Dispose()` is called, even when an exception is thrown; it compiles to `try`/`finally`.

```csharp
using (var conn = new SqlConnection(cs))   // using statement: disposed at the end of the block
{
    conn.Open();
}

using var stream = File.OpenRead(path);    // using declaration (C# 8): disposed at the end of the scope
await using var db = new AppDbContext();   // IAsyncDisposable: DisposeAsync
```

Rules: dispose what you create; don't dispose what you receive (e.g. from DI, the container owns it). Implementing the full dispose pattern with finalizers is a senior topic (#591).

**Follow-up:** what happens if `finally` itself throws? (Its exception replaces the original one, which is lost. Keep `finally` blocks simple.)
