## Hints

- What is a primary constructor parameter: a field, a property, or something else? Can you reassign it?
- What type does `[1, 2, 3]` have, and what decides that?
- Where did a property's backing field live before the `field` keyword, and why did that make one line of validation annoying?

## Answer

A new C# version ships every November with .NET (#560). Interviewers ask this to see whether you keep up and, more importantly, whether you can say *what problem* a feature solves.

**C# 12 (.NET 8, 2023)**

- **Primary constructors** on classes and structs put constructor parameters in scope for the whole type. They are **captured parameters**, not fields or properties (records are the exception: there they become public properties), so they're mutable, invisible to reflection and serializers (#607), and the compiler warns (CS9124) when you assign one to a field *and* keep using the parameter, because the value is then stored twice. Use them for DI (#581); keep an explicit `readonly` field when you need that guarantee.

```csharp
public sealed class OrderService(IOrderRepository repo, ILogger<OrderService> log)
{
    public Task<Order?> GetAsync(int id, CancellationToken ct) => repo.FindAsync(id, ct);
}
```

- **Collection expressions**: `[1, 2, 3]`, `[]`, `[..first, ..second]` build arrays, `List<T>`, `Span<T>`, `ImmutableArray<T>` and any type with a collection builder. The **target type** decides what is built, so `var x = [1, 2];` doesn't compile. They replace `new List<int> { … }`, `Array.Empty<T>()` and `Concat` chains, and the compiler picks an efficient construction (exact capacity, no intermediate copies).
- Also: `using Point = (int X, int Y);` aliases for any type, default values for lambda parameters, `ref readonly` parameters (#573).

**C# 13 (.NET 9, 2024)**

- **`params` collections**: `params ReadOnlySpan<T>`, `params IEnumerable<T>`, `params List<T>`. A span-based `params` method allocates nothing for the arguments, and the BCL added such overloads (`string.Join`, `Path.Combine`, `Task.WhenAll`), so existing calls got cheaper without a source change.
- **`System.Threading.Lock`**: `lock (_lock)` on a `Lock` compiles to `EnterScope()` instead of `Monitor`; faster, and the field's type documents its purpose (#592). Don't pass a `Lock` around as `object`: that path falls back to `Monitor` and doesn't exclude the other (CS9216 warns).
- `ref` locals and `ref struct`s in `async` methods and iterators, as long as they don't live across an `await` or `yield` (#593); `allows ref struct` constraints (#577); partial properties; implicit `^1` index in object initializers; the `\e` escape.

**C# 14 (.NET 10, 2025)**

- **`field`**: the auto-property's backing field without declaring it.

```csharp
public string Name { get; set => field = value.Trim(); }
public int Retries { get; init => field = value is >= 0 and <= 10 ? value : throw new ArgumentOutOfRangeException(nameof(value)); }
```

Before, one line of validation forced a manual backing field and a full property (#565). A member of your own named `field` now needs `@field` or `this.field`.

- **Extension members**: an `extension` block groups extension methods, **properties**, operators and static members for a receiver:

```csharp
public static class EnumerableExtensions
{
    extension<T>(IEnumerable<T> source)
    {
        public bool IsEmpty => !source.Any();                                 // an extension property
        public IEnumerable<T> WhereNotNull() => source.Where(x => x is not null);
    }
}
if (orders.IsEmpty) { }
```

Classic `this`-parameter extension methods still work and compile to the same thing (#572).

- **Null-conditional assignment**: `customer?.Address = address;` and `stats?.Count += 1;` assign only when the receiver isn't `null` (#569).
- Also: `nameof(List<>)` for unbound generics, first-class `Span<T>` conversions, lambda parameter modifiers without types (`(ref x) => …`), partial constructors and events, user-defined compound assignment operators.

**Still worth knowing from C# 10 and 11:** file-scoped namespaces and global usings, `record struct` (#578), raw string literals (`"""…"""`) and UTF-8 literals (`"…"u8`), `required` members (#565), list patterns (#580), static abstract interface members and generic math (#577).

**How to say it:** name two or three features with the problem they solve ("primary constructors removed DI boilerplate, collection expressions replaced four ways of building a list, `field` made validated auto-properties one-liners") and one trap (primary constructor parameters are mutable and invisible to serializers). That beats reciting release notes.

**Follow-up:** a teammate replaces `private readonly IRepo _repo;` with a primary constructor parameter, and a method later does `repo = new FakeRepo();` "just for a test". Why does that compile? (Captured parameters aren't `readonly`, so nothing stops reassignment, and every other method now sees the fake. Keep an explicit `readonly` field where immutability matters.)
