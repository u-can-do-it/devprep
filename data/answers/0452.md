## Hints

- When does `useSelector` run, and how does it decide whether to re-render?
- What does `state.todos.filter(...)` return on every call, even if nothing changed?
- What is a memoized selector's cache size, and what happens when two components call it with different arguments?

## Answer

`useSelector(selector)` subscribes the component to the store. **After every dispatched action**, React-Redux runs the selector and compares the new result with the previous one using **reference equality (`===`)** by default. If the result differs, the component re-renders.

So a selector that **builds a new object or array** re-renders the component on every action, even unrelated ones:

```ts
// Bad: new array every time → re-renders on any action anywhere in the app
const done = useSelector((s: RootState) => s.todos.filter((t) => t.done));

// Bad: new object every time
const { a, b } = useSelector((s: RootState) => ({ a: s.x.a, b: s.y.b }));
```

React-Redux 9 warns about this in development ("Selector returned a different result when called with the same parameters").

**Fixes:**

- Select **primitives or existing references** separately: `useSelector(s => s.x.a)`, `useSelector(s => s.y.b)`.
- Pass `shallowEqual` as the equality function for small objects: `useSelector(sel, shallowEqual)`.
- Use a **memoized selector** for derived data:

```ts
import { createSelector } from '@reduxjs/toolkit';

const selectTodos = (s: RootState) => s.todos;
export const selectDoneTodos = createSelector([selectTodos], (todos) => todos.filter((t) => t.done));
```

`createSelector` (Reselect) runs the input selectors and **only recomputes the result when an input reference changes**. Otherwise it returns the cached array, so `===` passes and nothing re-renders. Because Immer keeps unchanged parts of the state tree as the same objects, input references stay stable.

**Pitfalls:**

- **Selectors with arguments:** `selectItemsByCategory(state, category)` used by several components with different categories. Reselect 5 uses `weakMapMemoize` by default, which caches per argument set. With older versions (cache size 1) the components invalidate each other. A per-component instance (`useMemo(() => makeSelector(), [])`) also works.
- **Input selectors that transform data** (`s => s.todos.map(...)`) break memoization: inputs should only *extract*.
- Memoizing something cheap like `s => s.user.name` is pointless.
- **Context is different:** a Context consumer re-renders whenever the provider value changes and can't select a slice. That's why Redux (and Zustand, Jotai) scale better for frequently changing shared state.

**Follow-up:** you have a list of 1,000 rows, each with `useSelector(s => s.rows.byId[id])`. One row changes. How many selectors run, and how many components re-render?
