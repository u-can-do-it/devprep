## Hints

- What bug or duplication existed before the type?
- Which TypeScript features did it use (generics, mapped types, conditional types, template literals)?
- Was it worth the complexity? How did teammates use it?

## Answer

The interviewer wants to see that you can **explain advanced types out loud** and that you use them to solve real problems, not to show off. Structure the answer as: problem → type → how it's used → trade-off.

**Strong candidates for a story:**

- A **typed API client** where the route decides the request and response types
- A **typed event emitter / message bus** where the event name decides the payload type
- A **polymorphic design-system component** (`as` prop) with correct props and refs
- **Form field paths** (`'address.city'`) checked against the form type with template literal types
- **Discriminated union state** for an async flow, with exhaustive handling

**Example: a typed event bus**

```ts
type AppEvents = {
  'clip:exported': { clipId: string; format: 'mp4' | 'webm' };
  'clip:deleted': { clipId: string };
};

class TypedEmitter<E extends Record<string, unknown>> {
  private handlers: { [K in keyof E]?: Array<(payload: E[K]) => void> } = {};

  on<K extends keyof E>(event: K, handler: (payload: E[K]) => void): () => void {
    const list = (this.handlers[event] ??= []);
    list.push(handler);
    return () => {
      this.handlers[event] = this.handlers[event]?.filter((h) => h !== handler);   // read the current list, not the one captured at subscribe time
    };
  }

  emit<K extends keyof E>(event: K, payload: E[K]): void {
    this.handlers[event]?.forEach((h) => h(payload));
  }
}

const bus = new TypedEmitter<AppEvents>();
bus.on('clip:exported', (p) => p.format);      // p is { clipId; format }
bus.emit('clip:deleted', { clipId: '1' });     // OK
// bus.emit('clip:deleted', { id: '1' });      // error: wrong payload
// bus.emit('clip:exportd', { clipId: '1' });  // error: unknown event
```

**How to tell it (about 90 seconds):**

> "Several modules communicated through string events, and payloads were typed as `any`. We had two bugs where an event was renamed in one place but not another. I wrote a generic emitter where a single map type defines every event and its payload. `K extends keyof E` ties the event name to `E[K]`, the payload type, so a wrong name or payload is a compile error, and autocomplete lists the events. The trade-off is one central map that everyone edits, which we accepted because it also documents every event."

**Be ready for follow-ups:** why `K extends keyof E` instead of `string`; what `E[K]` is (indexed access); how you would make `emit` accept no payload for events whose payload is `void`; and how you'd test types (`expectTypeOf`, `@ts-expect-error`).
