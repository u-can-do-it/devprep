## Hints

- What happens when you put a union inside a template literal type?
- Can `infer` pull parts out of a string type?
- How could you turn `'/users/:id'` into a params type `{ id: string }`?

## Answer

**Template literal types** use the same syntax as JS template strings, but work on string **types**:

```ts
type Size = 'sm' | 'md' | 'lg';
type Variant = 'primary' | 'ghost';
type ClassName = `btn-${Variant}-${Size}`;  // every combination: 6 members

type EventName<T extends string> = `on${Capitalize<T>}`;
type Click = EventName<'click'>;            // 'onClick'
type Px = `${number}px`;                    // accepts '12px', rejects '12em'
```

Unions **distribute**, which gives the cartesian product of the combinations. The built-in helpers are `Uppercase`, `Lowercase`, `Capitalize` and `Uncapitalize`.

**Parsing with `infer`:** you can pattern-match a string type and extract parts recursively. A classic example is typed route params:

```ts
type Params<P extends string> =
  P extends `${string}:${infer Name}/${infer Rest}` ? Name | Params<Rest>
  : P extends `${string}:${infer Name}` ? Name
  : never;

type R = Params<'/users/:id/posts/:postId'>; // 'id' | 'postId'

function link<P extends string>(path: P, params: Record<Params<P>, string>) { /* ... */ }
link('/users/:id', { id: '42' });     // ok
// link('/users/:id', { userId: '42' }); // error
```

**Key remapping in mapped types:**

```ts
type Getters<T> = { [K in keyof T as `get${Capitalize<K & string>}`]: () => T[K] };
type G = Getters<{ name: string }>; // { getName: () => string }
```

**Real uses:** typed routers (TanStack Router, typed Next.js routes), CSS-in-JS tokens, event emitter names, i18n key paths (`'home.title'`), and SQL builders.

**Pitfalls:** unions blow up quickly, and TypeScript caps them at about 100,000 members. Deep recursion slows down the editor. Keep these types at library boundaries, and test them with type tests (`expectTypeOf`).
