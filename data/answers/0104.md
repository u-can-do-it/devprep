## Hints

- Where does the browser look first before asking anyone on the network?
- What is the difference between a recursive resolver and an authoritative name server?
- How does TTL affect how quickly a DNS change reaches users?

## Answer

DNS translates a hostname (`api.example.com`) into an IP address.

**Resolution steps:**

1. **Local caches** – browser cache, OS cache, `/etc/hosts`.
2. **Recursive resolver** – usually your ISP's, the company's, or a public one (`1.1.1.1`, `8.8.8.8`). If it has a cached answer, it returns it.
3. Otherwise it walks the hierarchy (iterative queries):
   - **Root servers** → "ask the `.com` TLD servers"
   - **TLD servers** → "ask `example.com`'s authoritative name servers"
   - **Authoritative server** → returns the record
4. The resolver caches the answer for its **TTL** and returns it to the client.

**Common record types:**

- `A` / `AAAA` – IPv4 / IPv6 address
- `CNAME` – alias to another name
- `MX` – mail servers
- `TXT` – verification, SPF/DKIM
- `NS` – authoritative name servers

```bash
dig +trace api.example.com    # shows each step from root to authoritative
dig api.example.com A +short
```

**Practical points:**

- Lower the TTL **before** a migration so the cutover propagates quickly.
- DNS is traditionally unencrypted UDP on port 53; **DoH/DoT** (DNS over HTTPS/TLS) add privacy and integrity.
- DNS is used for load balancing and geo-routing (CDNs return the nearest edge IP).
- Use `<link rel="dns-prefetch">` / `preconnect` for third-party origins to hide lookup latency.
