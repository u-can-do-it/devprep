## Hints

- Which direction do children flow in by default: a row or a column?
- What unit is `width: 100`?
- There are no media queries. How does a component learn the screen width or the colour scheme?

## Answer

> Styles are JavaScript objects passed to the `style` prop, usually created with `StyleSheet.create`. The property names are camelCased CSS, but only a subset exists and there is no cascade. Layout is Flexbox (by the Yoga engine) with different defaults: `flexDirection` is `column`. Numbers are density-independent pixels. For responsive layout you use flex, percentages and `useWindowDimensions`; for dark mode you use `useColorScheme`.

```tsx
const styles = StyleSheet.create({
  card: { padding: 16, borderRadius: 12, backgroundColor: '#fff', gap: 8 },
  title: { fontSize: 18, fontWeight: '600' },
});

<View style={[styles.card, selected && styles.selected, { opacity }]} />
```

An array merges left to right, and falsy entries are skipped. There are no selectors, no `:hover`, no pseudo-elements and no global styles. Each component styles itself.

**Flexbox differences from the web**

| | Web | React Native |
|---|---|---|
| `display` | `block` by default | every `View` is a flex container |
| `flexDirection` | `row` | `column` |
| `alignContent` | `stretch` | `flex-start` |
| `flexShrink` | `1` | `0` |
| `flex` | shorthand for three values | a single number: `flex: 1` means "take the free space" |
| `position` | `static` | `relative` |
| `box-sizing` | `content-box` | `border-box` |

The most common layout bug: a child has no size because its parent has no `flex: 1` or height. A screen root usually needs `flex: 1`.

**Units**

- Plain numbers are density-independent pixels (dp or points). `100` is the same physical size on every screen, and the device multiplies it by its pixel ratio (2x, 3x).
- Percentages work as strings: `width: '50%'`.
- No `rem`, `em`, `vh` or `vw`. No `calc()`.
- `StyleSheet.hairlineWidth` is the thinnest line the device can draw.
- Font sizes also scale with the user's system text size setting (#689).

**What exists and what doesn't**

Available: Flexbox, `gap`, absolute positioning, `transform`, `opacity`, borders, `aspectRatio`, `zIndex`, and in current versions also `boxShadow`, `filter` and `display: 'contents'`. Missing: CSS Grid, floats, media queries, `position: fixed`, the cascade and inheritance (except between nested `Text`).

**Adapting to the screen**

```tsx
function ProductGrid() {
  const { width } = useWindowDimensions();   // updates on rotation and split screen
  const columns = width >= 768 ? 3 : 2;
  const scheme = useColorScheme();           // 'light' | 'dark'
  const colors = scheme === 'dark' ? dark : light;
  // ...
}
```

- Prefer flex and percentages over fixed widths. Use `useWindowDimensions` for breakpoints. Avoid `Dimensions.get()` at module level, because it doesn't update.
- For dark mode, keep colours in a theme object chosen by `useColorScheme`, and pass it through Context or a styling library.
- Phones differ in notches and system bars, so respect safe areas (#679).

**Libraries**

NativeWind (Tailwind classes), Unistyles (themes, breakpoints, variants) and Tamagui add breakpoints and theming on top. They compile down to the same style objects.
