## Hints

- Who decides the value of each one: the component itself or its parent?
- What happens if a component tries to assign to `props.title`?
- If a value can be computed from props on every render, does it need to be state?

## Answer

**Props** are a component's inputs, passed in by the parent. They're **read-only** from the component's point of view. A component should never modify its props.

**State** is data the component **owns** and that changes over time, usually because of user interaction or async results. You update it with the setter from `useState`/`useReducer`, and the update schedules a re-render.

| | Props | State |
|---|---|---|
| Owned by | parent | the component itself |
| Mutable by component | no | yes, via setter |
| Change triggers re-render | yes (parent re-renders) | yes |

```jsx
function Counter({ step }) {            // prop: configured by parent
  const [count, setCount] = useState(0); // state: owned here
  return <button onClick={() => setCount(c => c + step)}>{count}</button>;
}
```

They connect: one component's state is often passed as props to its children.

**Guidelines:**

- Don't copy props into state (`useState(props.value)`). It only reads the initial value and then goes stale. Use the prop directly, or name it `initialValue` to make the intent clear.
- Don't store **derived data** in state. Compute `fullName` from `first` and `last` during render.
- Keep state minimal and as close as possible to where it's used.

**Follow-up:** "How does a child change something its parent owns?" The parent passes down a callback prop. That's one-way data flow.
