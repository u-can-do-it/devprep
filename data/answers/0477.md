## Hints

- Why can't you use `EventSource` to send a POST with the chat history?
- What does the user expect to happen when they click "Stop generating"?
- What breaks when you render half of a Markdown code block?

## Answer

LLM responses take seconds, so the UI should show tokens **as they're generated**. The building blocks:

**1. Transport**

- **Server-Sent Events (SSE)** (`Content-Type: text/event-stream`) is the usual format: one-way server → client over plain HTTP, which works through most proxies.
- The browser's `EventSource` only supports **GET without custom headers**, so chat UIs usually send a **POST with `fetch`** and read the response body as a stream, parsing SSE frames themselves (or with a helper like `eventsource-parser`).
- **WebSockets** when you need two-way traffic on one connection: interrupting, tool approvals or collaborative sessions.

```ts
const controller = new AbortController();

async function send(messages: Message[], onToken: (t: string) => void) {
  const res = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ messages }),
    signal: controller.signal,
  });
  if (!res.ok || !res.body) throw new Error(`HTTP ${res.status}`);

  const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = '';
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += value;
    const events = buffer.split('\n\n');
    buffer = events.pop()!;                       // keep the incomplete frame
    for (const e of events) {
      const data = e.replace(/^data: /, '');
      if (data === '[DONE]') return;
      onToken(JSON.parse(data).delta);
    }
  }
}
// "Stop generating" → controller.abort()
```

The backend route (a Node handler, a Next.js Route Handler or FastAPI) calls the model with streaming on and forwards chunks. It keeps the API key on the server and disables proxy buffering (`X-Accel-Buffering: no`, no compression buffering).

**2. Rendering**

- **Batch updates:** dozens of tokens per second each calling `setState` will thrash React. Accumulate in a ref and flush once per animation frame, or use `useTransition`.
- **Partial Markdown:** an unclosed code fence or table renders badly mid-stream. Use a streaming-aware renderer or close open blocks temporarily. Memoise finished messages so only the last one re-renders.
- **Sanitise:** model output is untrusted. Render Markdown without raw HTML, and block or proxy external images (a prompt-injected image URL can leak data).
- **Scrolling:** stick to the bottom while streaming, but stop auto-scrolling if the user scrolls up.

**3. UX and robustness**

- Stop button (abort), retry and regenerate, edit the last message, copy, and keep the partial answer on error with a clear message.
- Show tool calls and sources ("Searching documents…", citations) for RAG answers.
- Accessibility: an `aria-live="polite"` region that announces the finished answer, not every token, and focus management after sending.
- Rate limits and long-request timeouts (serverless functions have time limits); resume or recover dropped connections.

Libraries such as the **Vercel AI SDK** (`useChat`) package this: streaming protocol, message state, abort, tool calls.

**Follow-up:** the user switches tabs mid-answer and comes back after the connection dropped. How would you make the response resumable?
