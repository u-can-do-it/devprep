## Hints

- `int?` and `string?` look the same. Is one of them a different type at run time?
- Does enabling nullable reference types stop a `null` from reaching your method at run time?
- When is the `!` (null-forgiving) operator justified, and why is it a smell when it's everywhere?

## Answer

**Nullable value types (`int?`):** value types can't be `null`, so `int?` is shorthand for the struct `Nullable<int>`, which holds a value plus a `HasValue` flag. It's a real, different type.

```csharp
int? age = null;
if (age.HasValue) Console.WriteLine(age.Value);
int years = age ?? 0;                  // default if null
int bad = age.Value;                   // InvalidOperationException when null
int? sum = age + 1;                    // null: arithmetic "lifts" null through
```

Typical uses: optional database columns, optional query parameters, "not set yet".

**Nullable reference types (NRT, C# 8, on by default in new projects via `<Nullable>enable</Nullable>`):** reference types could always be `null`. NRT is a **compile-time annotation and analysis** feature: `string` means "should never be null", `string?` means "may be null", and the compiler warns when you might dereference `null` or assign `null` where it isn't allowed. At run time `string` and `string?` are the **same type**; nothing is enforced, so validate public inputs anyway (`ArgumentNullException.ThrowIfNull(x)`).

```csharp
public string GetDisplayName(User? user)
{
    // return user.Name;       // warning CS8602: possible null dereference
    if (user is null) return "Guest";
    return user.Name;          // OK: the compiler tracks the null check
}
```

**Operators:**

| Operator | Meaning | Example |
|---|---|---|
| `?.` | call or access only if not null, else `null` | `user?.Address?.City` |
| `?[]` | null-conditional index | `items?[0]` |
| `??` | use the right side if the left is null | `name ?? "anonymous"` |
| `??=` | assign only if currently null | `_cache ??= Load();` |
| `!` | "trust me, not null": silences the warning, no runtime check | `FindUser(id)!.Name` |

C# 14 also allows `?.` on the left of an assignment: `customer?.Order = GetOrder();` assigns only if `customer` isn't null.

**About `!`:** it changes nothing at run time; if you're wrong you still get a `NullReferenceException`. It's acceptable where the compiler can't see a guarantee (e.g. a field set by a framework after construction). Prefer fixing the types, adding a null check, or using attributes like `[NotNullWhen(true)]` on your `TryGet` methods.

**Follow-up:** what does `default` give for `int?` and `string`? (`null` for both: `Nullable<int>` with no value, and a null reference.)
