## Hints

- Can a browser run JSX directly, or does something transform it first?
- What does the tool turn `<Button color="red">Hi</Button>` into — markup or a function call?
- How would the compiler know whether `<button>` means an HTML tag or a variable in scope?

## Answer

JSX is syntax sugar. A compiler (TypeScript, SWC, Babel, esbuild) turns it into plain function calls. With the **automatic runtime** (the default since React 17), the import is added for you:

```jsx
// source
const el = <Button color="red">Hi</Button>;

// compiled (roughly)
import { jsx as _jsx } from 'react/jsx-runtime';
const el = _jsx(Button, { color: 'red', children: 'Hi' });
```

The older classic runtime produced `React.createElement(Button, { color: 'red' }, 'Hi')`. That's why old files needed `import React` at the top.

The call returns a **React element**, a plain immutable object like `{ type: Button, props: {...}, key: null }`. It describes the UI. It is not a DOM node.

**Why capital letters:** the compiler uses case to choose the `type`:

- `<div>` (lowercase) becomes the **string** `'div'`, a host DOM element.
- `<Button>` (capitalized) becomes a **reference** to the `Button` variable, a component.

If you name a component `button`, JSX treats it as an unknown HTML tag and your function never runs.

Other rules that follow from "it's just JavaScript": `{}` holds expressions, not statements; `className` and `htmlFor` replace the reserved words; you must return one root (or a Fragment); and strings in `{}` are escaped automatically, which protects against XSS unless you use `dangerouslySetInnerHTML`.

**Follow-up:** you can write React without JSX by calling `createElement` yourself. JSX only makes the tree readable.
