## Hints

- Before free space is shared out, what size does each flex item start from?
- What happens when items don't fit, and which ones give up space first?
- Why does a long word or a `<pre>` block sometimes refuse to shrink in a flex item?

## Answer

Flex sizing works in two steps. First each item gets a **base size** (`flex-basis`). Then the container shares out the **remaining space**, or the **overflow**.

- **`flex-basis`**: the starting size along the main axis. `auto` (the default) means "use `width`/`height`, or the content size".
- **`flex-grow`**: how many shares of the **positive** free space the item takes. `0` means don't grow.
- **`flex-shrink`**: how readily the item shrinks when the items overflow. It's weighted by the base size, so bigger items shrink more. `0` means never shrink below the basis.

**Shorthands:**

| Shorthand | Expands to | Meaning |
|---|---|---|
| default | `0 1 auto` | Content-sized, can shrink, won't grow |
| `flex: 1` | `1 1 0%` | Ignore content size and split space **equally** |
| `flex: auto` | `1 1 auto` | Grow and shrink, starting from content size, so items end up **unequal** |
| `flex: none` | `0 0 auto` | Rigid, content-sized |
| `flex: 0 0 240px` | | Fixed 240px sidebar |

```css
.layout { display: flex; gap: 1rem; }
.sidebar { flex: 0 0 15rem; }
.main { flex: 1; min-width: 0; } /* takes the rest, and is allowed to shrink */
```

**The classic pitfall:** flex items have `min-width: auto` by default, so they won't shrink below their **content's minimum size**. A long URL, a wide table or a `<pre>` overflows the layout, and `text-overflow: ellipsis` doesn't work. Fix it with `min-width: 0` (or `overflow: hidden`) on the item. In a column layout, the same applies to `min-height`.

**Other tips:**

- Use `gap` for spacing instead of margins.
- Use `flex-wrap: wrap` together with `flex-basis` for simple responsive rows.

**Follow-up:** if you need items in different rows to line up as columns, that's a two-dimensional problem, so use Grid.
