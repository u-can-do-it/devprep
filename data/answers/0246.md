## Hints

- Is it slow for real users (field data) or just in Lighthouse (lab data)? Which Core Web Vital is bad?
- Is the problem the server (TTFB) or the browser (too much JavaScript, slow hydration)?
- Which component in the tree pulled a 300 KB charting library into the client bundle?

## Answer

**1. Measure before changing anything.**

- **Field data:** Core Web Vitals (LCP, INP, CLS) from CrUX, Vercel Speed Insights or your RUM tool. Report your own with `useReportWebVitals` from `next/web-vitals`.
- **Lab data:** Lighthouse or the Performance panel for a specific route; React DevTools Profiler for re-renders.
- **Build output:** `next build` shows which routes are static and which are dynamic.
- **Bundles:** `next experimental-analyze` (the Turbopack bundle analyzer, 16.1+) or `@next/bundle-analyzer` with webpack. Find large modules and the import chain that pulled them in.

**2. Fix by symptom.**

*Slow TTFB / server:*

- Routes that are unexpectedly dynamic (a `cookies()` call in a shared layout). Move runtime access down the tree behind `<Suspense>`.
- Waterfalls: run independent requests with `Promise.all`, and stream slow parts.
- Cache stable data with `'use cache'` + `cacheLife`. Remember `fetch` is uncached by default since v15.

*Poor LCP:*

- `next/image` with correct `sizes`, plus `preload` on the hero image. Use `next/font` to avoid font-blocking.
- Keep the LCP element out of Suspense fallbacks and client-only rendering.

*Poor INP / too much JS:*

- Push `'use client'` **to the leaves**. Keep big libraries (markdown, date, syntax highlighting) in Server Components.
- `next/dynamic` for heavy client widgets (editors, maps, charts).
- Avoid barrel files, and use `optimizePackageImports` for icon or UI libraries.
- Load third-party scripts with `next/script` `lazyOnload`.
- Turn on the **React Compiler** (`reactCompiler: true`) to cut unnecessary re-renders.

*CLS:* image dimensions, skeletons that match the final layout, and `next/font` fallback metrics.

**3. Verify** with the same metrics, and add a performance budget to CI (bundle size, Lighthouse CI).

**Note:** Turbopack (the default bundler in v16) makes **dev and builds** faster, not the app your users run.

**Follow-up:** a strong candidate names the metric, the cause and the tool, not a generic list of tips.
