## Hints

- How many base classes can a C# class have, and how many interfaces?
- Which one can hold state (fields) and a constructor?
- Does a default interface method mean interfaces and abstract classes are now the same thing?

## Answer

**An interface is a contract** ("can do X"); **an abstract class is a partial implementation** ("is a kind of X") that subclasses complete.

| | Interface | Abstract class |
|---|---|---|
| Inheritance | a class implements **many** | a class extends **one** |
| Instance fields / state | **no** | yes |
| Constructors | no | yes |
| Member access | public by default; can have private helpers since C# 8 | any modifier |
| Implementation | default methods (C# 8+) and static members | regular, virtual and abstract members |
| Works for structs | yes | no |
| Typical use | capabilities, DI seams, testing: `IRepository`, `IComparable<T>` | shared base logic for closely related types |

```csharp
public interface INotifier
{
    Task SendAsync(string to, string message);
}

public abstract class NotifierBase : INotifier
{
    protected readonly ILogger Log;                       // shared state
    protected NotifierBase(ILogger log) => Log = log;

    public async Task SendAsync(string to, string message) // template method
    {
        Log.LogInformation("Sending to {To}", to);
        await SendCoreAsync(to, message);
    }
    protected abstract Task SendCoreAsync(string to, string message);
}

public sealed class EmailNotifier(ILogger<EmailNotifier> log) : NotifierBase(log)
{
    protected override Task SendCoreAsync(string to, string message) => Task.CompletedTask;
}
```

**Default interface methods (C# 8):** an interface member can have a body. The main purpose is **versioning**: you can add a member to a published interface without breaking every class that implements it.

```csharp
public interface ILogger2
{
    void Log(string msg);
    void LogError(string msg) => Log("ERROR: " + msg);   // existing implementers get this for free
}

ILogger2 l = new ConsoleLogger();
l.LogError("x");                                          // works through the interface
// new ConsoleLogger().LogError("x");                     // compile error: not a member of the class
```

They still **can't hold instance state**, and the default is only reachable through the interface type. So the distinction remains: interfaces for contracts, abstract classes for shared state and code.

**In practice:** in ASP.NET Core code, interfaces dominate because dependency injection and mocking work against them (#581, #588). Prefer composition over deep inheritance; use an abstract base class only when several implementations really share code and state.
