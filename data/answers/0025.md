## Hints

- How do you write one function that works for many types without losing type information?
- If a generic function reads `.length` or `.id` from its argument, what must you tell the compiler?
- How does `K extends keyof T` make property access type-safe?

## Answer

**Generics** are type parameters. They let one function, class or type work with many types while **keeping the relationship** between input and output. That is something `any` would lose.

```ts
function first<T>(arr: T[]): T | undefined { return arr[0]; }
first([1, 2]);        // number | undefined (T inferred as number)
```

**Constraints** (`extends`) require the type argument to have a certain shape, so the function body can safely use those members:

```ts
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}
longest('abc', 'de');    // string
longest([1, 2], [3]);    // number[]
// longest(1, 2);        // error: number has no 'length'

function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
getProp({ id: 1, name: 'Ann' }, 'name'); // string
// getProp({ id: 1 }, 'email');          // error
```

**More patterns:**

- **Defaults:** `interface ApiResponse<T = unknown> { data: T; error?: string }`.
- **Generic classes and hooks:** `class Repo<T extends { id: string }>`, `useState<User | null>(null)`.
- **`const` type parameters** (TS 5.0+): `function tuple<const T extends readonly unknown[]>(x: T)` infers literal types and readonly tuples.
- **`NoInfer<T>`** (TS 5.4+) keeps one parameter from affecting what `T` is inferred as.

**Good practice:**

- Let the compiler **infer** type arguments.
- Only add a type parameter if it relates two or more things (inputs to outputs). A generic used only once is usually unnecessary.
- Constrain as loosely as possible.
