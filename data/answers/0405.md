## Hints

- How could a designer or product manager try a feature before it's merged?
- What does each environment need besides the app itself: a database, URLs, secrets?
- What happens to the cost if environments are never cleaned up?

## Answer

> Reviewing a pull request from the diff alone misses bugs that only show up in a running app. A preview environment is a short-lived, full deployment of one PR with its own URL. CI creates it when the PR opens, updates it on every push, and deletes it when the PR closes. Give it its own seeded or branched database, low-privilege secrets and sandboxed third parties. Never use production data with real PII, and put the preview URLs behind authentication.

A **preview environment** (also called an ephemeral or review app) is a short-lived, full deployment of a pull request, with its own URL like `pr-123.preview.example.com`. It's created when the PR opens, updated on every push, and **destroyed when the PR is merged or closed**.

**Why:** reviewers, QA, designers and PMs can click through real changes; E2E tests run against a realistic deployment; and integration bugs show up before merge.

**How to implement:**
- **Frontends:** platforms like Vercel, Netlify or Cloudflare Pages do it automatically per branch.
- **Full stack:** a CI workflow on `pull_request` builds an image tagged with the commit SHA and deploys it into an isolated namespace (Kubernetes namespace, Cloud Run service, Fly app) named after the PR, then posts the URL as a PR comment.
- **Data:** a fresh database seeded with fixtures, a branch of a database that supports branching (Neon, PlanetScale-style), or a shared staging DB with care. **Never production data with real PII.**
- **Config:** separate, low-privilege secrets; disabled or sandboxed third parties (payments in test mode, email to a catcher).
- **Teardown:** a workflow on `pull_request: closed` deletes everything, plus a scheduled job that removes stale environments.

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened, closed]
concurrency: preview-${{ github.event.number }}
```

**Trade-offs:** cost, slower pipelines, and complexity for systems with many dependencies (sometimes only the changed service is deployed and the rest point to shared staging).

**Pitfall:** public preview URLs that expose unreleased features. Put them behind authentication.
