## Hints

- If `<Button as="a">` is allowed, how should TypeScript know that `href` is valid but `<Button as="button" href>` isn't?
- Which props belong to your component, and which come from the underlying element?
- What does Radix's `asChild` do differently from an `as` prop?

## Answer

A **polymorphic** component renders as different elements or components while keeping its styles and behavior, for example a `Button` rendered as an `<a>` or a router `Link`. Type-safe means props are checked against whatever it renders as.

**`as` prop with generics** (React 19, where `ref` is a regular prop):

```tsx
type PolymorphicProps<C extends React.ElementType, Own = {}> =
  Own & { as?: C } & Omit<React.ComponentProps<C>, keyof Own | 'as'>;

type ButtonOwnProps = { variant?: 'primary' | 'ghost' };

function Button<C extends React.ElementType = 'button'>(
  { as, variant = 'primary', className, ...rest }: PolymorphicProps<C, ButtonOwnProps>
) {
  const Comp = as ?? 'button';
  return <Comp className={cx('btn', `btn-${variant}`, className)} {...rest} />;
}

<Button href="/x" as="a">Docs</Button>        // ok: href is valid on <a>
<Button as={Link} to="/settings">Go</Button>   // Link's props are inferred
<Button href="/x">Oops</Button>               // error: no href on <button>
```

Notes:

- `Omit<..., keyof Own>` makes your props override the element's conflicting ones.
- The generic default (`'button'`) gives correct types when `as` is omitted.
- Before React 19 you needed `forwardRef` plus type-casting tricks, because `forwardRef` loses generics.

**`asChild` / Slot pattern** (Radix, shadcn/ui):

```tsx
<Button asChild><Link to="/settings">Go</Link></Button>
```

The component doesn't render its own element. It **merges** its props, class names, event handlers and ref into its single child. The typing is much simpler: the child keeps its own types. It also avoids wide prop unions that slow down the TypeScript compiler. The downside is that it requires exactly one child that accepts and spreads props.

**Trade-offs to discuss:**

- `as` gives an explicit API but complex and slower types, and confusing errors.
- `asChild` gives cleaner types, but merging handlers and refs needs care.
- Both need **accessibility guardrails**. `<Button as="div">` loses keyboard and role semantics, so restrict `C` to a safe union (`'button' | 'a' | typeof Link`) in a design system.
