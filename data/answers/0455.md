## Hints

- If the brand blue changes, how many files should you have to edit?
- What's the difference between a token called `blue-600` and one called `color-action-primary`?
- How would a dark theme work if components only reference semantic tokens?

## Answer

**Design tokens** are named design decisions (colours, spacing, font sizes, radii, shadows, motion durations) stored in a platform-neutral format and turned into code for each platform: CSS variables, a Tailwind theme, iOS and Android constants.

They're usually organised in **tiers**:

| tier | example | purpose |
|---|---|---|
| primitive (global) | `blue-600: #2563eb` | the raw palette, never used directly in components |
| semantic (alias) | `color-bg-action: {blue-600}` | intent; this is what themes change |
| component (optional) | `button-primary-bg: {color-bg-action}` | per-component overrides |

Components reference **semantic** tokens only. Dark mode or a second brand is then just a different mapping:

```css
:root            { --color-bg-action: var(--blue-600); --color-text: var(--gray-900); }
[data-theme=dark]{ --color-bg-action: var(--blue-400); --color-text: var(--gray-50);  }
.button          { background: var(--color-bg-action); }
```

**Keeping Figma and code in sync:**

- In Figma, tokens live as **Variables**, with **modes** for light/dark or brands. Designers apply variables instead of raw values, so the design file uses the same names as the code.
- Export them (the Tokens Studio plugin, or the Figma Variables REST API) to JSON in the **W3C Design Tokens (DTCG) format** (`$value`, `$type`, aliases like `{color.blue.600}`), which reached a stable spec in 2025.
- Commit the JSON to the repo and transform it with **Style Dictionary** (or Terrazzo) into CSS variables, TypeScript constants and a Tailwind `@theme`.
- Automate it: a token change in Figma opens a pull request with the generated diff, and CI runs visual regression tests on the component library.
- Pick **one source of truth**. Usually that's the token repo, with Figma kept in sync by a plugin. Two-way manual syncing always drifts.

**Pitfalls:** naming tokens after values (`spacing-16`) makes them hard to change; too many component-level tokens recreate the chaos tokens were meant to fix; and tokens alone don't make a design system without shared components and usage rules.
