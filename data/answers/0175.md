## Hints

- Which loop gives you values and which one gives you keys?
- Why is `for...in` a bad choice for arrays?
- What happens if you `await` inside a `forEach` callback or try to `break` out of it?

## Answer

| Construct | Iterates | `break`/`continue` | `await` works? | Notes |
|---|---|---|---|---|
| `for (let i...)` | indexes | yes | yes | full control, e.g. stepping backwards |
| `for...of` | **values** of iterables (arrays, strings, Map, Set, generators) | yes | yes | the default choice for arrays |
| `for...in` | enumerable **string keys**, including **inherited** ones | yes | yes | for objects only; never for arrays |
| `arr.forEach(fn)` | array values | no | no (doesn't wait) | skips holes |
| `Object.keys/values/entries` | own enumerable props as an array | used with `for...of` | yes | the clean way to loop over an object |

```js
const scores = { ann: 3, bo: 5 };
for (const [name, score] of Object.entries(scores)) console.log(name, score);

for (const [i, v] of ['a', 'b'].entries()) console.log(i, v);

const map = new Map([['x', 1]]);
for (const [k, v] of map) console.log(k, v);
```

**Why not `for...in` on arrays:** the keys are strings (`'0'`, `'1'`), order isn't guaranteed in edge cases, and it also picks up any enumerable properties added to the array or to `Array.prototype`.

**The `forEach` + `async` trap:**

```js
items.forEach(async (item) => { await save(item); });
console.log('done'); // runs before any save finishes
```

Use `for...of` with `await` to run things one after another, or `await Promise.all(items.map(save))` to run them in parallel.

**Rule of thumb:** `for...of` for iterables, `Object.entries` for objects, `map`/`filter`/`reduce` when you're building a new value, and a classic `for` loop when you need the index arithmetic.
