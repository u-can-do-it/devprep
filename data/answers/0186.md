## Hints

- What happens to the remaining type arguments when you explicitly pass only the first one?
- How can a function infer `['a', 'b']` as a tuple of literals without the caller writing `as const`?
- If a type parameter appears in two arguments, which one should "own" the inference?

## Answer

**Generic defaults** work like default function arguments, but for types:

```ts
interface ApiResult<T = unknown, E = Error> { data?: T; error?: E }
type R = ApiResult;            // ApiResult<unknown, Error>
type S = ApiResult<User>;      // ApiResult<User, Error>
```

Parameters with defaults must come after required ones. A key subtlety: TypeScript has **no partial inference**. If you pass some type arguments explicitly, the rest **use their defaults instead of being inferred**:

```ts
declare function fetchJson<T, Q = Record<string, string>>(url: string, query: Q): Promise<T>;
fetchJson<User>('/u', { page: 1 });  // error: Q is not inferred, it falls back to its default
```

The common workaround is **currying**: `fetchJson<User>()('/u', query)`. The first call fixes `T`, and the second call infers the rest.

**`const` type parameters (TS 5.0)** infer the narrowest literal types, as if the caller had written `as const`:

```ts
function defineRoutes<const T extends readonly string[]>(paths: T) { return paths; }
const r = defineRoutes(['/home', '/about']); // readonly ['/home', '/about']
```

For arrays, the constraint must be `readonly`. Otherwise inference falls back to `string[]`.

**`NoInfer<T>` (TS 5.4)** stops one position from contributing to inference, so another argument decides the type:

```ts
function createMachine<S extends string>(cfg: { states: S[]; initial: NoInfer<S> }) {}
createMachine({ states: ['idle', 'loading'], initial: 'done' });
// error: 'done' is not 'idle' | 'loading'
// without NoInfer, S would widen to 'idle' | 'loading' | 'done'
```

**Other inference tools:**

- **Constraints keep literals:** `<T extends string>` infers `'a'` instead of widening to `string` in more places.
- The older trick `T & {}` lowered an argument's inference priority, before `NoInfer` existed.
- **Inference order:** TypeScript infers from non-function arguments first, then from context-sensitive callbacks. Putting the "data" argument before the callback improves inference.

These features matter mostly to **library authors** (routers, form libraries, state machines, ORMs). Good inference lets users write zero type annotations and still get precise errors.
