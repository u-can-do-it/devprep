## Hints

- What happens to total load time if a component awaits `getUser()` and then `getOrders()` one after the other?
- If the header and the page both call `getCurrentUser()`, how many DB queries run?
- Can a Server Component start a request and let a Client Component wait for the result?

## Answer

Server Components can be `async` and `await` data directly. Fetching moves to the server, close to the database, but **waterfalls** can still happen.

**1. Sequential awaits.** Requests that don't depend on each other should run in parallel:

```tsx
// Waterfall: ~300 ms + 400 ms
const user = await getUser(id);
const orders = await getOrders(id);

// Parallel: ~400 ms
const [user, orders] = await Promise.all([getUser(id), getOrders(id)]);
```

**2. Nested component waterfalls.** A parent that awaits before rendering a child delays the child's own fetch. Fixes:

- Let each component fetch its own data and wrap the slow ones in `<Suspense>`, so they **stream independently**.
- Start a promise early and pass it down. A Client Component can unwrap it with React's `use()`:

```tsx
export default function Page() {
  const reviewsPromise = getReviews(); // not awaited
  return (
    <Suspense fallback={<Spinner />}>
      <Reviews reviewsPromise={reviewsPromise} />
    </Suspense>
  );
}
```

**3. Request deduplication (memoization).** During **one render pass**:

- Identical `fetch` GET calls (same URL and options) are automatically deduplicated.
- Non-`fetch` work (ORM queries, SDK calls) should be wrapped in **`React.cache`**:

```ts
import { cache } from 'react';
export const getCurrentUser = cache(async () => {
  const session = await getSession();
  return db.user.findUnique({ where: { id: session.userId } });
});
```

Now the layout, page and `generateMetadata` can all call `getCurrentUser()`, and the query runs once. This memoization lasts **only for that request**. It is not a persistent cache: that's what `'use cache'` (or `fetch` caching) is for.

**Other tips:** use `next/dynamic` or Suspense for slow non-critical widgets; avoid calling your own Route Handlers from the server; push data needs down the tree instead of fetching everything in the layout.

**Follow-up:** remember that `fetch` is **not cached by default since Next.js 15**. Decide per call what to memoize, cache or stream.
