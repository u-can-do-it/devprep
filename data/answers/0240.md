## Hints

- Why does text sometimes "jump" when a web font finishes loading?
- Does loading a Google Font the classic way send your visitor's IP address to Google?
- Should a chat widget load before or after your page is interactive?

## Answer

### `next/font`

```tsx
// app/layout.tsx
import { Inter } from 'next/font/google';
const inter = Inter({ subsets: ['latin'], display: 'swap', variable: '--font-inter' });

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="en" className={inter.variable}><body>{children}</body></html>;
}
```

- **Self-hosting**: Google Font files are downloaded at **build time** and served from your domain. That means no extra DNS/TLS connection to Google and no visitor IP sent to a third party (relevant for GDPR).
- **Less layout shift**: it creates a fallback font with adjusted metrics (`size-adjust` and similar), so swapping in the real font barely moves the text.
- Automatic **preloading** and **subsetting**. Variable fonts are supported.
- `next/font/local` gives the same benefits for your own font files.

### `next/script`

It loads third-party scripts with an explicit **strategy** and runs each script only once, even across client navigations:

| Strategy | When it loads | Use for |
|---|---|---|
| `beforeInteractive` | In the initial HTML, before hydration. Root layout only | Truly critical scripts: consent managers, bot detection |
| `afterInteractive` (default) | Soon after the page becomes interactive | Analytics, tag managers |
| `lazyOnload` | When the browser is idle | Chat widgets, social embeds |
| `worker` | In a web worker via Partytown. Experimental, not supported in the App Router | – |

```tsx
<Script src="https://widget.example.com/chat.js" strategy="lazyOnload" onLoad={() => initChat()} />
```

Event handlers (`onLoad`, `onReady`, `onError`) require a Client Component.

**Why it matters:** third-party JS is often the main cause of poor **INP** and slow LCP. Deferring it keeps the main thread free during hydration.

**Follow-up:** `@next/third-parties` has optimized wrappers for Google Analytics, Tag Manager and YouTube embeds. Audit how heavy each script is before adding it at all.
