## Hints

- What happens to the operand types before `==` compares them?
- What would `0 == ''` or `null == undefined` return, and why?
- Is there one case where even `===` behaves surprisingly?

## Answer

`===` (strict equality) compares **value and type** with no conversion. If the types differ, the result is `false`.

`==` (loose equality) first applies **type coercion** using the Abstract Equality algorithm, then compares. That produces rules that are hard to remember:

```js
0 == '';            // true  ('' -> 0)
'1' == 1;           // true
false == '0';       // true  (both -> 0)
null == undefined;  // true  (special case)
null == 0;          // false
[] == false;        // true  ([] -> '' -> 0)

0 === '';           // false
null === undefined; // false
```

For objects, both operators compare **references**, not contents: `{} === {}` is `false`.

**Rule of thumb:** use `===` everywhere. The one idiom some teams accept is `x == null`, which is a short way to check for both `null` and `undefined`.

Edge cases of `===`:

- `NaN === NaN` is `false` (use `Number.isNaN(x)`).
- `+0 === -0` is `true`.

`Object.is()` fixes both: `Object.is(NaN, NaN)` is `true` and `Object.is(0, -0)` is `false`.

**Follow-up:** "What does `[] == ![]` return?" It returns `true`: `![]` is `false`, then both sides coerce to `0`.
