## Hints

- May you set a Google Analytics cookie before the user clicks "Accept" in the EU?
- Why does a client-side A/B test often cause a visible "flicker"?
- What happens to an experiment's code after the experiment ends?

## Answer

**1. Analytics events**

- Define a **tracking plan**: event names, properties and owners (`checkout_started { cart_value, items }`), versioned like an API. Use consistent naming (`object_action`).
- Send events through **one `track()` facade**, not direct SDK calls everywhere. The facade checks consent, adds common context (route, release, experiment variants), batches, and lets you change vendors (GTM `dataLayer`, GA4, Segment, PostHog, Amplitude).
- **Server-side tagging and conversion APIs** (a server GTM container, Meta CAPI) send key conversions from your backend: more reliable with ad blockers and less third-party JavaScript in the page.
- Never send PII (emails, names) in event properties or URLs.

**2. Consent (GDPR and ePrivacy)**

- In the EU, **non-essential cookies and trackers need prior, opt-in consent**. Analytics and marketing tags must not load or set cookies until the user agrees. Strictly necessary cookies (session, cart, security) don't need consent.
- Use a **consent management platform (CMP)** with "Reject all" as easy as "Accept all", granular categories, and a way to change the choice later. Store the consent state and its version.
- **Google Consent Mode v2:** default everything to denied, then update after the user's choice; tags then adjust their behaviour.

```js
gtag('consent', 'default', { ad_storage: 'denied', analytics_storage: 'denied', ad_user_data: 'denied', ad_personalization: 'denied' });
// after the user accepts analytics:
gtag('consent', 'update', { analytics_storage: 'granted' });
```

- Gate other scripts by category (`type="text/plain" data-category="analytics"` until consent), and audit with the network tab that nothing fires early.

**3. A/B tests and feature flags**

- **Assign variants deterministically:** hash a stable id (user id or a first-party cookie) so users always see the same variant across sessions and devices.
- **Avoid flicker:** decide the variant on the **server or at the edge** (middleware) and render the right version, instead of swapping the DOM after load. Client-only tools hide the page until they run, which hurts LCP.
- Use flag tools (GrowthBook, LaunchDarkly, Statsig, PostHog). Log an **exposure event** when the user actually sees the variant, define the primary metric and guardrail metrics (errors, performance) up front, and decide the sample size before you peek at results.
- **Clean up:** remove losing variants and stale flags after the decision. Old flags are tech debt and a source of bugs.

**Follow-up:** the marketing team wants a new tag added via GTM without a deploy. What are the performance, security and privacy risks, and how would you control them?
