## Hints

- How does an LLM answer questions about documents it was never trained on?
- What is an embedding, and why do "car" and "automobile" end up close together?
- Two users ask the same question but may see different documents. Where must permissions be enforced?

## Answer

**Retrieval-augmented generation (RAG)** answers questions using **your own data**: retrieve the most relevant pieces of your documents and put them in the prompt, so the model answers from them, ideally with citations. It's cheaper and more up to date than fine-tuning, and the sources can be checked.

**Indexing (offline):**

1. **Load and clean** documents (PDFs, pages, tickets) and keep metadata: source, URL, date, access rights.
2. **Chunk** them into passages of a few hundred tokens, with some overlap, split on headings and paragraphs rather than at arbitrary characters.
3. **Embed** each chunk: an embedding model turns text into a vector (e.g. 1,536 numbers) where semantically similar texts are close together.
4. **Store** vectors and metadata in a vector index: **pgvector** in Postgres, Qdrant, Pinecone, Weaviate, or OpenSearch/Elasticsearch.

**Query time:**

1. Embed the user's question with the same model.
2. Find the nearest chunks by **cosine similarity**, using an approximate nearest-neighbour index (**HNSW**) for speed, filtered by metadata (tenant, permissions, date).
3. Optionally combine with keyword search (**hybrid search**, BM25), which catches exact terms like error codes and product names, and **re-rank** the top results with a cross-encoder.
4. Build the prompt: instructions + retrieved chunks with ids + question, and ask for an answer that **cites sources** and says "I don't know" when the context doesn't contain the answer.

```sql
-- pgvector: the 5 most similar chunks this user may see
SELECT id, content, source_url
FROM chunks
WHERE tenant_id = $1
ORDER BY embedding <=> $2          -- cosine distance
LIMIT 5;
```

**What goes wrong:**

- **Bad chunking:** answers split across chunks, or tables and code broken apart.
- **Retrieval misses:** the question uses different words than the documents. Fix with hybrid search, query rewriting, and better metadata.
- **Permissions:** filter by the user's access rights **at retrieval time**, never by asking the model to hide things.
- **Stale index:** re-embed when documents change or are deleted.
- **Prompt injection** hidden in documents.
- **Evaluation:** measure retrieval (did the right chunk appear in the top k?) separately from generation (is the answer faithful to the sources?).

**Frontend side:** show sources and highlight cited passages, stream the answer, let users give feedback, and make it obvious when the answer comes from documents and when it doesn't.
