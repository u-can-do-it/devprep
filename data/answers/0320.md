## Hints

- If one of three concurrent tasks fails, what happens to the other two with `gather` vs `TaskGroup`?
- How is a task actually cancelled: what does it see inside its code?
- What happens to timeouts and `TaskGroup` shutdown if your code catches `CancelledError` and carries on?

## Answer

**`asyncio.gather(*aws)`** runs awaitables concurrently and returns results in order. If one raises, `gather` propagates the **first** exception, but the **other tasks keep running**, unsupervised (orphaned work, "Task exception was never retrieved" warnings). `return_exceptions=True` collects errors as values instead.

**`asyncio.TaskGroup`** (3.11+) is **structured concurrency**: tasks can't outlive the `async with` block. If any task fails, the group **cancels the rest**, waits for them, and raises an **`ExceptionGroup`** with all the failures.

```python
import asyncio

async def load_dashboard(user_id):
    try:
        async with asyncio.timeout(2):                 # 3.11+
            async with asyncio.TaskGroup() as tg:
                profile = tg.create_task(get_profile(user_id))
                orders = tg.create_task(get_orders(user_id))
                recs = tg.create_task(get_recs(user_id))
    except* ConnectionError as eg:
        log.warning("downstream failed: %s", eg.exceptions)
        raise
    return profile.result(), orders.result(), recs.result()
```

**How cancellation works:** `task.cancel()` injects `CancelledError` at the task's current `await`. The coroutine can clean up (`finally`, `async with`) and must then **let the exception propagate**. `CancelledError` subclasses `BaseException`, so `except Exception` doesn't catch it.

**Swallowing it** (`except asyncio.CancelledError: pass`, or a bare `except BaseException`) breaks things:

- `asyncio.timeout()` and `TaskGroup` rely on the cancellation arriving. Swallowing it makes timeouts silently not fire, or shutdown hang.
- Server shutdown (uvicorn, FastAPI lifespan) waits forever on tasks that refuse to die.
- If you really must suppress a cancellation you requested yourself, call `task.uncancel()`. Otherwise always re-raise.

Other tools: `asyncio.shield()` protects an inner operation from outer cancellation (e.g. finishing a commit), though the outer await still gets cancelled. `asyncio.wait(..., return_when=FIRST_COMPLETED)` handles racing and hedging. Keep references to fire-and-forget tasks, or they may be garbage-collected mid-run.
