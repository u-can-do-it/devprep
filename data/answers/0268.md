## Hints

- Does the effect need a trigger such as a hover or a class change, or should it run by itself?
- How would you animate an element that appears from `display: none`?
- Which pipeline steps (layout, paint, composite) does changing `width` trigger, compared with `transform`?

## Answer

**Transitions** animate **between two states** when a property value changes (hover, a class toggle, a JS style change):

```css
.button {
  transition: background-color 150ms ease, transform 150ms ease;
}
.button:hover { background-color: var(--brand-dark); transform: translateY(-1px); }
```

- Only a start and an end state, and they need a trigger.
- They reverse smoothly if the state flips halfway through.

**`@keyframes` animations** define a **timeline with any number of steps**, and run without a state change:

```css
@keyframes pulse {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.4; }
}
.skeleton { animation: pulse 1.5s ease-in-out infinite; }
```

- They autoplay, loop (`iteration-count`), alternate, can be paused (`animation-play-state`), and can keep their end state (`animation-fill-mode: forwards`).
- Use them for loaders, attention effects and multi-step sequences.

**Entry and exit animations, the modern way:**

```css
.toast {
  transition: opacity 200ms, display 200ms allow-discrete;
  opacity: 1;
  @starting-style { opacity: 0; } /* the "from" state when it first appears */
}
.toast[hidden] { display: none; opacity: 0; }
```

`@starting-style` and `transition-behavior: allow-discrete` let you animate to and from `display: none` and into the top layer (dialogs, popovers) without JavaScript timeouts.

**Which properties are cheap to animate:**

- **`transform` and `opacity`** (and usually `filter`) can run on the **compositor**. They skip layout and paint, stay smooth, and keep running even when the main thread is busy.
- `color`, `background-color` and `box-shadow` trigger **repaint**: acceptable for small elements.
- `width`, `height`, `top`, `left`, `margin` and `font-size` trigger **layout** every frame: avoid. Use `transform: scale()` or `translate()` instead.

**Also:** respect `prefers-reduced-motion`, use `will-change` sparingly, and use the Web Animations API (`el.animate()`) when JavaScript needs to control the timing.

**Follow-up:** scroll-driven animations (`animation-timeline: scroll()` / `view()`) link keyframes to scroll position, with no scroll listeners.
