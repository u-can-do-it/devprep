## Hints

- Why does a remote image need an explicit width and height, while a local one doesn't?
- What are `logo@2x.png` and `logo@3x.png` for?
- A 4000×3000 photo is shown as a 60×60 avatar. What does it cost?

## Answer

> Local images are bundled with `require()` and the bundler knows their size. Remote images are loaded from a URL and need explicit dimensions, because nothing is known before the download. Ask the server for an image close to the displayed size, and use a caching image component such as `expo-image` for lists. Custom fonts are embedded at build time or loaded before the first screen. SVG needs a library.

**Local vs remote**

```tsx
// Local: packed into the app, size known at build time
<Image source={require('./assets/logo.png')} />

// Remote: you must give a size (or flex / aspectRatio)
<Image
  source={{ uri: 'https://cdn.example.com/p/42.jpg?w=400' }}
  style={{ width: '100%', aspectRatio: 4 / 3 }}
  resizeMode="cover"
/>
```

`require()` must be a static string, because the bundler resolves it at build time. `require('./' + name + '.png')` doesn't work.

**`resizeMode`** (`contentFit` in `expo-image`): `cover` fills the box and crops, `contain` fits inside with empty bands, `stretch` distorts, `center` doesn't scale up.

**Pixel density**

A style width of 100 is 200 physical pixels on a 2x screen and 300 on a 3x screen. Provide `logo.png`, `logo@2x.png` and `logo@3x.png`, and the right one is chosen. For remote images, request roughly `layout size × PixelRatio.get()`.

**Size and memory**

A decoded image uses about `width × height × 4` bytes, whatever the file size. A 4000×3000 photo is about 48 MB in memory. A list of these crashes Android with an out-of-memory error. So:

- Have the server or an image CDN resize (`?w=400`) and serve WebP or AVIF.
- Never download originals for thumbnails.

**Caching: `expo-image`**

The core `Image` has only basic, platform-dependent caching. `expo-image` adds what a real app needs:

```tsx
import { Image } from 'expo-image';

<Image
  source={product.imageUrl}
  placeholder={{ blurhash: product.blurhash }}   // shown while loading
  contentFit="cover"
  transition={150}
  cachePolicy="memory-disk"
  recyclingKey={product.id}                      // for recycled list rows (#673)
  style={styles.thumb}
/>
```

It also has `Image.prefetch(urls)` for images you know are coming next.

**Fonts**

- With Expo, add the font files through the `expo-font` config plugin. They are embedded at build time and available immediately as `fontFamily: 'Inter-Bold'`.
- Or load at runtime with `useFonts`, and keep the splash screen visible until they are ready, so text doesn't flash in a fallback font.
- On Android, `fontWeight` doesn't synthesise weights for a custom font. Use a separate file per weight.

**Icons and SVG**

- Icon sets: `@expo/vector-icons` or `react-native-vector-icons` render icons as font glyphs.
- SVG isn't supported by the core `Image`. Use `react-native-svg` (with a transformer you can `import Logo from './logo.svg'`), or `expo-image`, which renders SVG files.
- Prefer SVG or icon fonts for icons. They stay sharp at every density.

**Accessibility:** give meaningful images an `accessibilityLabel`, and hide decorative ones from screen readers (#689).

**Follow-up:** images in a long list flicker and show the wrong picture for a moment when you scroll fast. Why? (The list recycles row views, so the old image stays until the new one loads. Set `recyclingKey`, use placeholders, and make sure keys are stable.)
