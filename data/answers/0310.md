## Hints

- What does each kind of method receive as its first argument?
- How would you add an alternative constructor like `User.from_dict(data)`?
- How can an attribute compute its value or validate assignment without changing the caller's syntax?

## Answer

```python
from datetime import date

class Person:
    adults_age = 18                       # class attribute

    def __init__(self, name: str, born: date):
        self.name = name
        self._born = born

    def greet(self) -> str:               # instance method: gets self
        return f"Hi, I'm {self.name}"

    @classmethod
    def from_dict(cls, data: dict) -> "Person":   # gets the class
        return cls(data["name"], date.fromisoformat(data["born"]))

    @staticmethod
    def is_valid_name(name: str) -> bool:  # gets nothing implicit
        return bool(name.strip())

    @property
    def age(self) -> int:                  # computed, read like an attribute
        today = date.today()
        return today.year - self._born.year - (
            (today.month, today.day) < (self._born.month, self._born.day))

    @property
    def born(self) -> date:
        return self._born

    @born.setter
    def born(self, value: date) -> None:   # validation on assignment
        if value > date.today():
            raise ValueError("born in the future")
        self._born = value
```

- **Instance method**: works with one object's state (`self`).
- **`@classmethod`**: receives `cls`. Use it for **alternative constructors** and factories. It respects subclasses, since `Employee.from_dict` returns an `Employee`.
- **`@staticmethod`**: a plain function placed in the class namespace for organization. It can't access the instance or class. A module-level function is often just as good.
- **`@property`**: exposes a method as an attribute (`p.age`, not `p.age()`), with an optional setter or deleter. It lets you start with a plain public attribute and later add logic **without breaking callers**. That's why Python doesn't need Java-style getters and setters.

Pitfall: properties should be cheap and have no side effects. For expensive values computed once, use `functools.cached_property`.

**Follow-up:** Can a property be defined on the class itself (a "class property")? (Not reliably. Chaining `@classmethod` with `@property` was deprecated and then removed in 3.13. Use a metaclass or a plain class attribute.)
