## Hints

- If you can't see the page, how would you get a quick overview of what's on it?
- Which HTML elements map to landmarks without any ARIA?
- On a site with a 40-link navigation bar, how many Tab presses does a keyboard user need to reach the content?

## Answer

Screen reader users rarely read a page top to bottom. They **skim by structure**, using shortcuts and lists (the VoiceOver rotor, the NVDA elements list) to jump by **headings**, **landmarks**, links and form fields. Surveys of screen reader users regularly put headings as their main way of finding information.

**Headings**

- Give the page one clear `<h1>`, then nest `<h2>`–`<h6>` **without skipping levels** for structure. Choose the level by hierarchy, not font size (style with CSS).
- A heading should describe the section that follows. Don't use heading tags just to make text big, and don't fake headings with bold `<div>`s.
- In SPAs, move focus to the new page's `<h1>` (or announce the change) after navigation.

**Landmarks** come from semantic elements:

| Element | Landmark |
|---|---|
| `<header>` (top-level) | banner |
| `<nav>` | navigation |
| `<main>` (only one visible) | main |
| `<aside>` | complementary |
| `<footer>` (top-level) | contentinfo |
| `<form>` / `<section>` **with an accessible name** | form / region |
| `<search>` | search |

When the same landmark appears more than once, label each one: `<nav aria-label="Primary">`, `<nav aria-label="Breadcrumb">`. Put all content inside some landmark.

**Skip links** let keyboard users bypass repeated navigation:

```html
<body>
  <a class="skip-link" href="#main">Skip to main content</a>
  <header>...</header>
  <main id="main" tabindex="-1">...</main>
</body>
```

The link is the first focusable element. It's visually hidden until focused, then appears. This satisfies WCAG 2.4.1 (Bypass Blocks).

**Other quick wins:** a descriptive `<title>` per page, `lang` on `<html>`, link text that makes sense out of context (no lone "click here"), and DOM order that matches visual order.

**Follow-up:** check the outline with a browser extension (HeadingsMap) or the accessibility tree in DevTools, and try navigating with VoiceOver or NVDA yourself.
