## Hints

- After server rendering, the HTML is already on screen. What does React need to do in the browser to make it interactive?
- What happens if the first client render produces different markup than the server did?
- What's different between the server and the browser at render time: clock, locale, `window`, extensions?

## Answer

**Hydration** is how React makes server-rendered HTML interactive. In the browser, `hydrateRoot` renders the same component tree. Instead of creating DOM nodes, it **adopts the existing ones**, attaches event listeners, and connects state. The client's first render must produce **exactly the same output** as the server.

A **hydration mismatch** happens when it doesn't. React then throws away the server HTML for that part of the tree and re-renders it on the client, up to the nearest Suspense boundary or the root. This costs performance and can cause flicker. React 19 reports it with one error that includes a diff.

**Common causes:**

- **Non-deterministic values in render:** `Date.now()`, `new Date().toLocaleString()` (server and user time zones differ), `Math.random()`, random IDs.
- **Environment branches:** `typeof window !== 'undefined' ? <A/> : <B/>`, `localStorage`, `matchMedia` read during render.
- **Invalid HTML nesting:** `<div>` inside `<p>`, `<a>` inside `<a>`, a `<tr>` without `<tbody>`. The browser's parser rearranges the DOM.
- **Browser extensions** modifying the DOM before hydration.
- Server and client getting **different data**.

**Fixes:**

- Use `useId` for IDs.
- Render client-only values **after mount**: set state in `useEffect`, or use `useSyncExternalStore` with a `getServerSnapshot`.
- Format dates with an explicit time zone and locale, or render them in a client-only component.
- Fix HTML nesting.
- Use `suppressHydrationWarning` only for unavoidable one-level text differences, like a timestamp.

```jsx
const [now, setNow] = useState(null);
useEffect(() => setNow(new Date()), []);
return <time>{now ? now.toLocaleTimeString() : ''}</time>;
```

**Follow-up:** with streaming SSR, React hydrates **selectively**, Suspense boundary by boundary, and gives priority to the parts the user interacts with.
