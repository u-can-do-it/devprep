## Hints

- What must happen to a pending timer when the value changes again, or when the component unmounts?
- Is "the value from the previous render" the same as "the previous different value"?
- What can go wrong when reading `localStorage`: on the server, in private mode, or with corrupted JSON?
- Does the `storage` event fire in the tab that made the change?

## Answer

**`useDebounce`: debounce a value** (for example a search query):

```ts
export function useDebounce<T>(value: T, delay = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);   // a newer value or unmount cancels the pending update
  }, [value, delay]);
  return debounced;
}
```

**Debouncing a callback** (for example autosave) needs the latest function without restarting the timer on every render:

```ts
export function useDebouncedCallback<A extends unknown[]>(fn: (...args: A) => void, delay = 300) {
  const fnRef = useRef(fn);
  const timer = useRef<ReturnType<typeof setTimeout>>(undefined);
  useLayoutEffect(() => { fnRef.current = fn; });            // always call the newest fn
  useEffect(() => () => clearTimeout(timer.current), []);    // cancel on unmount

  return useCallback((...args: A) => {
    clearTimeout(timer.current);
    timer.current = setTimeout(() => fnRef.current(...args), delay);
  }, [delay]);
}
```

**`usePrevious`.** First decide which "previous" you mean.

```ts
// The previous *different* value. This is the version the React docs recommend: no refs read during render.
export function usePrevious<T>(value: T): T | undefined {
  const [current, setCurrent] = useState(value);
  const [previous, setPrevious] = useState<T | undefined>(undefined);
  if (!Object.is(value, current)) {
    setPrevious(current);   // setting state during render is allowed for this pattern
    setCurrent(value);
  }
  return previous;
}
```

The classic version, `useEffect(() => { ref.current = value }); return ref.current;`, returns the value from the *previous render*. It reads a ref during render, which lint rules and the React Compiler flag.

**`useLocalStorage`:**

```ts
export function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    try {
      const raw = localStorage.getItem(key);
      return raw === null ? initial : (JSON.parse(raw) as T);
    } catch {
      return initial;   // no window (SSR), storage blocked, or invalid JSON
    }
  });

  useEffect(() => {
    try { localStorage.setItem(key, JSON.stringify(value)); } catch { /* quota exceeded or blocked */ }
  }, [key, value]);

  useEffect(() => {
    function onStorage(e: StorageEvent) {
      if (e.storageArea !== localStorage || e.key !== key) return;
      try { setValue(e.newValue === null ? initial : JSON.parse(e.newValue)); } catch { /* ignore */ }
    }
    window.addEventListener('storage', onStorage);   // fires only in *other* tabs
    return () => window.removeEventListener('storage', onStorage);
  }, [key]); // eslint-disable-line react-hooks/exhaustive-deps -- `initial` is only a fallback

  return [value, setValue] as const;
}
```

**Edge cases to mention:**

- **SSR:** reading storage during the first render causes a hydration mismatch. Read it in an effect, or use `useSyncExternalStore` with a server snapshot (#222).
- **Two components using the same key in the same tab** don't sync, because `storage` only fires in other tabs. Fix it with a shared store (`useSyncExternalStore` plus a custom event).
- **Changing `key`** doesn't re-read the stored value in this version.
- **Validate what you read** (Zod), because users and old app versions can leave anything in storage (#182).
- **Never store tokens or personal data** in `localStorage` (#56, #505).

**General rules:** hook names start with `use`, every call gets its own state (#38), and you test them with `renderHook` and fake timers (#463).
