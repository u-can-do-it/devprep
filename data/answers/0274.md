## Hints

- How do you guarantee that utility classes beat component styles without raising specificity?
- How would you stop a third-party library's CSS from fighting your own?
- How can a component's styles apply inside it but not inside a nested component?

## Answer

**Cascade layers (`@layer`)** let you decide priority **explicitly**, independent of specificity. When two declarations conflict, the layer order is checked **before** specificity:

```css
/* declare the order once, at the very top */
@layer reset, vendor, tokens, base, components, utilities;

@import url("normalize.css") layer(reset);
@import url("datepicker.css") layer(vendor);

@layer base {
  a { color: var(--link); }
}
@layer components {
  .btn#save.primary { background: var(--brand); } /* high specificity... */
}
@layer utilities {
  .bg-danger { background: crimson; } /* ...still loses to a later layer */
}
```

Rules to know:

- **Later layers win.** **Unlayered styles beat all layers.** That's handy for overrides during a migration, and dangerous if forgotten.
- With `!important` the order is **reversed**: an important declaration in `reset` beats one in `utilities`. This lets low layers protect critical styles.
- Layers can be nested (`components.forms`). Tailwind v4 emits its own layers (`theme`, `base`, `components`, `utilities`).

**`@scope`** limits where selectors match, with an optional **lower boundary** (a "donut" scope):

```css
@scope (.card) to (.card-content) {
  img { border-radius: 0.5rem; }   /* card images, but not images inside slotted content */
  :scope { padding: 1rem; }
}
```

- When two rules have the same specificity, **scope proximity** decides: the rule whose scope root is the closest ancestor wins. This solves "a light theme nested inside a dark theme" without specificity hacks.
- Unlike Shadow DOM, it's **not** encapsulation. Outside styles still apply.

**Architecture for a large codebase / design system:**

1. One file declares the layer order. Third-party CSS is imported into `vendor` so it can never win by accident.
2. `reset` and `base` use `:where()` (zero specificity).
3. Components live in `components`. Each is scoped with `@scope`, CSS Modules or a BEM block, and themed only through custom properties.
4. `utilities` sit last for one-off adjustments. Avoid unlayered CSS except deliberate overrides.
5. Lint for `!important` and ID selectors.

**Follow-up:** `@scope` now has cross-browser support, but check your support matrix. Unsupported browsers drop the whole block, so for critical styles you may need a fallback.
