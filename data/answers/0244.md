## Hints

- If a Server Component passes a full `user` row to a Client Component, what ends up in the page source?
- What build-time guard stops a database module from being imported into client code?
- Which environment variables are inlined into the JavaScript bundle?

## Answer

With Server Components, server and client code live in the same tree, so it's easy to leak data by accident. Defend in layers:

**1. Only serializable props cross the boundary, and they are all public.** Everything passed to a Client Component is serialized into the RSC payload that the browser downloads. Don't pass whole DB records:

```tsx
// BAD: passwordHash, email, internal flags go to the browser
<ProfileCard user={userRow} />
// GOOD: a minimal DTO
<ProfileCard user={{ name: userRow.name, avatarUrl: userRow.avatarUrl }} />
```

**2. A Data Access Layer (DAL)** — one `server-only` module that does auth checks and returns **DTOs** with just the fields the UI needs. Only the DAL reads `process.env` secrets and talks to the database.

**3. `import 'server-only'`** at the top of modules with secrets or DB access. If a Client Component imports them, even indirectly, the **build fails**. (`client-only` is the mirror package.)

**4. Environment variables** are server-only unless prefixed with `NEXT_PUBLIC_`, which **inlines** the value into the client bundle. Never prefix secrets.

**5. React Taint APIs** (enable `experimental.taint`) as a safety net:

```ts
import { experimental_taintObjectReference, experimental_taintUniqueValue } from 'react';
experimental_taintObjectReference('Do not pass the user row to the client', userRow);
experimental_taintUniqueValue('Do not leak the API key', process, process.env.API_KEY!);
```

React then throws if a tainted object or value is passed to the client. It's a backstop, not a replacement for DTOs.

**6. Server Actions:** return minimal data. Don't capture secrets in closures: captured variables are encrypted but still round-trip through the client. Never trust IDs that come back.

**7. Errors and logs:** production errors from Server Components reach the client only as a digest. Don't put sensitive data in thrown messages or `console.log` calls that run in Client Components.

**Audit checklist:** `'use client'` files with overly broad prop types, `'use server'` files without auth checks or validation, imports of `db`/`process.env` outside the DAL, and `[param]` folders whose input isn't validated.

**Follow-up:** check the RSC payload in the Network tab (the `?_rsc` requests) to see exactly what was sent.
