## Hints

- What does the model actually produce at each step, and from what?
- Why does a chat seem to remember what you said, when each API call is independent?
- Why can a model describe a function that doesn't exist, in a confident tone?

## Answer

> A large language model predicts the next token from the text it has been given, one token at a time. A token is a piece of a word. The context window is how many tokens the model can see in one call, input and output together, and the model has no memory beyond it. Its knowledge stops at the training cutoff. It hallucinates because it generates likely text, not looked-up facts, so anything that matters has to be grounded in sources or tools and then verified.

**The loop:** text is split into **tokens**, the model computes a probability for every possible next token, one is chosen and appended, and the process repeats until a stop token or a length limit. Everything else (chat, code generation, agents) is built on that loop.

| Term | Meaning | Why it matters to you |
|---|---|---|
| Token | a word piece; roughly 4 characters of English, more tokens for Polish and for code | limits and prices are counted in tokens |
| Context window | the maximum tokens in one call: system prompt, history, files, tool results and the answer | what doesn't fit, or isn't included, the model doesn't know |
| Weights | the model's parameters, fixed after training | it doesn't learn from your conversation |
| Knowledge cutoff | the date its training data ends | it may not know a library's latest version |
| Temperature, top-p | how randomly the next token is picked | the same prompt can give different answers |
| System prompt | instructions placed before the conversation | sets role, rules and format |
| Hallucination | fluent output that is false or made up | you must verify |

**No memory between calls:** the API is stateless. A chat "remembers" because the application sends the whole conversation again each time. Long chats cost more, and old messages are eventually cut or summarised. "Memory" features are text that the application stores and puts back into the context (#483).

**Why answers vary:** the next token is sampled. A higher temperature gives more varied output, a lower one more repeatable output, and even at 0 results are not guaranteed to be identical. Some reasoning models don't let you change these settings. So you can't test an LLM feature with one exact expected string; you check properties or use an evaluation set (#482).

**Why it hallucinates:** the model produces text that is *likely* given its training, and likely is not the same as true. It has no built-in step that looks a fact up. The risk is highest for:

- exact details: version numbers, function signatures, configuration options, URLs, quotes, citations
- niche or new things with little or no training data (anything after the cutoff)
- questions with a false premise ("how do I use the `retryAll` option?" gets an answer even if no such option exists)
- arithmetic and counting over long inputs

**How to reduce it**

- **Give it the source:** paste or retrieve the documentation, the file, the schema (RAG, #478), and ask it to answer from that.
- **Give it tools:** search, running code, querying a database. A model that can execute a test doesn't have to guess (#479).
- **Allow "I don't know"** and ask for the source of each claim.
- **Verify:** compile it, run it, check that the package and the API exist (#526).

**Things that follow from this**

- The model has **no access** to your files, the internet or the current date unless the application provides them through the context or tools.
- **Reasoning ("thinking") models** generate intermediate reasoning before the answer. It helps on hard problems and costs time and tokens.
- A **bigger context is not automatically better**: quality drops when the relevant part is buried in irrelevant text.
- Everything in the context is text to the model, including instructions hidden in a web page or a file. That is the root of prompt injection (#481).
- **Embeddings** are a different output of the same kind of model: a vector that represents meaning, used for search (#478).

**Follow-up:** the model gives you code that calls a method your library doesn't have. Why did that happen, and what do you change in how you ask? (It generated a plausible name, perhaps from another version or a similar library. Provide the real docs or type definitions, state the version, and let it run the type checker.)
