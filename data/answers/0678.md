## Hints

- If an animation is driven by `setState` on every frame, which thread must be free for it to stay smooth?
- Which style properties can the native driver animate, and which can't it?
- A card must follow the finger while JS is busy loading data. Where must the gesture code run?

## Answer

> A smooth animation must not depend on the JS thread, because JS is often busy rendering or fetching. The built-in `Animated` API with `useNativeDriver: true` sends the whole animation to the UI thread, but only for `transform` and `opacity`. Reanimated goes further: animation logic is written as small functions (worklets) that run on the UI thread, so it can animate any style and react to gestures frame by frame. Gesture Handler recognises touches natively and feeds them to those worklets.

**The options**

| Tool | Where it runs | Use for |
|---|---|---|
| `Animated` + `useNativeDriver: true` | UI thread | simple fades, slides, scale; no extra library |
| `Animated` without the native driver | JS thread, every frame | avoid; needed only for layout props like `height` |
| `LayoutAnimation` | native | "animate whatever changes in the next layout": simple list insertions |
| Reanimated | UI thread, via worklets | everything else: gestures, layout, shared transitions |

```tsx
// Animated: fine for a fade
const opacity = useRef(new Animated.Value(0)).current;
useEffect(() => {
  Animated.timing(opacity, { toValue: 1, duration: 200, useNativeDriver: true }).start();
}, [opacity]);
```

**Reanimated**

- A **shared value** (`useSharedValue`) is state that lives on the UI thread. Changing it doesn't re-render the component.
- `useAnimatedStyle` is a **worklet**: a function that Reanimated runs on the UI thread whenever the shared values it reads change.
- `withTiming`, `withSpring` and `withDecay` describe how a value moves to its target.

```tsx
function SwipeCard() {
  const x = useSharedValue(0);

  const pan = Gesture.Pan()
    .onChange((e) => {
      x.value += e.changeX;              // runs on the UI thread, every frame
    })
    .onEnd(() => {
      x.value = withSpring(0);
    });

  const style = useAnimatedStyle(() => ({ transform: [{ translateX: x.value }] }));

  return (
    <GestureDetector gesture={pan}>
      <Animated.View style={[styles.card, style]} />
    </GestureDetector>
  );
}
```

The card follows the finger even if the JS thread is blocked, because neither the gesture callback nor the style update touches it.

- Worklets can't call normal JS functions directly. To update React state or navigate at the end of a gesture, schedule the call back on the JS thread (`runOnJS`, or `scheduleOnRN` in Reanimated 4).
- Reanimated also has entering and exiting animations (`entering={FadeIn}`), layout transitions and, in version 4, CSS-style `transition` and `animation` props. Reanimated 4 requires the New Architecture.

**Gesture Handler**

`react-native-gesture-handler` uses the platform's own gesture recognisers instead of the JS responder system. Gestures compose (`Gesture.Simultaneous`, `Gesture.Race`, `Gesture.Exclusive`), which you need for pinch plus pan, or a swipeable row inside a scrolling list. Navigation libraries, bottom sheets and swipeable rows are built on it.

**Rules for smooth motion**

- Animate `transform` and `opacity` where you can. Animating `width`, `height` or `margin` forces layout on every frame.
- Never drive an animation with `setState` in a loop or in `onScroll`.
- Keep the frame budget in mind: 16 ms at 60 Hz, 8 ms at 120 Hz (#694).
- Respect the user's "reduce motion" setting (`useReducedMotion`).
- Test in a release build on a slow Android phone.

**When you need more:** Lottie or Rive for designer-made animations, and React Native Skia for custom drawing and shaders.

**Follow-up:** a header should shrink as the list scrolls. How do you build it without re-rendering on scroll? (`useAnimatedScrollHandler` writes the scroll offset to a shared value, and `useAnimatedStyle` with `interpolate` maps it to a translation or scale.)
