## Hints

- Which pipeline stages run again when you change `width`, `color`, or `transform`?
- What does the browser have to do if you write to the DOM and then immediately read `offsetHeight`?
- Which work can run on the compositor thread even while the main thread is busy?

## Answer

After the first render, changes re-run only part of the pipeline: **style → layout → paint → composite**.

- **Reflow (layout)** — recomputing geometry. Triggered by changes to size/position: `width`, `height`, `margin`, `top`, `font-size`, adding/removing DOM nodes, changing text, resizing the window. It is the most expensive step and can cascade to ancestors, descendants and siblings.
- **Repaint** — redrawing pixels without changing geometry: `color`, `background`, `box-shadow`, `visibility`.
- **Composite only** — `transform` and `opacity` on an element with its own layer can be handled by the **compositor thread** on the GPU, skipping layout and paint. This is why animations should use them.

**Layout thrashing (forced synchronous layout):** the browser normally batches layout until the next frame. But **reading** a layout property (`offsetHeight`, `getBoundingClientRect()`, `scrollTop`, `getComputedStyle`) after a **write** forces it to lay out immediately. Doing that in a loop causes N layouts per frame:

```js
// Bad: read/write interleaved → layout on every iteration
items.forEach(el => {
  el.style.height = container.offsetHeight / 2 + 'px';
});

// Good: read once, then write
const h = container.offsetHeight / 2;
items.forEach(el => { el.style.height = h + 'px'; });
```

**Techniques:**

- Batch reads, then writes; schedule writes in `requestAnimationFrame` (or use a library like fastdom).
- Animate `transform`/`opacity`, never `top`/`left`/`width`.
- Use `will-change: transform` sparingly — each layer costs GPU memory.
- Limit the scope of work with `contain: layout paint` or `content-visibility: auto` for off-screen sections.
- Use `ResizeObserver`/`IntersectionObserver` instead of polling geometry in scroll handlers.
- Virtualize long lists to keep the DOM small.

**Diagnosing:** the DevTools Performance panel flags "Forced reflow" warnings and purple Layout blocks; the Rendering tab can highlight paint flashing and layer borders.

**Follow-up:** connect this to INP — long layout and style recalculation tasks are a common cause of slow interaction responses.
