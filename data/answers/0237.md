## Hints

- When does this code run: before or after the route is matched and rendered?
- Why was it renamed from "middleware"?
- Should this be the *only* place that protects `/admin`?

## Answer

`proxy.ts` (at the project root or in `src/`) exports one function that runs **before a request reaches your routes**. It can redirect, rewrite, set request or response headers and cookies, or return a response directly. Next.js 16 renamed `middleware.ts` to `proxy.ts` (there's a codemod) to make it clear that it's a network-boundary layer, not Express-style middleware. It runs on the **Node.js runtime** by default and you can't change the `runtime` there. The deprecated `middleware.ts` remains only for Edge use cases.

```ts
// proxy.ts
import { NextResponse, type NextRequest } from 'next/server';

export function proxy(req: NextRequest) {
  if (!req.cookies.has('session') && req.nextUrl.pathname.startsWith('/app')) {
    return NextResponse.redirect(new URL('/login', req.url));
  }
  return NextResponse.next();
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico|.*\\.png$).*)'],
};
```

**Good uses:**

- **Optimistic auth redirects**: a cheap cookie check that sends logged-out users to `/login`
- Redirects and rewrites: locale detection, A/B tests, multi-tenant routing by hostname, legacy URLs
- Headers: a CSP nonce, security headers, request IDs
- Simple bot or geo blocking

**What not to do:**

- **Don't make it your only authorization layer.** Server Actions are POSTs to the page they're used on, so a matcher change can silently skip them. CVE-2025-29927 (spring 2025) let attackers bypass middleware with a crafted header. Check auth again in the data layer, Server Components, Actions and Route Handlers.
- No slow work on every request, such as DB queries or calls to other services. It adds latency to *every* matched request, including prefetches.
- Don't forget the **`matcher`**. Without it, proxy also runs for static assets and images.
- Don't rely on shared module state or globals between invocations.

**Follow-up:** prefer `redirects`/`rewrites`/`headers` in `next.config.ts` for static rules. The Next.js team recommends proxy as a last resort.
