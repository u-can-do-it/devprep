## Hints

- In concurrent rendering, React can pause halfway through rendering a tree. What if an external store changes during that pause?
- Why isn't `useState` + `useEffect` subscribing to a store enough?
- What happens if `getSnapshot` returns a new object every call?

## Answer

`useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)` is the official way to **read state that lives outside React**: a Redux or Zustand store, browser APIs (`navigator.onLine`, `matchMedia`), or a WebSocket cache. Libraries use it internally.

**Tearing:** with concurrent rendering, React may render part of the tree, yield, and continue later. If a mutable external store changes in between, some components render with the old value and others with the new one. The UI is then inconsistent ("torn"). The older pattern of subscribing in `useEffect` and copying into `useState` has this problem, and it also renders stale values first. `useSyncExternalStore` lets React check the snapshot. If the snapshot changed during render, React re-renders **synchronously** so all components see one consistent value.

**Minimal store with selectors:**

```ts
function createStore<T>(initial: T) {
  let state = initial;
  const listeners = new Set<() => void>();
  return {
    get: () => state,
    set(update: (s: T) => T) {
      state = update(state);              // must produce a NEW object
      listeners.forEach(l => l());
    },
    subscribe(l: () => void) { listeners.add(l); return () => listeners.delete(l); },
  };
}

type CartState = { items: Item[]; open: boolean };
const cart = createStore<CartState>({ items: [], open: false });

function useCart<S>(selector: (s: CartState) => S) {
  return useSyncExternalStore(cart.subscribe,
    () => selector(cart.get()),
    () => selector(cart.get()));          // server snapshot for SSR/hydration
}

const count = useCart(s => s.items.length); // re-renders only when count changes
```

**Pitfalls:**

- `getSnapshot` must return a **cached or immutable** value. Returning a fresh object (`s => ({ ...s })`) changes on every call and causes an infinite loop. Select primitives, or memoize the selector result (as Zustand's `useShallow` does).
- Define `subscribe` **outside** the component, or keep it stable. Otherwise React resubscribes on every render.
- Updates from external stores **can't be transitions**. They always render synchronously, so heavy derived work should use `useDeferredValue`.
