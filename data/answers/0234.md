## Hints

- How does Next.js know which `/blog/[slug]` pages exist at build time?
- Do you have to prerender all 200,000 product pages during the build?
- What should `/blog/does-not-exist` return?

## Answer

`generateStaticParams` is exported from a dynamic route segment. It returns the list of params to **prerender at build time**. It replaces `getStaticPaths` from the Pages Router.

```tsx
// app/blog/[slug]/page.tsx
export async function generateStaticParams() {
  const posts = await getPublishedPosts();
  return posts.map((p) => ({ slug: p.slug }));
}

export default async function Post({ params }: PageProps<'/blog/[slug]'>) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) notFound();
  return <Article post={post} />;
}
```

Each returned object becomes a static HTML + RSC payload that can be served from a CDN. Identical `fetch` calls made across these renders are deduplicated during the build.

**Unknown params** (not returned at build time):

- Default (`dynamicParams = true` in the classic model): the page is **rendered on the first request and then cached**, which is ISR-style. With Cache Components, the visitor gets the route's App Shell immediately while the concrete page is generated in the background.
- `export const dynamicParams = false` (classic model): unknown params return **404**. Good for a closed set such as a fixed list of categories.
- Either way, call `notFound()` for slugs that don't exist in your data, so you don't cache an empty page.

**Practical strategies:**

- Large catalogs: prerender only the **top N** popular pages and let the rest be generated on demand. This keeps build times reasonable.
- Nested dynamic segments: a child's `generateStaticParams` receives the parent's `params`, or a single function can return every combination.
- `output: 'export'` (static export) **requires** it for every dynamic route, because there is no server to render on demand.

**Follow-up:** after content changes, use on-demand revalidation (`revalidatePath`, or `revalidateTag` from a CMS webhook) instead of rebuilding the whole site.
