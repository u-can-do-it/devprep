## Hints

- Should you parse and validate the file in the browser, on the server, or both?
- Row 4,812 of 10,000 has an invalid date. Do you reject the whole file, skip the row, or ask the user?
- An import takes three minutes. What does the HTTP request return, and how does the UI follow the progress?
- A user exports "everything I filtered" and gets only the first 100 rows. What went wrong?
- An exported cell contains `=HYPERLINK("http://evil.example", "Click")`. What is that attack called, and how do you prevent it?

## Answer

> Import is a wizard: upload → map columns → preview with per-row errors → confirm → result report. Parse in the browser for a fast preview if you like, but the server validates again and is the authority. Large imports run as async jobs (`202 Accepted` with a job id) that the UI polls. Decide up front whether an import is all-or-nothing or partial, and make it idempotent. Export small, already-loaded data on the client. Export the full filtered dataset on the server, using the same filter and sort as the grid. Handle encodings and Polish number formats, and neutralize CSV injection by escaping cells that start with `=`, `+`, `-` or `@`.

**Import flow**

1. **Upload.** `accept=".csv,.xlsx"`, a size limit checked in the browser and on the server, drag and drop (`@mantine/dropzone`), and upload progress (Axios `onUploadProgress`, #647). Upload very large files straight to object storage with a presigned URL. Next.js Server Actions have a small default body limit, so use a Route Handler or the API for uploads (#236).
2. **Parse.** CSV with PapaParse (`worker: true` keeps the UI responsive). Excel with SheetJS or ExcelJS. Detect the encoding: files from Polish Excel are often Windows-1250 or UTF-8 with a BOM, and use `;` as the separator, a decimal comma (`1 234,56`) and local dates (`19.11.2026`).
3. **Map columns.** Auto-match headers (normalize case, spaces and diacritics), let the user fix the mapping, and remember it for next time.
4. **Validate each row** with the same schema as the form (#625):

```ts
const RowSchema = z.object({
  taxId: z.string().regex(/^\d{10}$/, 'NIP must have 10 digits'),
  name: z.string().trim().min(1),
  limit: z.string().transform(parsePlNumber).pipe(z.number().nonnegative()),
  validFrom: z.string().transform(parsePlDate).pipe(z.string().date()),
});

const results = rows.map((raw, i) => ({ line: i + 2, raw, result: RowSchema.safeParse(raw) }));   // +2: header + 1-based
const errors = results.flatMap(({ line, result }) =>
  result.success ? [] : result.error.issues.map((iss) => ({ line, column: String(iss.path[0]), message: iss.message })));
```

   Also check duplicates within the file and against the database (by business key), and references to dictionaries (#652).

5. **Preview.** A grid with invalid cells highlighted (`cellClassRules`, #645), a "show only errors" toggle, counts ("9,812 valid, 188 with errors"), and a downloadable error report (the original row plus an error column) that the user can fix and re-upload.
6. **Confirm and run.**
   - *All-or-nothing:* one transaction, nothing is saved if any row fails. This is common for regulatory data.
   - *Partial:* valid rows are saved and the report lists the rejects. Be explicit in the UI about which mode applies.
   - *Idempotent:* an import id, plus upserts by business key, so a retried or double-clicked import doesn't create duplicates.
7. **Async job.**

```ts
const { mutateAsync: start } = useMutation({ mutationFn: (fileId: string) => http.post<{ jobId: string }>('/imports', { fileId }) });

const job = useQuery({
  queryKey: ['import-job', jobId],
  queryFn: () => http.get<ImportJob>(`/imports/${jobId}`).then((r) => r.data),
  enabled: !!jobId,
  refetchInterval: (q) => (['done', 'failed'].includes(q.state.data?.status ?? '') ? false : 2000),
});
```

   Show progress ("4,000 / 10,000"). Let the user leave the page and find the job later in an "Imports" list. Notify them when it finishes. Server-Sent Events can replace polling when updates must feel instant.

8. **Result.** Created, updated and rejected counts, the error report, a link to the affected records, and an audit entry for the import (#650).

**Export**

- **Client-side** (data already in the browser, a few thousand rows): AG Grid `exportDataAsCsv`, or build the file in the browser. Fast and simple, but limited to the loaded rows. In a server-side grid that means only the loaded blocks, which is the "first 100 rows" bug (#646).
- **Server-side** (everything matching the filter): send the grid's current filter, sort and visible columns to the API, which streams the file:

```ts
// app/api/orders/export/route.ts
export async function GET(req: Request) {
  const session = await auth();                                     // #631
  if (!session) return new Response(null, { status: 401 });
  const filters = parseFilters(new URL(req.url).searchParams);       // whitelisted, as in the grid
  const stream = ordersCsvStream(filters, session.user);             // rows read in chunks, permission-filtered
  return new Response(stream, {
    headers: {
      'Content-Type': 'text/csv; charset=utf-8',
      'Content-Disposition': `attachment; filename="orders-${new Date().toISOString().slice(0, 10)}.csv"`,
    },
  });
}
```

  A plain `<a href="/api/orders/export?…">` link downloads it with the session cookie and nothing buffered in JS memory. For very large or slow exports, run a job and offer a download link when it's ready.

- **Excel compatibility:** start CSVs with a UTF-8 BOM (`﻿`) so Polish characters open correctly. Consider `;` as the separator for Polish Excel, or generate real `.xlsx` (ExcelJS, or AG Grid Enterprise's Excel export) with typed number and date cells.

**Security**

- **CSV/formula injection:** a cell starting with `=`, `+`, `-`, `@`, a tab or a carriage return can run as a formula when opened in Excel. Prefix such values with `'` (OWASP's recommendation), on export and in any error report you generate.
- Validate on the server regardless of the client preview. Limit file size and row count, and parse in a worker or job, not in the request thread.
- Export only what the user may see, the same as the grid (#622). Audit who exported what and with which filter (#650).
- Don't trust the file extension; check the content. Never execute macros. Keep uploaded files private and delete them after the retention period.

**Follow-up:** "Why validate in the browser if the server does it again?" Feedback. The user sees all 188 problems in seconds and can fix them before a three-minute job runs and fails. The server check is what guarantees correctness.
