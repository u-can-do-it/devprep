## Hints

- An effect connects to a chat room and shows a toast in the current `theme` when connected. Should changing the theme reconnect?
- What happens if you leave `theme` out of the dependency array to avoid that?
- What's the difference between "reactive" logic (should re-sync) and "non-reactive" logic (should only read the latest value)?

## Answer

Every value an effect reads must be in its dependency array, so the effect re-runs when any of them change. Sometimes part of the effect's logic needs the **latest** value but **shouldn't trigger** a re-sync. Before `useEffectEvent`, developers either reconnected unnecessarily or disabled the lint rule, which leads to stale-closure bugs.

`useEffectEvent` (stable in React 19.2) extracts that non-reactive part into an **Effect Event**. It always sees the latest props and state, and it isn't a dependency:

```jsx
function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showToast('Connected!', theme);      // reads the latest theme
  });

  useEffect(() => {
    const conn = createConnection(roomId);
    conn.on('connected', () => onConnected());
    conn.connect();
    return () => conn.disconnect();
  }, [roomId]);                          // reconnects only when roomId changes
}
```

Other uses: logging analytics with the current cart in a page-visit effect, or reading the latest callback prop inside an interval without restarting it.

**Rules:**

- Call it **only from inside effects** (or functions called from them). Not during render, and not from event handlers. Regular handlers already see the latest values.
- **Don't pass it** to other components or hooks, and **don't put it in dependency arrays**. The hooks lint plugin knows it's non-reactive.
- It is **not** a general replacement for `useCallback`. Its identity is intentionally unstable.

**Before 19.2:** the "latest ref" pattern did the same job: store the callback in a ref, update it in a layout effect, and call `ref.current()` inside the effect.

**Follow-up:** if you need it everywhere, ask whether the logic belongs in an event handler instead of an effect.
