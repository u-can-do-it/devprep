## Hints

- `MantineProvider` uses context. Can it sit in a Server Component `layout.tsx`, and what does `ColorSchemeScript` prevent?
- Why can't you write `<Tabs.Tab>` in a Server Component, and what's the workaround?
- Where do you change every `Button`'s default `radius` without wrapping it?
- Tailwind's preflight and Mantine's styles both target the same elements. Who wins, and how do CSS layers decide?
- Mantine's dark mode is a `data-` attribute on `<html>`. How do you make Tailwind's `dark:` variant follow it?

## Answer

> Import `@mantine/core/styles.css` once, put `ColorSchemeScript` in `<head>` and spread `mantineHtmlProps` on `<html>` so the colour scheme is set before hydration. `MantineProvider` can be rendered directly from the root layout. Mantine components are client components, so use them in client files or use the non-compound exports (`TabsTab`) in Server Components. Theme with `createTheme` (colours, fonts, `components` defaults) and style parts of components with the Styles API (`classNames` plus CSS Modules). With Tailwind, load Mantine's layered CSS and order the layers so Tailwind utilities override Mantine, and point Tailwind's `dark:` variant at Mantine's colour-scheme attribute.

**Setup in the App Router (Mantine 7/8)**

```tsx
// app/layout.tsx
import '@mantine/core/styles.css';            // or styles.layer.css with Tailwind (see below)
import '@mantine/notifications/styles.css';   // each extra package has its own CSS
import { ColorSchemeScript, MantineProvider, mantineHtmlProps } from '@mantine/core';
import { Notifications } from '@mantine/notifications';
import { theme } from './theme';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="pl" {...mantineHtmlProps}>
      <head>
        <ColorSchemeScript defaultColorScheme="auto" />
      </head>
      <body>
        <MantineProvider theme={theme} defaultColorScheme="auto">
          <Notifications />
          {children}
        </MantineProvider>
      </body>
    </html>
  );
}
```

- `ColorSchemeScript` is a tiny inline script that sets `data-mantine-color-scheme` on `<html>` before the page paints. Without it you get a light flash in dark mode. `mantineHtmlProps` adds `suppressHydrationWarning`, because the script changes the attribute before React hydrates.
- Mantine's components ship with `'use client'`, so a Server Component can render `<Button>` and `<Title>`. **Compound components** (`Tabs.Tab`, `Menu.Item`) don't work there, because property access on a client reference isn't supported. Import `TabsTab` and `MenuItem` instead, or move the piece into a `'use client'` file.
- Hooks (`useDisclosure`, `useForm`, `useMantineColorScheme`) and event handlers always need a client component.
- Mantine 7+ uses plain CSS (CSS Modules plus CSS variables), not Emotion, so there's no style registry and no runtime CSS-in-JS cost. Add `postcss-preset-mantine` to get `light-dark()`, the `rem()` function and breakpoint mixins in your own `.module.css` files.

**Theming**

```ts
// app/theme.ts
import { Button, createTheme, TextInput } from '@mantine/core';

export const theme = createTheme({
  primaryColor: 'brand',
  colors: { brand: ['#eef3ff', '#dce4f5', /* … 10 shades … */ '#1d3a8a'] },  // exactly 10 shades
  fontFamily: 'Inter, sans-serif',
  defaultRadius: 'sm',
  components: {
    Button: Button.extend({ defaultProps: { radius: 'md' } }),
    TextInput: TextInput.extend({ classNames: { label: 'formLabel' } }),
  },
});
```

The theme becomes CSS variables (`--mantine-color-brand-6`, `--mantine-spacing-md`, `--mantine-primary-color-filled`), so your own CSS and Tailwind can reuse them.

**Styles API.** Every component has named inner parts (`root`, `label`, `input`, `section`…) listed in its docs:

```tsx
<TextInput classNames={{ input: classes.input, label: classes.label }} />   // preferred: CSS Modules
<TextInput styles={{ input: { fontFamily: 'monospace' } }} />               // inline styles, for one-offs
<Button vars={() => ({ root: { '--button-height': '2rem' } })} />           // component CSS variables
```

Components expose state as data attributes (`data-disabled`, `data-variant`, `data-error`), which you target in CSS: `.input[data-error] { … }`. Use `theme.components` for app-wide defaults and `classNames` for local variations. Avoid deep descendant selectors into Mantine's internal markup, because they break on upgrades.

**Mantine and Tailwind together.** Both libraries style the same elements, and Tailwind's preflight resets buttons and headings. Use **CSS cascade layers** to set a deterministic order:

```css
/* app/globals.css (Tailwind v4) */
@layer theme, base, mantine, components, utilities;   /* utilities win over Mantine */
@import 'tailwindcss';
@import '@mantine/core/styles.layer.css';             /* Mantine's CSS inside @layer mantine */

@custom-variant dark (&:where([data-mantine-color-scheme='dark'], [data-mantine-color-scheme='dark'] *));

@theme {
  --color-brand: var(--mantine-color-brand-6);         /* bg-brand, text-brand reuse Mantine's tokens */
}
```

- `className="mt-4 w-full"` on a Mantine component then reliably overrides its root styles. Inner parts still need `classNames={{ input: 'font-mono' }}`.
- One source of truth for colours and spacing is the Mantine theme. Tailwind only references its variables, so the two can't drift apart.
- Agree on a team rule, for example: Mantine for components and their variants, Tailwind for layout and spacing around them. Mixing both on the same concern makes reviews painful (#271, #458).

**Useful packages:** `@mantine/hooks` (`useDisclosure`, `useDebouncedValue`, `useMediaQuery`), `@mantine/notifications`, `@mantine/modals` (`modals.openConfirmModal` for "Are you sure?" dialogs), `@mantine/dates` (date pickers; dayjs-based, and Mantine 8 uses `YYYY-MM-DD` strings instead of `Date` objects), and `@mantine/dropzone` for file uploads (#651).

**Follow-up:** "`useMediaQuery` returns the wrong value on the first render. Why?" On the server there is no window, so it starts with the initial value (default `false`) and updates after hydration. Prefer CSS breakpoints or Mantine's `hiddenFrom`/`visibleFrom` props for layout. Use the hook only for behaviour, and pass `getInitialValueInEffect` so the server and client agree.
