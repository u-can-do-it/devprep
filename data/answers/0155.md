## Hints

- Does `...` collect values or spread them out? How can you tell from where it appears?
- Is a copy made with object spread deep or shallow?
- When does a default value in destructuring apply: for `undefined`, for `null`, or for both?

## Answer

The same `...` syntax does two opposite things, depending on where it is used:

- **Spread** expands an iterable or object into separate elements: in array literals, object literals and function calls.
- **Rest** collects the remaining items into an array or object: in function parameters and destructuring patterns. It must come last.

```js
const nums = [1, 2, 3];
Math.max(...nums);                    // spread into arguments
const copy = [...nums, 4];            // spread into a new array
const user2 = { ...user, name: 'Bo' }; // later keys win

function log(level, ...messages) {}   // rest parameter
const [first, ...others] = nums;      // first = 1, others = [2, 3]
const { password, ...safeUser } = user; // drop a field
```

Object spread makes a **shallow** copy. It copies only own enumerable properties, calls getters (storing their values), and loses the prototype, so class instances become plain objects.

**Destructuring** pulls values out by position (arrays) or by name (objects). You can rename, nest and give defaults:

```js
const { id, profile: { city = 'Unknown' } = {}, role: userRole = 'guest' } = user;
const [a = 1, b = 2] = [undefined, null]; // a = 1, b = null
[x, y] = [y, x];                          // swap
```

A default applies **only when the value is `undefined`**, not when it is `null`.

A common pattern is an options object with defaults:

```js
function connect({ host = 'localhost', port = 5432 } = {}) {}
```

The `= {}` at the end lets you call `connect()` without arguments. Without it, destructuring `undefined` throws.
