## Hints

- How many different places could a piece of data be cached between your database and the user's screen?
- After a user submits a form, how do you make sure they see their own change immediately?
- What changed about caching defaults between Next.js 14, 15 and 16?

## Answer

Next.js caches at several layers. A strong answer names them and how each is invalidated.

**1. Request memoization** — within a single server render, identical `fetch` calls (and functions wrapped in React's `cache()`) are deduplicated. It lasts one request; there's nothing to invalidate.

**2. Data cache** — persistent cache of fetch results or cached functions, shared across requests and users until it expires or is invalidated.

**3. Full route cache** — prerendered HTML + RSC payload for static routes, built at build time or by ISR.

**4. Client router cache** — the browser keeps RSC payloads of visited/prefetched segments for instant back/forward navigation. Cleared by `router.refresh()` or by revalidation in a Server Action.

**Defaults have changed.** Next.js 14 cached `fetch` aggressively by default. Next.js 15 made `fetch`, GET Route Handlers and client page segments **uncached by default** (opt in with `cache: 'force-cache'` or `next: { revalidate }`). Next.js 16 made **Cache Components** stable (it started as the experimental `dynamicIO` flag): with it enabled, everything is dynamic unless you explicitly mark it with the `'use cache'` directive:

```ts
async function getProducts() {
  'use cache';
  cacheLife('hours');      // time-based freshness profile
  cacheTag('products');    // label for on-demand invalidation
  return db.product.findMany();
}
```

**Revalidation:**

- **Time-based** — `revalidate` / `cacheLife`; stale-while-revalidate, so one request still gets stale data.
- **On-demand by tag** — `revalidateTag('products', 'max')` marks it stale (stale-while-revalidate; good for webhooks from a CMS). `updateTag('products')` inside a Server Action expires it immediately so the user **reads their own write**.
- **On-demand by path** — `revalidatePath('/products')`.

```ts
'use server';
export async function addProduct(data: FormData) {
  await db.product.create(/* ... */);
  updateTag('products');
}
```

**Pitfalls:** personalized data accidentally cached for everyone; one `cookies()` call in a layout making the whole tree dynamic; forgetting the client router cache when debugging "stale" UI; self-hosting on multiple instances without a shared cache handler.

**Follow-up:** explain how you'd debug stale data — check which layer serves it, using response headers like `x-nextjs-cache` and build output that marks routes as static or dynamic.
