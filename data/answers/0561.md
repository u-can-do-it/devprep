## Hints

- When you write `b = a`, is the data copied, or only something that points to it?
- If a method changes a `struct` parameter, does the caller see the change? And for a `class`?
- Is "structs live on the stack" always true? Where does a `struct` field of a class live?

## Answer

**The difference is what a variable holds:**

- A **value type** variable holds the **data itself**. Assignment and passing to a method **copy** the whole value. Value types: `int`, `double`, `bool`, `char`, `decimal`, `DateTime`, enums, `struct`s, tuples (`(int, string)`).
- A **reference type** variable holds a **reference** (an address) to an object on the managed heap. Assignment copies the reference, so both variables point to the **same object**. Reference types: `class`, `string`, arrays, delegates, `record` (class), interfaces.

```csharp
struct PointS { public int X; }
class  PointC { public int X; }

var s1 = new PointS { X = 1 };
var s2 = s1;          // copy of the data
s2.X = 99;            // s1.X is still 1

var c1 = new PointC { X = 1 };
var c2 = c1;          // copy of the reference
c2.X = 99;            // c1.X is now 99: same object

void Move(PointC p) { p.X = 5; p = new PointC(); }   // first line changes the caller's object,
                                                     // the second only rebinds the local copy of the reference
```

**Passing to methods:** by default C# passes **everything by value**. For a struct that's a copy of the data; for a class it's a copy of the reference, so the method can mutate the object but can't make the caller's variable point to a different one. To pass the variable itself, use `ref` (#573).

**Stack vs heap, precisely:** a value type lives **where it's declared**. A local `int` lives on the stack (or in a register); an `int` field of a class lives on the heap, inside that object. Reference type objects always live on the heap and are cleaned up by the GC (#591). Converting a value type to `object` or an interface copies it to the heap (boxing, #562).

| | `struct` | `class` |
|---|---|---|
| Assignment | copies data | copies reference |
| `null` | no (unless `Nullable<T>`, #569) | yes |
| Inheritance | none (can implement interfaces) | yes |
| Default equality | compares field values | compares references |
| Good for | small, immutable values: `Money`, `Point` | entities, services, anything with identity |

**Rule of thumb:** use a `class` by default. Use a `struct` for small (around 16 bytes or less), immutable values; a large mutable struct gets copied on every pass and changes get lost on copies. Mark it `readonly struct` to prevent mutation.

**Follow-up:** why is `string` a reference type that behaves like a value? (It's immutable and overrides `==` to compare contents, so sharing references is safe; see #563.)
