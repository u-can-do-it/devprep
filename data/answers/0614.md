## Hints

- What is `default(OrderStatus)`, and what happens if you cast `42` to it?
- Why must `[Flags]` values be powers of two, and what should `0` mean?
- If you insert a new member in the middle of an enum, what happens to the rows already stored as integers?

## Answer

**Basics.** An enum is a set of named integer constants. The underlying type is `int` unless you say otherwise, values start at 0 and count up, and **any** integer converts to the enum, named or not:

```csharp
public enum OrderStatus : byte            // smaller storage; int is the default
{
    Unknown = 0,                          // 0 is what default(T), new T[n] and a missing JSON field give: make it mean "not set"
    Pending = 10,                         // explicit values: members can be inserted later, stored values stay stable
    Paid = 20,
    Shipped = 30,
}

OrderStatus s = default;                  // Unknown
var bad = (OrderStatus)42;                // compiles and runs; Enum.IsDefined(bad) is false
Console.WriteLine(bad);                   // "42"
```

- Comparisons and `switch` are plain integer operations. `ToString()` and `Enum.Parse` go through cached reflection data and are slower than they look in a hot loop. A `switch` over an enum still needs a `_` arm (#580), because undefined values exist.
- Give every member an explicit value and never renumber: integers already stored keep their old meaning.

**`[Flags]`:** an enum used as a bit set.

```csharp
[Flags]
public enum Permissions
{
    None   = 0,
    Read   = 1 << 0,
    Write  = 1 << 1,
    Delete = 1 << 2,
    All    = Read | Write | Delete,
}

var p = Permissions.Read | Permissions.Write;
bool canWrite = (p & Permissions.Write) != 0;        // or p.HasFlag(Permissions.Write): no boxing since .NET Core 2.1
p &= ~Permissions.Write;                             // remove a flag
Console.WriteLine(Permissions.Read | Permissions.Delete);   // "Read, Delete": [Flags] changes ToString and parsing, nothing else
```

Rules: powers of two, `None = 0`, named combinations are fine. The bit operators work without the attribute; `[Flags]` only makes names print and parse as a list.

**Parsing and validating input**

```csharp
if (Enum.TryParse<OrderStatus>(input, ignoreCase: true, out var status) && Enum.IsDefined(status))
    order.Status = status;
```

`TryParse` also accepts **numeric strings** (`"42"` succeeds and yields an undefined value), so pair it with `Enum.IsDefined`. `Enum.GetValues<T>()` and `Enum.GetNames<T>()` list the members, for dropdowns and tests.

**In API contracts:** send enums as **strings** (`"status": "paid"`), not numbers: readable, stable when values change, and self-describing in OpenAPI. Configure `JsonStringEnumConverter` once (#607). Adding a member is a **breaking change for strict clients**: an old client that doesn't know `"refunded"` fails to deserialize. Version the contract, or document that unknown values can appear and let clients fall back to `Unknown`.

**In the database:** EF Core stores an enum as its integer by default: compact, but opaque in SQL and silently corrupted by renumbering. `.HasConversion<string>()` stores the name instead (readable, robust to renumbering, breaks on rename), and Npgsql can map PostgreSQL native enum types. Add a `CHECK` constraint if the database must reject unknown values.

**When an enum isn't enough: smart enums**

An enum can't carry data or behaviour, so display names end up in `switch` statements or in `[Description]` attributes read by reflection (#612), and the rules about each member spread across the codebase. A **smart enum** (enumeration class) is a class with a fixed set of static instances:

```csharp
public sealed class ShippingMethod
{
    public static readonly ShippingMethod Standard = new(1, "Standard", days: 5, price: 4.99m);
    public static readonly ShippingMethod Express  = new(2, "Express", days: 1, price: 14.99m);
    public static readonly IReadOnlyList<ShippingMethod> All = [Standard, Express];

    private ShippingMethod(int id, string name, int days, decimal price) =>
        (Id, Name, Days, Price) = (id, name, days, price);

    public int Id { get; }
    public string Name { get; }
    public int Days { get; }
    public decimal Price { get; }

    public static ShippingMethod FromId(int id) => All.First(m => m.Id == id);
}
```

Ardalis.SmartEnum packages this pattern; EF Core maps it with a value converter on `Id`. Use a plain enum for a simple closed set of states, and a smart enum (or a record hierarchy with pattern matching, #580) when members carry data or behaviour. Don't over-reach: an enum plus a small extension method (`status.DisplayName()`) is often all you need.

**Follow-up:** why does `ToString()` on a `[Flags]` value sometimes print a number? (When the bits don't match any combination of named members, e.g. an undefined bit is set, there's no name to print, so you get the integer. The same happens for any enum holding an undefined value.)
