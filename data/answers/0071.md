## Hints

- Which of these keep insertion order, and which allow duplicates?
- What's the time complexity of `x in my_list` compared with `x in my_set`?
- Which ones can be used as dictionary keys, and why?

## Answer

| Type | Ordered | Mutable | Duplicates | Lookup `in` |
|------|---------|---------|------------|-------------|
| `list` | yes | yes | yes | O(n) |
| `tuple` | yes | no | yes | O(n) |
| `set` | no | yes | no | O(1) avg |
| `dict` | insertion order (3.7+) | yes | unique keys | O(1) avg by key |

When to use which:

- **list** – an ordered, changing sequence of items: results, queues of work, things you append to and iterate.
- **tuple** – a fixed group of values, like a record or return value (`return lat, lng`). Immutable and hashable (if its items are), so it can be a dict key or set member. Slightly lighter than a list.
- **set** – uniqueness and fast membership tests, deduplication, set algebra (`a & b`, `a | b`, `a - b`).
- **dict** – mapping keys to values: lookups by id, counting, grouping, JSON-like data.

```python
seen = set()
for user_id in events:
    if user_id in seen:      # O(1) instead of O(n) with a list
        continue
    seen.add(user_id)

counts: dict[str, int] = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1
```

Also worth mentioning: `collections.deque` for fast pops from both ends, `Counter`, `defaultdict`, `frozenset`, and `NamedTuple`/dataclasses when a tuple's fields need names.
