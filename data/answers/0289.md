## Hints

- What does the browser show while a custom font is still downloading?
- Why does text sometimes "jump" when the web font finally arrives?
- Do you need every weight, style and character set of a font on every page?

## Answer

**The problem.** Fonts are discovered late: only after the CSS has been parsed **and** text that uses the font is found. While the font downloads, browsers either:

- hide the text (**FOIT**, flash of invisible text), which delays FCP and LCP, or
- show a fallback font and swap it later (**FOUT**, flash of unstyled text), which causes **layout shift** (CLS) when the metrics differ.

**`font-display`** controls the trade-off:

| Value | Block period | Swap period | Use |
|---|---|---|---|
| `block` | ~3 s | Infinite | Icon fonts (avoid) |
| `swap` | Very short | Infinite | Brand fonts that must appear |
| `fallback` | ~100 ms | ~3 s | Compromise |
| `optional` | ~100 ms | None: used only if already available | Best for CLS and LCP. Text fonts on slow networks |

**Loading fonts well:**

1. **Self-host WOFF2.** Browsers now partition the HTTP cache per site, so a shared CDN no longer gives a cache benefit, and self-hosting saves connections.
2. **Subset** to the characters you need and split with `unicode-range`. Ship only the weights you use, or one **variable font** instead of many files.
3. **Preload** the one or two most critical files (`<link rel="preload" as="font" type="font/woff2" crossorigin>`).
4. **Match the fallback's metrics** to cut CLS from swapping:

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-var.woff2") format("woff2");
  font-display: swap;
}
@font-face {
  font-family: "Inter Fallback";
  src: local("Arial");
  size-adjust: 107%;
  ascent-override: 90%;
  descent-override: 22%;
  line-gap-override: 0%;
}
body { font-family: "Inter", "Inter Fallback", system-ui, sans-serif; }
```

Tools generate these values for you. **`next/font`** and Fontaine/Capsize do it automatically, and `next/font` also self-hosts and preloads.

5. Consider a **system font stack** (`system-ui`) for body text. It costs nothing to load.
6. Use the CSS Font Loading API (`document.fonts.ready`) when JavaScript measures text, for example in canvas or virtualized lists.

**Pitfalls:** loading fonts through a third-party CSS `@import` chain (a render-blocking waterfall), icon fonts instead of SVG (accessibility problems and FOIT), and preloading fonts the page doesn't use.

**Follow-up:** check the DevTools Network panel for font requests that start late, and the CLS debugger in the Performance panel for shifts caused by the font swap.
