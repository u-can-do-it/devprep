## Hints

- Can you call a hook outside a component?
- Your component calls `useSelector` and `useNavigate`. What does the test have to provide?
- Why should each test get a fresh store and a fresh query cache?

## Answer

Hooks only run inside components, and most components depend on **providers**: a Redux store, a router, a TanStack Query client, a theme or i18n. Tests need the same context, but isolated per test.

**1. Testing a custom hook with `renderHook`** (from `@testing-library/react`; the old `@testing-library/react-hooks` package is no longer needed):

```ts
import { renderHook, act } from '@testing-library/react';

test('useCounter increments', () => {
  const { result } = renderHook(() => useCounter(5));
  act(() => result.current.increment());
  expect(result.current.count).toBe(6);
});
```

Test hooks directly when they're **reusable logic** (`useDebounce`, `usePagination`). For hooks used by a single component, test through the component instead.

**2. A `renderWithProviders` helper** creates fresh providers for every test:

```tsx
export function renderWithProviders(
  ui: React.ReactElement,
  { preloadedState, route = '/' }: { preloadedState?: Partial<RootState>; route?: string } = {},
) {
  const store = setupStore(preloadedState);                         // new Redux store per test
  const queryClient = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  const Wrapper = ({ children }: { children: React.ReactNode }) => (
    <Provider store={store}>
      <QueryClientProvider client={queryClient}>
        <MemoryRouter initialEntries={[route]}>{children}</MemoryRouter>
      </QueryClientProvider>
    </Provider>
  );
  return { store, ...render(ui, { wrapper: Wrapper }) };
}

test('shows the cart count from the store', () => {
  renderWithProviders(<Header />, { preloadedState: { cart: { items: [{ id: 1, qty: 2 }] } } });
  expect(screen.getByRole('link', { name: /cart \(2\)/i })).toBeInTheDocument();
});
```

The same `wrapper` option works for `renderHook`.

**Guidelines:**

- **Use the real store and real reducers** with `preloadedState`, not a mocked `useSelector`. You test the actual integration and can still assert on `store.getState()` after interactions.
- **Fresh instances per test:** a shared store or `QueryClient` leaks state between tests. Turn off query retries so error tests don't wait.
- Mock the **network** (MSW), not the hooks.
- Assert on what the user sees (`getByRole`, `findByText`), and use `userEvent` for interactions.
- **Async:** prefer `findBy…` and `waitFor` over manual timeouts; wrap direct state changes from outside React in `act`.
