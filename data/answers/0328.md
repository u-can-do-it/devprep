## Hints

- How many engines and how many sessions should exist: per app, per request, or per query?
- What happens when you access a lazy-loaded relationship on an async session?
- Who commits the transaction, and what happens on an exception?

## Answer

Create **one engine (connection pool) per process** at startup, and **one `AsyncSession` per request** via a `yield` dependency.

```python
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager
from typing import Annotated
from fastapi import Depends, FastAPI
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import selectinload

engine = create_async_engine(settings.database_url,  # postgresql+asyncpg://...
                             pool_size=10, max_overflow=5, pool_pre_ping=True)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)

@asynccontextmanager
async def lifespan(app: FastAPI):
    yield
    await engine.dispose()

async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:
        async with session.begin():      # commit on success, rollback on error
            yield session

SessionDep = Annotated[AsyncSession, Depends(get_session)]

@app.get("/users/{uid}")
async def get_user(uid: int, session: SessionDep):
    stmt = select(User).where(User.id == uid).options(selectinload(User.orders))
    return (await session.scalars(stmt)).one_or_none()
```

Pitfalls:

- **Implicit lazy loading doesn't work** with async. Touching `user.orders` outside an eager load raises `MissingGreenlet`. Use `selectinload`/`joinedload`, `lazy="raise"` on relationships to catch it early, or `AsyncAttrs` with `await obj.awaitable_attrs.orders`.
- **`expire_on_commit=False`**, or attributes expire after commit and accessing them triggers I/O (often while Pydantic serializes the response).
- **Never share a session** across concurrent tasks. An `AsyncSession` isn't safe for `asyncio.gather` over the same session. Use one session per task.
- **Pool sizing**: pool × workers × replicas must fit the DB's `max_connections`. Use PgBouncer if needed. Long requests that hold a session exhaust the pool.
- Decide where the transaction boundary lives (dependency vs service layer) and keep it consistent. Don't commit in many places.
- Mixing sync SQLAlchemy in `async def` endpoints blocks the event loop.
- Use **Alembic** for migrations, never `create_all` in production.

**Follow-up:** With a `yield` dependency, does the commit happen before or after the response is sent? (By default, `yield` exit code runs **after** the response is sent, so a failed commit can follow a 200. Use `Depends(get_session, scope="function")` in recent FastAPI versions, or commit explicitly in the service before returning.)
